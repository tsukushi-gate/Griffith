1. MNISTを学習する

ただの論理ゲートの塊が、学習によって手書き数字を読めるようになる。 実数の重みも乗算も一切持たない 4000 個の AND / OR / XOR が、勾配降下で配線先の 真理値表を決めていくだけで、MNIST の 86% を当てるようになる ── それをこのページで 実際に走らせて確かめる。

道具立ては LutLayer 2段 + GroupSum + 普通の PyTorch 学習ループだけ。 回路の俯瞰図・学習曲線(soft/hard)・誤分類例の3枚で、 「学習された回路」がどんな姿をしているかを見る。

このページで学ぶこと

  1. LutLayer 2段 + GroupSum を普通の PyTorch 学習ループで回すだけで、論理ゲート4000個が手書き数字を読めるようになること
  2. soft(連続緩和)と hard(離散回路)の精度を必ず並べて見る理由と、その読み分け
  3. 学習された回路の姿 ── 俯瞰図・学習曲線・誤分類例の読み方

前提

  • 基本コンセプト — soft/hard・LutLayer・GroupSum・IR・HDL の5概念
  • 入門3. MLPをDLGNへ置き換える — NN が初めてならここから

このページについて

所要時間の目安: 約10分 / 実行環境: CPU のみ(GPU 不要) 元スクリプト: examples/06_mnist.py 手元で試す: notebooks/06_mnist.ipynb(このページと同じ内容の未実行ノートブック。uv run --group docs jupyter lab notebooks/ で開ける) コード出力はすべて 実際に実行した結果をそのまま埋め込んでいます。

▶ Colabで開く(リポジトリ公開後に有効化)

MNIST(20x20)を微分可能論理ゲート網で学習する例。

XOR(examples/01_xor.py)は4パターンの玩具問題だった。ここでは同じ道具立て (LutLayer + GroupSum + 普通のPyTorch学習ループ)のまま、入力400ビット・10クラスの 実データへスケールさせ、4000ゲートの回路が手書き数字を読むところまでを見る。

difflogic公式レシピ(6層×8000ゲート・200k iter)は論文水準97.7%に届くが、 GPUで数時間かかる。このサンプルはCPUで1〜2分に収まるよう 「2層×2000ゲート・訓練20000枚・4000 iter」へ縮めた縮小版で、 到達するhard accuracyは0.86前後になる(精度を狙うレシピは tests/l3_paper/test_dlgn_mnist.py の DLGN_FULL=1 を参照)。

このページで一番大事な概念は soft と hard の2つの姿である。

  • soft(学習時の姿) … 各ゲートは16種の論理関数の連続的な混合。微分できるので学習できるが、 この状態のままではハードウェアに焼けない
  • hard(回路としての姿) … 混合をargmaxで1種類に確定させた本物の論理回路。 推論はビット演算だけで済むが、微分はできない

学習はsoftで進め、実際に使うのはhard。したがって**両者の正解率の差(離散化ギャップ)**が 小さいことを常に確認する必要がある。以下の図はそのための道具立てになっている。

回路の全体像(XORと同じ形のまま、数だけ増やす)

畳み込みも行列積も無く、全体で4,000個の2入力ゲートしか無いことに注目してほしい。 そのうち実数が出てくるのは最後の GroupSum 以降だけである。

どう実現しているか

  • 1画素 = 1本の入力線。20×20の画像をそのまま400本のビット線として回路へ差し込む (28×28 の外周は difflogic 公式レシピと同じく黒枠として落としてある)
  • 1ゲートは前層の2本だけを見る。全結合ではなく、各ゲートの入力2本はランダムに選んで 固定する(疎結合)。だから2,000ゲートでもパラメータは 2000×16 = 32,000 で済む
  • クラス分けは「数える」だけ。GroupSum は2,000本の出力を200本ずつ10グループに分け、 各グループで1が立っている本数を数える。多いクラスがその画像の答えになる。 τ=10 はその本数を割る温度で、softmax をなだらかにして学習を安定させる
  • soft と hard の2つの姿。学習中(soft)は各ゲートが16種の論理関数の混合、 推論時(hard)は argmax で1種類に確定した本物の回路。 この例の主題は両者の差(離散化ギャップ)を測ること

実行: uv run python examples/06_mnist.py 期待結果: hard accuracy 0.86前後(assertは0.70で緩めに置いてある)

準備: import と乱数種

Section titled “準備: import と乱数種”

必要なのは PyTorch 一式と、本ライブラリの3つだけ。

  • LutLayer … 1ニューロン = 1枚の LUT(ルックアップテーブル=真理値表) になる層
  • GroupSum … 論理の世界からクラススコアへの出口(ビットをクラスごとに数える)
  • plot_circuit … 学習後のモデルを回路図として描く

専用の学習フレームワークは登場しない。以降の学習ループは普通の PyTorch そのものである。

ハイパーパラメータ

Section titled “ハイパーパラメータ”

K が最重要のつまみである。K は1層あたりのゲート数で、そのまま 「FPGA に焼いたときのゲート数」= ハードウェアの面積になる。実数 NN のチューニングでは 幅は精度と計算時間のトレードオフだが、論理ゲート網では幅 = 実装コストそのものであり、 精度と K のバランスを取ることがチューニングの中心になる。

データセット: 画像を400本のビット線として読む

Section titled “データセット: 画像を400本のビット線として読む”

MNIST の 28x28 から黒い縁を落とし、20x20 = 400 画素にしたものを使う (difflogic 論文の公式レシピと同じ前処理)。この 400 画素が、そのまま 回路の入力線 400 本になる ── 1画素 = 1本のワイヤ、という対応である。

binarize_threshold=None なので値は [0,1][0,1][0,1] の連続値のまま読み込む。 学習は連続値で行い、評価だけ round() でビットに落とす、というのが公式レシピの作法。

評価用の入力をビットに落とす

Section titled “評価用の入力をビットに落とす”

なぜ評価だけ二値化するのか ── hard eval は「実際に FPGA へ焼いた回路」を 模した測定である。回路の入力端子に入るのは信号線の High/Low だけなので、 0.37 のような実数を食わせた測定は現実の性能を過大評価してしまう。

モデル定義: LutLayer 2段 + GroupSum

Section titled “モデル定義: LutLayer 2段 + GroupSum”

このページで扱う回路は下の3行がすべてである(合計 4,000 ゲート)。

  • LutLayer(400, K, n_inputs=2) … 400本の入力線のうち2本だけを見るゲートを K 個並べる。どの2本を見るか(配線)は初期化時にランダムに決めて固定し、 学習で動くのは「その2入力に対する真理値表」だけ
  • 2段目の LutLayer(K, K) … XOR のような複雑な論理は、このゲートの合成で作られる
  • GroupSum(k=10, tau=10.0) … 最終2000ビットを10クラス×200本に分け、 各組で1が立っている本数を数える。tau はその本数を割る温度で、 大きいほど softmax がなだらかになり学習が安定する

なぜ全結合ではなく2入力なのか ── 2入力の論理関数は全部で16種類しかないので、 「16種への重み付け」を学習すれば微分できる(1ゲート16パラメータ)。 全結合にすると真理値表が指数的に爆発して、この筋が使えなくなる。

学習: 普通のPyTorchループでsoft/hardを両方測る

Section titled “学習: 普通のPyTorchループでsoft/hardを両方測る”

学習の中身は完全に普通の PyTorch(cross_entropy + Adam)で、論理ゲート網で あることを意識する箇所はどこにもない。そこがこの手法の実用上の利点である。

唯一の作法が model.train() / model.eval() の使い分けで、これが soft / hard の 切り替えスイッチになっている。BatchNorm のような統計の話ではなく、 eval() でモデルの数学そのものが「16種の混合」から「argmax で確定した1種」へ変わる。 だから両方を毎回測り、その差(離散化ギャップ)を監視する。

可視化: 学習された回路の姿を見る

Section titled “可視化: 学習された回路の姿を見る”

読み取り: 上のログで soft と hard がほぼ並んで上がり、最終的に hard accuracy が 0.86 前後に達している。実数の重みも乗算も一切持たない 4,000 個のゲートが、 手書き数字の 86% を当てられるということ。以下、この回路の姿を3枚の図で見ていく。

図1: 学習した回路の俯瞰

Section titled “図1: 学習した回路の俯瞰”

まず全体像。ゲートが4,000個あるので全ノードは描けず、plot_circuit は自動的に 俯瞰図(層=箱、間の矢印=配線本数)へ切り替わる。 付録: XOR の全ノード描画と見比べると、同じ API が規模に応じて 表示を変えていることが分かる。

読み取り: 400本の入力線が2つの LutLayer(各2,000ゲート)を通り、 GroupSum で10クラスへ落ちる、という一本道であることが確認できる。 分岐も畳み込みも正規化も無い ── この単純さのまま 86% が出ている。

図2: 学習曲線(soft と hard)

Section titled “図2: 学習曲線(soft と hard)”

soft(橙)と hard(緑)の2本を重ねる。hard が本命で、これが焼ける回路の成績である。 2本の隙間が離散化ギャップ。

読み取り: 序盤で少し開いた2本の差が、学習が進むにつれて閉じていく。 つまり「学習中のモデル」と「焼いたあとの回路」が同じものへ収束しており、 そのまま回路として取り出してよい状態にある。もし橙だけが上がって緑が付いてこないなら、 ゲートの混合が中間状態に居座っている(どの論理関数か決めきれていない)サインで、 学習量・tau・パラメータ化を疑うことになる。

図3: 回路が間違えた数字

Section titled “図3: 回路が間違えた数字”

hard eval で外した10枚を、回路が実際に受け取ったビット列(round 後)のまま表示する。 前処理後の姿で見ないと「なぜ間違えたか」を判断できないためである。

読み取り: 並ぶのは 4 と 9、7 と 1、5 と 3 のように人間でも紛らわしいペアが中心で、 回路が形をまともに捉えていることが分かる。無関係なペア(0 を 7 と読む等)ばかりなら、 学習不足を疑うところである。

評価を掘り下げる: 弱点と判断のキレ

Section titled “評価を掘り下げる: 弱点と判断のキレ”

全体の正解率という1つの数字では、「どのクラスが弱いか」も「どれくらい自信を持って 答えているか」も分からない。そこで2つの量を追加で測る。

  • クラス別 hard 正解率 … 苦手な数字を特定する
  • マージン … 1位のロジット −-− 2位のロジット。その1枚をどれだけ引き離して 選べたかを表す。GroupSum のロジットは「そのクラスの200ゲートのうち何本が1を出したか」を tau で割った値なので、マージンは素朴に票差として読める

マージンを soft と hard で並べると、離散化で判断のキレがどれだけ失われたかを 精度の数字とは別の角度から測れる。

図4の下ごしらえ: クラス別正解率とマージンを計算する

Section titled “図4の下ごしらえ: クラス別正解率とマージンを計算する”

図4: どのクラスが苦手か(左)と、判断のキレ(右)

Section titled “図4: どのクラスが苦手か(左)と、判断のキレ(右)”

左はクラス別の hard 正解率(破線=全体平均、橙=最も苦手なクラス)、 右はマージンのヒストグラム(橙の塗り=soft、緑の輪郭=hard)。

読み取り(この図が最後なので先に書く): 左では 0 や 1 が易しく、 8・5・2 のように「形の似た仲間が多い」クラスが沈む ── 全体の正解率1つでは 見えない偏りがここで初めて見える。右では soft と hard の分布がほぼ重なる。 これは離散化しても判断のキレが失われていない、つまりそのまま回路にしてよい、という意味である。 もし hard 側だけが 0 付近へ寄っていたら、argmax で情報が落ちているサインになる。

画像を96ビットに畳む — 二値潜在VAE

VAE の再パラメータ化トリック(ガウス潜在の乗算と平方根)を捨てる。 代わりに潜在を「比較器そのもの」である Bernoulli ビット列に置き換えると、 VAE がまるごと論理回路に乗る ── 196画素の数字を 96ビットへ畳んで復元する。

recon BCE 43.27 / 画素一致率 0.907。再構成は数字としてはっきり読める。 潜在1ビットを反転すると画像がどう変わるかの差分図(赤=点灯・青=消灯)で、 96本のビットそれぞれが何を担当しているのかを覗く。

  3. 潜在1ビットを反転した差分図から「各ビットが何を担当しているか」を読む方法

LogicVAE — 二値潜在VAEを論理ゲートだけで組む例。

06_mnist.py の識別器は「画像 → クラス」の一方向だった。ここでは逆向き、 回路から画像を作る側へ踏み込む。VAE(変分オートエンコーダ)を LutLayer スタックだけで構成し、画像を 96ビットの潜在ビット列 に圧縮してから 復元する。

なぜ「二値潜在」なのか(この例の主題): 普通のVAEの潜在は連続ガウスで、再パラメータ化 z = μ + σ·ε に 乗算と平方根 が要る。論理回路にとってこれは最悪の相手で、そのままでは回路に落ちない。 LogicVAE は潜在を Bernoulli ビット列に取り替えることでこの壁を回避する。 Bernoulli サンプリングは u ~ U(0,1) に対する z = 1{q > u} —— つまり 確率的なしきい値比較 = 比較器 であり、論理回路そのものである。 勾配は straight-through(forward=比較器 / backward=σの勾配)で エンコーダまで流す(griffith_logic/models/logic_vae.py の _STBernoulli 参照)。

全体データフロー(実クラス名つき)

Section titled “全体データフロー(実クラス名つき)”

緑が ビットのまま進む論理回路、橙が 実数が現れる場所、青が 実数をビットへ落とす比較器。実数はロジット(=足し算の結果)としてしか現れず、 比較器を通した瞬間にビットへ戻る。

どう実現しているか(4行で)

Section titled “どう実現しているか(4行で)”
  1. エンコーダ。画素を Thermometer 符号(明るさを「棒温度計」の 0/1 列にする)で ビット化し、LutLayer のスタックへ通す。最後に GroupSum が「1になったゲートの本数」を 数え、96本ぶんの実数ロジットにする。
  2. 連続値を確率とみなす。ロジットに sigmoid をかけた q = σ(ロジット) を、 そのまま「そのビットが1になる確率」と読む。ガウス潜在のように平均と分散の 2本を持たず、確率1本だけを持つのがビット潜在の身軽さ。
  3. 比較器でビットにする。一様乱数 u を1つ引き、z = 1 if q > u とする。これは Bernoulli(q) からの厳密なサンプルであると同時に、しきい値比較=比較器そのもの。 推論時は乱数生成器と比較器1個で済む。勾配は straight-through で、前向きは ハードなビット・後ろ向きは ∂q/∂ロジット = q(1−q) を流す。
  4. デコーダと損失。96ビットを LutLayer スタックへ通し、GroupSum で画素ロジットへ。 損失は ELBO = recon + β·KL で、recon は画素の BCE、KL は KL(Bern(q) ‖ Bern(0.5)) = q·log(q/0.5) + (1−q)·log((1−q)/0.5) という閉じた式 (積分もサンプリングも要らない)。

初めて見る言葉:

  • 潜在(latent) — 画像を圧縮した「中身の表現」。ここでは96ビットの列。
  • ロジット — 「大きいほど1らしい」という実数のスコア。sigmoid で確率になる。
  • straight-through(ST) — 前向きは離散化した値を使い、後ろ向きは滑らかな近似の 勾配を流すテクニック。離散サンプリングで勾配が切れるのを防ぐ。
  • KL — 2つの確率分布のズレの量。ここでは「潜在ビットが表裏五分五分(Bern(0.5))から どれだけ偏ったか」の値。

普通のVAEとの違い

Section titled “普通のVAEとの違い”
見るところ普通のVAELogicVAE
潜在の形連続ガウス z ∈ R^dビット列 z ∈ {0,1}^96
エンコーダの出力平均 μ と分散 σ² の2本1になる確率 q の1本
サンプリング再パラメータ化 z = μ + σ·ε(乗算と平方根)比較器 z = 1 if q > u

KL項ガウス同士の閉形式Bern(q) ‖ Bern(0.5) の閉形式
潜在の動かし方ベクトルを少しずらす(連続)ビットを反転する(離散)
必要な演算浮動小数の乗算真理値表引きと比較(実数は和だけ)

準備: import と乱数種

Section titled “準備: import と乱数種”

使うのは PyTorch と matplotlib、そして本ライブラリの LogicVAE(モデル本体)・ load_mnist(データ)・plot_circuit(回路描画)だけ。VAE のための特別な フレームワークは要らない。

先に言葉をそろえておく。

  • オートエンコーダ — 画像をいったん小さな表現へ押し込め、そこから元の画像を 復元するように学習するモデル。「押し込める側」をエンコーダ、「戻す側」をデコーダと呼ぶ。
  • VAE(変分オートエンコーダ) — オートエンコーダに「押し込めた表現を、あらかじめ 決めた分布(prior)へ近づける」という縛りを足したもの。この縛りがあるおかげで、学習後は 分布からランダムに引くだけで新しい画像を作れるようになる。
  • 潜在(latent) — 押し込めた先の表現そのもの。この例では 96 ビットの 0/1 の列。
  • 事前分布(prior) — 潜在が従ってほしい分布。ここでは全ビット表裏五分五分の Bernoulli(0.5)、つまり「96 回のコイン投げ」。

ハイパーパラメータとデータ

Section titled “ハイパーパラメータとデータ”

CPU で2〜3分に収まる縮小レシピ。IMG / LATENT / STEPS を増やすほど再構成は 綺麗になるが、ページの生成時間もそのまま延びる。

いちばん効くのは LATENT = 96 で、これが回路の情報の通り道の幅にあたる。 196 画素ぶんの絵は、必ずこの 96 本の線を通ってから復元される。 KL_WEIGHT は後の「学習」章で出てくる β(潜在を prior へ寄せる罰の重み)である。

データ: 14x14 の二値 MNIST

Section titled “データ: 14x14 の二値 MNIST”

手書き数字を 2値画像にして使う。VAE の再構成損失は画素ごとの BCE(後述)なので、 目標となる画素は厳密に 0 か 1 でなければならない。

28x28 のままだと 784 画素を 96 ビットへ落とすことになり、3000 step では形が潰れる。 2x2 平均プーリングで 14x14 = 196 画素に縮めてからしきい値 0.3 で二値化し、 「196 画素 → 96 ビット → 196 画素」という素直な圧縮問題にしている。

モデル: エンコーダ・比較器サンプラ・デコーダ

Section titled “モデル: エンコーダ・比較器サンプラ・デコーダ”

このページで使う記号は q / u / z の3つだけ。ここで一度に定義しておく。

  • q — エンコーダが出す、潜在の各ビットが 1 になる確率(0〜1 の実数)。 潜在は 96 ビットあるので、q も 96 本ぶんある。「この画像なら 3 番目のビットは 0.8 の確率で 1」という読み方をする値である。
  • u — サンプリングのために引く一様乱数(0〜1 のあいだから等確率で引く数)。 ビットごとに 1 個ずつ引くので、これも 96 本ぶん。
  • z — 実際にサンプリングされた潜在ビット列(96 個の 0/1)。作り方は z = 1 if u < q else 0 の 1 行だけ。q が大きいビットほど 1 になりやすい。

この u < q というたった 1 回の比較が、そのまま Bernoulli(q) からのサンプリングに なっている(Bernoulli = 表の出る確率が q のコイン投げ)。つまり **確率 q を持つ回路の実体は「乱数源 1 個と比較器 1 個」**であり、掛け算も指数関数も要らない。 後の図5の数直線は、まさにこの比較のようすを絵にしたものである。

なぜガウス潜在ではなく Bernoulli(二値潜在)なのか。 普通の VAE の潜在は実数ベクトルで、 サンプリングは 再パラメータ化(乱数を外から入れて微分可能にする常套手段) z = μ + σ·ε ── 乗算と平方根を含む式で行う。実数の潜在を選んだ時点で 回路の途中に浮動小数が居座ることになり、そのままではハードウェアに焼けない。 潜在をビット列に取り替えると、エンコーダの出口からデコーダの入口までがちょうど 96 本の配線になり、回路として綺麗に閉じる。

straight-through — 前向き(推論)では 0/1 に丸め、後ろ向き(勾配)だけは 丸めなかったことにして通す近似。離散化すると勾配は本来ゼロになって学習が止まるが、 この手口で「比較器の向こう側」へ勾配を届かせる。離散サンプリングを微分可能に扱う定番。

部品の名前も見ておく。

  • ThermometerEncoder — 明るさを「棒温度計」のように 0/1 の列へ変換する符号化。 1 画素を 4 ビットにするので 196 画素 → 784 ビットになる。
  • GroupSum — 論理ゲートの出口。出力ビットを k 組に分け、組ごとに 1 の本数を数えて 実数に変える。ここが「ビットの世界」と「実数の世界」の境目である。

評価関数: 純ブール回路として測る

Section titled “評価関数: 純ブール回路として測る”

品質は必ず hard eval の経路で測る。hard eval とは、各 LUT を argmax で 1 枚の 真理値表に確定させ、学習用の連続緩和を一切使わない状態のこと ── FPGA に焼くのと 同じ純粋な Boolean 回路として動かす、ということである。

見る数字は2つ。pix_acc は再構成画像を 0.5 でしきい値化したときの画素一致率。 active は潜在 96 ビットのうち「常時 0/常時 1 に張り付いていない」割合で、 posterior collapse(潜在が使われなくなり、デコーダが入力を無視して平均的な絵ばかり 出すようになる現象)が起きていないかの見張り役である。1.0 に近いほど健全。

学習: ELBO = recon + β·KL

Section titled “学習: ELBO = recon + β·KL”

損失は ELBO(evidence lower bound。VAE で最小化する標準の目的関数)で、中身は recon + β·KL という 2 項の足し算しかない。

  • recon(再構成項) — 元画像をどれだけ復元できたかの罰。画素ごとの BCE(binary cross entropy = 2値の食い違いを測る損失)の総和で測る。 実装は BCEWithLogits、つまり sigmoid を内側に畳み込んだ数値的に安定な版を使う。
  • KL(KL ダイバージェンス) — 2つの確率分布のズレの量。ここでは、エンコーダが出した 潜在分布 Bern(q) を prior の Bern(0.5) からどれだけ離したかの罰であり、平たく言えば 「潜在に情報を詰め込むためのコスト」。ビットが表裏五分五分から偏るほど高くつく。
  • β — その KL にかける重み(このコードでは KL_WEIGHT = 0.1)。大きくするほど潜在は prior に寄り、情報を捨てて生成寄りになる。小さくすると復元は良くなるが潜在が prior から 離れ、コイン投げからの生成が効かなくなる。

Bernoulli 同士の KL は q·log(q/0.5) + (1−q)·log((1−q)/0.5) という閉じた式で書けるので、積分も サンプリングも要らない。ガウス VAE と同じく、KL 項は 1 行で済む。

上のログで、recon が下がりながら KL が上がっていくのが見どころ。KL の上昇は 「潜在ビットを五分五分から偏らせて情報を詰め込んだ」ことの表れで、その対価として 再構成が良くなっている。2 項のせめぎ合いがそのまま学習の実体である。

active bits が 1.00 のまま推移していれば posterior collapse は起きておらず、 96 ビットが全部働いていることになる。

可視化: 再構成・ビット反転・生成

Section titled “可視化: 再構成・ビット反転・生成”

図1: 元画像 / 96ビット潜在 / 再構成

Section titled “図1: 元画像 / 96ビット潜在 / 再構成”

8 枚の数字について、上段に元画像、中段に潜在ビット列 z(96 ビットを 8x12 に 折り返して帯にしたもの)、下段に再構成を並べる。

見るべきは中段である。ここに写っているモノクロの点々が、回路が持ち歩いている情報の すべてであり、下段の絵はこの 96 個の 0/1 だけから作られている。

下段の再構成は数字として読める一方、線は元より太く、細かい跳ねは丸められている。 196 画素を 96 ビットへ落としているので、捨てられた情報が「細部」として消えている わけである。中段の帯を見比べると、同じ数字どうしでも帯の模様が違う ── 潜在は 「クラス」ではなく「この 1 枚の絵」を符号化している。

図2: 潜在ビットを1本ずつ反転する

Section titled “図2: 潜在ビットを1本ずつ反転する”

学習済みの潜在から 1 枚選び、先頭 8 ビットを 1 本ずつ反転して復号し直す。 上段が反転後の画像、下段がもとの画像との差分(赤=新たに点いた画素 / 青=消えた画素)。

なぜ「潜在を少し動かす」ができないのか。 連続潜在の VAE なら潜在ベクトルを わずかにずらして中間の絵を作れるが、二値潜在で許される操作は ビット反転しかない。 連続潜在の補間に相当するのがこの 1 ビット反転で、生成の操作が完全に離散に なっている。1 ビット反転とは、要するに回路への入力線 1 本の 0/1 を差し替えることである。

下段の差分を見ると、ビットごとに担当する場所がはっきり違うことが分かる。あるビットは 数字の上半分を、別のビットは左下の払いを塗り替える。1 本 1 本が画像のどこかの特徴を 受け持っており、96 ビットはただの圧縮結果ではなく部品として意味を持った表現になっている。 また 1 ビット動かしただけで絵が大きく飛ぶことがあるのも二値潜在の特徴で、 連続潜在のようなじわじわした変化は原理的に作れない。

図3: prior からの生成と、学習曲線

Section titled “図3: prior からの生成と、学習曲線”

1 枚目は prior Bernoulli(0.5) からの生成。つまり潜在 z を96 回のコイン投げで作り、 デコーダに通しただけのもの ── 訓練画像のどれとも違う新しい絵である。 2 枚目は学習曲線で、左軸に recon(橙)、右軸に KL(緑)を重ねている。

生成のほうは、3000 step の縮小レシピでは**「数字の種」が見え始める程度**で、はっきりした 数字にはならない。潜在が prior にまだ十分寄っていないためで、生成品質を狙うレシピは 本走スクリプト(experiments/train_logic_vae.py)を参照してほしい。

学習曲線のほうははっきりしている。KL が上がりながら recon が下がる ── 潜在ビットを 五分五分から偏らせる罰を払って、そのぶん復元を買っている。これが β のつまみで 調整している綱引きそのものである。

アーキテクチャ図解と実回路

Section titled “アーキテクチャ図解と実回路”

図の部品(ヘルパー関数)

Section titled “図の部品(ヘルパー関数)”

ここから先はアーキテクチャ図を描く準備。角丸の箱・矢印・図中に埋め込む小さな実データ画像の 3つを描く関数を用意する(図の見た目の都合だけなので、読み飛ばしてよい)。

図4: 端から端まで、実データを1枚流す

Section titled “図4: 端から端まで、実データを1枚流す”

実際の画像 1 枚がモデルを通り抜けるようすを、そのまま図にする。上段がエンコーダ (画像 → ビット → ゲート網 → 確率 q が 96 本)、下段がサンプラとデコーダ (q → 比較器 → 潜在ビット z → ゲート網 → 復元画像)。

図中の小さな画像は説明用のイラストではなく、このコードが計算した本物の値である。 箱の中の数字も実際のゲート数(= LutLayer の出力ニューロン数)。

配色はプロジェクト共通で、緑=論理ゲート(ビットのまま進む) / 橙=実数が現れる場所 / 青=比較器(実数をビットへ落とす) / 灰=データ。どこまでが回路として焼ける区間かを 色で追えるようにしてある。

橙の箱が 2 つしかないことがこの図の要点である。GroupSum が「1 になったゲートの本数」を 数えるところだけが実数で、あとは全部ビットのまま流れている。実数はロジット(=足し算の 結果)としてしか現れず、青い比較器を通った瞬間にビットへ戻る(= 周辺 FP 方針。実数を 回路の周辺部だけに追いやり、中心はビットで閉じる設計方針)。

上段の出口の q の絵と下段の z の絵を見比べると、なめらかな濃淡だった q が、比較器を 通った直後に白黒 96 個の点に変わっているのが分かる。ここがこの回路で唯一、実数が ビットになる場所である。

図5: 連続値がビットになる瞬間

Section titled “図5: 連続値がビットになる瞬間”

前の図の青い箱 ── 比較器の中身を数直線で拡大する。

左は潜在の先頭 10 ビットぶん。緑の帯の長さが q(そのビットが 1 になる確率)、 青い三角が引いた一様乱数 u の位置で、u が帯の中に落ちれば z = 1、外なら z = 0。 なぜ比較器 1 個で確率が作れるのか ── u < q というこの 1 回の比較が、そのまま Bernoulli(q) からのサンプリングだからである(乱数源 + 比較器 = 確率的ビット源)。

右は同じ 1 枚の画像についての 96 ビットぶんの q のヒストグラム。0 と 1 の両端に寄った ビットほど「乱数によらずほぼ決め打ち」で、真ん中付近のビットほど揺らぐ。

数直線の右側、q が 0 か 1 に振り切れたビットは、乱数 u をどこに引いても答えが変わらない。 学習が進むほどこうした「決め打ちビット」が増える一方、KL 項がそれを押し戻すので、 全ビットが振り切れることはない ── その均衡が β で決まっている。

図6: 学習済みデコーダの実回路

Section titled “図6: 学習済みデコーダの実回路”

最後に、ここまで「デコーダ」と呼んできたものの中身そのものを描く。

左は学習済みデコーダ。ゲートが 2,592 個あるので plot_circuit は俯瞰図 (層=箱・矢印=配線本数)へ自動で切り替わる。右は同じクラス・同じ配線規則で組んだ 縮小版(潜在 8 ビット → 2x2 画素、44 ゲート)で、こちらは 1 ノード = 1 個の LUT、 線 = 実際の配線をすべて描いている。

読み取りを先に書いておく。右の図で、左端に並ぶ 8 個の入力が潜在ビット z であり、 そこから右へ向かう配線の束がそのまま「デコーダ = 論理回路」の姿である。VAE のデコーダが 行列積の連なりではなくゲートと配線の網として存在していることが、この 1 枚で見て取れる。 縮小版は未学習なのでノードは LUT(16 種の論理関数の混合)のまま表示されるが、 学習が進むとこの 1 つ 1 つが AND / XOR などの具体的な論理関数に確定する。 左の俯瞰図の矢印に書かれた本数は、エンコーダの出口からここまで 96 本で閉じている という、この例の主題そのものを数字で示している。

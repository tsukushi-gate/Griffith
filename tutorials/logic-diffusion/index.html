拡散モデルを丸ごとブール回路にする

拡散モデルを丸ごとブール回路にする。前向き過程のノイズ付加は XOR、デノイザは LUT、逆過程のビット組み直しも論理演算 ── 生成の全工程が乗算なしで閉じる。

ベースラインの取り方まで含めて教材にしている: 当初 “denoise margin” を主指標に していたが、学習前から +0.26 出てしまう(=「全画素0」の自明解の分)ことが実測で判明した。 そこで blank(全画素0)ベースラインを明示し、「acc@t1 が blank を超える = 回路が xtx_txt​ を実際に読んでいる」を合格条件に据え直した。完全ノイズからの再構成が まだ blank 近傍に留まる現状も、誇張せずそのまま書いている。

このページで学ぶこと

  1. 前向き過程 = XOR、デノイザ = LUT、逆過程 = ビット組み直し、という拡散の論理化
  2. 自明解(全画素0)に勝てているかを判定する blank ベースラインの置き方
  3. 生成モデルの指標を「誇張せずに」報告するとはどういうことか

前提

  • 1. MNISTを学習する
  • 学習曲線の見方 — ベースラインの取り方

LogicBinaryDiffusion — 拡散モデルを丸ごとブール回路にする例。

拡散モデルの正体は「ノイズを足す前向き過程」と「ノイズを取り除く逆過程」の対である。 普通の拡散モデル(DDPM)は前向きにガウスノイズを足し、デノイザに巨大なU-Netを使う。 ここではその 3つ全部 を論理演算に置き換える:

先行研究の BDPM(Kinakh & Voloshynovskiy, arXiv:2501.13915)はXORノイズ拡散を提案したが、 デノイザ自体は通常のCNN/Transformerだった。デノイザまで論理ゲートで閉じた拡散モデルの 先行研究は 2026-09 時点で確認できていない(最近接は上記 BDPM)。主張の強度・最近接文献は 世界初主張の監査を参照し、対外的な文言はそちらの 限定形に従うこと(実装の詳細は griffith_logic/models/logic_diffusion.py の冒頭docstring を参照)。 乗算も浮動小数もどこにも現れず、生成の全工程がXORと真理値表引きだけで進む。

全体データフロー(実クラス名つき)

Section titled “全体データフロー(実クラス名つき)”

緑が ビットのまま進む経路(論理)、橙が 実数が現れる唯一の場所。 実数はゲートの出力を足してロジットにするところだけに現れ、しきい値を通すと すぐビットへ戻る(周辺FP方針)。

どう実現しているか(4行で)

Section titled “どう実現しているか(4行で)”
  1. ノイズを足す = XOR。反転率 p_t = 0.5·t/T のくじを引き、当たったビットだけ 0↔1 を入れ替える。t=T では半分のビットが反転し、完全にランダムなビット列になる。
  2. 時刻の伝え方 = thermometer 符号。t を「左から順に1が増える単調なビット列」に 直し、画像とチャネル方向に並べる。LUT は「今どれくらい壊れているか」を配線として読める。
  3. デノイザ = 論理回路。LogicUNet の全段が LutConv2d で、1出力は深さ2のLUT木 (リーフ4本 → ゲート3個)。受容野 3x3 × 入力チャネルからランダムに選ばれた 4本のビットだけを見て、1ビットを吐く。
  4. ノイズを取る = 事後分布からのXOR祖先サンプリング。予測 x0_hat と、いま何ビットが 反転しているかの指示子 d_t = (x_t ≠ x0_hat) から、1つ手前の指示子 d_prev の確率を 厳密に計算し、x_t-1 = x0_hat XOR d_prev を組み直す。

使う数式は3本だけ:

  • 前向き: x_t = x_0 ⊕ z_t、z_t 〜 Bernoulli(p_t)、p_t = 0.5·t/T
  • 1ステップ反転率 β: (1 − 2p_t) = (1 − 2p_t-1)(1 − 2β)
  • 事後分布: P(d_prev=1 | d_t) ∝ P(d_t | d_prev=1)·p_t-1

初めて見る言葉:

  • ロジット — 「大きいほど1らしい」という実数のスコア。sigmoid を通すと確率になる。
  • 祖先サンプリング — 逆過程を1ステップずつ確率的に巻き戻していく生成の作り方。
  • thermometer 符号 — 数を棒温度計のように「単調に増える 0/1 列」で表す符号化。

普通の拡散モデル(DDPM)との違い

Section titled “普通の拡散モデル(DDPM)との違い”
見るところ普通のDDPMLogicBinaryDiffusion
ノイズガウス雑音の加算 x_t = √ᾱ_t·x_0 + √(1−ᾱ_t)·εビット反転(XOR)
予測するもの乗せたノイズ εx_0 のビットそのもの

ページ末尾に、実データが流れるアーキテクチャ図と、学習後のデノイザから取り出した **実回路(LUT木)**の図を置いた。「どこが論理回路か」はそこで確認できる。

このサンプルの縮小レシピ: 本走(experiments/train_logic_diffusion.py)は 28x28 binary MNIST を4エポック回し、 acc@t1 0.886 に到達する。ここはCPUで3〜4分に収まるよう 「8x8 に縮小・T=8・訓練6000枚・1200 step」まで削った。 到達点は 「数字の塊としての形が見え始める」レベル であって、はっきりした 数字にはならない。生成品質を狙うレシピは本走スクリプトを参照。

ベースラインの読み方(この例で一番大事なところ): 二値画像の復元精度は、2つの自明解と比べないと意味を持たない。 - copy : 何もせず x_t をそのまま出す(t=T では ≈0.50) - blank : 全画素0と答える(= 1 − 前景率。この8x8データでは ≈0.75) 「精度0.84」のような数字は blank(0.75)を超えて初めて意味がある。 実測では低ノイズ(t=1)で 0.851 と blank(0.761)を明確に超える一方、 完全ノイズ(t=T)では 0.754 と blank 近傍に留まる —— つまり 回路は x_t を確かに読んでいるが、完全ノイズからの再構成はまだ 「MNISTらしい塊」を出すのが精一杯 である。これが現在地であり、誇張せず提示する。 (学習前は acc@t1 が blank と完全に一致する 0.761 から始まる。この動きを追うと 「自明解から抜け出した瞬間」が見える。)

実行: uv run python examples/17_logic_diffusion.py 期待結果(seed=0 実測・CPU約50秒): acc@t1=0.851(blank 0.761 / copy 0.938)、 acc@tT=0.754(copy 0.501)、生成画像の前景率 0.156(訓練データ 0.250)

準備: import と乱数種

Section titled “準備: import と乱数種”

使うのは PyTorch と matplotlib、そして本ライブラリから拡散モデル本体 (LogicBinaryDiffusion)・LUT畳み込み(LutConv2d)・MNIST・真理値表の取り出しだけ。 拡散モデル専用のフレームワークは要らない。

先に3つの言葉だけ決めておく。拡散モデル(DDPM) は「画像を少しずつ壊していく 前向き過程」と「壊れた画像から元を復元する 逆過程」の対で作る生成モデルで、 逆過程で復元を担当するネットワークを デノイザ と呼ぶ。このページはその3つ全部を 論理演算に置き換える。

ハイパーパラメータ

Section titled “ハイパーパラメータ”

t / T — t は拡散ステップ番号、T は総ステップ数(ここでは TIMESTEPS = 8)。 t=0 が元画像、t=T が完全に壊れた状態で、逆過程は t=T から t=0 へ1ステップずつ戻る。

データ: 二値 MNIST を 8x8 のビット列にする

Section titled “データ: 二値 MNIST を 8x8 のビット列にする”

x_0 — 元画像のビット列。学習データの画像を 0/1 に二値化したもので、この ページでは 8×8 = 64 ビットである。以降 x_0 と書いたら常にこれを指す。

データを二値にするのは趣味ではなく必然で、前向き過程が XOR だからである。 0.3 のような中間値は XOR できない —— 厳密に 0 か 1 でなければ演算が定義されない。

もうひとつ、28×28 のままでは学習が自明解に落ちる。前景(白い画素)が 13% しか ないので、デノイザは「全部 0 と答える」だけで 87% を取れてしまう。中央 24×24 を 3×3 平均プーリングで 8×8 へ潰すと前景率が 25% まで上がり、自明解が割に合わなくなる —— これがこの縮小レシピの肝である。

モデル: 拡散を作る3つの要素

Section titled “モデル: 拡散を作る3つの要素”

拡散モデルは「前向き過程 / デノイザ / 逆過程」の3点セットで決まり、ここではその全部が 論理演算に置き換わっている。以下がこのページで繰り返し出てくる記号である。

  • z_t — どのビットを反転させるかを決めたマスク(0/1 の「くじ」)。 z_t 〜 Bernoulli(p_t)、p_t = 0.5·t/T。Bernoulli は「確率 p で 1、 そうでなければ 0」を返すコイン投げの分布で、1 が立った位置のビットだけがひっくり返る
  • x_t — t ステップ分ノイズが乗った画像。x_t = x_0 XOR z_t。t が大きいほど 反転したビットが増え、t=T では半分が反転して完全なランダムビット列になる
  • β(1ステップ反転率) — 隣り合う2ステップの間で反転する確率。 (1 − 2p_t) = (1 − 2p_t-1)(1 − 2β) から決まる
  • 時刻ビット(thermometer 符号) — t を「左から順に 1 が増える単調なビット列」に したもの(棒温度計のイメージ)。画像とチャネル方向に並べて LUT に読ませることで、 回路は「今どれくらい壊れているか」を配線として受け取れる
  • logits(ロジット) — 「大きいほどそのビットは 1 らしい」という実数のスコア。 sigmoid を通すと確率になり、しきい値 > 0 でビットへ戻す。 このページで実数が現れるのはここだけである
  • x0_hat(x̂_0) — デノイザが予測した x_0 のビット列。x0_hat = (logits > 0)
  • d_t / d_prev — 「いま x_t と x̂_0 のどのビットが食い違っているか」を表す 反転指示子。d_t = (x_t ≠ x0_hat)。1つ手前の指示子 d_prev の確率を事後分布 (観測 d_t を見たうえでの d_prev の確率分布)から計算し、 x_t-1 = x0_hat XOR d_prev でビットを組み直す。これを t=T から t=0 まで繰り返すのが 祖先サンプリング(逆過程を1ステップずつ確率的に巻き戻す生成の作り方)である

学習と評価: 2つの自明解を基準にする

Section titled “学習と評価: 2つの自明解を基準にする”

二値画像の復元精度は、自明解と比べないと意味を持たない。ここでは2つ置く。

  • blank ベースライン — 「全画素 0 と答える」自明解。値は 1 − 前景率 (この 8x8 データでは約 0.75)。二値画像で一番騙されやすい相手
  • copy ベースライン — 「x_t をそのまま出して何もしない」自明解(t=T では約 0.50)

「精度 0.84」のような数字は、blank を超えて初めて「回路が入力を読んでいる」証拠になる。 測るときは hard eval(各 LUT を argmax で1つの論理関数に確定させた、FPGA に焼けるのと 同じ純ブール回路としての評価経路)を使う。

学習ループ

Section titled “学習ループ”

学習そのものは普通の PyTorchである。model.loss(x0) が「ランダムな t を引く → q_sample で XOR ノイズを乗せる → デノイザに x_0 を当てさせる → BCEWithLogits」を 一括でやってくれる。BCEWithLogits はロジットを直接受け取る2値クロスエントロピー損失で、 「各ビットが 1 か 0 か」を1ビットずつ当てにいく損失だと思えばよい。

予測する対象が「乗せたノイズ」ではなく x_0 のビットそのものである点が、普通の DDPM と 違うところ(x_0 予測型。先行研究 BDPM 準拠)。

上の数字の読み方はこうである。acc@t1 は blank を明確に超え、acc@tT は blank 近傍に 留まる。つまり低ノイズなら回路は確かに x_t のビットを読んでいるが、完全ノイズからの 再構成はまだ「MNIST らしい塊」を出すのが精一杯 —— これが現在地であり、誇張せず提示する。

可視化: 前向き過程と逆過程

Section titled “可視化: 前向き過程と逆過程”

図1: XOR でビットが壊れていく

Section titled “図1: XOR でビットが壊れていく”

なぜ XOR なのか。 ガウス拡散の「ノイズを足して、あとで引く」に対応するビット版の 演算が XOR である。XOR は自己逆元、つまり (x XOR z) XOR z = x が常に成り立つ。 ノイズを乗せる操作と取り除く操作がまったく同じ演算になるので、前向き過程と逆過程を 1つの演算で閉じられる。実数の足し算・引き算のように 0.5 のような中間値を作ることも ないので、画像がビットのまま壊れて、ビットのまま戻る。

下の図で見るのは、その壊れ方そのものである。行=4枚のサンプル、列=t=0(元画像)から t=T まで。t が進むごとに反転率 p_t = 0.5·t/T が上がり、反転したビットが増えていく。

ガウス拡散の「だんだんぼやける」とは見た目がまるで違い、ビットがパラパラと反転して いくのが XOR ノイズ拡散の壊れ方である。右端の t=T では反転率が 0.5、つまり元画像の 情報が消えた一様ランダムビット列になっている。ここが逆過程の出発点になる。

図2: 逆過程(完全ノイズ → 生成)

Section titled “図2: 逆過程(完全ノイズ → 生成)”

今度は逆向きに見る。行=サンプル、列=逆過程のステップで、一番左が Bernoulli(0.5) の 完全ノイズ、最後の列が生成結果である。1ステップの中身は「デノイザで x0_hat を予測 → 事後分布から d_prev を引く → x_t-1 = x0_hat XOR d_prev で組み直す」の繰り返し (= 祖先サンプリング)で、全工程が LUT 引きと XOR だけで進んでいる。

左端の一様ノイズが右へ進むほどまとまり、最後には数字らしい塊が浮かぶ。縮小レシピ なのではっきりした数字にはならないが、生成画像の前景率が訓練データの前景率に近い値へ 寄っていることが、「真っ黒にも真っ白にも潰れていない」ことの数値的な裏付けになる。

Section titled “可視化: 学習曲線とベースライン”

図3: 学習曲線を2つの自明解と一緒に見る

Section titled “図3: 学習曲線を2つの自明解と一緒に見る”

縦軸は hard eval での x_0 復元精度、横軸は学習ステップ。緑が低ノイズ(t=1)、橙が完全 ノイズ(t=T)、灰の破線が blank、灰の点線が copy。ベースラインを描かずに精度だけ出すと 数字の意味が読めなくなるので、この図では常に4本を一緒に描く。

緑は blank の破線を明確に追い越して伸びる = 回路は x_t のビットを実際に読んでいる。 一方の橙は blank 近傍に張り付いたままで、完全ノイズからの再構成が今後の課題であることが そのまま見える。緑が学習開始時に blank とぴったり一致する点から出発しているのも重要で、 そこから離れていく瞬間が「自明解から抜け出した瞬間」である。

アーキテクチャ図解と実回路

Section titled “アーキテクチャ図解と実回路”

ここからは「どこが論理回路なのか」を実データと実回路で確かめる。まずは図を描くための 小さなヘルパー(角丸の箱・矢印・小画像)を用意する。

図4: 逆過程の1ステップに実データを流す

Section titled “図4: 逆過程の1ステップに実データを流す”

上段は実際のテンソルが左から右へ流れる様子(x_0 → z_t → x_t → ロジット → x0_hat)、下段はデノイザの中身を開いたものである。色は緑=ビットのまま進む論理の 経路、橙=実数が現れる唯一の場所。

下段に出てくる部品を1行ずつ: LutConv2d は畳み込みの積和を LUT木(真理値表引き)に 置き換えた層、OrPooling は 2x2 の OR で解像度を半分にする論理版プーリング、 SpatialGroupSum は最終段の 8 本のビットを足してロジットにする出口である。 LutConv2d のゲート数は「出力チャネル数 × ツリー内部ノード数」で、同じ木が全空間位置で 使い回される(だから 8x8 でも 64x64 でもゲート数は変わらない)。

実数(橙)が現れるのは右端の SpatialGroupSum ただ1か所で、しきい値 > 0 を通すと すぐビットへ戻る。そして下段の全体が、上段の巨大に見える処理の正体である —— 巨大な U-Net の代わりに、数百ゲートの小さな回路が全画素位置で使い回されている。

図5: デノイザから取り出した実回路(LUT木)

Section titled “図5: デノイザから取り出した実回路(LUT木)”

最後に、学習後のデノイザから実際に取り出した回路を描く。LutConv2d の1出力は 「深さ2の LUT木」= ゲート3個・リーフ4本で、下の図の1枚がその1本の木にあたる。

読み取り方はこうである。灰色のリーフは受容野 3x3 と入力チャネルからランダムに 選ばれた入力配線で、x_t (+dy,+dx) と time bit k が同じ木に混ざって入っている —— つまり回路は画像ビットと時刻ビットを1つのゲートの中で突き合わせている。緑の箱は 学習後に argmax で確定した論理関数の名前(AND / XOR / NAND など)で、 ここに出る名前は IR や Verilog に焼かれる名前とそのまま同じである。 したがってこの絵は概念図ではなく、焼ける回路そのものを写したものになっている。

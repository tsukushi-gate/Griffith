乱数ビット列から画像を作る、そして壊す(LogicGAN)

物理乱数や LFSR からそのまま供給できる乱数ビット列を論理回路に通して画像を作る。 そして、壊す。安定化した設定(STABLE)と未調整の設定(NAIVE)を同一の初期回路から 学習させて並べ、敵対学習がどう壊れるかを実測で見せる。

差分は4つのつまみ(G:D=3:1 / D入力のビット反転ノイズ / label smoothing / D の学習率↓) だけ。未調整版は G loss が 7.22 まで発散し D 精度が 1.000 に張り付く ── Generator が 淘汰された状態。縮小レシピでは両条件ともモード崩壊(1/4)が起きることも隠さず出す。

このページで学ぶこと

  1. 物理乱数や LFSR から供給できる乱数ビット列を入力に、論理回路で画像を作る方法
  2. 敵対学習を安定させる4つのつまみ(更新比・入力ノイズ・label smoothing・D の学習率)
  3. 壊れた GAN の見分け方 ── G loss の発散と D 精度 1.000 の張り付き、モード崩壊

前提

  • VAE(二値潜在オートエンコーダ) — 敵対学習を使わない生成
  • 学習を回す

LogicGAN — 乱数ビット列から論理回路だけで画像を作る例(と、その壊れ方)。

18_logic_vae.py の生成は「潜在ビット → デコーダ回路 → 画像」だった。GAN では そこに Discriminator(判別器) が加わり、Generator と敵対的に競わせる。 LogicGAN はその両方を LutLayer スタックで組んだもので、Generator の入力は 連続ガウスノイズではなく 乱数ビット列 z ~ Bernoulli(0.5) —— 物理乱数源やLFSRでそのまま供給できる、論理回路にとって最も自然なノイズ源である。

全体データフロー(実クラス名つき)

Section titled “全体データフロー(実クラス名つき)”

緑が ビットのまま進む論理回路、橙が 実数が現れる場所(判別器の最後の和だけ)、 青が 乱数ビット源。生成の入口から出口まで、掛け算は1回も出てこない。

どう実現しているか(4行で)

Section titled “どう実現しているか(4行で)”
  1. ノイズ源 = コイン投げ。z は連続ガウスではなく Bernoulli(0.5) の64ビット。 u < 0.5 の比較器で作れるので、物理乱数源や LFSR(疑似乱数を作る小さな回路)を そのまま繋げる。
  2. Generator = LutLayer スタック。z は既にビットなので前処理(Thermometer 等)は不要。 最後の LutLayer の出力をそのまま画素にする。学習時は soft(連続値=画素確率)、 推論時は hard(純ブール回路)で厳密に 0/1 を吐く。
  3. Discriminator も論理回路。画素を LutLayer に通し、最後に GroupSum で 「1になったゲートの本数」を数えて real/fake のロジット1本にする。
  4. 勾配は soft 相を逆流する。学習中だけは各ゲートが16種の論理関数の重み付き和 (連続)なので、D → G へ勾配が流れる。焼き上がった回路は離散でも、 学習しているあいだは滑らかな影が並走している、という二重構造。

普通のGANとの違い

Section titled “普通のGANとの違い”
見るところ普通のGANLogicGAN
ノイズ z連続ガウス N(0, I)乱数ビット列 Bernoulli(0.5)
Generator転置畳み込み+BatchNorm(積和)LutLayer スタック(真理値表引き)
出力連続画素画素ビット 0/1(推論時は厳密に離散)
DiscriminatorCNNLutLayer + GroupSum(実数は最後の和だけ)
損失non-saturating GAN loss同じ(BCEWithLogits)
不安定さ敵対的 min-max敵対的 min-max ×離散出力の二重

安定化の4つのつまみと、その効き目の実測は下の STABLE / NAIVE の比較そのものである。 ページ末尾に、実データが流れるアーキテクチャ図と、学習後の Generator の実回路 (1画素=ゲート1個。argmax で確定した論理関数の名前まで書いた図)を置いた。

この例のもう一つの主題は「壊れ方」: GAN は「敵対的な min-max」×「離散出力」という二重の不安定性を抱える。 未調整の設定では Discriminator が Generator を圧倒し、G loss が発散して Generator が淘汰される —— これは本リポジトリで実測済みの失敗モードで、 tests/test_logic_gan.py::test_training_dynamics_smoke がその健全域を守っている。 このスクリプトは 安定版と未調整版を両方回して並べる ことで、 どの設定がどう効くのかを目で見えるようにする。

このサンプルの縮小レシピ: 本走(experiments/train_logic_gan.py)は 28x28 binary MNIST を30エポック回すが、 ここはCPUで3分以内に収まるよう「8x8 の二値パターン4種」という極小タスクにした。 到達点は「パターンの形が見え始める」レベルで、しかも縮小レシピでは モード崩壊(全サンプルが似た形になる)が起きる。それも含めて教材である。

実行: uv run python examples/19_logic_gan.py 期待結果(seed=0、CPU約90秒): 安定版 late G loss 0.9〜1.0 / late D精度 0.8〜0.9 / 未調整版 late G loss 7 台 / late D精度 1.00(崩壊)。どちらもモード被覆は 1/4。 GAN は浮動小数点の微小な差で軌道が分かれるので、数値は CPU(Apple Silicon と x86)で 少し変わる。安定版のレシピは seed 0〜2 × 両 CPU で D 精度 < 0.99 を確かめた設定にしてある (以前の D 学習率 0.003 / smoothing 0.1 は x86 で D が完勝に張り付いた)

準備: import と乱数種

Section titled “準備: import と乱数種”

使うのは PyTorch と matplotlib、そして本ライブラリの LogicGAN(モデル本体)と 回路描画ユーティリティだけ。GAN 用の特別なフレームワークは要らない。

GAN(敵対的生成ネットワーク / 敵対学習) — 絵を描く側と、その絵が本物か偽物かを 当てる側の2つのネットワークを競わせて前者を鍛える学習の枠組み。描く側が Generator(生成器)、当てる側が Discriminator(判別器) で、以下それぞれ G / D と書く。 D が見抜けないほど本物らしい絵を G が出せるようになることを目指す。

LogicGAN はその G と D を両方とも論理ゲート(LutLayer)のスタックで組んだもので、 入口から出口まで掛け算が1回も出てこない。

ハイパーパラメータ

Section titled “ハイパーパラメータ”

画像を 8x8=64画素の極小サイズに絞ってあるので、CPU でも数分で最後まで走る。 NOISE_BITS は G に入れる乱数ビット列 z の本数(次の章で定義する)。 DISC_HIDDEN を Generator の HIDDEN よりずっと小さくしてあるのは、 D を勝たせすぎないための最初の一手である ── 理由は「学習」の章で見る。

データ: 崩壊を数えられる4パターンのトイ分布

Section titled “データ: 崩壊を数えられる4パターンのトイ分布”

訓練分布は「上半分・下半分・左半分・右半分だけが黒い 8x8 の二値パターン」の 4種類だけにしてある。手書き数字ではなく、こんなに単純な分布を選ぶのには理由がある。

モード崩壊(mode collapse) — 生成器が分布の一部しか出さなくなり、何度サンプリング しても似た絵ばかりが返る現象。GAN で最も有名な失敗モードである。

分布が4点しかないなら、生成した画像を最も近い訓練パターンへ割り当てて数えるだけで 「4種のうち何種を出せているか」が機械的に測れる。MNIST では「崩壊した」を目で 判定するしかないが、このトイ分布なら崩壊が数字になる ── 図3がまさにそれである。

モデル: Generator と Discriminator

Section titled “モデル: Generator と Discriminator”

コードに入る前に、このページで繰り返し出てくる記号を定義しておく。

  • z — Generator への入力である乱数ビット列(0/1 が NOISE_BITS=64 本並んだもの)。 普通の GAN が使う潜在(latent)ベクトル ── 「絵の種」にあたる、外から与える乱数 ── の役割をそのまま担うが、こちらは実数のガウス乱数ではなくビットである。 つまり物理乱数源や LFSR(線形帰還シフトレジスタ。数個のフリップフロップと XOR だけで 疑似乱数ビットを吐く小さな回路) からそのまま供給できる。 結果として LogicGAN は「回路の外から 0/1 を64本与えるだけで画像が出てくる」構造になる。
  • G(Generator) — z を受け取って画像のビット(8x8=64ビット)を返す論理回路。
  • D(Discriminator) — 画像のビットを受け取って、ロジットを1本だけ返す論理回路。
  • ロジット — 「大きいほど本物らしい」という実数のスコア。sigmoid を通すと確率になり、 符号がそのまま「本物と判定 / 偽物と判定」の境目(0)になる。 LogicGAN で実数が現れるのは、D の最後にビットを数える GroupSum から先だけである。
  • D 精度 — D が本物/偽物を当てられた割合。0.5 付近なら拮抗していて健全、 1.0 に張り付いたら D が勝ちすぎで、G に返る勾配が枯れる(=崩壊のサイン)。

下のヘルパーは安定化のつまみの1つ、入力ノイズの実装である。

つまみ: D 入力へのビット反転ノイズ

Section titled “つまみ: D 入力へのビット反転ノイズ”

学習ループ本体: 4つのつまみだけを引数にする

Section titled “学習ループ本体: 4つのつまみだけを引数にする”

GAN は G と D のバランスが取れているときだけ学習が進む。どちらかが勝ってしまうと 勾配が枯れて、もう一方は何も学べなくなる。だから GAN には「バランスを保つためのつまみ」が 要る。この関数はそのつまみをちょうど4つだけ引数にしてあり、あとで比べる 安定版(STABLE)と未調整版(NAIVE)の差はこの4つに閉じている。

  • 更新比 g_steps — D を1回更新するあいだに G を何回更新するかの比(D:G の更新回数比)。 D のほうが学習が速いので、G を多めに回して追いつかせる。
  • 入力ノイズ flip_prob — 本物にも偽物にも同じ確率でビット反転をかけてから D に見せる。 D が両者を完全に見分けられる状態になるのを防ぐ。
  • label smoothing label_smoothing — 「本物のラベルを 1.0 ではなく 0.8 にする」 つまみ(STABLE は 0.2)。 D に「絶対に本物だ」と言い切らせないための、GAN では定番の手当て。
  • D の学習率 disc_lr — 単純に D の歩幅を小さくして、勝ちすぎを抑える。

学習が終わったら gan.generate(...) で 128 枚サンプリングする。これは hard eval (各ゲートを argmax で1つの論理関数に確定させた、純ブール回路としての実行) 経路なので、 返ってくる画素は連続緩和の近似値ではなく厳密に 0/1 である。

学習: 安定版と未調整版を並べて回す

Section titled “学習: 安定版と未調整版を並べて回す”

このページの主役はここである。同じ初期回路から、つまみだけを変えた2本を回す。

  • STABLE — 更新比 G:D=3:1 / 入力ノイズ p=0.1 / label smoothing 0.2 / D の学習率 0.001(G の 1/10)
  • NAIVE — 4つの安定化を全部外した、素直に書いただけの GAN

出力の数字で見るのは 2つ。late G loss(終盤200イテレーションの平均)は G が生きているかどうか、late D 精度は敵対バランスの体温計で、1.0 は崩壊を意味する。 「GAN は不安定だ」と言葉で言う代わりに、崩れ方を実測で並べるのがこの例の狙いである。

描画ヘルパー: 移動平均

Section titled “描画ヘルパー: 移動平均”

敵対学習の損失と判別精度はステップごとの振れが大きく、生の系列のままでは傾向が読めない。 以下の推移図はすべて、この移動平均で均してから描く。

図1: 生成サンプル(安定版 / 未調整版)

Section titled “図1: 生成サンプル(安定版 / 未調整版)”

上段が STABLE、下段が NAIVE の生成画像を8枚ずつ。見るのは **「訓練分布の4パターン(半分だけ黒い正方形)の形になっているか」**の一点である。

描いているのは hard eval(argmax で確定した純ブール回路)の出力なので、白黒の各マスは 文字通り回路が出力したビットそのものであり、連続緩和した近似値ではない。

読み取り: どちらの段も、8x8 の極小タスクではまだ「パターンの形が見え始めた」程度で、 最近傍パターンとのハミング距離は 64 画素中 20 前後ある(実行ごとの数値は上の出力)。 ここで見るべき差は絵の綺麗さではなく学習が生きているかどうかで、それは次の図2に出る。 同じ回路・同じ初期値で、違うのは4つのつまみだけである。どちらも8枚がよく似た形を している ── これがモード崩壊で、数として見えるのは図3。

図2: 敵対バランスの推移(崩壊の見分け方)

Section titled “図2: 敵対バランスの推移(崩壊の見分け方)”

G と D の力関係を時系列で見る。上段が G loss、下段が D 精度。見どころは下段で、 0.5 付近をうろついていれば拮抗して健全、1.0 に張り付いたら D が勝ちすぎである。 その結果として上段の G loss が単調に上がっていくのが、崩壊の典型的な足跡になる。

読み取り: NAIVE(赤)は D 精度が早々に 1.0 へ張り付き、G loss が 7 台まで 上がり続ける ── D が完全に勝ち、G に返る勾配が枯れた状態である。STABLE(緑)は D 精度が 0.8〜0.9 で止まり(1.0 に張り付かない)、G loss も破線(2.0)の下に留まる。 4つのつまみは「G を強くする」ためではなく「D を勝たせすぎない」ために効いている。

図3: モード被覆(縮小レシピでは崩壊するのが正常)

Section titled “図3: モード被覆(縮小レシピでは崩壊するのが正常)”

生成した128枚を最も近い訓練パターンへ割り当てて、4本の棒に数える。破線が訓練分布 (4種が均等なので各 0.25)で、棒が破線あたりに4本そろえば分布を覆えている、 1本だけ突出していたらモード崩壊である。

読み取り: どちらの条件も棒が1本だけ立ち、被覆モード数は 1/4。つまり 安定版でもモード崩壊している。8x8・4000イテレーションという縮小レシピでは ここまでしか行かない、というのがこの例の正直な到達点であり、 「敵対バランスを保つこと(図2)」と「分布を覆うこと(図3)」が別の難しさだと いうことでもある ── 本走(experiments/train_logic_gan.py)は 28x28 の二値 MNIST を 30エポック回してこの先へ進む。

図4: アーキテクチャ図(安定版の実データを1枚流す)

Section titled “図4: アーキテクチャ図(安定版の実データを1枚流す)”

学習済みの安定版に実データを1枚だけ流し、その途中経過を図の中に貼り付ける。 上段が G(64本の乱数ビット z → 論理回路 → 画像ビット)、下段が D(画像ビット → 論理回路 → 実数ロジット1本)。箱の中の数字は実際のゲート数で、右端の点は 本物と偽物に対して D が出したロジットの位置(破線が判定の境目)である。

注目してほしいのは readout の箱 ── 出力段のことで、ここは 1画素 = LUT 1個の対応になっている。色の凡例はプロジェクト共通で、 緑=論理ゲート / 橙=実数が現れる場所 / 青=乱数ビット源 / 灰=データ。

読み取り: 橙(実数)は D の末尾、ビットを数える GroupSum から先にしか無い。 z から画像まで、そして画像から判定の直前まで、流れているのは 0/1 のビットだけで 掛け算は一度も現れない。ロジットは本物側のほうが偽物側より高く出ており(差は上の出力)、 図2で見た「D 精度が 1.0 に張り付かない」様子の内訳がこの1枚に見えている。

図5: 実回路(学習後の Generator そのもの)

Section titled “図5: 実回路(学習後の Generator そのもの)”

締めくくりは、学習の結果そのものである回路の絵。この図はコードの模式図ではなく、 学習後のパラメータから起こした実物である。

  • 左 — Generator 全体(320ゲート)。大きいので plot_circuit が自動的に俯瞰図 (層=箱、矢印=配線の本数)へ切り替わる。
  • 右 — 出力段 generator.readout を画像の並びのまま広げたもの。1マス = 1画素 = LUT 1個で、マスに書かれているのは argmax で確定した論理関数の名前 (XOR / NAND / A>=B など)。マスの濃さは、生成サンプルでその画素が 1になった頻度である。

読み取り: 生成画像のどのマスをどのゲートが吐いているかが、そのまま名前で読める。 この名前は IR(このライブラリが回路の真実源として持つ JSON 表現) と、そこから 吐かれる Verilog(FPGA・ASIC に流し込むハードウェア記述) に焼かれるゲート名と 同一である。最後の print が示すとおり出力段64ゲートは数種類の論理関数に 集中しており、「乱数ビットを入れると絵が出てくる小さな回路」が確かに手元にできている。

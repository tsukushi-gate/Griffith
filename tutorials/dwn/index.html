DWN — 温度計符号化とn入力LUTで解くMNIST

離散化ギャップがゼロという、論理NN界の例外。実数画素を単調なビット列へ落とす ThermometerEncoder と 64 エントリの n 入力 LUT を組み合わせた DWN (Differentiable Weightless Neural Network)は、train() と eval() のロジット最大差が 0.0 ── つまり学習中のモデルと焼かれる回路が最初から同一である。

test acc 0.958。他の多くのページで扱う「soft では出るのに hard で崩れる」問題が、 パラメータ化の選び方だけで消えることを見せる回。

このページで学ぶこと

  1. ThermometerEncoder で実数画素を単調なビット列へ落とす二値化の作法
  2. 64 エントリの n 入力 LUT を使う DWN の組み方(test acc 0.958)
  3. 離散化ギャップが 0.0 になる仕組み ── 学習中のモデルと焼かれる回路が同一であること

前提

  • 1. MNISTを学習する — 素の LutLayer と比較するための基準
  • パラメータ化を選ぶ

このページについて

所要時間の目安: 約7分 / 実行環境: CPU のみ(GPU 不要) 元スクリプト: examples/16_dwn.py 手元で試す: notebooks/16_dwn.ipynb(このページと同じ内容の未実行ノートブック。uv run --group docs jupyter lab notebooks/ で開ける) コード出力はすべて 実際に実行した結果をそのまま埋め込んでいます。

DWN(Differentiable Weightless Neural Network)でMNISTを解く例。

06_mnist.py の DLGN は「2入力の論理ゲートを疎に配線した回路」だった。 DWN(Bacellar et al., ICML 2024)は同じ論理回路でも設計思想が違う:

  • ゲートではなく n入力LUT(ルックアップテーブル) を基本素子にする。 n=6 なら 2^6=64 エントリの真理値表を丸ごと学習する(表現力はゲートの比ではない)。
  • 実数入力は ThermometerEncoder(温度計符号化) でビット列に落とす。 「値の大きさ」を「立っているビットの本数」で表す単調な符号。
  • forwardは訓練中も 常にハード(LUTは二値、接続はargmax)。 そのため DLGN のような soft/hard の離散化ギャップが構造的に存在しない — 訓練中に見ている精度が、そのまま焼いた回路の精度になる。

全体像: 1画素の実数がロジットになるまで

数値はこのサンプルの実設定(BITS=3 / 400画素 / WIDTHS=(2000,1000) / N_INPUTS=6)と 実測値。画素#71は学習データ1枚目(ラベル5)の実際の画素で、しきい値も encoder.thresholds[:, 71] の実測値である。

どう実現しているか(NNを触ったことがない人向け)

  • LUT(ルックアップテーブル) = 入力の組み合わせごとに答えを書いた表。6入力なら 組み合わせは 2^6 = 64通りなので、64個のマス目に0か1を書けば「6入力の任意の論理関数」を 表せる。DWNが学習するのはこの表の中身そのもので、掛け算の重みではない。
  • 温度計符号化 = 「値の大きさ」を「立っているビットの本数」で表す書き方。 0.714 → 1 1 0、もっと濃い画素 → 1 1 1。one-hot と違って順序が保たれるので、 近い値が近いビット列になり、下流のLUTが大小関係を扱いやすい。
  • しきい値の置き方(distributive) = しきい値を訓練データの分位点に置く。MNISTは 画素の大半が0付近に固まっているので、等間隔に置くとビットがほとんど死ぬ。
  • 配線を学習する(LearnableMapping) = どのLUTがどの入力線を見るかは、普通は ランダムに決め打ちする。DWNは「入力1,200本 × 選択先12,000スロット」の行列を持ち、 列ごとの argmax で1本を選ぶ。この行列にも勾配が流れるので配線が学習される。
  • EFD(Extended Finite Difference) = 表を引く操作は階段状で微分できない。そこで 「隣のマスの値」を使った有限差分を勾配の代わりに使う。これがDWNの核心アイデア。
  • GroupSum = 最終層1,000本のビットを10クラス×100本に分け、1の本数を数えて 温度τで割るだけ。学習可能な重みが1つも無いので “weightless” と呼ばれる。
  • 離散化ギャップが構造的に0 = forwardが訓練中も常にハード(LUT出力は{0,1}、 接続はargmax)。つまり学習中に見ている精度がそのまま焼いた回路の精度になる。 DLGN(06_mnist.py)の soft/hard の乖離チェックが要らない。

このサンプルでは4枚の図を見る:

  1. 温度計符号化で1枚の画像がビット平面の束になる様子(図1)
  2. 学習済みの重みで描いたアーキテクチャ全体像(図2) — 1画素 → ビット列 → 配線 → 64エントリの真理値表 → popcount → ロジット、を実際の数値で追う
  3. MNIST 20x20 での学習曲線(図3)と誤分類例(図4)

準備: import と乱数種

Section titled “準備: import と乱数種”

使うのは PyTorch と matplotlib、そして本ライブラリの ThermometerEncoder / DWNLayer / DWNClassifier の3つだけである。

用語をここで確定しておく。DWN(Differentiable Weightless Neural Network)の weightless(重みを持たない)とは、掛け算の重み行列を1つも持たないという意味である。 普通の NN が学習するのは「重み」だが、DWN が学習するのは LUT(ルックアップテーブル = 入力の組み合わせごとに答えを書いた表)の中身そのものだ。 表を引く操作は掛け算ではないので、この回路はそのままハードウェアに焼ける。

ハイパーパラメータ

Section titled “ハイパーパラメータ”

記号を先に定義しておく。以降ずっとこの意味で使う。

  • q — 1つの画素が持つ実数の濃さ。MNIST では [0, 1] の連続値
  • z = BITS — 1画素を何ビットに符号化するか。ここでは 3
  • t_1 … t_z — 温度計符号化のしきい値。q をこれらと比べてビットにする
  • n = N_INPUTS — 1つの LUT が見る入力線の本数。ここでは 6。 入力の組み合わせは 2^n = 64通りなので、**LUT は 64 個のエントリ(表のマス目)**を持つ
  • アドレス — 引かれる表の行番号。n 本の入力ビットをそのまま n 桁の2進数と 読んだ値で、0 … 2^n - 1 の範囲に入る

つまり 1 個の LUT は「6 本のビットを 6 桁の2進数(=アドレス)と読んで、64 行の表を1回引く」 だけの素子である。学習されるのはこの表の 64 マスの中身であって、係数ではない。

データ: 実数のまま渡す

Section titled “データ: 実数のまま渡す”

06_mnist.py の DLGN では入力を先に 0/1 へ潰していたが、ここでは潰さない。 二値化は次の章の ThermometerEncoder の仕事であり、しかもその際に 訓練データの分布を見てしきい値を決める必要があるからである。 ここで先に潰してしまうと、その分布の情報が失われてしまう。

温度計符号化: 実数を「近さが保たれるビット列」に落とす

Section titled “温度計符号化: 実数を「近さが保たれるビット列」に落とす”

なぜ符号化が要るのか。 LUT は「ビットを並べてアドレスにする」素子なので、 実数の画素値 q をそのまま食わせることができない。どこかで二値化が必要になる。

なぜ one-hot ではだめなのか。 素朴に「値の区間ごとに1本立てる」one-hot にすると、 0.31 と 0.33 のように近い値が、まったく離れたビット列になってしまう。 表を引くだけの LUT には「このアドレスとあのアドレスは近い」という情報が無いので、 大小関係を扱う手がかりが下流に一切残らない。

温度計符号化(thermometer encoding) はここを解く。q が超えたしきい値の分だけ 下から順に 1 が立つ、つまり 1 の本数が単調に増えるだけの符号なので、 「近い値は近いビット列」という関係が保たれる。だから下流の LUT が大小関係を扱える。 名前のとおり、温度計の水銀柱がじわじわ伸びる様子と同じ形の符号である。

なぜしきい値を経験分位点(実データを並べて何%地点かで区切った値)に置くのか。 mode='distributive' は t_1 … t_z を訓練データの経験分位点に置く。MNIST の画素は 大半が真っ黒(0 付近)に偏っているので、しきい値を 0.25 / 0.5 / 0.75 のように 等間隔に置くと、ほとんどの画素でどのビットも常に 0 になり、情報が何も乗らない。 分位点なら「データが実際に散らばっている場所」で切るので、全ビットが働く。

図1: 1枚の画像がビット平面の束になる

Section titled “図1: 1枚の画像がビット平面の束になる”

この図で何を見るか。 一番左が元のグレースケール画像、右の3枚が T(q) = (1_{q>t_1}, …, 1_{q>t_z}) の各ビットを 20x20 に戻したもの(=ビット平面)である。 見るべきは 右へ行くほど黒い点が減っていくか。しきい値 t_b は b が進むほど高いので、 単調性が正しく効いていれば、生き残るのは濃い画素だけになるはずである。

読み取り。 タイトルの N on の数字が bit 0 → bit 2 と進むにつれて確実に減っている。 これが温度計符号の単調性そのもので、bit b が 1 の画素の集合は bit b+1 が 1 の集合を 必ず含む(入れ子になる)。3 枚の絵は「別々の特徴」ではなく、同じ数字を濃さのしきい値で 輪切りにした地層だと読むのが正しい。元画像の輪郭が全ビットで保たれていることも重要で、 二値化しても形の情報が失われていないことを意味する。

DWNLayer: n入力LUTを並べただけの層

Section titled “DWNLayer: n入力LUTを並べただけの層”

ここからはすべてビットの世界になる。DWNLayer が何をする層なのか、 いきなり分類器に組み込む前に 8 個だけの小さな層で単体確認しておく。

EFD(Extended Finite Difference = 拡張有限差分) についてもここで触れておく。 表を引く操作は「アドレスが 1 変わると出力が飛ぶ」階段状の関数なので、そのままでは 微分できない(勾配がどこでも 0 になる)。DWN は微分の代わりに 隣のマス(アドレスが 1 ビット違うエントリ)との差を勾配として流す。 これが有限差分であり、DWN の核心アイデアである。

分類器の組み立て: encoder → LUT 2層 → GroupSum

Section titled “分類器の組み立て: encoder → LUT 2層 → GroupSum”

部品が揃ったので直列につなぐ。ここで残る語をまとめて定義しておく。

  • LearnableMapping(学習される配線) — 「どの LUT が入力のどのビット線を見るか」は 普通ランダムに決め打ちする。DWN は「入力 1,200 本 × 選択先 12,000 スロット」の行列を 持ち、列ごとの argmax で 1 本を選ぶ。この行列にも勾配が流れるので配線自体が学習される
  • GroupSum / popcount(1 の本数を数える操作) — 最終層 1,000 本のビットを 10 クラス × 100 本に分け、各グループで立っているビットを数えるだけ。 数えた値を温度 τ で割ってロジットにする。学習可能な重み付き和が 1 つも無いことが、 この手法が weightless と呼ばれる理由である

学習: 中身は普通の PyTorch ループ

Section titled “学習: 中身は普通の PyTorch ループ”

特別な学習則は要らない。Adam で cross_entropy を下げるだけである。 ただし 01_xor.py や 06_mnist.py と決定的に違う点が 1 つある ── soft accuracy を測る場所が無い。DWN の forward は学習中も常にハードな表引きなので、 測れる精度は最初から 1 種類しか存在しない。

離散化ギャップの確認: なぜ DWN ではギャップが 0 なのか

Section titled “離散化ギャップの確認: なぜ DWN ではギャップが 0 なのか”

離散化ギャップとは「学習中に見ていた精度」と「回路に焼いたあとの精度」の差である。 用語を対にしておくと、soft eval は連続緩和したままの評価(train() モード)、 hard eval は離散化して確定させた評価(eval() モード)を指す。

なぜ DLGN にはギャップが出るのか。 DLGN(06_mnist.py)の 1 ゲートは学習中、 2 入力論理関数 16 種のソフト混合であり、「7 割 XOR・3 割 AND」のような中間状態を 取れる。焼くときは argmax で 1 種類に確定させるので、学習していたモデルと 焼かれる回路が別物になる。ゆえに乖離チェックが必須だった。

なぜ DWN はギャップが 0 なのか。 DWN の forward は学習中も常にハードな表引きで、 LUT の出力は必ず {0,1}、配線も常に argmax で 1 本に確定している。中間状態が存在しない。 勾配だけを EFD(有限差分)で近似的に流しているので、 学習しているモデルと焼かれる回路が最初から同一なのである。

主張が本当かを下で機械的に確かめる。同じ重みを train() と eval() の両モードで 評価し、ロジットの最大差が 厳密に 0.0 であることを assert する。

可視化: 1画素の運命・学習曲線・誤分類

Section titled “可視化: 1画素の運命・学習曲線・誤分類”

図2の材料: 学習済みモデルから「1画素の運命」を取り出す

Section titled “図2の材料: 学習済みモデルから「1画素の運命」を取り出す”

ここから 3 枚の図を見る。まず、抽象的な説明を実測値に置き換えるための材料を集める。 追跡するのは画素 #71 ただ 1 点で、その実数値 q・3 本のしきい値 t_1…t_3・ 温度計ビット・LearnableMapping が実際に選んだ 6 本の入力線・引かれたアドレスと エントリの値を、すべて学習済みモデルから読み出す(図中の数字は全部この実測値)。

図2: 1画素の実数がロジットになるまで(全体像)

Section titled “図2: 1画素の実数がロジットになるまで(全体像)”

この図で何を見るか。 6 つのパネルを (1) → (6) の順にたどると、 1 個の実数の画素が 1 本のロジットになるまでが全部つながる。 (1) 追跡する画素 q を画像上で赤枠にする → (2) 3 本のしきい値と比べてビット列 T(q) にする → (3) 画像全体が 1,200 ビットのベクトルになる → (4) LearnableMapping が 1,200 本から 6 本を選び、それを 6 桁の2進数=アドレスと読む → (5) そのアドレスで 64 エントリの表を 1 回引く → (6) 2 層の LUT と popcount を経てロジット。

特に (4) から (5) へ伸びる赤い矢印に注目してほしい。「選んだ 6 ビットを 1 つの アドレスと読んで表を引く」という、DWN の唯一の演算がそこに描かれている。 緑の箱はビットしか流れない領域(そのままハードウェアに焼ける)、 橙の箱は実数の領域で、橙は GroupSum とロジットだけである。

読み取り。 (5) の表を見ると、64 マスが濃い緑と濃い紫にはっきり分かれている。 つまり学習は「表の中身を中間値のまま濁らせる」のではなく、 各マスを 0 側か 1 側かに振り切らせる方向に進む。赤枠のマスがこの画像に対する答えで、 表のどこを引くかは (4) で選ばれた 6 本のビットだけで決まっている。 (6) の脚注にあるとおり総計 3,000 個の LUT / 192,000 エントリが学習対象で、 箱と箱の間を流れるのは全部 {0,1} のビット、実数はいちばん右の 2 箱だけである。

図3: 学習曲線(引ける線が1本しかない)

Section titled “図3: 学習曲線(引ける線が1本しかない)”

この図で何を見るか。 01_xor.py の学習曲線は soft と hard の 2 本だったが、 ここは 1 本しか引けない。DWN には soft eval が存在しないからで、 この「線が 1 本しか無い」ことこそが離散化ギャップ 0 の視覚的な帰結である。 見どころは立ち上がりの速さと、最終的にどこで頭打ちになるかである。

読み取り。 最初の数百ステップで 0.9 付近まで一気に立ち上がり、その後はゆるやかに 0.95 前後へ収束する。ここで表示されている値は eval() の値であると同時に 学習中のモデルそのものの値でもある(上で最大差 0.0 を確認済み)。 つまりこの曲線は「あとで焼いたら落ちるかもしれない暫定値」ではなく、 回路の精度そのものを最初から示している。DLGN のように soft の高さに一喜一憂して hard で裏切られる、という事故がこの手法では原理的に起きない。

図4: 回路が間違えた数字

Section titled “図4: 回路が間違えた数字”

この図で何を見るか、そして何が読み取れるか。 3,000 個の LUT でできた回路が 取りこぼした 10 枚を並べる。各図のタイトルは pred(予測) / true(正解) である。 見るべきは「回路特有の変な壊れ方をしていないか」で、実際に並ぶのは 4 と 9、3 と 5、7 と 1 のような、人間が見ても紛らわしい字形が中心になる。 誤り方が人間の感覚と地続きであることは、ビット列と表引きだけで組んだ回路が 数字の形をきちんと捉えられている証拠である。 逆に、もし無関係な字がランダムに混ざるなら符号化かしきい値の設定を疑うべきところだ。

ゲーティングはブール演算である(LSTM/GRU)— RNNの論理化

LSTM の忘却ゲートは 2:1 マルチプレクサそのもの、出力ゲートはビット AND そのものである。 {0,1}\{0,1\}{0,1} 上ではゲーティングの掛け算が論理演算に化ける ── その同型性を、遅延コピー タスクで LogicLSTM / LogicGRU / ゲートなし Elman の3者を比べて確かめる。

ゲートを持つ2つは hard acc 1.000、ゲートなし Elman は 0.578 で頭打ちになる。 隠れ状態は hard eval で厳密に {0,1}\{0,1\}{0,1} に閉じ、忘却ゲートの開度は時刻ごとに 「いつ記憶を保持し、いつ捨てるか」を数値で見せてくれる。

このページで学ぶこと

  1. 忘却ゲート = 2:1 マルチプレクサ、出力ゲート = ビット AND という同型性
  2. ゲートあり(LSTM/GRU)と無し(Elman)の差が、遅延コピー課題でどう出るか
  3. hard eval で隠れ状態が厳密に {0,1}\{0,1\}{0,1} に閉じることの確かめ方

前提

  • RNNだけで作るseq2seq(RDDLGN) — ゲートを持たない再帰回路を先に見る
  • 基本コンセプト

論理ゲート版LSTM/GRU: 「ゲーティング=MUX/AND」を体感する例。

前のサンプル(08_rddlgn_seq2seq.py)のRDDLGNは、リカレント部が

という Elman型 だった。毎ステップ、状態を丸ごと作り直す形である。 この形には弱点がある: 「1ステップ目に見たビットを8ステップ後まで保持する」ような 純粋な記憶タスクだと、状態を運ぶ経路が毎回LUTの層を通って書き換わってしまい、 情報が持たない。

つまりLSTMのゲート構造は、論理回路へ落とすときに「近似」でなく「一致」する。 eval(hard)時、LogicLSTMCell の h と c は厳密に {0,1} になる —— これも本サンプルで確認する。

タスクは 遅延コピー: 長さT=8のランダムビット列を読み、最後に「1ステップ目の ビット」を答える。途中の7ビットは全部ノイズなので、latch(掛け金)が要る。 tests/test_logic_recurrent.py で較正済みの通り、LogicLSTMCell は200step以内に hard accuracy 100% に達し、同条件のElman型は最後まで100%に届かない。 この対比が教材の核である。

アーキテクチャ図解 1: セルの中身(LogicLSTMCell)

Section titled “アーキテクチャ図解 1: セルの中身(LogicLSTMCell)”

まず1時刻ぶんの中身を開く。ゲート f/i/o と候補 c̃ は、どれも cat([x_t, h_(t-1)]) を入力に取る LutLayer 2段のスタック(_LutStack)で、 本サンプルの構成では入力9ビット(=x 1 + h 8)→ 8ゲート → 8ゲートである。 出てきた4本のビット列を、MUX と AND という 2つの部品だけ で組み合わせる。

学習中の f/i/o は 0〜1 の連続値なので上式は「重み付き平均」だが、 eval(hard)では f/i/o が {0,1} に落ちるため、近似ではなく厳密に 2:1マルチプレクサとビットANDの回路へ崩壊する。ここが本サンプルの主張。

アーキテクチャ図解 2: 時間展開(遅延コピー T=8)

Section titled “アーキテクチャ図解 2: 時間展開(遅延コピー T=8)”

実データ1件目のビット列 0 1 0 1 0 1 0 0 を流し、最後に 1ステップ目の 0 を 答えさせる。答えるべきビットは t=1 で入ってきたきり二度と現れないので、 セルの中のどこかがそれを掴んだまま7ステップ運ぶ必要がある。

どう実現しているか(初めて読む人向けの要点)

  • ゲート1本 = LutLayer 2段。行列積も sigmoid も使わない。f/i/o/c̃ の4本ぶんで 1セルあたり 4×16 = 64 ゲート(hidden=8 の構成)。
  • ゲーティング = 配線の選択。MUX は「2本の入力のうち片方を通す」だけの素子で、 FPGA なら 1 LUT に収まる。LSTM の「掛け算」はここに一致する。
  • latch(記憶)の正体: f(t)=1 が続く限り c(t) は変化しない。回路としては 「フィードバックのある保持回路」そのもの。学習は「いつ f を閉じるか」を覚える。
  • Elman型との違い: ゲート無しの再帰 h(t)=L2(L1([x,h])) は毎時刻すべての ビットを作り直すため、保持専用の経路が無い。図の MUX がまるごと欠けた形になる。
  • 最後の読み出し: GroupSum が隠れビットを2グループに割り、それぞれの1の個数を 数えてロジットにする(学習パラメータを持たない)。数える部分だけが実数。

実行: uv run python examples/09_logic_lstm.py 期待結果: LSTM=1.00 / GRU=1.00 / Elman は1.00に届かない(0.6前後。CPUで20秒程度)

準備: import とハイパーパラメータ

Section titled “準備: import とハイパーパラメータ”

LogicLSTMCell / LogicGRUCell がゲート付きの再帰セル、scan_cell が時間方向の ループを回すヘルパー。比較用のゲート無し Elman 型は LutLayer から自分で組む。

ハイパーパラメータ

Section titled “ハイパーパラメータ”

T=8 が系列長で、答えるべきビットは 7 ステップ運ばれる。HIDDEN=8 は隠れ状態の ビット幅 ── 1ビットを保持するだけなら 8 本もあれば十分すぎるので、「容量が足りない から解けない」という言い訳を先に潰してある。差が出るなら構造の差だけが理由になる。

タスク: 遅延コピー(最初に見たビットを最後に答える)

Section titled “タスク: 遅延コピー(最初に見たビットを最後に答える)”

長さ8のランダムなビット列を読み、最後に1ステップ目のビットを答えさせる。 途中の7ビットは全部ノイズなので、回路は最初のビットを掴んだまま7ステップ運ぶ必要がある。

なぜ「最初」なのか: 「最後に見たもの」を答えるタスクにすると、直近の入力さえ 反映できれば解けてしまい、記憶の有無で差が出ない。保持そのものを試すには、 答えが二度と現れない形にするしかない。

Section titled “モデル定義: ゲート付き vs ゲート無し”

初期状態をビットで作る

Section titled “初期状態をビットで作る”

再帰回路には「t=0 の状態」が要る。既定値の 0.5 は「論理的に不定」を表す中立値で 学習には都合がよいが、hard 評価では回路に存在しない値になってしまう。 中間値を受けた LUT は 0.25 や 0.75 を返し、それが時間方向へ伝播して隠れ状態全体を 連続値に汚す。初期状態も 1.0(=ビット1)に固定して、回路を最初から閉じさせる。

ゲート付きセル + GroupSum の分類器

Section titled “ゲート付きセル + GroupSum の分類器”

最終時刻の隠れ状態を GroupSum で2クラスのロジットに集計するだけの最小構成。 GroupSum は学習パラメータを持たず「ビットをクラス数のグループに割って1の個数を 数える」だけなので、判定まで含めて回路として焼ける。

比較対象: ゲート無しの Elman 型

Section titled “比較対象: ゲート無しの Elman 型”

ht=L2(L1([xt;ht−1]))h_t = L_2(L_1([x_t ; h_{t-1}]))ht​=L2​(L1​([xt​;ht−1​])) ── 毎時刻、状態を丸ごと作り直す形である (RDDLGN の K層・P層と同じ)。保持専用の経路が無いことがこのモデルの弱点で、 冒頭のセル図から MUX がまるごと抜け落ちた形にあたる。読み出しも学習条件も ゲート付き側と完全に揃えてあるので、差が出るなら再帰の作り方だけが原因になる。

学習ループ

Section titled “学習ループ”

普通の Adam + cross entropy。ひとつだけ作法があって、記録するのは常に hard(eval)側 の精度である。soft accuracy だけ上がっても、argmax で確定した回路が同じ答えを 出さなければ意味がない ── 論理ゲート NN で最も多い自己欺瞞がここなので、最初から hard しか見ないようにしておく。

3モデルを同条件で学習

Section titled “3モデルを同条件で学習”

種・データ・step 数・学習率・読み出しをすべて揃え、違うのは再帰の作り方だけにする。 代表値に「学習中の最高値」を使うのは、hard accuracy が離散化の都合で step 間を 行き来するためで、最終値だけ見ると実力を過小評価しやすいからである。

上の出力で、ゲート付き(LSTM / GRU)は 1.0000、ゲート無し(Elman)は 1.0 に届かない。 パラメータ数はむしろ Elman のほうが少ないくらいで、差は容量ではなく構造から来ている。 下の2つの assert が、その対比そのものを機械的な受入条件として固定している。

可視化: ゲートは実際に何をしているか

Section titled “可視化: ゲートは実際に何をしているか”

図1: 学習曲線(ゲートの有無で分かれる)

Section titled “図1: 学習曲線(ゲートの有無で分かれる)”

この図で何を見るか: 縦軸は hard accuracy(離散回路のまま測った正解率)、点線が コイントス水準の 0.5。3本の線が同じ図に乗っているので、ゲートの有無だけで結果が 分岐するかどうかがそのまま読める。

読み取り: LSTM / GRU は 100 step 前後で 階段状に 1.0 へ跳ぶ。じわじわ上がるのでは なく跳ぶのは、「どのビットを latch(掛け金)にするか」が決まった瞬間に回路が完成する ためで、連続的な近似の改善ではない。一方 Elman は 0.5 から少しずつ上がって天井に当たる ── 保持の経路が無いので、途中の7ビットのノイズに毎回上書きされている。

図2: 隠れ状態は本当にビットか

Section titled “図2: 隠れ状態は本当にビットか”

この図で何を見るか(次のセルで描く): 隠れ状態を時間×ビットのマス目にして、 1ステップ目の入力が 0 だったサンプルと 1 だったサンプルで左右に並べる。 左右で色が違う行があれば、それが「最初のビットを最後まで保ち続けたビット」= 回路が見つけた latch である。その前に、状態が厳密に {0,1}\{0,1\}{0,1} かを assert で確かめる。

出現値が [0.0, 1.0] の2つだけであることが上の出力で確認できた ── ゲート f,i,of,i,of,i,o が {0,1}\{0,1\}{0,1} に落ちれば MUX も AND も厳密なビット演算になるので、これは近似ではない。

読み取り: 左右のパネルを見比べると、ほとんどの行は同じ模様なのに、いくつかの行だけ 色が反転している。その行が latch を担当したビットで、t=0 から t=7 まで一定の色を 保っていることが「7ステップ運べた」ことの直接の証拠になる。残りの行は入力の一時的な 処理に使われており、8ビットの中で自然に分業が起きている。

図3: ゲートは実際に「閉じて」いるか

Section titled “図3: ゲートは実際に「閉じて」いるか”

この図で何を見るか: 忘却ゲート ftf_tft​ の平均開度を時刻ごとに棒で並べる。 ft=1f_t=1ft​=1 なら MUX は過去側 ct−1c_{t-1}ct−1​ を選ぶ(=保持)、ft=0f_t=0ft​=0 なら候補で上書きする。 棒の高さは「その時刻に保持側へ倒れたビットの割合」である。

読み取り: 棒は 1.0 にも 0.0 にも張り付かず、中間の高さに落ち着く。全ビットが 一斉に保持するのではなく、一部のビットだけが閉じて残りは開いているからである ── 平均を取っているので、その分業の比率がそのまま高さになる。時刻が進んでも高さが 大きく崩れないことが、latch が途中で外れていないことを示す。

図4: 忘却ゲートの「実物」

Section titled “図4: 忘却ゲートの「実物」”

この図の見方と読み取り(このページ最後の図)。ここまでは振る舞いの図だったので、 最後に学習後の忘却ゲートを回路そのものとして描く。左端が入力9ビット ([xt;ht−1][x_t ; h_{t-1}][xt​;ht−1​])、中央と右が LutLayer 2段の8ゲートずつで、箱の中の文字が argmax で 確定したゲート名(AND / XOR / NAND …)である。

読み取りどころは、箱に LUT ではなく具体的なゲート名が入っていること。この配線と ゲート名は export_ir が Verilog を吐くときと同じ離散化経路から取っているので、 「LSTM の忘却ゲート」がそのまま合成可能な組み合わせ回路になっている、という主張の いちばん直接的な証拠になる。

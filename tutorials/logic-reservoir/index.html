回路を学習しないという選択(リザバー計算=学習しないRNN)

回路を学習しない、という選択。512ビットの凍結ランダム論理回路に系列を流し込み、 学習するのは readout(全体の 5.9%)だけ ── それでも parity や遅延再生は解けてしまう。

このページの主題は「リザバーが持っているのは記憶であって、記憶への非線形演算では ない」こと。delay-d recall は d=0..5 すべて満点なのに、parity は k が増えるほど劣化する。 さらに hard 化した純ブール回路(leak=1.0)は有界だが収縮しない(1ビットの差がむしろ 拡散する)ことを摂動カーブで示し、fading memory とハードウェア化のトレードオフを扱う。

このページで学ぶこと

  1. 凍結したランダム論理回路 + readout だけの学習(全体の 5.9%)で何が解けるか
  2. リザバーが持っているのは記憶であって、記憶への非線形演算ではないこと
  3. hard 化した純ブール回路が「有界だが収縮しない」という、ハードウェア化の落とし穴

LogicReservoir: 回路を 学習しない という選択肢(リザバーコンピューティング)。

ここまでの系列モデル(08 RDDLGN / 09 LogicLSTM / 10 LogicWaveNet)は、 どれも回路そのものを勾配で学習していた。本サンプルはまったく逆の発想を試す:

これがリザバーコンピューティング。回路(リザバー)は乱数で1回作ったら二度と 触らない。系列を流し込むと、リザバーの内部状態が入力の履歴を 「高次元のビットパターン」へ勝手に広げてくれる。学習するのは、その状態から 答えを取り出す最後の線形層だけである。

なぜ本ライブラリの物語と噛み合うか:

タスクは parity(排他的論理和)。系列の末尾 k ビットのXORを答える。 parityは「記憶 × 非線形」の合わせ技で、線形readoutにとって最も苦手な形の 問題であり、リザバーの能力の限界を測る古典的なベンチマークである。 併せて、リザバーの記憶容量そのものを測る 遅延再生(delay-k recall) も回す。

アーキテクチャ図解: 学習するのは端の1層だけ

Section titled “アーキテクチャ図解: 学習するのは端の1層だけ”

いちばん大事な絵は「どこが凍っていて、どこが学習されるか」である。 灰色の箱(リザバー)は乱数で作られたきり一度も更新されない。学習の勾配は 橙の readout にしか流れず、灰色の箱へは1本も戻らない。

時間方向に展開すると、同じ凍結回路を8回くり返し通しているだけになる (実データ1件目のビット列 1 0 0 1 0 1 0 1 を流したときの図)。

どう実現しているか(初めて読む人向けの要点)

  • 回路は乱数で1回だけ作る。LogicReservoirConfig.seed から決まる配線と真理値表を 生成した直後に requires_grad=False を立て、状態計算も no_grad で回す。 だから逆伝播は readout の1層ぶんしか流れない ── 学習が極端に安い理由。
  • 状態は毎時刻まるごと作り直される。s(t) = 凍結回路([x(t) ⊕ s(t-1)])。 LSTM のような保持専用の経路は無いが、512ビットもの広い状態にランダムな配線で ばらまかれるため、過去の入力の痕跡がしばらく残る。
  • 状態は厳密に 0/1。leak=1.0 では完全置換なので、リザバーは純ブール回路のまま。 発散も飽和も原理的に起きない(状態空間が有限)。
  • 学習するのは読み出しだけ。512ビットから2クラスへの線形写像(1,026パラメータ)で、 回路本体の 16,384 パラメータは凍ったまま(学習対象は全体の約6%)。
  • 限界も見える: 線形 readout は「覚えている」ことは読めるが、 「覚えたものを XOR する」のは苦手。parity で k を増やすと崩れるのはそのため。

実行: uv run python examples/11_logic_reservoir.py 期待結果: parity は k=1,2 で 1.00・k=3,4 で劣化 / delay recall は d=0..5 で 1.00 (CPUで15秒程度)

準備: import とハイパーパラメータ

Section titled “準備: import とハイパーパラメータ”

使うのは LogicReservoir と、その構成を決める LogicReservoirConfig。最後に回路図を 描くので plot_circuit も読み込む。

ハイパーパラメータ

Section titled “ハイパーパラメータ”

目を引くのは RESERVOIR = 512 ── 入力は1ステップあたり1ビットしかないのに、 状態は512ビットある。この「勝手に広がる高次元空間」がリザバー計算の道具立てで、 そこへ入力履歴を写し取り、読み出しだけを学習する。

データ: ランダムビット列

Section titled “データ: ランダムビット列”

長さ8のランダムなビット列を512本作るだけ。教師信号はこの列から後で何通りにも 作れるので、リザバーの状態は1回計算すれば全タスクで使い回せる(それが速さの正体)。

1ビットを8本に複製して入れているのは、512ビットの状態に対して1本では駆動力が 弱すぎ、状態が入力を無視した固定パターンに落ちてしまうためである。

モデル定義: 凍結リザバー + 学習する readout

Section titled “モデル定義: 凍結リザバー + 学習する readout”

リザバー計算(reservoir computing)は、再帰回路の中身をまったく学習しないという 設計である。乱数で作った再帰回路に入力を流し込み、そこに現れた状態を特徴量とみなして、 読み出し(readout)の1層だけを学習する。

なぜ学習しなくても成立するのか: 再帰回路に求められる仕事は「過去の入力を、 互いに区別できる形で状態へ写し取る」ことである。写し方が読みやすい向きであれば、 それが設計された写像である必要はない ── ランダムな高次元写像でも、線形な読み出しが 後から必要な成分を取り出せる。学習の負担を再帰から読み出しへ丸ごと移す、という発想。

leak=1.0 は「毎時刻、状態を完全に置き換える」の意味で、このとき状態は厳密に {0,1}\{0,1\}{0,1} のまま ── つまりリザバー全体が純粋なブール回路になる。図3でここを揺さぶる。

readout だけを学習する

Section titled “readout だけを学習する”

逆伝播が流れるのは readout の1層ぶんだけで、リザバーの中へは1歩も入らない。 だから状態は一度計算すれば使い回せて、タスクを変えても再計算が要らない。

タスクごとにまっさらな readout を用意して解かせる。リザバーは毎回同じ(seed 固定で 決定的に再生成される)なので、タスク間の差は純粋に「その特徴が読めるかどうか」になる。

リザバー状態を一度だけ計算する

Section titled “リザバー状態を一度だけ計算する”

まず学習対象の内訳を出す。全パラメータのうち readout が占める割合が、そのまま 「このモデルで学習されている部分」の大きさである(実測で約 5.9%)。

続いて全時刻の状態をまとめて計算する。states() の内部は no_grad + detach なので 計算グラフはここで完全に切れており、この先どんなタスクを解いても再計算されない。

出現値が [0.0, 1.0] の2つだけであることを確かめる ── leak=1.0 のリザバーは 純ブール回路なので、状態に中間値が現れたらそれ自体が不具合である。最終時刻の状態を 「読み出し用の特徴」として取り出し、以降のすべてのタスクでこれを使い回す。

実験: parity と遅延再生

Section titled “実験: parity と遅延再生”

実験1: parity(末尾kビットのXOR)

Section titled “実験1: parity(末尾kビットのXOR)”

parity(パリティ) = ビット列の1の個数が偶数か奇数か、つまり XOR を並べたもの。 k=1k=1k=1 は「最後のビットをそのまま答える」なので簡単だが、kkk が増えるほど 「kkk 個を覚えたうえで XOR する」ことが要る。記憶と非線形演算の両方を試す課題である。

実験2: 遅延再生(memory capacity)

Section titled “実験2: 遅延再生(memory capacity)”

「ddd ステップ前に入ってきたビットをそのまま答えよ」。XOR が要らないので純粋な 記憶容量のテストになり、リザバー研究では memory capacity と呼ばれる古典的な指標である。 実験1と対にすることで、「記憶が無いのか」「非線形演算ができないのか」を切り分けられる。

凍結の確認

Section titled “凍結の確認”

「リザバーは学習しない」は口約束では意味がないので、機械的に確かめる。学習の前後で リザバーの state_dict が bitwise に一致することを assert し、さらに同じ seed で 作り直した回路とも一致することを見る ── 回路が乱数種だけで決まるなら、 誰が実行しても同じ回路になり、そのままハードウェアの設計図として配れる。

可視化: 何が持てて、何が持てないか

Section titled “可視化: 何が持てて、何が持てないか”

図1: parity は k が増えると崩れる / delay recall は崩れない

Section titled “図1: parity は k が増えると崩れる / delay recall は崩れない”

この図で何を見るか: 左が parity(kkk を増やす)、右が遅延再生(ddd を増やす)で、 どちらも縦軸は hard accuracy、点線がコイントス水準。2枚の崩れ方の違いが主役で、 片方だけが崩れるならリザバーの限界がどちら側にあるかが分かる。

読み取り: 右(遅延再生)は d=0d=0d=0 から d=5d=5d=5 まで満点のまま崩れない ── 8ステップの 履歴はまるごと512ビットの中に残っている。一方 左(parity)は k=3,4k=3,4k=3,4 で急に落ちる。 つまり足りないのは記憶ではなく、記憶に対する非線形演算である。リザバーが提供するのは 「過去を区別できる形で保持すること」までで、そこから先(XOR のような合成)は 線形な読み出しの仕事にはならない ── これがこのページの結論である。

図2: リザバーの状態そのもの

Section titled “図2: リザバーの状態そのもの”

この図で何を見るか: 1サンプルぶんの状態の時間発展を白黒で描く(縦=状態ビット、 横=時刻、黒が1)。入力は1ステップ1ビットしかないのに状態が512ビットあるので、 「ランダム回路が入力履歴を高次元へ写している」様子がそのまま絵になる。

読み取り: 灰色の一様な帯ではなく、時刻ごとに模様が切り替わる ── 入力ビットに 駆動されて状態が動いている証拠である。逆にどの時刻も同じ縦縞なら、入力を無視した 固定パターンに落ちており(入力の駆動力不足)、読み出しが何も取り出せない状態になる。 中間の灰色が1つも無いことも、ここが純ブール回路であることの確認になる。

図3: fading memory と leak のトレードオフ

Section titled “図3: fading memory と leak のトレードオフ”

この図で何を見るか(数セル先で描く): fading memory(echo state property)= 「大昔の入力や初期条件の影響が時間とともに薄れる」性質。これが無いとリザバーは 初期状態をいつまでも引きずり、同じ入力に対して安定した特徴を出せない。

測り方は簡単で、先頭3ステップだけ差し替えた系列を用意し、元の系列との状態の差が 時刻とともに減るかを見る。青(leak=1.0、純ブール)と橙(leak=0.5、leaky 統合)を 重ねて、減衰するのはどちらかを比べる。

leak は状態の上書き速度を決めるつまみで、st=leak⋅new+(1−leak)⋅st−1s_t = \mathrm{leak}\cdot\text{new} + (1-\mathrm{leak})\cdot s_{t-1}st​=leak⋅new+(1−leak)⋅st−1​ という低域通過フィルタである。1.0 なら完全置換(=純ブール)、 1 未満だと過去の状態が混ざる代わりに、状態は厳密な {0,1}\{0,1\}{0,1} でなくなる。

2つの leak で状態差の推移を出す。数値を先に見ておくと、次の図がどちらへ倒れるかが 印刷された数字の並びからも読める。

読み取り(次に出る図3): 橙(leak=0.5)は摂動窓を抜けたあと右下がりに減衰するが、 青(leak=1.0)は下がらない ── ランダム論理回路は1ビットの違いを層をまたいで 拡散させる方向にも働くので、有界ではあってもそれだけでは収縮しないのである。

ここがハードウェア化の落とし穴になる。fading memory が欲しければ leak を下げるしかないが、 下げた瞬間に状態は {0,1}\{0,1\}{0,1} を外れ、「純ブール回路のまま焼ける」という利点を失う。 fading memory と純ブール性は綱引きの関係にある ── これがこのページ最後の教訓である。

図4: 凍結ランダム回路の「実物」

Section titled “図4: 凍結ランダム回路の「実物」”

この図の見方と読み取り(このページ最後の図)。512ビットのリザバーは大きすぎて 全ゲートを描けないので、同じ作り方でうんと小さいリザバー(状態8ビット・depth=2)を 生成して回路図にする。左端が入力([xt;st−1][x_t ; s_{t-1}][xt​;st−1​] の12ビット)、中央と右が LutLayer 2段の8ゲートずつ、箱の中の文字が確定したゲート名である。

読み取りどころは、学習していないのに具体的なゲート名が付いていること。乱数で引いた 真理値表がそのまま回路として意味を持っているので、このモデルは「作った瞬間から焼ける 回路」であり、学習で変わるのはこの図の外側にある readout だけである。

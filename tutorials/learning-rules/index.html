6. 学習則を切り替える(DFA / AP法)

with_learning() でレイヤ単位に学習ルールを注釈し、HybridTrainer が BP / DFA / EGGROLL / AP法 を協調実行する仕組みを確認する。ここでは DFA(誤差の固定ランダム射影)と AP法(Akiho Propagation。backprop 不要の直接更新)で同じ XOR を解く。

図の読み方: AP法は損失(cross entropy)を最適化対象にしていないため、損失曲線では 値が高いまま短く途切れ「失敗して止まった」ように見える。実際には正解率100%に到達して 早期終了しているだけなので、AP法の成否は右パネルの正解率で判断すること。

このページで学ぶこと

  1. with_learning() + HybridTrainer でレイヤ単位に学習則を混ぜる書き方
  2. DFA(誤差の固定ランダム射影)と AP法(Akiho Propagation。backprop 不要の直接更新)の違い
  3. AP法の成否は損失曲線ではなく正解率で判断する、という図の読み方

前提

  • 付録: XORで仕組みを最小で覗く — 同じ問題を BP で解いた場合
  • 学習を回す — 学習の基本操作

学習アルゴリズム切り替えの例。

with_learning() でレイヤ単位に学習ルールを注釈し、 HybridTrainer が BP / DFA / EGGROLL / AP法 を協調実行する。

論理ゲート網は「backpropが使えるなら使う」が、ハードウェア上での局所学習や 勾配が流せない状況も想定される。そこで本ライブラリは層ごとに学習則を選べる 設計になっている。ここでは同じXORを、誤差逆伝播を使わない2つの方式 (DFA / AP法)で解いて、モデル定義は同じまま学習則だけ差し替えられることを確認する。

3つの学習則の違いは一言でいうと「誤差がどの経路で各層に届くか」だけである。

  • BP … 出力の誤差を、後ろの層の重みを使って1層ずつ逆向きに運ぶ(層が直列に依存)
  • DFA … 出力の誤差を、固定のランダム行列で各層へ直接ばらまく(層が互いに独立)
  • AP法 … 誤差を運ばない。各ゲートが自分の真理値表を局所的に書き換える(微分なし)

実行: uv run python examples/03_learning_rules.py 期待結果: DFAとAP法の両方でXORが学習される

読み方の注意: AP法は損失(cross entropy)を最適化対象にしていないので、 損失曲線だけを見ると「高いまま途中で止まった=失敗」に見えてしまう。AP法の成否は 正解率で判断すること(正解率100%に達した時点で打ち切っている)。そのため下の図は 左=損失・右=正解率の2パネルにしてある。

準備: 学習則を切り替えるためのAPI

Section titled “準備: 学習則を切り替えるためのAPI”

本ライブラリから使うのは3つで、これだけで層ごとに学習則を混ぜられる。

  • with_learning(layer, spec) … 層をラップして「この層はこの規則で更新せよ」と 注釈する。層そのものの定義は変えない
  • LearningSpec(rule=...) … 学習則の指定('bp' / 'dfa' / 'ap' / 'eggroll')
  • HybridTrainer … 注釈を読み取り、層ごとに適切な更新を呼び分ける学習器

3つの学習則は「誤差の届き方」だけが違う

Section titled “3つの学習則は「誤差の届き方」だけが違う”

実験に入る前に、3つの学習則の違いを一言で押さえておく。違いは 誤差(= どちらへパラメータを動かすかの信号)がどの経路で各層に届くかだけである。

  • BP(誤差逆伝播) … 出力の誤差を、後ろの層の重みを使って1層ずつ逆向きに運ぶ。 層が直列に依存するので、前の層の更新は後ろの層を待たなければならない
  • DFA(Direct Feedback Alignment) … 出力の誤差を固定のランダム行列で 各層へ直接ばらまく。層同士が依存しないので並列・局所的に更新できる
  • AP法(Akiho Propagation) … 誤差を層間で運ばない。各ゲートが自分の真理値表を 局所的に書き換える。微分を一切使わないので optimizer すら要らない

なぜ BP 以外が要るのか ── ハードウェア上での学習や、勾配を流せない状況を 想定しているため。局所更新で済む規則ほど回路として実装しやすい。

Section titled “図1の下ごしらえ: 「誤差の経路」を描く関数”

図1: 誤差はどこから来るのか

Section titled “図1: 誤差はどこから来るのか”

上の説明を3枚の模式図にする。縦に積んだ箱が層(下が入力・上が出力)で、 灰色の上向き矢印が forward(値の流れ)。色付きの矢印が誤差の届き方で、 ここが3つの唯一の違いである。

読み取り: 左(BP)は矢印が層を1段ずつ降りてくる。中央(DFA)は出力から 各層へ矢印が直接伸びており、層が互いを待たない。右(AP)は矢印が層をまたがず、 各層の中で完結している ── 誤差の輸送そのものが無い。

重要なのは、モデルの定義は3つとも同じでよいということ。変わるのは with_learning による注釈だけである。

データ: 同じXORを3つの規則で解く

Section titled “データ: 同じXORを3つの規則で解く”

問題を 付録: XOR と同じ4パターンに固定する。 問題を固定して学習則だけを差し替えるので、以降に見える差はすべて 「更新のしかた」の差として読める。

DFA: 誤差を固定ランダム行列でばらまく

Section titled “DFA: 誤差を固定ランダム行列でばらまく”

「でたらめな行列で本当に学習できるのか」 ── これが DFA を初めて見たときの 当然の疑問である。答えは「できる」で、理由は前向きの重みの側が、その固定行列に 合わせて向きを揃えていくから(feedback alignment と呼ばれる現象)。

層同士が依存しないので並列・局所的に更新でき、ハードウェア実装と相性が良い。 代償として精度は BP に劣ることが多い。

コード上は with_learning(..., LearningSpec(rule='dfa')) で層を包むだけで、 LutLayer の定義は XOR のページとまったく同じである。

AP法: 誤差を運ばない直接更新

Section titled “AP法: 誤差を運ばない直接更新”

AP法は各ゲートについて「その真理値表エントリを選んだとき正解に近づくか」を集計し、 良かった方向へスコアを直接足し込む。微分を一切使わないので optimizer も要らず、 HybridTrainer に optimizer を渡していない点がそのまま現れている。

1つだけ制約がある。parameterization='independent' が必須で、真理値表の各エントリを 独立な変数として持たせる必要がある ── AP法がエントリ単位で加算更新するため、 16種の論理関数上の softmax 混合では書き換えられないからである (学習則がパラメータ化を要求する、という具体例)。

BP: 比較のためのベースライン

Section titled “BP: 比較のためのベースライン”

学習則を注釈しなければ、ただの PyTorch モデルとして backward() で学習する。 HybridTrainer すら要らず、zero_grad → forward → backward → step の定型どおり。 3本を同じ図に重ねると「どこまで速く落ちるか」の差がそのまま見える。

評価: 何ステップで解けたかを数える

Section titled “評価: 何ステップで解けたかを数える”

最終正解率だけを見ると3つとも 1.00 で並んでしまい、差が見えない。実際に効くのは 速さなので、収束したステップ数を拾う。

ただし XOR は4サンプルしかなく「たまたま1回だけ全問正解した」がすぐ起きる。 そこで初到達ではなく、そこから最後まで 1.0 を維持した位置(= 腰を据えて解けた点)を 収束と定義する。過大評価を避けるための定義であり、指標の設計そのものが教材である。

図2: loss 曲線(左)と正解率曲線(右)

Section titled “図2: loss 曲線(左)と正解率曲線(右)”

3本を左右2パネルに重ねる。横軸のスケールが大きく違う(AP法は早期打ち切り)ので、 対数軸(symlog)にして形を比べる。

左パネルだけで AP法を評価しないこと。AP法は損失を最適化対象にしていないため、 損失は高いまま短く途切れ、一見「失敗して止まった」ように見える。 AP法の成否は右パネル(正解率)で判断する。右では AP法の終点(=早期終了した瞬間)に ★と注釈を付けてあり、そこが「成功して止まった」ことの証拠になる。

読み取り: 左では BP(青)と DFA(橙)の損失が下がり、AP(緑)だけが高い位置で 途切れる。右を見ると3本とも hard accuracy 1.0 に到達しており、AP は最も早く到達して そこで打ち切られている ── 「損失を見て失敗と判断する」誤読がいかに起きやすいかが分かる。

図3: 何ステップで解けたか(棒グラフ)

Section titled “図3: 何ステップで解けたか(棒グラフ)”

曲線図は形を見るためのもので、速さの比較は棒のほうが一目で分かる。 横軸は hard accuracy が 1.0 に落ち着くまでのステップ数で、短いほど速い。

読み取り(この図が最後なので先に書く): 3つとも数ステップ〜十数ステップで解けており、 「backprop を捨てても解ける」ことが XOR の規模では実際に確認できる。 ただしこれは4サンプルの極小問題での話で、AP法が常に BP より速いという主張ではない。 1. MNISTを学習する の規模では、BP が基準線として最も強いことが多い。

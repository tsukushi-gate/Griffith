乗算器ゼロの物体検出(CenterNet)

乗算器ゼロの物体検出。LutConv2d と OrPooling2d だけで組んだ CenterNet が、 合成 Multi-MNIST の数字を見つけてバウンディングボックスを描くまでを最小構成で追う。 総ゲート数 784、mAP@0.5 = 0.255(500 step の最小予算での実測)。

数分の予算に収めるため、このページはクラス非依存(1クラス)検出に落としてある (10クラス版は同じ予算では立ち上がらなかった)。GT heatmap をクラス方向の max で畳む2行を戻せば10クラス版になる。本番レシピは experiments/train_detection.py を参照(そちらの実測値は compute_map の 画像スコープ修正より前の計測なので再計測待ち)。

このページで学ぶこと

  1. LutConv2d と OrPooling2d だけで CenterNet 型の検出器を組む方法(総ゲート数 784)
  2. heatmap + サイズ回帰から、バウンディングボックスを取り出すまでの後処理
  3. 数分の予算に収めるための縮小の作法と、10クラス版・本番レシピへの戻し方

  • U-Net(セグメンテーション) — 密予測ヘッドの基礎

論理ゲート回路で物体検出(CenterNet-LUT)を解く例。

examples/06_mnist.py は「画像1枚 → クラス1個」の分類だった。物体検出はそこから 2段階むずかしくなる: どこに(座標)を個数不定で答えなければならない。

ここでは CenterNet(Zhou et al. 2019)の考え方をそのまま論理ゲートに載せる。 CenterNet はアンカーもNMSネットワークも使わず、3枚の特徴マップだけで検出する:

この「出力が全部Conv特徴マップ」という構造が論理ゲートNNと相性が良い。 バックボーンは LutConv2d(3x3窓の真理値表を学習する微分可能LUTツリー)と OrPooling2d(OR/maxプーリング)だけで組め、size/offsetのような数値は SpatialGroupSum(発火しているゲートの本数を数えて定数倍する)で作れる。 つまり乗算器を1つも使わずに座標回帰まで完結する検出器になる。

回路の全体像(このサンプルの縮小レシピ k=8・3層の実寸)

具体例が図としてどこに出るか: 上の流れは、このページの図で実際に見られる。

  1. 「input (binarized)」= 上図の TH の出力(64×64のビット平面)
  2. 「GT center heatmap」vs「predicted heatmap (16x16)」= 上図の HMS の出力。 数字の中心の位置に山が立つようになれば学習できている
  3. 「predicted boxes」= 上図の BOX。山のピーク位置に size/offset を当てはめて箱を描いた結果

どう実現しているか

  • 入口で画像をビットにする。グレースケールを3つの閾値で切り、 「濃さ」を3枚のビット平面(3ch)に変換する。論理回路は0/1しか受け取れないので、これが作法
  • 畳み込み = 3×3窓の真理値表。LutConv2d は 3×3=9画素の窓を見て 0/1 を返す LUT の木(深さ3)。CNNのフィルタが「重みの内積」なのに対し、こちらは「表引き」で、 学習するのは表の中身だけ
  • プーリングは OR。max プーリングは、ビットの世界では「どれか1つでも1なら1」= OR に一致する。 比較器も加算器も要らない
  • 数値(確率・幅・高さ・座標)は本数を数えて作る。乗算器を持たない回路が実数を出す方法が SpatialGroupSum で、「32本のうち何本が1か」を16本ずつ数え、1/16 倍して 0〜1 の値にする。 分解能は 1/16 刻み ── 精度が要るなら size_group を増やす。 ヒートマップも同じ作りにしてある: 論理ゲートの出力は評価時に 0/1 へ離散化されるので、 1chのままだとヒートマップが二値になりピークが全部同点になってしまう。 16本の平均(hm_group=16)にすることで 0, 1/16, …, 1 の17段階の確からしさが出せる
  • アンカーもNMSも要らない。CenterNet は「中心セルだけを1にする」問題に落としてあるので、 出力は全部特徴マップのまま。デコードは局所ピーク探索だけで済む

【importについて】 モデル定義 experiments/detection_model.py はまだパッケージ外(experiments/配下)に あるため、本サンプルは sys.path を通して読み込む。将来 griffith_logic 側の 公開APIへ移す予定で、そのときは import 行だけが変わる。

【スケールについて】 CPUで数分に収まるよう、本サンプルは大幅に絞った縮小版になっている:

  • 64x64キャンバスに1〜2個のMNIST数字(本番レシピは96x96)
  • バックボーン幅 k=8(本番は64)・3層(本番は8層)
  • 500イテレーション
  • クラス非依存(1クラス)検出: 「数字がある/ない」だけを当てる 狙いは精度ではなく「ボックスがそれらしい位置・大きさに出る」ことを目で見ること。 10クラス(数字の識別まで行う)本気のレシピは experiments/train_detection.py にある (→モデル一覧)。なおモデル一覧に載っている検出の実測値は compute_map の画像スコープ修正より前の計測なので、再計測待ちである。

実行: uv run python examples/21_detection.py 所要: CPUで2〜4分(マシン負荷による) 期待結果: クラス非依存 mAP@0.5 は 0.20〜0.30 程度。最後の図に予測ボックスが描かれる

ハイパーパラメータ(CPUで数分に収まる縮小レシピ)

Section titled “ハイパーパラメータ(CPUで数分に収まる縮小レシピ)”

出力ストライド(STRIDE)は「入力画像の何画素が検出格子の1マスに対応するか」。 64×64 の画像をストライド4で見るので、検出格子は 16×16 になる。座標はこの格子の上で 予測され、最後に × STRIDE で画像座標へ戻す。SCORE_TH はヒートマップのピークを 「検出1個」として採用する下限スコアで、下げるほど拾い過ぎ・上げるほど取りこぼす。

データ: 合成 Multi-MNIST と CenterNet 形式の教師

Section titled “データ: 合成 Multi-MNIST と CenterNet 形式の教師”

MNIST の数字を 64×64 キャンバスへランダムに置き(重なりなし)、CenterNet 形式の教師を作る。 教師は3種類の特徴マップで、これがそのままモデルの3つの出力に対応する。

  • heatmap ── 物体の中心がそのセルにある確率。中心セルを1、その周りを なだらかなガウシアン(山なりの重み)にして、少しのズレを強く罰しないようにする
  • size(2ch) ── そのセルの物体の幅・高さ(画像サイズで正規化した 0〜1 の値)
  • offset(2ch) ── 格子は粗いので、セルの中心から真の中心までのサブピクセルのずれ

画像のほうは閾値二値化されて (3, 64, 64) のビット平面3枚になる。 論理回路の入力線は 0/1 しか受け取れないので、この二値化が入口の作法である。

モデル: 全部 LutConv2d の CenterNet

Section titled “モデル: 全部 LutConv2d の CenterNet”

先頭3行でデータを実体化してから、検出器を組む(1つのセルにまとめてある)。 バックボーンは Conv→Pool→Conv→Pool→Conv の3ステージで 64×64 を 16×16 に落とし、 その同じ特徴マップから3つのヘッド(heatmap / size / offset)を生やす。

なぜ中心点だけで物体を検出できるのか: 「物体を囲む枠」を直接当てにいくのではなく、 「中心がどのセルか」というセル単位の分類と「そのセルでの幅・高さ・ずれ」という 数値予測に分解しているから。アンカー(あらかじめ用意した候補枠)も NMS(重複枠を消す後処理ネットワーク)も要らず、出力は全部 Conv の特徴マップのままになる。 この「出力が全部特徴マップ」という性質が、論理ゲート回路と相性が良い理由でもある。

なぜ幅・高さのような数値を出せるのか: 乗算器を持たない回路が実数を作る手段が SpatialGroupSum で、「32本のうち何本が1か」を16本ずつ数えて 1/16 倍する。 分解能は 1/16 刻み ── 精度が要るなら size_group を増やす。

損失と評価: focal loss と mAP@0.5

Section titled “損失と評価: focal loss と mAP@0.5”

focal loss は「正解が極端に少ない」分類のための損失で、簡単に当たる背景セルの寄与を 弱めて、中心セルの学習に重みを寄せる。16×16=256 マスのうち中心はたかだか2マスなので、 これが無いと「全部背景」と答えるだけの回路に落ち着いてしまう。

評価指標の mAP@0.5 は物体検出の標準的な指標。予測枠と正解枠の重なり具合を IoU(Intersection over Union = 重なりの面積 ÷ 合併の面積、0〜1)で測り、 IoU が 0.5 以上なら「当たり」とみなして、当たりの取りこぼしと拾い過ぎを平均で1つの数にする。

評価: decode → mAP

Section titled “評価: decode → mAP”

検出のデコードは学習パラメータを持たない後処理で、ヒートマップの局所ピーク (3×3 の窓の中で自分が最大のセル)だけを残し、そこへ size と offset を当てはめて枠を復元する。 「局所ピークを残す」操作が NMS の役割をそのまま果たしているので、専用の後処理器は要らない。

学習ループ

Section titled “学習ループ”

中身は普通の PyTorch で、論理ゲート回路であることを意識する箇所はどこにもない。 EVAL_EVERY ステップごとに mAP を測り、損失の内訳(hm / size / off)も一緒に出す。 内訳を見れば「どのヘッドが伸び悩んでいるか」がそのまま分かる。

可視化: 学習の推移と検出結果

Section titled “可視化: 学習の推移と検出結果”

図1: 損失と mAP の推移

Section titled “図1: 損失と mAP の推移”

この図で何を見るか: 左軸(橙)が CenterNet の合計損失、右軸(緑)が mAP@0.5。 損失が下がるだけでなく、検出指標のほうも一緒に伸びているかを確かめる図である。

読み取り: size の損失は早々に 0 付近へ落ちる ── MNIST の数字は常に 28×28 で、 幅・高さが実質的に定数だからである。難しいのは heatmap と offset のほうで、 mAP はほぼ heatmap のピーク品質だけで決まっていることが2本の線の形から読める。

図2: 学習した heatmap

Section titled “図2: 学習した heatmap”

この図で何を見るか: 左が入力(二値化後)、中央が教師の中心ヒートマップ、 右が回路の出力。数字の中心の位置に山が立っているかが唯一の見どころで、 ここが合っていれば残りは座標の細かい補正でしかない。

読み取り: 教師のヒートマップがなだらかな山なのに対し、予測は「点が数個光る」 見た目になる。評価時の LUT 出力が {0,1} へ離散化され、確からしさが 16本の多数決 (1/16 刻みの17段階)でしか表せないためで、山の裾野は再現されない。 それでもピークの位置さえ合っていればデコードは正しい枠を返す ── だからこの縮小 レシピでも mAP が立ち上がる。裾野の形まで欲しければ、幅 k と層数を増やす必要がある。

図3: 予測ボックスを画像に描く(本サンプルの締め)

Section titled “図3: 予測ボックスを画像に描く(本サンプルの締め)”

この図で何を見るか: 水色の破線が正解の枠、実線が予測の枠(緑 = 正解と IoU 0.5 以上、 赤 = 外した予測)。位置と大きさがそれらしく重なっていれば、乗算器を1つも持たない 論理ゲート回路だけで座標まで回帰できていることが目で確認できる、という締めの図である。

最後の図なので、読み取り方も先に書いておく。8枚のうち緑の枠が付いた数字は 位置も大きさも当たっている一方、赤い枠は「山が立った場所がずれた」ケースで、 数字どうしが近いときに起きやすい。枠の大きさがどれもよく似ているのは、 MNIST の数字が常に 28×28 だからで、size ヘッドが定数を覚えれば済むためである。 つまりこの縮小レシピで難しいのは大きさではなく中心の当て方だ、と図から言える。

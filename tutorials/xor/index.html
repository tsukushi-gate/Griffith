付録: XORで仕組みを最小で覗く

最小構成で、soft(連続緩和)から hard(離散回路)への崩壊のメカニズムを覗く付録。 入力2ビット・16ゲートしかないので、学習前後の回路を全ノード描画でき、 「学習とは16の候補からゲートを1つずつ選び切る作業だ」という主張がそのまま絵になる。 MNIST で起きていたことを、4サンプル・数十行に縮めて観察する回。

このページで学ぶこと

  1. 16ゲートの最小構成で、soft(連続緩和)から hard(離散回路)へ落とす瞬間を全部見る
  2. 学習とは「16種の論理関数の候補からゲートを1つずつ選び切る」作業だ、という見方
  3. 回路図の読み方(学習前 resolve=False の混合 / 学習後 resolve=True の確定ゲート)

前提

  • 基本コンセプト — soft/hard の用語だけ先に押さえる

このページについて

所要時間の目安: 約5分 / 実行環境: CPU のみ(GPU 不要) 元スクリプト: examples/01_xor.py 手元で試す: notebooks/01_xor.ipynb(このページと同じ内容の未実行ノートブック。uv run --group docs jupyter lab notebooks/ で開ける) コード出力はすべて 実際に実行した結果をそのまま埋め込んでいます。

▶ Colabで開く(リポジトリ公開後に有効化)

XOR学習の最小例。

微分可能論理ゲート層(LutLayer)でXORをsoft学習し、 離散回路(hard eval)としても100%になることを確認する。

このライブラリの中心的な主張——「連続緩和で勾配学習した論理ゲート網は、 argmaxで離散化して純粋なBoolean回路に落としても精度を失わない」——を、 4パターン・40行という最小構成で体験するためのスクリプト。XORは1層の線形分離では 解けない最小の問題なので、「本当に非線形な論理を学習できたか」の試金石になる。

回路の全体像(全32ゲート・入力2本・出力2クラス)

緑の区間はビットしか流れないので、そのまま FPGA の LUT に焼ける。 橙になるのは最後の「数えて比べる」ところだけである。 実際に学習された配線とゲート種別は、このページ2枚目の回路図(学習前 vs 学習後)で確認できる。

どう実現しているか

  • 1ニューロン = 1枚の真理値表。普通のNNのニューロンは「重み付き和 → 活性化関数」だが、 LutLayerのニューロンは「入力2本を見て 0/1 を返す表」に置き換わっている
  • 学習しているのは表の中身だけ。どのニューロンが前の層のどの2本を見るか(配線)は 最初にランダムで決めて固定する。動くのは「その表が AND なのか XOR なのか」の部分だけ
  • 表は16通りの候補の混ぜ合わせとして持つ。2入力の論理関数は全部で16種類しかないので、 「16種類への重み付け」(= 1ゲートあたり16パラメータ)を学習すれば微分できる。 使うときは一番重い1種類に確定させる ── これが soft → hard の離散化
  • 深さが表現力を作る。1段目の16ビットを2段目が読むことで、ゲートの合成として より複雑な論理を組み立てる。XOR は2入力なので1枚の表でも足りるが、 ここでは MNIST(例06)と同じ2層構成を最小サイズで体験しておく

実行: uv run python examples/01_xor.py 期待結果: soft/hard 両方で accuracy 1.00

準備: import と乱数種

Section titled “準備: import と乱数種”

必要なのは PyTorch と matplotlib、そして本ライブラリから LutLayer / GroupSum / データセット / 回路描画の4つだけ。特別な学習フレームワークは要らない。

ライブラリは import griffith_logic as gl と読み込むのが公式の慣用形で、 公開シンボルは gl.LutLayer のように参照する(from griffith_logic import LutLayer と書いても同じものが得られる)。

データセット: XORの4パターン

Section titled “データセット: XORの4パターン”

XOR は入力2ビットなので、取りうる入力は (0,0) / (0,1) / (1,0) / (1,1) の4通りで全部。 そのため訓練データとテストデータを分ける必要がない ── 見たいのは「暗記できたか」ではなく 回路として正しい真理値表に落ちたかだからである。

モデル定義: LutLayer 2段 + GroupSum

Section titled “モデル定義: LutLayer 2段 + GroupSum”

LutLayer は「出力ニューロン1個 = N入力の LUT(ルックアップテーブル=真理値表)1枚」に 対応する層で、普通の NN の nn.Linear + 活性化 の位置に入る。GroupSum は論理ゲートの 世界から分類スコアへの出口で、最終層のビットをクラスごとに数え上げる。

下の3行が、このページで扱う回路のすべてである(全32ゲート)。

学習の準備: soft/hard の測り方と確定度

Section titled “学習の準備: soft/hard の測り方と確定度”

このライブラリでは精度を必ず2通りで測る。

  • soft = train() モード。各ゲートは16種の論理関数の「確率的な混合」のまま (= 連続緩和)。勾配が流れる代わりに、まだ回路ではない
  • hard = eval() モード。各ゲートを argmax で1つの論理関数に確定させた状態。 ここから先は学習用の近似ではなく、FPGA に焼けるのと同じ純粋な Boolean 回路

soft だけを見て喜ぶのがこの分野で最も多い失敗なので、最初から両方を測る癖をつける。

学習ループ

Section titled “学習ループ”

中身は完全に普通の PyTorch。特別な学習則は要らない(そこがこの手法の利点)。 学習曲線を描くために、毎ステップ loss と soft/hard の両方を記録する。hard は毎回 eval() へ切り替えて測り直すので、「いつ回路として正解に到達したか」がステップ単位で 分かる(soft より遅れて立ち上がるのが典型的な挙動)。データが4パターンしかないので、 毎ステップ測っても実行時間はほぼ増えない。

評価: soft と hard を必ず両方見る

Section titled “評価: soft と hard を必ず両方見る”

学習が終わったら、まず2つの数字を並べる。hard が 1.00 であることが本質で、 soft だけ高くて hard が落ちる場合は、混合が中間状態に居座っており 「回路として決めきれていない」サインである。

可視化: 学習曲線・回路図・ゲート確定度

Section titled “可視化: 学習曲線・回路図・ゲート確定度”

図1: 学習曲線(loss と soft/hard accuracy)

Section titled “図1: 学習曲線(loss と soft/hard accuracy)”

左が loss(全500ステップ)、右が2種類の accuracy。accuracy が動くのは最初の数十ステップ だけなので、右は冒頭を拡大している(以降はどちらも 1.00 で平坦)。

見どころは右で、hard(実線・濃い緑)が soft(破線・灰)を追いかけ、最後は両方 1.0 で 重なること。これが「連続緩和で学習 → argmax で離散化しても壊れない」という、 このライブラリの中心的な主張そのものである。

右の hard が階段状に跳ぶのは、argmax の結果が切り替わった瞬間にだけ出力が変わる ためで、連続量がなめらかに動いているのではなく回路そのものが離散的に書き換わっている。 縦の点線は hard が「以後ずっと」1.00 になったステップで、その手前で一瞬 1.00 に触れて また落ちているのは、たまたま正解の回路を通り過ぎただけの状態である。

図2: 回路図(同じコードがこの回路になる)

Section titled “図2: 回路図(同じコードがこの回路になる)”

上で書いた3行の nn.Sequential は、実際には「ゲートのノードと、それを結ぶ配線」という 回路そのもの。学習前後を左右に並べて、学習で何が起きたのかを1枚で見る。

  • 左(resolve=False) — 学習前。各ノードは16種の論理関数の混合なので LUT 表示。 色の濃さが確定度(分布エントロピー)で、薄いほど迷っている
  • 右(resolve=True) — 学習後。argmax で確定した論理関数の名前 (AND / XOR / NAND / !A / A>=B …)がノードに入る

名前の元になる真理値表は export_ir が Verilog を吐くときに使うものと同一なので、 この図のゲート = 実際に焼かれる回路のゲートである。

左右を見比べると、学習前は全ノードが灰色に近い LUT のままなのに、学習後は XOR や NAND といった具体的な論理関数の名前が並ぶ。学習とは「16の候補から ゲートを1つずつ選び切る」作業だ、という主張がそのまま絵になっている。

図3: 「16の候補から1つを選び切れたか」を数字で見る

Section titled “図3: 「16の候補から1つを選び切れたか」を数字で見る”

図2の色の濃さ(確定度)を、全32ゲート分のヒストグラムにして定量化する。横軸は各ゲートの 論理関数分布の最大確率、縦軸はそこに入ったゲートの数。

  • 学習前(灰) — 左寄りの山。初期化は乱数なので完全な一様(破線の 1/16 = 0.0625)より 少しは偏っているが、どのゲートも「何者でもない」曖昧な混合のまま
  • 学習後(緑) — 分布ごと右へ移動し、多くのゲートが 0.9 超に到達する。各ゲートが 「自分は XOR だ / AND だ」と言い切れる状態になったということ

ここが右端に寄っていないのに hard acc が 1.00 なら、それは運が良かっただけで、わずかな 摂動で回路が別物に化ける危険がある。逆に右端に寄っていれば、argmax による離散化は 「ほぼ何も捨てていない」ので hard eval が壊れない。

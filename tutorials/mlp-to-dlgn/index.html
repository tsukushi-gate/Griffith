入門3. MLPをDLGNへ置き換える

前ページと同じデータ・同じ学習ループのまま、モデルの中身だけを論理ゲートにする。 nn.Linear + ReLU → LutLayer、出力の nn.Linear(+softmax)→ GroupSum という 1対1の置き換えを実際のコードで見せ、両者の学習曲線を1枚のグラフに重ねる。

実測は MLP 0.9535 に対し DLGN は soft 0.8745 / hard 0.8660(離散化ギャップ +0.0085)。 乗算を1つも持たない回路が、実数 NN の 9割の距離まで来ている。 「重み(掛ける実数)」と「真理値表(どの論理関数か)」の違い、そして DLGN で初めて 現れる soft/hard の二相を並べて確かめ、最後に置き換えチェックリストで締める。

このページについて

所要時間の目安: 約10分 / 実行環境: CPU のみ(GPU 不要) 元スクリプト: examples/26_mlp_to_dlgn.py 手元で試す: notebooks/26_mlp_to_dlgn.ipynb(このページと同じ内容の未実行ノートブック。uv run --group docs jupyter lab notebooks/ で開ける) コード出力はすべて 実際に実行した結果をそのまま埋め込んでいます。

MLPをDLGNへ置き換える ── 同じ問題を論理ゲートで解く(入門コース 3/3)。

前のページで作った MNIST 20x20 の MLP を、 同じデータ・同じ学習ループのまま、モデルの中身だけ論理ゲートへ置き換える。 書き換えるのは実質2行しかない。

置き換えると何が変わるのか、を実測で並べるのがこのページの目的である。

  • 学習の書き方は変わらない ── cross_entropy も backward() も Adam もそのまま
  • 学習される中身が変わる ── 実数の重み(掛け算に使う数)ではなく、 各ゲートの真理値表(AND なのか XOR なのか、という論理関数の選択)
  • 精度が2本になる ── 学習中の連続緩和(soft)と、 argmax で1つの論理関数に確定した回路(hard)の2つを必ず併記する。 この差が 離散化ギャップで、DLGN 特有の唯一にして最大の注意点

最後に「MLP を DLGN に移すときの置き換えチェックリスト」で締める。

実行: uv run python examples/26_mlp_to_dlgn.py 期待結果: MLP test acc 0.95 前後 / DLGN hard acc 0.87 前後(CPUで1分ほど)

準備: 実数側と論理側、両方の道具を持ってくる

Section titled “準備: 実数側と論理側、両方の道具を持ってくる”

前ページまでの PyTorch 一式に、本ライブラリから3つを足す。

  • LutLayer … LUT(ルックアップテーブル=真理値表)を学習する層。 nn.Linear + 活性化 の位置にそのまま入る
  • GroupSum … 論理の世界から分類スコアへの出口。出力ビットをクラスごとに数える
  • gate_labels … 学習後の各ゲートが16種の論理関数のどれに確定したかを名前で返す

ハイパーパラメータ

Section titled “ハイパーパラメータ”

データセット: 前ページとまったく同じ入力

Section titled “データセット: 前ページとまったく同じ入力”

比較の公平さがこのページの生命線なので、データは前ページと1バイトも変えない。 同じ MNIST 20x20、同じ枚数、同じ乱数種。違うのはモデルの中身だけである。

データ(前ページとまったく同じ)

Section titled “データ(前ページとまったく同じ)”

hard 評価用に入力をビットへ落とす

Section titled “hard 評価用に入力をビットへ落とす”

DLGN だけに必要な前処理が1つある。hard 評価(= 焼いた回路そのものとしての評価)では、 入力も 0/1 のビットでなければならない。実際の FPGA に入るのは信号線の High/Low であって 「0.37」のような実数ではないからである。round() で二値化した test_bits を作る。

モデル定義: 同じ問題を解く2つのモデル

Section titled “モデル定義: 同じ問題を解く2つのモデル”

比較対象を2つ並べる。モデルA は前ページと同一の実数 MLP(基準線)。

モデルA: 前ページと同じ実数MLP

Section titled “モデルA: 前ページと同じ実数MLP”

モデルB: 同じ問題を解くDLGN

Section titled “モデルB: 同じ問題を解くDLGN”

モデルB が本題。置き換えの規則は2つだけである。

  • nn.Linear + 活性化 → LutLayer(in, out, n_inputs=2)。 活性化関数は付けない ── 非線形性はゲート(AND / XOR …)そのものが持っているため
  • 出力の nn.Linear(h, 10) → GroupSum(k=10, tau=10.0)。 最終層のビットを10クラス×200本に分けて「1が立った本数」を数えるだけの層で、 重みを1つも持たない(ハードウェア側では加算器1つ)

なぜ幅が 128 から 2000 へ増えるのか ── n_inputs=2 の1ゲートは前層の 2本しか見ない。400入力すべてを見る nn.Linear のニューロンとは情報量が桁違いなので、 本数で補う必要がある。「幅を1〜2桁大きく取る」がDLGNの基本作法になる。

学習: 2つのモデルを同じループで回す

Section titled “学習: 2つのモデルを同じループで回す”

同じ for の中で A と B を並べて更新する。学習ループのコードは1文字も変わらない ── cross_entropy も backward() も Adam もそのまま使える。これが 「PyTorch の資産をそのまま持ち込める」という本ライブラリの主張の実演である。

違いは2点だけ。(1) 学習率を DLGN 側は10倍にする(理由は下のコメント)。 (2) DLGN は soft と hard の2つの精度を測る。soft は train() モードでの 連続緩和のまま、hard は eval() モードで各ゲートを1つの論理関数に確定させた 「焼ける回路そのもの」の精度である。

可視化: MLPとDLGNを並べて読む

Section titled “可視化: MLPとDLGNを並べて読む”

図1: 同じ問題・同じ学習ループでの学習曲線

Section titled “図1: 同じ問題・同じ学習ループでの学習曲線”

3本の線を1枚に重ねる。青=実数 MLP、橙=DLGN の soft、緑=DLGN の hard。 見るべきは緑で、これが「乗算器を1つも持たない回路」としての本当の成績である。

読み取り: MLP(青)が 0.95 前後で頭打ちになるのに対し、DLGN の hard(緑)は 0.87 前後まで来る。差は約 0.08 で、乗算を1つも持たない回路が実数 NN の9割の距離まで 到達している。橙(soft)と緑(hard)の隙間が離散化ギャップで、この実行では +0.01 程度しかない ── 学習中のモデルと焼いた回路がほぼ同じものだ、という意味である。 このギャップが大きく開くときは、ゲートが「どの論理関数か」を決めきれていない。

図2: 学習された「実数の重み」と「選ばれたゲート」

Section titled “図2: 学習された「実数の重み」と「選ばれたゲート」”

「学習された中身」の姿を左右に並べる。左は MLP の1層目の重みのヒストグラム、 右は DLGN の1層目 2000 ゲートがどの論理関数に確定したかの内訳である。 同じ「パラメータを学習した」でも、結果として得られるものがまるで違うことを見る。

読み取り: 左は 0 を中心になめらかに広がる連続分布 ── どの値も「中途半端な実数」で、 推論のたびに掛け算が要る。右は棒が16本(以下)しかない離散的な内訳で、 各ゲートは OR / NOR / パススルー(A や B をそのまま通す)など 名前の付いた論理関数に落ちている(直後の出力に上位5種が出る)。 学習の成果物が「実数のベクトル」から「回路の部品表」に変わった、というのがこの1枚の要点である。

図3: soft と hard は「別のモデル」である

Section titled “図3: soft と hard は「別のモデル」である”

同じ1枚のテスト画像に対する10クラスのスコアを、soft(左)と hard(右)で並べる。 普通の PyTorch では eval() は BatchNorm や Dropout の挙動を変えるだけだが、 DLGN では eval() がモデルの数学そのものを差し替える。この違いを実感するための図。

読み取り: 2つの棒グラフは形が似ているが値は一致していない。soft は16種の 論理関数の混合が生む連続値、hard は「200本のうち何本が1を立てたか」という 本数を tau で割った値であり、そもそも別の計算だからである。それでも最も高い クラスは一致する ── 直後の出力で soft・hard・正解の3つが揃うことを確認できる。

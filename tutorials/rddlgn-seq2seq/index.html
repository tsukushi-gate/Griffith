RNNだけで作るseq2seq(RDDLGN)

エンコーダ・デコーダの全結合層をまるごと LUT に置き換えた RDDLGN で、 copy / reverse という系列変換タスクを学習する。attention を持たない固定長 ボトルネック(384ビットの文脈ベクトル)が、どこまで系列を運べるのかを測る回。

落とし穴もそのまま教材にしている: RDDLGNConfig.init_mode の既定 'zero' は 初期状態を 0.5(中立値)にするため、hard eval のはずの文脈ベクトルへ非二値が流れ込む。 init_mode='one' にすると hard 経路が純ブールで閉じ、精度まで上がる(0.938 → 0.969)。

このページで学ぶこと

  1. 全結合層をまるごと LUT に置き換えた RNN(RDDLGN)で系列変換を学習する組み方
  2. attention を持たない固定長ボトルネックが、どこまで系列を運べるのかの実測
  3. init_mode の選択が hard 経路の純ブール性と精度を左右すること(0.938 → 0.969)

前提

  • 1. MNISTを学習する
  • パラメータ化を選ぶ — init_mode が効く理由

RDDLGN(リカレント微分可能論理ゲート網)でseq2seqを学習する例。

ここまでのサンプル(XOR・MNIST)は「入力1個 → 出力1個」の分類器だった。 本サンプルは 系列 → 系列、つまり翻訳器と同じ形をした エンコーダ・デコーダを、全結合層ではなく論理ゲート(LutLayer)だけで組む。

モデルは RDDLGN(Bührer et al., 2025 / arXiv:2508.06097)。5つの論理ゲート群からなる:

Attentionは無い。エンコーダが読んだ系列は 文脈ベクトル1本に圧縮 され、 デコーダはそれだけを頼りに出力を組み立てる。ここが本サンプルの見どころで、 「論理ゲートだけで固定長ボトルネックを通した記憶ができるか」を確かめる。

タスクは copy(入力をそのまま出す)と reverse(入力を逆順に出す)。 どちらも語彙8・長さ4の合成データで、experiments/data/synthetic.py の CopyDataset / ReverseDataset と同じ作り方をexample内で自己完結させている。

アーキテクチャ図解

Section titled “アーキテクチャ図解”

まずブロック単位の全体像。緑が論理ゲート(LutLayer)、橙が実数のまま残る部分、 青がビット列である。

Attention が無いので、エンコーダが読んだ4トークンぶんの情報は この 384 ビットを通るしかない。ここが唯一の通り道であることが、 このモデルのいちばん大事な性質である。

時間方向に 展開 した詳しい図は、下の「図0」で描く (横軸が時刻で、同じ箱=同じ回路が毎時刻くり返し使われる様子と、 各ブロックのゲート数が入る)。流れているのは copy タスクの実データ1件目 3 5 4 4 → 3 5 4 4 である。

⊕ は 連結(concat) であって加算ではない。P層・M層は [p(t-1) ⊕ context ⊕ l(t)] という長いビット列をそのまま入力に取る。

どう実現しているか(初めて読む人向けの要点)

  • トークン → ビット列: 単語IDを埋め込み表で実数ベクトルにし、sigmoid で 0〜1に押し込む。これが「論理値」。eval のときは 0.5 を境に 0/1 へ切り捨てる (LogicEmbedding)。ここだけは実数の表を引く普通のNN(橙)。
  • 層 = 論理ゲートの束: N/K/L/P/M はどれも LutLayer を積んだだけ。 1個の LutLayer は「入力ビットを2本ずつランダムに拾って、16通りの2入力論理関数から どれを使うかを学ぶゲート」を out_dim 個並べたもの。行列積は1つも無い。
  • 時間方向の記憶: K層は前の時刻の出力 k(t-1) を 入力に連結 して受け取る (図の横向き矢印)。これだけで「前に見たビットを次の時刻へ運ぶ」経路になる。
  • ボトルネック: 系列を最後まで読み終えた k(T) が文脈ビット列。デコーダはこの 384ビットしか見ない。長い系列や順序の入れ替え(reverse)は、この384ビットに 入りきるかどうかが勝負になる。
  • 出力: M層の出したビットを GroupSum が語彙ごとにグループ分けして「1の個数」を数え、 それをスコアにする。数えるところだけが実数(橙)。

実行: uv run python examples/08_rddlgn_seq2seq.py 期待結果: copy / reverse ともに hard token accuracy 0.95 前後(CPUで約1分半)

準備と設定

Section titled “準備と設定”

使うのは RDDLGN と RDDLGNConfig の2つだけ。図0(アーキテクチャの時間展開図)を 自前で描くので、matplotlib の図形パーツも読み込んでおく。

再現性

Section titled “再現性”

論理ゲートの初期真理値表も、ゲート間のランダム配線(どのゲートが前段のどの2本を 見るか)も乱数で決まる。配線は学習中も固定なので、種を変えると回路そのものが別物になる。

タスクとハイパーパラメータ

Section titled “タスクとハイパーパラメータ”

語彙8・長さ4の合成データで、系列を丸ごと運べるかだけを見る極小設定。特殊トークンの PAD / BOS(系列の開始印) / EOS(終了印)は、通常の seq2seq と同じ約束事である。

なぜ二値化正則化が要るのか: LogicEmbedding は sigmoid(埋め込み) を論理値として 使うので、値が 0.5 付近に居座ったまま学習が終わると、eval 時の Heaviside 二値化で 情報がまるごと飛ぶ。x(1−x)x(1-x)x(1−x) を薄く罰して 0 か 1 の端へ寄せておくのがこの重みである。

データ: copy と reverse

Section titled “データ: copy と reverse”

タスクは2つ。copy は入力をそのまま出す恒等写像、reverse は入力を逆順に出す。 どちらも「入力を全部覚えていないと解けない」ので、文脈ベクトルの容量を直接試せる。

両者の差が大事である。copy は先に読んだものを先に出すので、状態が上書きされながらでも 何とかなる。reverse は最後に読んだトークンを最初に出すため、系列の順序情報まで 384ビットに残っていなければ解けない ── ボトルネックへの要求が一段厳しい。

モデル定義: 5つの層群と init_mode

Section titled “モデル定義: 5つの層群と init_mode”

RDDLGN は5つの層群でできている。N層が入力側トークンの変換、K層が時間方向の リカレント(前時刻の出力を入力に連結して受け取る)、L層が出力側トークンの変換、 P層がデコーダ側のリカレント、M層が語彙ロジットを作る出力層である。 どれも LutLayer を積んだだけで、行列積は1つも登場しない。

このセルでもう1つ効いてくるのが init_mode ── リカレント隠れ状態の初期値をどう 置くかの選択で、hard 経路が純粋なブール回路として閉じるかどうかを左右する。 理由はコード中のコメントに書いた通りで、結果は図3で実測する。

teacher forcing(学習時だけ正解を見せる)

Section titled “teacher forcing(学習時だけ正解を見せる)”

自己回帰モデルは本来「自分が出した1つ前のトークン」を入力に取るが、学習中それをやると 序盤の誤りが雪だるま式に増えて学習が進まない。そこで学習時だけ正解列を1つ右へずらして 入力に使う。これが teacher forcing で、seq2seq の定石である。

学習ループ

Section titled “学習ループ”

中身は普通の PyTorch。損失は各時刻のトークン分類 cross entropy に、埋め込みの 二値化正則化を足したものである。150 step ごとに soft(学習時の連続緩和のままの姿)と hard(埋め込みもゲートも二値化した「焼いた回路」の姿)の精度を両方記録しておき、 学習が進むにつれて2本がどう近づくかを図1で見る。

指標はトークン単位の accuracy(位置ごとに1文字ずつ当たったかを平均する)。 系列まるごと一致で数える指標より甘いが、「どの位置で崩れたか」を図2で追える。

図解: アーキテクチャを時間方向に展開する

Section titled “図解: アーキテクチャを時間方向に展開する”

次の2つは作図用のヘルパー(ブロックと矢印)。色は冒頭の Mermaid 図と同じ凡例 ── 緑=論理ゲート / 橙=実数演算 / 青=ビット列 / 灰=トークン ── に揃えてある。

図0: 時間展開したアーキテクチャ

Section titled “図0: 時間展開したアーキテクチャ”

この図で何を見るか: 横軸が時刻、縦軸が層。左半分がエンコーダ(4トークンを読む)、 右半分がデコーダ(1トークンずつ書く)で、真ん中の青い箱が両者をつなぐ唯一の経路である 文脈ビット列。流れているのは copy タスクの実データ1件目 3 5 4 4 そのもの。

見どころは3つ。(1) 縦に並ぶ列はどれも同じ回路で、時刻ごとに使い回されているだけ (だから時間展開しても回路は増えない)。(2) 横向きの矢印は K層と P層にしかない ── 情報が時間方向へ渡る道はそこだけ。(3) 青い箱の幅 384 ビットが、系列全体の情報が 通り抜けなければならない穴の大きさである。

読み取り: エンコーダ側は K層だけが横に伸びており、k(1) → k(2) → k(3) → k(4) と 上書きされながら進む。デコーダ側の3列はすべて同じ青い箱(点線)から給電されている ── つまりデコーダは元の系列を一度も見ず、畳み込まれた 384 ビットだけを頼りに書いている。 Attention 付きのモデル(論理ゲートGPT)がこの点線の代わりに全時刻への直通路を持つ、 という対比で見ると両者の違いがはっきりする。

学習の実行と結果

Section titled “学習の実行と結果”

copy と reverse を同じ設定・同じ種で順に学習する。両方が同じ回路容量で解けるのか、 それとも順序の反転がボトルネックに効くのかを、次の出力と図1で比べる。

hard accuracy が 0.95 前後まで来ていれば、論理ゲートだけで固定長ボトルネックを 通した系列変換ができたことになる。下の assert の閾値 0.80 は環境差を見込んだ緩い線で、 「回路が読めている」ことの最低ラインとして置いている。

可視化: ボトルネックはどこまで運べたか

Section titled “可視化: ボトルネックはどこまで運べたか”

図1: 学習曲線(copy vs reverse)

Section titled “図1: 学習曲線(copy vs reverse)”

この図で何を見るか: 左が copy、右が reverse で、縦軸はトークン accuracy。 橙が soft(学習時の姿)、緑が hard(argmax で確定した実回路)。2本が重なって伸びれば 「学習した性能がそのまま回路に残っている」ことを意味する。

読み取り: 2枚ともほぼ同じ高さまで上がる ── この長さ(4トークン)なら、順序を 反転する reverse でも 384 ビットに十分収まる。ここで reverse だけが伸び悩むようなら、 文脈ベクトルの幅(k_layer_sizes)か系列長がボトルネックに当たっているサインである。 soft と hard が近いのは、埋め込みの二値化正則化と init_mode='one' が効いているため。

図2: 予測列の答え合わせ

Section titled “図2: 予測列の答え合わせ”

この図で何を見るか: 先頭16サンプルについて「正解/予測」を位置ごとにマス目で並べる。 緑が一致、赤が外れ。全体の平均だけでなくどの位置で崩れるかを見るための図である。 Attention を持たないモデルは系列の中ほどを落としやすい、というのが典型的な予想。

読み取り: 赤マスが散らばっていれば「特定の位置が苦手」ではなく、単に容量が足りて いない一様な誤りである。逆に特定の列(位置 t)だけ赤が集中していたら、その時刻の情報が ボトルネックで押し出されている ── 系列を長くすると、まずそういう形で崩れ始める。

図3: 文脈ベクトルは本当に「離散ビット列」か

Section titled “図3: 文脈ベクトルは本当に「離散ビット列」か”

この図で何を見るか: エンコーダが出した文脈ベクトルを、そのまま白黒の画像として描く。 黒が 1、白が 0。ここが灰色を1つも含まないことが、このモデルが「そのまま HDL に 落ちる」ことの担保である(灰色があれば、それは回路に存在しない中間値)。

直前の assert が実際にその判定をしている。init_mode='zero' にすると初期状態 0.5 が 時間方向へ伝播してここが崩れる ── init_mode を config で選ぶ理由がこれである。

読み取り(このページ最後の図): 白と黒しか無く、中間の灰色が1つも無いはずである。 さらに、行ごと(=サンプルごと)に模様が違うのに縦縞のように揃った列もある ── 揃った列は どの入力でも同じ値になる「使われていないビット」で、そこがボトルネックの余裕にあたる。 系列を長くしていくと、まずこの余裕が食い潰され、次に図2の赤マスが増え始める。

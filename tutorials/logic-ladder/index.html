Transformerの論理化の梯子: attentionはどこまで回路にできるか

attention はどこまで論理回路にできるのかを、1段ずつ登って確かめる梯子。 普通の浮動小数点 Transformer(L0)から、射影のゲート化(L1)→ XNOR-popcount スコア(L2) → MUX 選択器(L3-C)へ順に置き換え、コピー課題の精度と attention マップで比較する。

結論は直感に反する。一番落ちるのは L1(射影のゲート化)であり、XNOR 化と softmax の 除去はほぼ無料(L2 で 1.000 に戻り、L3-C でも 0.990)。L3-C の attention マップは 各行で1マスだけが点灯する ── つまり attention とは学習された MUX だった、という絵。

このページで学ぶこと

  1. 浮動小数点 Transformer(L0)から MUX 選択器(L3-C)まで、1段ずつ論理化する道筋
  2. どの段で精度が落ちるか ── 一番効くのは射影のゲート化(L1)であること
  3. attention マップが one-hot になる = attention とは学習された MUX という見方

前提

  • Transformer(論理ゲートGPT) — 登りきった先の完成形
  • 2. ハイブリッドNNを作る — 途中の段で止める設計

「論理化の梯子」— attention をどこまで論理回路にできるかを段階比較する例。

examples/07_logic_gpt.py は「最初から全部論理ゲート」のGPTだった。ここでは逆に、 普通の浮動小数点Transformer(L0)から出発して、attention を1段ずつ論理化し、 どこで性能が落ちるかを測る。これが LogicLadderGPT(D1)の梯子である。

L3-C まで来ると attention は「論理ゲート + 比較器 + MUX」だけで書ける。 つまり softmax の exp/除算が消え、そのまま回路に焼ける。 研究上の主張「attention = 学習されたマルチプレクサ(MUX)」の実証で、 sMNIST/Shakespeare での本格結果は experiments/attention_ladder/REPORT.md にある。

Attentionを回路にする3つの置き換え(具体値つき)

Attentionは「問い(Q)に一番近い相手(K)を探して、その中身(V)を取り出す」操作である。 実数のTransformerはこれを掛け算・指数関数でやるが、論理回路には掛け算器が無い。 そこで各段を、初心者の言葉でいえば次の部品に置き換える。

  • XNOR = 一致検出器: 2本の線が同じなら1を出す1個のゲート。ビット幅ぶん並べる
  • popcount = 多数決(加算木): 1の本数を数えれば「何ビット揃ったか」= 類似度。 二値ベクトル同士の内積は一致数と同じものなので、類似度の意味は失われない
  • MUX = 選択器: 「何番を通すか」で入力を1本だけ出口へ通す交通整理のスイッチ

梯子: 各段で何が実数のまま残り、何が回路になるか

橙 = 実数(乗算器・exp が要る) / 緑 = 論理ゲート(そのまま回路に焼ける)。 このサンプルの構成は d_model=64・n_heads=2・n_layers=2・qk_bits=v_bits=64。 L1以降の論理部は 896 ゲート(LutLayer の出力本数の合計。射影 64×3×2層 + FFN (128+128)×2層)で、モデル全体のパラメータは L0 の 68,422 に対し L3-C は 5,578 (うち LutLayer が 3,584)。乗算器を捨てると規模も1桁落ちる。

実装は griffith_logic/blocks/causal_attention.py の LadderAttention 1クラスで、 score(fp_dot / xnor_popcount)と norm(softmax / mux_gumbel)の2つの文字列を 切り替えるだけで段を移動できる。射影は _LogicProjection(Binarize + LutLayer)、 FFN は L1 以降どの段も LogicMLP に固定して「1段=1変数」を守っている。

タスクは「コピー課題」: 乱数列 → 区切り記号 → 同じ列、を次トークン予測させる。 コピーするには「K+1個前を見る」attention が必須なので、attention の質が そのまま精度に出る(FFNだけでは解けない)。CPUで2〜3分に収まる小サイズ。

実行: uv run python examples/12_logic_ladder_gpt.py 期待結果: L0 = コピー精度1.00、L1 ≈ 0.7、L2 / L3-C ≈ 1.00 付近まで回復

準備: import と乱数種

Section titled “準備: import と乱数種”

4段ぶんのモデルはすべて LogicLadderGPT 1クラスで作る。段の違いは設定辞書だけで 表現され、実装を切り替えたりはしない ── これが「1段=1変数」を守るための仕掛けである。

段どうしを比べるページなので、初期条件は全段で揃える。ここで固定するのは データ生成と重み初期化の両方で、あとで段ごとにも同じ種を引き直す。

タスク: コピー課題

Section titled “タスク: コピー課題”

乱数列 → 区切り記号 → 同じ列、という系列を次トークン予測させる。後半の K 個は 「K+1K+1K+1 個前のトークンをそのまま写す」だけで当たるので、attention が正しい位置を 引けているかを精度が直接映す ── FFN をいくら厚くしても解けない、最小の induction 課題。

バッチ生成は3行。前半 K 個の乱数列、区切り記号 SEP、そして同じ列をもう一度連結する。 採点は後半 K 個だけを対象にする ── 前半は乱数なので、そもそも当てようがない。

梯子の各段: 何を1段ずつ論理化するか

Section titled “梯子の各段: 何を1段ずつ論理化するか”

梯子は4段で、上へ登るほど attention が回路に近づく。

  • L0 — 普通の nn.MultiheadAttention + 実数 FFN。論理化ゼロの天井(比較の基準)
  • L1 — q/k/v の射影だけを LutLayer にし、出力を {0,1}\{0,1\}{0,1} へ二値化する。 スコアはまだ実数の内積、正規化も softmax のまま
  • L2 — スコアを XNOR-popcount へ。乗算器が消え、「ビットが何本一致したか」の 勘定になる(XNOR = 一致なら1を出すゲート、popcount = 立ったビットを数える加算木)
  • L3-C — softmax の加重平均を MUX 選択器へ。最も似ているキーを1本だけ通す

なぜ MUX で選べるのか: softmax の加重平均は、突き詰めれば「どのスロットの中身を どれだけ通すか」を決める装置である。重みが1本に集中していれば、それは 2:1 マルチプレクサ (選択線で2入力の片方を通す素子)の木と同じ働きになる。L3-C はその極限を構造として 最初から強制しており、だからこそ「attention とは学習された MUX である」と言える。

差分は attention 側だけで、d_model などの骨格は全段そろえてある。これを崩すと、 性能差が論理化のせいなのか容量差のせいなのか分からなくなる。

学習ループ(4段に共通)

Section titled “学習ループ(4段に共通)”

同じループを4段すべてに使う。段ごとに違う処理は一切書かず、設定辞書の差だけで 挙動が変わるようにしてある。押さえるべき仕掛けは2つ。

  • 温度アニーリング — 選択器の温度を 2.0 → 0.5 へ徐々に下げ、「ぼんやり混ぜる」から 「1本を選ぶ」硬い挙動へ寄せていく。最初から硬くすると勾配が流れず学習が始まらない
  • 補助損失 — 選択を鋭くする項を AUX_LAMBDA 倍して足す。L0〜L2 では 0 になるので、 全段で同じ式のまま書ける

評価は必ず eval()(選択器が決定的な hard argmax になる=焼いた回路の姿)で行う。

実行: 4段を同じ初期条件で登る

Section titled “実行: 4段を同じ初期条件で登る”

4段を順に学習し、最後にコピー精度を並べる。注目するのは絶対値ではなく段差で、 「どの段で落ちるか」がそのまま「論理化のコストがどこにあるか」の答えになる。

可視化: どこで落ちて、どこで戻るか

Section titled “可視化: どこで落ちて、どこで戻るか”

図1: 梯子の学習曲線

Section titled “図1: 梯子の学習曲線”

この図で何を見るか: 4段の学習曲線を1枚に重ねる。縦軸はコピー精度(hard eval)、 破線がでたらめに答えたときの水準 1/51/51/5。見るべきは到達点そのものより、 どの段の曲線が他から離れるかである。

読み取り: 落ちるのは L1(射影のゲート化) だけで、そこから上の L2・L3-C は ほとんど無料で通る。つまり論理化のコストは「スコアの計算方法」でも「softmax を捨てること」 でもなく、ベクトルをビットに落とすところに集中している。attention の仕組みそのものは 回路と相性が良い、というのがこの梯子の結論である。

図2: 最終精度の比較バー

Section titled “図2: 最終精度の比較バー”

この図で何を見るか: 図1の終点だけを横棒にして、段差を数値で読めるようにしたもの。 曲線が重なって見分けにくい部分を、最終値の並びとして確認するための図である。

読み取り: L0 と L3-C の差はごくわずかで、L1 だけが一段くぼむ。完全に論理化した attention が、浮動小数点の attention とほぼ並ぶことがこの1枚で言える。 逆に L1 の窪みは、射影の二値化をどう設計するかがこの分野の実質的な争点だと示している。

図3: attention の中身

Section titled “図3: attention の中身”

この図で何を見るか: L0(softmax)と L3-C(MUX 選択器)の attention 重みを、 同じ入力で並べたヒートマップ。縦がクエリ位置、横がキー位置で、明るいほど重みが大きい。 コピー課題の正解は「K+1K+1K+1 個前を見る」なので、主対角から K+1K+1K+1 ずれた斜め線が 出ていれば正しく引けている。

読み取り: どちらにも斜め線が出るが、質が違う。L0 は線の周りがぼんやり滲むのに対し、 L3-C は1マスだけが点灯し、残りは真っ黒である。加重平均ではなく選択だからで、 「ぼかす自由度」が構造的に存在しない。同じタスクを、片方は平均で、片方は選択で 解いていることが1枚で見える。

図4: 同じ1行を4段で読み比べる(具体的な重みの数値)

Section titled “図4: 同じ1行を4段で読み比べる(具体的な重みの数値)”

この図の見方と読み取り(このページ最後の図)。図3のヒートマップから 最後のクエリ位置の1行だけを取り出し、4段を縦に並べて棒グラフにする。各段とも 全レイヤ・全ヘッドのうち最も鋭い1本を選んで描くので、「その段がコピー元を指せているか」を 1行で判定できる。赤い破線がコピー元の正解位置である。

読み取りどころは4段の対比。L0 は正解位置に 1.00 で張り付く。L1 は山を作れず 散らばる(=精度が落ちる段の正体がここに映る)。L2 は XNOR スコアでも再び 1.00 に戻る。 そして L3-C は MUX なので構造的に必ず1本になる ── L0・L2 の 1.00 が 「softmax がたまたま鋭くなった結果」なのに対し、L3-C は選択そのものが離散である。 「attention とは学習された MUX」という主張が、重みの数値として読める最後の1枚。

BinaryBrain互換APIでFPGA向けLUT網を学習する

FPGA 向け OSS BinaryBrain と同じ部品構成(RealToBinary → DifferentiableLutBlock → BinaryToReal)で MNIST を学習する。実数画像を確率的に7枚の二値フレームへ変調し、 LUT6 を 430 個並べ、最後に多数決で実数へ戻す ── FPGA の LUT を直接学習する系譜。

このページの主題は「まだ焼けない」ことの定量化である。連続の真理値表(BinaryBrain 本来の推論経路)では eval acc 0.803 だが、エントリを 0/1 へ丸めると 0.211 に崩壊する。 BatchNorm 統計を再較正しても 0.632 までしか戻らない ── 主因は統計ズレではなく、 真理値表エントリが 0.5 付近(std 0.048)に密集したまま決めきれていないこと。 短縮レシピが正直に見せてくれるこの離散化ギャップを、ヒストグラムまで含めて測る。

このページで学ぶこと

  1. RealToBinary → DifferentiableLutBlock → BinaryToReal という BinaryBrain 流の構成
  2. 実数画像を確率的に二値フレームへ変調し、最後に多数決で実数へ戻す仕組み
  3. まだ焼けないことの定量化 ── 真理値表を 0/1 へ丸めたときの崩壊とその主因

前提

  • DWN(二値NN・温度計符号化) — 逆にギャップが 0 になる例
  • パラメータ化を選ぶ

このページについて

所要時間の目安: 約10分 / 実行環境: CPU のみ(GPU 不要) 元スクリプト: examples/22_binarybrain.py 手元で試す: notebooks/22_binarybrain.ipynb(このページと同じ内容の未実行ノートブック。uv run --group docs jupyter lab notebooks/ で開ける) コード出力はすべて 実際に実行した結果をそのまま埋め込んでいます。

BinaryBrain互換API(Binarize / RealToBinary / BinaryToReal / DifferentiableLutBlock)で MNISTを学習する例。

BinaryBrain(https://github.com/ryuz/BinaryBrain)は、FPGAへLUT網を直接焼くことを 前提に設計された日本発のOSSで、「微分可能LUT(Differentiable LUT)」という考え方を 早くから実装していた。本ライブラリはその中核コンポーネントを PyTorch で再実装し、 griffith_logic から素の nn.Module として使えるようにしてある。

なぜ互換性が要るのか

  1. 検証済みレシピをそのまま持ち込める。BinaryBrainのMNISTノートブックの 層構成・初期値(BatchNorm gamma=0.3 / beta=0.5)・Unbinarize bias=0.25 まで 一致させてあるので、精度が出ないときに「実装が違うのか設定が違うのか」を切り分けられる。
  2. FPGA側の資産と接続できる。BinaryBrainのLUTはFPGAのLUT6に1対1で対応する。 同じ構成で学習した重みは、そのままFPGA向けの真理値表として解釈できる。
  3. パラメータ化の比較対象になる。本ライブラリのLutLayerは5通りのパラメータ化を持ち、 BinaryBrain方式は parameterization='raw' に相当する(下記参照)。

LutLayer との関係

つまり BinaryBrain のブロックは「LutLayer を挟んだサンドイッチ」であって、別物ではない。 違いは真理値表のパラメータ化にある:

  • difflogic系(既定 parameterization='softmax'): 16通りの論理ゲートに対する softmax重みを学習し、推論時は argmax で1つのゲートに確定する。
  • BinaryBrain系(parameterization='raw'): 2^N 個の真理値表エントリを [0,1] の 実数として直接保持し、毎ステップ clamp して範囲内に押し戻す。 sigmoid を挟まないので勾配に sigmoid のヤコビアンが乗らない。 FPGAへ焼くときは各エントリを 0/1 に丸めるだけでよい。

回路の全体像(バイナリ変調で実数を挟み込む)

具体例が図としてどこに出るか: このページ1枚目の図 「RealToBinary: one real image -> 7 binary frames -> mean」が、上図の R2B と B2R の実物である。 濃い画素ほど多くのフレームで1になり、7枚を平均すると元の濃淡がほぼ復元される ── これが「実数を、本数という形でビットの世界へ持ち込む」仕掛けの正体である。

どう実現しているか

  • 濃さを「1の本数」に変える。RealToBinary は1枚の実数画像を7枚の二値画像へ複製する。 閾値が等間隔なので、値 0.7 の画素は7枚中およそ5枚で1になる。 これで確率的な情報が、回路が扱えるビット列に化ける
  • 層構成には設計ルールがある。6入力LUTなので「次層のノード数×6 ≧ 前層のノード数」を 満たさないと、誰にも読まれない未接続ノードが出る。400 → 360 → 60 → 10 はその最小構成
  • BatchNorm がビットの偏りを直す。LUT の出力をそのまま次段へ入れると 0 か 1 に偏るので、 実数として正規化してから Binarize で切り直す。この BatchNorm は実数演算なので、 焼くときは閾値としてたたみ込む必要がある(橙のブロック)
  • Binarize は前向きが階段関数、逆向きが素通し(STE)。だから微分できないはずの 二値化を挟んだまま勾配が最後まで届く
  • 真理値表を直接持つ(raw)。difflogic 系が「16種の論理関数への重み」を学ぶのに対し、 BinaryBrain 方式は 2⁶=64 個のエントリを [0,1] の実数のまま持ち、毎ステップ clamp する。 焼くときは各エントリを丸めるだけでよい

実行: uv run python examples/22_binarybrain.py 期待結果: eval accuracy 0.80前後(CPUで約2分)

なお本サンプルは短時間レシピなので、真理値表はまだ 0/1 に決めきれていない。 「学習は動くが、そのまま焼くには足りない」ところまでを、 離散化ギャップとして最後に定量的に見る(図2・図3)。

準備: import と乱数種

Section titled “準備: import と乱数種”

使うのは BinaryBrain 互換の3部品 ── RealToBinary(実数をビット列へ)、 DifferentiableLutBlock(LUT のサンドイッチ1段)、BinaryToReal(ビット列を実数へ)── と、20×20 に縮めた MNIST だけ。LUT の接続(どの入力線を見るか)はランダムに決まるので、 再現性のために乱数種を固定する。

ハイパーパラメータ

Section titled “ハイパーパラメータ”

記号の意味を先に決めておく。N_INPUTS(= LUT の入力数) は1つの真理値表が見る線の本数で、 6 は FPGA の LUT6 に1対1で対応する本命の値。エントリ数は 2⁶ = 64 になる。 FRAME_M(= バイナリ変調のフレーム数、本文では M) は、1枚の実数画像を何枚の 二値画像に分解するかで、大きいほど濃淡を細かく表せるが、そのぶん計算量も M 倍になる。

データ: 20×20 の MNIST を実数のまま受け取る

Section titled “データ: 20×20 の MNIST を実数のまま受け取る”

ここが他の例と違うところ。多くの論理ゲート NN の例では入口で画像を二値化してしまうが、 BinaryBrain 流では実数の濃淡のまま受け取り、モデルの中の RealToBinary が 「濃さ → 1 になるフレームの本数」へ変換する。だから binarize_threshold=None で読む。

モデル: DifferentiableLutBlock を3段重ねる

Section titled “モデル: DifferentiableLutBlock を3段重ねる”

1段の中身は Unbinarize → LutLayer(raw) → BatchNorm1d → Binarize の サンドイッチである。なぜ BatchNorm を挟むのか: LUT の出力をそのまま次段へ入れると 0 か 1 に偏ってしまい、次の LUT がどの入力を見ても同じ答えを返す状態に陥る。 いったん実数として正規化し直してから Binarize で切り直すことで、 各段のビットの偏りをならしている(この BatchNorm は実数演算なので、FPGA へ焼くときは 閾値としてたたみ込む必要がある)。

Binarize は前向きが階段関数、逆向きが素通し(STE = straight-through estimator、 微分できない関数の勾配をそのまま通す近似)。だから二値化を挟んだまま勾配が最後まで届く。

学習: clamp を1行足すだけの普通の PyTorch

Section titled “学習: clamp を1行足すだけの普通の PyTorch”

中身は完全に普通の PyTorch で、BinaryBrain 固有なのは 「optimizer.step() のあとに clamp_weights() を呼ぶ」の1行だけ。 なぜ clamp が要るのか: raw パラメータ化では真理値表のエントリを 「そのエントリが1を出す確率」としてそのまま持つので、勾配で [0,1] の外へ逃げると 意味を失う。sigmoid で押し込める代わりに毎ステップ切り戻す、というのが本家の流儀で、 勾配に sigmoid のヤコビアン(傾きの掛け算)が乗らないぶん学習が素直になる。

学習中は毎回2つの精度を測る。eval(連続の真理値表のまま = BinaryBrain 本来の推論経路)と、 rounded(エントリを 0/1 へ丸めた複製 = 素朴に FPGA へ焼いた場合)。 この2本の差が離散化ギャップで、このページの主題そのものである。

離散化ギャップ: 丸めるとなぜ壊れるのか

Section titled “離散化ギャップ: 丸めるとなぜ壊れるのか”

丸めると精度が大きく落ちる。原因の候補は2つある。(a) 真理値表がまだ 0/1 に 決めきれておらず、丸めが情報を壊している。(b) LUT 出力の分布が激変して、 BatchNorm が持っている移動平均の統計が合わなくなっている。 (b) なら統計を測り直せば戻るはずなので、訓練データを流して再較正し、 どちらが主因かを実験で切り分ける。原因の切り分けまでやるのがこの節の主題である。

可視化: 変調・学習曲線・真理値表の分布

Section titled “可視化: 変調・学習曲線・真理値表の分布”

図1: バイナリ変調(RealToBinary)が何をしているか

Section titled “図1: バイナリ変調(RealToBinary)が何をしているか”

この図で何を見るか: 左端が元の実数画像、続く7枚が閾値 (f+0.5)/M をずらして 作った二値フレーム、右端がそれを平均して戻したもの。濃い画素ほど多くのフレームで1になる という対応を、1枚ずつ目で追う図である。

バイナリ変調とは、値の大きさを「1になるフレームの本数」で表す符号化のこと (パルス密度変調と同じ発想)。閾値が等間隔なので、値 0.7 の画素は7枚中およそ5枚で1になる。 これで連続値の情報が、回路が扱えるビット列に化ける。

読み取り: 右端(7枚の平均)が左端(元画像)とほぼ同じに見えることが要点で、 ビットの本数だけで濃淡が往復できているということ。逆に言えば、M を小さくするほど この復元は粗くなる(M=7 なら濃さは 8 段階しか区別できない)。

図2: 学習曲線と離散化ギャップ

Section titled “図2: 学習曲線と離散化ギャップ”

この図で何を見るか: 緑が BinaryBrain 本来の推論経路(連続の真理値表)、 橙が「いま丸めて焼いたら」の精度、赤い破線が丸めたうえで BatchNorm を再較正した場合。 緑と橙の隙間の広さと、赤い破線がその隙間をどれだけ埋めるかの2点を見る。

読み取り: 緑と橙の隙間はこの縮小レシピでは大きく開いたままで、赤い破線 (BatchNorm 再較正)はその一部しか埋めない。つまり離散化ギャップの主因は **統計のズレ(b)ではなく、真理値表がまだ 0/1 に決めきれていないこと(a)**だと結論できる。 その裏付けを次の図で直接見る。

図3: 真理値表エントリの分布

Section titled “図3: 真理値表エントリの分布”

この図で何を見るか(最後の図なので読み取り方も先に置く): 横軸は LUT エントリの値 (= そのエントリが1を出す確率)、縦軸は個数(対数)。灰が学習前、青が学習後。 焼ける回路とは、この分布が 0 と 1 の両端へ張り付き、round() しても情報が失われない状態 を指す。ところがここでは、分布は初期値 Normal(0.5, 0.01) から少し広がっただけで、 依然として 0.5 付近に密集したままになる ── だから丸めると壊れる(図2の橙)。 BinaryBrain の推論が連続重みのままで成立するのもこのためで、 「学習は動くが、まだ焼ける状態ではない」というのがこのページの正しい読み方である。 両端へ寄せるには本家並みの長い学習(あるいは二値化を促す正則化)が要る。

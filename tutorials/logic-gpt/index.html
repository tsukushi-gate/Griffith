論理ゲートGPTでシェイクスピアを書く

Attention も FFN も出力ヘッドも、全部が論理ゲートの decoder-only Transformer で シェイクスピアを書く。実数の行列積を一切持たない LogicGPT を Tiny Shakespeare の 文字レベル言語モデルとして学習し、uniform baseline の 5.00 bpc から 3.13 bpc まで 落ちていく様子と、生成されたテキスト(話者行・単語らしい綴り・改行構造まで出る)を見る。

同時に、このページは離散化ギャップの一番わかりやすい実例でもある。soft(学習時の 連続緩和)では読める文が出るのに、hard(argmax で確定した離散回路)にすると崩れる ── 言語モデルという難しいタスクほど、この差が正直に出る。

このページで学ぶこと

  1. attention・FFN・出力ヘッドまで全部が論理ゲートの decoder-only Transformer の構成
  2. 文字レベル言語モデルの指標 bpc の読み方(uniform baseline 5.00 → 3.13)
  3. 言語モデルでは離散化ギャップ(soft は読めるのに hard で崩れる)が最も正直に出ること

前提

  • 1. MNISTを学習する — soft/hard の読み分けを先に体験する
  • 学習曲線の見方

このページについて

所要時間の目安: 約10分 / 実行環境: CPU のみ(GPU 不要) 元スクリプト: examples/07_logic_gpt.py 手元で試す: notebooks/07_logic_gpt.ipynb(このページと同じ内容の未実行ノートブック。uv run --group docs jupyter lab notebooks/ で開ける) コード出力はすべて 実際に実行した結果をそのまま埋め込んでいます。

▶ Colabで開く(リポジトリ公開後に有効化)

LogicGPT で文字レベル言語モデルを学習し、シェイクスピア風テキストを生成する例。

MNIST(examples/06_mnist.py)では「画像を分類する回路」を作った。ここでは同じ 論理ゲートで decoder-only Transformer(GPT) を組み、次の1文字を予測する 言語モデルを学習する。attention も FFN も出力ヘッドも、内部の値はすべて [0,1] の論理域で動く(浮動小数点の行列積で「意味」を作っていない)。

LogicGPT の全体像(実クラス名とゲート数つき)

このサンプルの構成(d_model=192・2層・語彙32文字)で、学習されるゲートは 合計 2,560 ゲート / 48,640 パラメータ。緑が論理ゲート(そのまま回路になる)、 橙が実数演算(訓練の都合で残っている部分で、IR では blackbox 扱いになる)。

Attention をどう回路にしているか(初心者向けの言い換え)

  • XNOR = 一致検出器。2本の線が同じ値なら1を出す1個のゲート。クエリとキーの ビットを1本ずつ突き合わせる
  • popcount = 多数決(加算木)。一致した本数を数えれば「どれくらい似ているか」。 実数Transformerの内積(掛け算の山)がこれに置き換わる
  • MUX = 選択器。softmax の加重平均をやめ、eval では一番似ているスロットの 中身だけを1本通す。LogicAttention(mode='hard') の argmax がこれにあたる

置き換えの理屈を1段ずつ確かめる回は Transformerを段階的に論理化、 4つの引き方を比べる回は 論理ゲートAttentionの4変種ツアーにある。

このサンプルは CPU で3〜4分に収まるよう、d_model=192・2層・コンテキスト32文字・ 1500 step まで縮めてある(本気のレシピは configs/recipes/logic_gpt_shakespeare.yaml、 実験結果はモデル一覧を参照)。 その規模でも「単語らしい綴り・改行・ROMEO: のような話者行」までは出てくる。

読みどころは3つある:

  1. bpc が下がるか(図1)。bpc = bits per character は「次の1文字を当てるのに 何ビット必要か」で、32文字を当てずっぽうに選ぶと log2(32)=5.0 bpc。 ここから下がった分だけ、回路が文字の並びの規則を覚えたことになる。
  2. soft と hard の差(図2)。学習中はゲートを連続緩和して微分するが、 実際にFPGAへ焼くのは argmax で確定した離散回路。この2つの性能差が 「離散化ギャップ」で、論理NN最大の関門。縮小レシピでは差が残る。
  3. どこまで過去を見ているか(図3)。causal self-attention なので、系列の先頭は 手がかりが1文字も無く、後ろへ行くほど当てやすくなるはず。位置ごとの正解率を 見ると、最初の数文字で急に立ち上がってすぐ頭打ちになる ── この規模の回路が 実際に使えている文脈の長さが、そのまま形に出る。

実行: uv run python examples/07_logic_gpt.py 期待結果: val bpc(bits per character)が 5.0 → 3.1 前後まで下がり、 最後に生成テキストが表示される(ランダム文字列ではないことが目で分かる)

準備: import と乱数種

Section titled “準備: import と乱数種”

必要なのは PyTorch と matplotlib、そして本ライブラリの LogicGPT / LogicGPTConfig の2つだけ。 学習ループも生成ループも通常の GPT とまったく同じ書き方で、差し替わっているのは モデルの中身(行列積 → 論理ゲート)だけである。

ゲートの初期配線(各ゲートが前段のどの2本の線を見るか)と初期の真理値表は乱数で決まる。 配線は学習中も固定されたままなので、種を変えると回路そのものが別物になり、bpc の 落ち方も変わる。比較できる結果にするため、最初に種を固定しておく。

設定とデータ: 縮小レシピと Tiny Shakespeare

Section titled “設定とデータ: 縮小レシピと Tiny Shakespeare”

ハイパーパラメータ

Section titled “ハイパーパラメータ”

このページは CPU で3〜4分に収まる縮小レシピである。D_MODEL は1文字を表す ビット幅(=回路を流れる論理線の本数)、BLOCK は文脈長(次の1文字を予測するのに 何文字さかのぼるか)。増やすほど文章は良くなるが、そのぶん学習時間も伸びる。

REG_LAMBDA は埋め込みを {0,1}\{0,1\}{0,1} へ押し付ける正則化の強さで、あとで見る 「離散化ギャップ」に直接効くつまみである。

データ: Tiny Shakespeare

Section titled “データ: Tiny Shakespeare”

学習コーパスは Tiny Shakespeare(戯曲の台詞を集めた約110万文字のテキスト)。 リポジトリに置いていない環境でも動くよう、無ければ下の埋め込みサンプルへ自動で切り替える。

語彙(vocabulary)= モデルが扱う文字の種類。ここでは大文字を落として記号を絞り、 32文字まで縮める。出力ヘッドのゲート数は語彙サイズに比例する(vocab × head_group_factor) ので、語彙を小さくすることは回路を小さくすることとほぼ同義である。

文字を ID の列へ変換し、前半90%を学習用・後半10%を検証用に分ける。言語モデルの 検証は「見たことのない続きをどれだけ当てられるか」なので、時間方向で切るのが定石である。

学習データの作り方も普通の GPT と同じ。入力 x は連続する32文字、正解 y はそれを 1文字だけ右にずらした列である。こうすると1回の forward で32個の位置すべてについて 「次の1文字」を同時に学習でき、causal マスク(後述)が未来のカンニングを防ぐ。

モデル定義: 論理ゲート版 GPT

Section titled “モデル定義: 論理ゲート版 GPT”

骨格は普通の GPT(埋め込み → 位置符号 → causal self-attention × N → 出力ヘッド)で、 中身の演算子だけが総入れ替えになっている。なぜそんな置き換えが可能なのかは、 実数 Transformer の各部品を「何をしている装置か」で読み替えると分かる。

  • 内積(類似度)→ XNOR + popcount。内積は「2本のベクトルがどれだけ揃っているか」を 測る装置にすぎない。ビット列なら、各桁を XNOR(一致なら1を出すゲート)に通して 1の本数を数えれば同じことができる。popcount = 立っているビットの本数を数える加算木
  • softmax の加重平均 → MUX(選択器)。加重平均は「どのスロットの中身をどれだけ通すか」の 装置。eval では一番似ているスロットだけを通す 2:1 マルチプレクサの木に置き換わる
  • Linear + 活性化 → LutLayer。1ニューロン = 1枚の真理値表(LUT)

つまり attention は「注目度で重みを付ける魔法」ではなく、一致検出 → 本数を数える → 選ぶという3段の回路であり、そのどれもが論理ゲートで書ける。

学習ループ

Section titled “学習ループ”

中身は完全に普通の PyTorch で、特別な学習則は要らない(そこがこの手法の実用上の利点)。 違いは損失が2本あることだけ: 通常の cross entropy に加えて、forward が返す emb_reg_loss(埋め込みのビットを 0 か 1 に押し付ける正則化)を REG_LAMBDA 倍して足す。

なぜ正則化が要るのか: 学習中の埋め込みは 0.5 のような中間値を取れてしまうが、 実際の回路にそんな値は存在しない。中間値に依存した解を学習すると、argmax で確定した 瞬間に性能が崩れる。あらかじめ端へ寄せておくことが、次章で測る離散化ギャップを縮める。

評価: soft と hard の離散化ギャップ

Section titled “評価: soft と hard の離散化ギャップ”

ここで使う指標が bpc(bits per character、1文字あたりのビット数)である。 「次の1文字を言い当てるのに何ビットの情報が要るか」で、小さいほど良い。32文字から 当てずっぽうに選ぶなら log⁡232=5.00\log_2 32 = 5.00log2​32=5.00 bpc で、そこからの差が学習した分になる。 (言語モデルでよく見る ppl(perplexity)は 2bpc2^{\text{bpc}}2bpc で、同じものの別表現。)

そして論理ゲート NN では、精度を必ず2通りで測る。train() と eval() が ドロップアウトの有無ではなく回路そのものの姿を切り替えるからである。

同じ検証バッチ256本を soft / hard の両方で流し、bpc と「次の1文字の的中率」を並べる。 出力の3行目に出る 離散化ギャップ = hard の bpc − soft の bpc が、 「soft で得た性能のうち、ハードウェアに持ち込めなかった分」である。

テキスト生成: 回路に続きを書かせる

Section titled “テキスト生成: 回路に続きを書かせる”

bpc は数字なので、実際に文章を吐かせて目でも確かめる。自己回帰生成とは 「直近32文字を回路に入れて次の1文字を得る → それを末尾に継ぎ足して窓を1つ右へずらす」を 繰り返すこと。1文字ごとに回路を1回通すだけで、特別な仕掛けは無い。

温度(temperature)は次の1文字の選び方の大胆さを決める割り算の分母で、1.0 が モデルの確率そのまま。下げるほど確信の高い文字ばかり選ぶ(綴りは安定するが同じ語を 繰り返しやすい)。soft と hard の2通りで同じプロンプトから書かせて、下に並べて出す。

可視化: 何を学び、離散化で何を失ったか

Section titled “可視化: 何を学び、離散化で何を失ったか”

図1: 学習曲線(val bpc)

Section titled “図1: 学習曲線(val bpc)”

この図で見るのは「どれだけ学んだか」の総量。縦軸は検証データの bpc、破線は 何も学んでいない状態(32文字から等確率で選ぶ 5.00 bpc)。破線からどれだけ下へ 離れたかが、そのまま回路が覚えた文字の並びの規則性である。

読み取り: 序盤で一気に落ちてから 3.1 bpc 付近で寝る。落ちた約1.9 bpc ぶんが 学習量で、寝るのは 1500 step という縮小レシピの上限に当たっているためである (本番レシピではここからさらに下がる)。曲線がまだ下向きなら学習を延ばす余地がある、 という読み方をする図でもある。

図2: 離散化ギャップ(soft vs hard)

Section titled “図2: 離散化ギャップ(soft vs hard)”

このページで一番見てほしい図。棒は3本で、左が「何も学ばない」基準線、中央が 学習時の連続緩和モデル(soft)、右が argmax で確定した実際に焼ける回路(hard)。 棒は低いほど良い。中央と右の差=離散化ギャップが、この分野の最大の関門である。

読み取り: soft は基準線から大きく下がっているのに、hard はそのかなり手前で止まる。 つまり soft の性能の一部は、実回路に存在しない中間値の上に乗っていた。分類課題(MNIST)より 言語モデルでギャップが大きく出るのは、次の文字の確率という細かい差を扱うためで、 論理ゲート NN の弱点が最も正直に現れるのがこのタスクである。縮めるには REG_LAMBDA を上げて埋め込みを {0,1}\{0,1\}{0,1} へ強く寄せ、より長く学習する。

図3: 位置ごとの的中率

Section titled “図3: 位置ごとの的中率”

この図で見るのは「どこまで過去を使えているか」。横軸は32文字の文脈の中の位置、 縦軸はその位置での次文字的中率。causal self-attention は各位置が自分より左しか 見られない制約なので、左端(position 0)は手がかりゼロ、右へ行くほど有利になるはず。 右上がりなら文脈を使っており、平坦なら文字の出現頻度だけで当てていることになる。

読み取り: soft は最初の数文字で急に立ち上がり、すぐ頭打ちになる ── この規模の 回路が実際に使えている文脈は数文字ぶんしかない(以降の凹凸は検証バッチの揺らぎ)。 一方 hard はほぼ平坦で、離散化で真っ先に壊れるのが文脈の利用だと分かる。 図2 のギャップの正体が「文脈を失うこと」だ、というのがこの2枚を並べた結論である。

図4: 学習した文字分布

Section titled “図4: 学習した文字分布”

この図で見るのは「一番易しい部分は学べたか」。コーパスの文字頻度(灰)と、 生成テキストの文字頻度(橙)を文字ごとに並べる。並びを覚える前に、まず英文の 文字統計を覚えるのが言語モデルの第一歩なので、その到達を確認する。

読み取り: 2本の棒がおおむね同じ形なら、空白・e・t といった頻度の階層は 回路の中に入っている。逆に空白と e だけが突出していたら、頻度は覚えたが並びは 覚えていない兆候で、これは離散化ギャップが大きいときに典型的に起きる崩れ方である。

図5: 自己回帰生成を時間方向に展開する

Section titled “図5: 自己回帰生成を時間方向に展開する”

最後に、生成が実際どう進むのかを1ステップずつ切り出して並べる。次のセルでは、 各ステップの文脈・出した文字・そのとき上位だった3文字の確率を記録している。

この図の見方と読み取り(このページ最後の図)。各行が1ステップで、上から下へ時間が進む。 灰色がプロンプト、緑がそれ以前に回路自身が出した文字、橙がそのステップで出した1文字。 右端は上位3文字とその確率である。

読み取りどころは2つ。(1) 橙の文字が次の行の右端に入り、窓が1マスずつ右へ滑る ── これが自己回帰そのもので、回路は文章を一度に書かず1文字ずつしか出さない。 (2) 出した文字が必ずしも上位1位ではない ── 温度 0.8 で確率的に選んでいるためで、 同じ回路・同じプロンプトでも種を変えれば別の文章になる。

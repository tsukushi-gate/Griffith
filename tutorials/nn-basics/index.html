入門1. ニューラルネットとPyTorchの基礎

機械学習をやったことがない人のための最初の1本。 このページに DLGN は出てこない。 テンソル → 自動微分 → nn.Module → 学習ループ、という PyTorch の全体像を 2次元のトイデータ(直線では分けられない三日月2つ)の分類で一周する。

主題は精度ではなく「学習とは何をしていることなのか」を目で見ること。 1パラメータの損失を勾配降下で下る図、学習前後の決定境界、そして 動いた実数の重みそのものの3枚で、NN が実数の世界に住んでいることを確かめる。

このページについて

所要時間の目安: 約8分 / 実行環境: CPU のみ(GPU 不要) 元スクリプト: examples/24_nn_basics.py 手元で試す: notebooks/24_nn_basics.ipynb(このページと同じ内容の未実行ノートブック。uv run --group docs jupyter lab notebooks/ で開ける) コード出力はすべて 実際に実行した結果をそのまま埋め込んでいます。

▶ Colabで開く(リポジトリ公開後に有効化)

ニューラルネットとは何か ── PyTorchの基礎をゼロから(入門コース 1/3)。

このページは「機械学習をやったことがない人」のための最初の1本である。 DLGN(微分可能論理ゲートNN)の話は一切出てこない。ここでやるのは、 普通のニューラルネット(NN)を PyTorch で書いて動かし、 **「学習とは何をしていることなのか」**を自分の目で見ることだけ。

扱うのは次の4つで、これがそのまま PyTorch の全体像になる。

  1. テンソル ── NN が扱う数の入れ物(表計算のセルが多次元になったもの)
  2. 自動微分 ── 「どっちへ動かせば正解に近づくか」を PyTorch が勝手に計算してくれる仕組み
  3. nn.Module ── 層を組み合わせてモデルを作る書き方
  4. 学習ループ ── 予測 → 誤差 → 修正 を何百回も回す、たった5行の型

題材は2次元のトイデータ(三日月が2つ噛み合った形。直線では分けられない)の分類で、 決定境界がぐにゃりと曲がっていく様子と、そのとき裏で 実数の重みがどう変わったかを並べて見る。

実行: uv run python examples/24_nn_basics.py 期待結果: test accuracy 0.95 以上(2層の小さな MLP・CPUで数秒)

次の1本 examples/25_pytorch_mlp.py では、同じ書き方のまま手書き数字(MNIST)へ、 その次の examples/26_mlp_to_dlgn.py で同じ問題を論理ゲートへ置き換える。

準備: このページで使う道具

Section titled “準備: このページで使う道具”

使うのは PyTorch(torch)と作図の matplotlib だけ。DLGN のライブラリは このページでは一切登場しない ── まず普通のニューラルネットを一周する。

  • torch … テンソル(多次元の数の並び)と自動微分を提供する本体
  • torch.nn … 層(nn.Linear など)とモデルの組み立て方
  • torch.nn.functional(F) … 損失関数など、状態を持たない関数群

学習の結果は乱数に依存する。重みの初期値(層が持つ数の出発点)も、 データのノイズも乱数から作られるので、種を固定しないと実行のたびに数字が変わり、 「コードを直したから変わったのか、乱数で変わったのか」が区別できなくなる。

テンソル: NNが扱う数の入れ物

Section titled “テンソル: NNが扱う数の入れ物”

テンソルとは多次元の数の並びのことで、NN の計算はすべてこの上で行われる。 0次元=スカラー、1次元=ベクトル、2次元=行列、と次元が増えていく。

ここでは「3サンプル × 2特徴」の入力 x、「2特徴 → 1出力」の重み w、 出力をずらすバイアス b を手で置き、NN の1層が何をしているのかを x @ w + b(行列積 + 足し算)の1行で確かめる。層の実体はこれだけである。

テンソルを作って掛けて足す

Section titled “テンソルを作って掛けて足す”

@ は行列積の演算子。1行目の答えは 1.0×0.5+2.0×(−1.0)+0.1=−1.41.0 \times 0.5 + 2.0 \times (-1.0) + 0.1 = -1.41.0×0.5+2.0×(−1.0)+0.1=−1.4 で、 手計算と一致する。掛けて足すだけが層の中身であり、 学習とは「この w と b の値を良いものに変えること」に他ならない。

自動微分: どちらへ動かせばよいかを機械に計算させる

Section titled “自動微分: どちらへ動かせばよいかを機械に計算させる”

良い w を人手で探すのは不可能なので、機械に「どちらへ動かせば良くなるか」を 計算させる。その情報が勾配(gradient)で、「そのパラメータを少し増やすと 損失がどれだけ増えるか」を表す1つの数である。

ここでは最小の例として、パラメータ ppp 1個だけの損失 loss=(p−3)2\mathrm{loss} = (p-3)^2loss=(p−3)2 を使う。p=3p=3p=3 で最小になる、ただの2次関数である。 requires_grad=True を付けたテンソルは計算の履歴を覚えており、 loss.backward() を呼ぶと勾配が p.grad に入る。

勾配を1つ計算してみる

Section titled “勾配を1つ計算してみる”

手で微分すると ddp(p−3)2=2(p−3)=2(0−3)=−6\frac{d}{dp}(p-3)^2 = 2(p-3) = 2(0-3) = -6dpd​(p−3)2=2(p−3)=2(0−3)=−6。 自動微分が返す値もこれと一致する ── PyTorch は魔法ではなく、 連鎖律を機械的に適用しているだけだと確認できる。

勾配降下: 勾配の逆向きへ少しずつ進む

Section titled “勾配降下: 勾配の逆向きへ少しずつ進む”

勾配が分かれば、あとはその逆向きへ少しずつ動かすだけでよい。これが 勾配降下法で、更新式は p←p−η⋅dlossdpp \leftarrow p - \eta \cdot \frac{d\mathrm{loss}}{dp}p←p−η⋅dpdloss​。 η\etaη(コード上の lr)は学習率、つまり一歩の大きさで、 大きすぎると谷を飛び越えて発散し、小さすぎるといつまでも着かない。

逆向きに進むのは、勾配が「増やすと損失が増える向き」を指しているため。 損失を減らしたいのだから、符号を反転させる必要がある。

図1: 勾配降下が谷を下りていく様子

Section titled “図1: 勾配降下が谷を下りていく様子”

灰色の曲線が損失 (p−3)2(p-3)^2(p−3)2、橙の点が各ステップでの ppp の位置である。 12ステップぶんの点が谷底(緑の破線 p=3p=3p=3)へ吸い込まれていく様子を見る。

読み取り: 点の間隔は谷底に近づくほど狭くなっている。勾配 2(p−3)2(p-3)2(p−3) が 谷底へ近づくほど小さくなり、歩幅 η⋅2(p−3)\eta \cdot 2(p-3)η⋅2(p−3) も自動的に縮むためである。 「最初は大きく、近づいたら慎重に」という挙動を、誰も明示的に書いていないのに 勾配降下がひとりでに実現している。NN の学習はこの点が数万〜数億個あるだけで、 起きていることは最後までこの図と同じである。

データセット: 直線では分けられない2クラス

Section titled “データセット: 直線では分けられない2クラス”

分類問題を1つ用意する。two moons(噛み合った三日月2つ)は、 わざと1本の直線では絶対に分けられない形にしたトイデータで、 「モデルが曲がった境界を作れるか」を試すための定番である。

直線で分けられる問題なら層を積む必要がない。層を積む理由そのものを 見るために、あえてこの形を選んでいる。

訓練データとテストデータに分ける

Section titled “訓練データとテストデータに分ける”

600点のうち400点を訓練、残り200点をテストに回す。テストは 学習に一度も使わない問題で、「丸暗記」ではなく「法則を学べたか」を測るために取り分ける。 訓練データだけで測った精度は、暗記でもいくらでも上げられるので指標にならない。

モデル定義: nn.Moduleで層を積む

Section titled “モデル定義: nn.Moduleで層を積む”

nn.Sequential は「層を上から順に通す」という組み立て方。ここでは nn.Linear(掛けて足す)と nn.ReLU(負をゼロにする)を交互に3枚重ねる。

なぜ ReLU を挟むのか ── nn.Linear は何枚重ねても、合成すると1枚の nn.Linear に潰れてしまう(線形写像の合成は線形写像)。つまり境界は直線のまま。 間に非線形関数を1つ挟むだけでこの潰れが止まり、折れ線を継ぎ合わせた 曲がった境界を作れるようになる。ReLU max⁡(0,z)\max(0, z)max(0,z) はその最も安いやり方である。

最後の nn.Linear(16, 2) の出力2つはロジット、つまり各クラスの生のスコアで、 大きい方が予測クラスになる。

学習ループ: 予測 → 誤差 → 修正

Section titled “学習ループ: 予測 → 誤差 → 修正”

ここからが学習の本体だが、書くことは4行しかない。しかもこの型はモデルが 何であっても変わらない ── 入門3で中身を論理ゲートに置き換えても、 このループは1文字も書き換えずに済む。

  • F.cross_entropy … 分類の定番の損失。正解クラスのスコアが他より 高いほど小さくなる量で、これを下げることが学習の目的になる
  • opt.step() … 勾配に従って全パラメータを更新する。ここでは 単純な勾配降下ではなく Adam(各パラメータごとに歩幅を自動調整する 改良版)を使う。手で学習率を詰める手間が減るため、実務ではまずこれを選ぶ

評価と可視化: 境界はどう曲がったか

Section titled “評価と可視化: 境界はどう曲がったか”

読み取り: 上のログで loss が単調に下がり、test accuracy が 0.5(=当てずっぽう)から 0.95 以上まで上がっている。「学習が進んだ」とは、この2つの数がこう動いたことを指す。

ただし数字だけではどんな境界を引いたのかが分からない。そこで平面全体に モデルを当てて、位置ごとの予測を色で塗った図を作る。次の関数はそのための格子を返す。

平面全体にモデルを当てるヘルパー

Section titled “平面全体にモデルを当てるヘルパー”

図2: 決定境界は学習で「曲がる」

Section titled “図2: 決定境界は学習で「曲がる」”

背景の色は「その位置に点があったらモデルはどちらのクラスと答えるか」で、 赤寄りがクラス1・青寄りがクラス0。黒い実線が決定境界(予測が切り替わる線)である。 左が学習前、右が学習後。散布している点は元のデータそのもの。

読み取り: 学習前(左)の境界は乱数任せの直線に近く、三日月をまたいで 真っ二つにしている。学習後(右)は2つの三日月の間をぬうように曲がっている。 この曲がりを作っているのが ReLU の折れ目で、どこで折るかを決めているのが 学習された重みである。同じ図を入門3では論理ゲート版で描き直す。

図3: 学習曲線と、動いた「重み」そのもの

Section titled “図3: 学習曲線と、動いた「重み」そのもの”

左は学習の進み方(橙=損失・緑=テスト正解率)。右は1層目の重み行列 2×162 \times 162×16 を 学習前後で縦に並べたヒートマップで、赤が正・青が負の値を表す。 上の境界の変化が、右のこの32個の数が動いた結果でしかないことを確かめる図である。

読み取り(先に書いておく): 左では損失が単調に下がり、正解率が階段状に上がって 0.95 超で頭打ちになる。右は上2行(学習前)がほぼ均一な薄い色なのに対し、 下2行(学習後)は濃い赤と濃い青がはっきり分かれる ── 各ニューロンが 「x0x_0x0​ が大きいほど反応する / x1x_1x1​ が大きいと抑制される」といった 役割を持ち始めた、ということ。 そして動いたのは中途半端な実数であって、0/1 では表せない。 次のページ以降では、この実数の重みが丸ごと論理ゲートの真理値表へ置き換わる。

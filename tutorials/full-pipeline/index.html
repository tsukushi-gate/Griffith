7. 通しチュートリアル: 学習からFPGAまで

学習 → 損失ログの読み方 → HDL エクスポート → FPGA 実装への接続、までを 1本の流れで通す通しチュートリアル。題材は最小の XOR に絞ってあるので、 個別ページ(MNIST / HDLエクスポート)を 先に読んでいなくても、このページだけで「学習してから回路になるまで」の全体像がつかめる。

このページで学ぶこと

  1. 学習 → 損失ログ → IR → Verilog → FPGA 実装まで、途切れない1本の流れ
  2. 各段でどの API を呼ぶか(このページだけで最後まで動く)
  3. 深掘りしたくなったとき、どの個別ページへ戻ればよいかの地図

前提

  • なし ── このページから読み始められる

このページについて

所要時間の目安: 約15分 / 実行環境: CPU のみ(GPU 不要) 元スクリプト: なし(examples/01_xor.py と examples/04_export_hdl.py を合成) 手元で試す: notebooks/07_full_pipeline.ipynb(このページと同じ内容の未実行ノートブック。uv run --group docs jupyter lab notebooks/ で開ける) コード出力はすべて 実際に実行した結果をそのまま埋め込んでいます。

1. データとモデル

Section titled “1. データとモデル”

XOR は「線形分離できない最小の問題」で、論理ゲート回路の表現力を測る定番のタスク。 griffith_logic.datasets.xor2() は4パターンを butterfly 規約の順で列挙したデータセットを返す。 モデルは LutLayer 2段 + GroupSum(クラスごとにゲート出力を集約)という最小構成。

2. 学習と損失ログの読み方

Section titled “2. 学習と損失ログの読み方”

学習は通常の PyTorch そのもの(cross_entropy + Adam)。特有なのは soft(学習時)と hard(離散回路)で精度が別物になりうる点で、 損失だけを見ていると「soft では下がっているのに回路にすると壊れる」状況を見逃す。 そこで損失と一緒に hard accuracy(model.eval() での精度)も同じ間隔でログする。

図1: 損失と soft/hard 精度の推移

Section titled “図1: 損失と soft/hard 精度の推移”

表だけでは「いつ回路が決まったのか」が見えにくいので、同じ履歴を1枚の図にする。 左が損失、右が精度で、soft(連続緩和のまま)と hard(argmax で確定した回路)を 重ねて描く。この2本が離れているあいだは「学習中のモデルは解けているが、 焼いた回路は解けていない」状態である。

読み方の要点:

  • loss が下がりきる前に hard acc が 1.00 に到達することが多い。回路としての正解は 離散化後の argmax で決まるため、損失の絶対値そのものは目標ではない。
  • loss は下がるのに hard acc が上がらない場合、連続緩和が「中間的な確率分布」に 居座っている(離散化で壊れる)サイン。温度 tau や学習率、層幅を疑う。
  • 逆に hard acc が 1.00 で振動する場合は、既に十分学習できているので早期終了してよい。

3. 同じコードがこの回路になる

Section titled “3. 同じコードがこの回路になる”

ここまでで書いたのは nn.Sequential(LutLayer(2, 16), LutLayer(16, 16), GroupSum(k=2)) という3行だけだが、実体は 16個のゲートのノードと、それを結ぶ配線 である。 plot_circuit() はモデルからその回路をそのまま図にする。

図2: 学習前と学習後の回路図

Section titled “図2: 学習前と学習後の回路図”
  • 左(resolve=False) — 学習前。各ノードは16種の論理関数(AND/OR/XOR/…)の 混合なので LUT としか呼べない。色の濃さがゲート分布の確定度で、 薄いほど「まだどの関数か決まっていない」。
  • 右(resolve=True) — 学習後。argmax で1つに確定した論理関数の名前 (AND / XOR / NAND / !A / A>=B …)がノードに入る。

学習とは、16の候補からゲートを1つずつ選び切る作業である、という主張が そのまま絵になっている。ノードの名前は後段の export_ir() が Verilog を吐くときに 使う真理値表から導いているので、この図のゲートは実際に焼かれる回路のゲートと同一。

ゲート数が数百を超える実モデルでは全ノードを描いても潰れるだけなので、 plot_circuit() は自動的に俯瞰図(層=箱、配線=本数付き矢印)へ切り替わる (plot_abstract() を直接呼んでもよい)。読み方は 配線の可視化 を参照。

4. IR へ抽出する

Section titled “4. IR へ抽出する”

export_ir() は学習済み nn.Module を走査し、どのパラメータ化で学習していても 真理値表へ万能離散化した IR(JSON)にする。IR がハードウェア側の真実源であり、 Verilog / VHDL / シミュレータはすべてここから派生する。validate(ir, target='hdl') で HDL 生成に必要な制約(ビット幅・トポロジ順序など)を先に検査しておく。

5. Verilog を生成して照合する

Section titled “5. Verilog を生成して照合する”

write_verilog() で合成可能な Verilog を書き出し、simulate()(numpy のビット厳密な golden model)と突き合わせる。iverilog が入っていれば、生成した Verilog 自体を シミュレートして golden model と全パターン一致するかまで自動検証できる。

ここまでで、同じ XOR が3つの別々の実装を通った: PyTorch の model.eval()、numpy 実装の simulate()、そして Verilog シミュレータ。 この3つが全入力パターンで一致することが「学習したモデル = 焼かれる回路」の保証になる。 4パターンしかないので、3段の予測を並べて全部見てしまう。

図3: 同じ XOR を3つの実装で通す

Section titled “図3: 同じ XOR を3つの実装で通す”

行が「教師ラベル / PyTorch eval / IR simulate」、列が4つの入力パターン。 セルの数字が予測クラスである。

読み取り: 3行が同じ並び 0 1 1 0 で埋まる ── 教師ラベルどおりの XOR を、 PyTorch の離散化経路と numpy の整数ビット演算がまったく同じように再現している。 1マスでも食い違えば、それはエクスポートのバグである。

生成された Verilog を覗く

Section titled “生成された Verilog を覗く”

最後に、書き出された RTL の冒頭を表示する(そのまま論理合成に掛けられる)。

6. ここから FPGA へ

Section titled “6. ここから FPGA へ”

生成した .v はベンダーツール(Vivado / Quartus 等)へそのまま投げられる合成可能 RTL。 ピン割り当て・クロック・ビットストリーム生成といった実機側の手順は HDL等価性検証ガイド を参照。

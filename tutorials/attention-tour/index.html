論理ゲートAttentionの4変種ツアー

内積を XNOR 類似度に、softmax を argmax に置き換えた Attention の4変種を、 連想想起・位置ルックアップ・ソートの小タスクで一気に動かして比べるツアー。

Boolean / MultiQuery / Positional の3つは hard accuracy 1.000(6,144 params)で解け、 4要素ソートを解く Pointer だけが 0.835 に留まる。hard attention の重み行列を描くと 全行が one-hot になり、Pointer では置換行列が現れる ── 「どこを見るか」が 連続的な加重平均ではなく、離散的な選択として学習されていることが目で分かる。

このページで学ぶこと

  1. 内積 → XNOR 類似度、softmax → argmax という Attention の置き換え方
  2. 4変種(Boolean / MultiQuery / Positional / Pointer)の使い分けと得手不得手
  3. hard attention の重み行列の読み方 ── one-hot 化と、Pointer に現れる置換行列

前提

  • Transformerを段階的に論理化 — なぜ softmax を捨てても解けるのか
  • Transformer(論理ゲートGPT)

論理ゲート版Attentionの4変種を、連想想起(key-value lookup)系の小タスクで比較する。

MNIST(examples/06_mnist.py)までの例は「入力ビット列 → クラス」の素直な分類器だった。 ここでは回路が「どこを見るか」を自分で決めるAttention機構に踏み込む。

論理ゲートNNのAttentionは、Transformerの内積+softmaxを次のように置き換える:

XNORとpopcountはどちらも純粋な組合せ回路なので、学習後の姿は「乗算器のない 連想メモリ(CAM)」そのものになる。訓練時だけ連続緩和(softmax)を使い、 eval()に入れた瞬間にargmaxの離散選択へ切り替わる——LutLayerのsoft/hardと同じ設計思想。

本サンプルで巡る4変種(griffith_logic.models.attention):

  1. DLGNBooleanAttention 単一クエリの連想想起。Attentionの最小形
  2. DLGNMultiQueryAttention 同じKVメモリに複数クエリを並列適用(multi-head的な拡張)
  3. DLGNPositionalAttention キーが入力ではなく「固定の位置番号」。内容ではなく位置で引く
  4. DLGNPointerAttention Pointer Network風。自己回帰+マスクで「引いては消す」を繰り返し ソートを解く(=連想想起の反復適用)

4変種は「メモリの引き方」だけが違い、学習ループ・損失・データ形式は共通にできる。 どこを差し替えると何が解けるようになるのか、という対比がこのページの主題になる。

Attentionを作る3つの部品(初心者向けの言い換え)

  • XNOR = 一致検出器。2本の線が同じ値なら1、違えば0を出す1個のゲート。 ビット幅だけ並べると「どのビットが揃ったか」の地図になる
  • popcount = 多数決(1の本数を数える加算木)。一致地図の1を数えれば 「何ビット揃ったか」= 類似度。掛け算器は1つも要らない
  • MUX(マルチプレクサ)= 選択器。「何番を通すか」の指示で入力を1本だけ出口へ通す 交通整理のスイッチ。softmaxの加重平均の代わりに、勝ったスロットの値をそのまま通す

図1はこの3部品に具体的なビット列を流し、クエリ 101101 と4本のキーの一致数 (3/6・6/6・4/6・4/6)から、MUXがバリュー 1010 を選び出すまでを1枚で追う。

4変種はどこが違うのか

違うのは「問いをどこから作るか」と「選んだ後に何をするか」だけで、真ん中の XNOR+popcount+MUX は4変種で完全に共通である。1〜3は同じ幅の設定なので回路規模も 同じ(各 6,144 パラメータ)になり、Pointerだけ自己回帰セルとクエリ生成器のぶん 増える(9,280 パラメータ)。

準備: import と乱数種

Section titled “準備: import と乱数種”

使うのは PyTorch と matplotlib、そして griffith_logic.models.attention の4変種だけ。 soft(訓練時の連続緩和)と hard(推論時の離散選択)の切り替えはモデル側が持っているので、 学習コードには特別な仕掛けが一切要らない ── そこが以降のコードの読みどころになる。

共通ハイパーパラメータ

Section titled “共通ハイパーパラメータ”

4タスクを合計で CPU 数分に収めるための縮小レシピ。STEPS と各エンコーダ幅を増やすほど 精度は上がるが、ここでは精度そのものより「4変種を同じ土俵で並べて比べる」ことを優先している。

心臓部の置き換え: 内積+softmax を XNOR+popcount+MUX へ

Section titled “心臓部の置き換え: 内積+softmax を XNOR+popcount+MUX へ”

Transformer の attention は softmax(q·k/√d)·V、つまり実数の内積で問い合わせと記憶の 近さを測り、softmax の加重平均でバリューを混ぜる。乗算器と指数関数が要るので、 論理ゲートだけの回路には重い。論理ゲート版はこれを3つの部品で置き換える。

  • XNOR(排他的論理和の否定)= 一致検出器。2本の線が同じ値なら1、違えば0を出す1個のゲート。 ビット幅だけ並べると「どのビットが揃ったか」の地図になる
  • popcount = 立っているビットの本数を数える加算木。一致地図の1を数えれば 「何ビット揃ったか」= 類似度になる。掛け算器は1つも要らない
  • MUX(マルチプレクサ)= 選択器。「何番を通すか」の指示線で、入力を1本だけ出口へ通す 交通整理のスイッチ。softmax の加重平均の代わりに、勝ったスロットの値をそのまま通す

なぜこの置き換えが成立するのか: 二値ベクトル同士の内積は「一致ビット数」そのもの (= ハミング距離の裏返し)なので、内積が測っていた類似度の意味は失われない。 選択側も同じ発想で、訓練中だけ softmax(温度 tau_attn)で全スロットを混ぜて勾配を流し、 eval() では最大スコアのスロットだけを取る argmax に切り替える(= hard attention)。 LutLayer の soft/hard と完全に同じ設計思想である。

図1: 具体ビットで追う「Attention = XNOR + popcount + MUX」

Section titled “図1: 具体ビットで追う「Attention = XNOR + popcount + MUX」”

この図で何を見るか: 学習前の手書きベクトルを左から右へ流し、クエリ 101101 と 4本のキーの一致ビット数(3/6・6/6・4/6・4/6)から、MUX がバリュー 1010 を選び出すまでを 1枚で追う。ビットの箱は塗り=1 / 白=0。緑は論理(そのまま回路に焼ける部分)、 橙は実数(訓練時の softmax だけで、回路には残らない部分)を表す。

読み取り: 完全一致したキー1本だけが popcount 6/6 に届き、他は必ずそれ未満に収まる。 だから「最大 popcount のスロットを選ぶ」という比較器だけの規則で正解が確定する ── 指数関数も除算も現れない。ここが以降の4変種すべてに共通する心臓部である。

データセット: 3つの小タスクをその場で合成する

Section titled “データセット: 3つの小タスクをその場で合成する”

Attention モデルの入力は「1本のフラットな二値ベクトル」で、どのビットがキーで どこからがクエリかは Config の取り決めだけで決まる。つまり下の3つのジェネレータが、 そのまま各タスクの入力レイアウトの定義になっている。

共通の学習ループ

Section titled “共通の学習ループ”

4モデルとも「forward して cross entropy」だけで学習できる。Attention の soft/hard 切り替えは model.train() / model.eval() が面倒を見るので、学習側の記述は4変種で完全に共通になる。

評価では毎回 soft と hard の両方を測る。soft は訓練中に見えている姿(softmax の加重平均)、 hard は焼いたときの姿(argmax で1スロットだけ選ぶ)で、両者が重なるほど Attention が 1スロットへ決めきれている、という読み方をするための2本立てである。

4変種を順に学習する

Section titled “4変種を順に学習する”

ここから4つの変種を上から順に回す。違うのは「問いをどこから作るか」と「選んだ後に 何をするか」だけで、真ん中の XNOR + popcount + MUX は4変種で完全に共通である。

1. BooleanAttention — Attention の最小形(内容で引く)。置き換えたのは 内積 → XNOR popcount と、softmax → (eval 時)argmax の2点だけ。Q/K/V を作るエンコーダも 選んだ V を読むデコーダも普通の LutStack で、Transformer の骨格はそのまま残っている。 タスクは「4組の(キー,バリュー)と1つのクエリを渡し、一致するキーのバリューを答える」 連想想起(key-value lookup)。クエリキーはメモリ内のどれかと完全一致するので、 一致ビット数は正解スロットで最大(= key_bits)、他では必ずそれ未満になる。 学習で決まるのは類似度の式ではなく、キー/クエリのエンコーダが 「一致を際立たせる符号」へビットを散らす配線のほうである。

Pointer は「系列完全一致」でも測り直す

Section titled “Pointer は「系列完全一致」でも測り直す”

系列タスクは「全ステップ正解」で測ると難しさが分かりやすい。要素単位で 0.85 でも、 4要素すべてが正しい確率はその4乗近くまで落ちうるからである。 学習は教師ポインタを流す teacher forcing、評価は自分の出力を次の入力にする free-running なので、そのズレも系列完全一致のほうに強く現れる。

評価: 4変種の最終成績を並べる

Section titled “評価: 4変種の最終成績を並べる”

以降の図は全部このテーブルから描く。連想想起系の3つ(1〜3)は同じ土俵に立っているので、 まとめて hard accuracy に下限を置いて「学べていない」ことだけを弾いておく。

可視化: 収束・回路規模・attention 重み

Section titled “可視化: 収束・回路規模・attention 重み”

図2: 4変種の収束曲線を重ね描き

Section titled “図2: 4変種の収束曲線を重ね描き”

この図で何を見るか: 実線 = hard(argmax、焼いた回路の姿)、破線 = soft(softmax、 学習時の姿)。4変種を1枚に重ね、どれがいつ立ち上がるか、そして実線と破線が どれだけ重なるかを見る。

読み取り: 1〜3では実線と破線がほぼ重なる。Attention が既に1スロットへ決めきれていて、 softmax を argmax に置き換えても出力が変わらない、ということである。4(Pointer)だけは 2本が離れたまま伸び悩む ── まだ確信の持てない加重平均に留まっているサイン。

図3: 精度とパラメータ数を並べる

Section titled “図3: 精度とパラメータ数を並べる”

この図で何を見るか: 左が最終 hard accuracy、右がパラメータ数(= 回路規模の目安)。 「解けたか」と「そのためにいくら払ったか」を同じ並びで見るためのコスパ比較である。

読み取り: 1〜3は同じ幅の設定なので規模もぴったり同じで、そのまま満点に届く。 つまりこの3タスクの難しさはメモリの引き方で決まっており、回路規模では決まっていない。 とくに MultiQuery は Boolean と同じ規模のままクエリを2本さばく ── KV エンコーダの共有が タダで効いており、「面積を増やさずに帯域を稼ぐ」という変種の狙いがそのまま出ている。 Pointer だけは自己回帰セルとクエリ生成器のぶん規模が上がり、それでも精度が届かない。

図4: Attention が実際にどこを指しているか

Section titled “図4: Attention が実際にどこを指しているか”

この図で何を見るか(最後の図なので読み取り方も先に置く): eval() の Attention は 行ごとに1マスだけ1になる one-hot(1本だけ立ったベクトル)になる。左3枚は 「テストサンプル(縦) × メモリスロット(横)」で、サンプルごとに引くべき場所が変わるため 模様はばらばらになる ── 内容(1・2)や番地(3)で正しく引き分けている姿である。 右端は1サンプルの「デコードステップ(縦) × 入力スロット(横)」で、見どころは 各行・各列に高々1マスしか光らないこと。これは出力が入力の置換行列 (並べ替えを表す0/1行列)になったということで、累積マスクが二度選びを禁じている証拠であり、 ソートが「連想想起の反復適用」に還元できたことの確認になる。

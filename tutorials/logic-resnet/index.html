論理NNの残差接続は恒等を「厳密に」作れる

論理NNの残差接続は、恒等写像を「厳密に」作れる。OR 残差と pass-through 初期化を 組み合わせると max⁡∣y−x∣=0.0\max|y - x| = 0.0max∣y−x∣=0.0 ── 近似ではなくビット単位の完全一致で入力が そのまま出る。実数の ResNet が初期化で近似的に狙うものが、ここでは厳密に成立する。

ただし代償がある。OR は一度立ったビットを落とせないので飽和する。同一 seed で 比べると hard acc は XOR 残差 0.361 > OR 残差 0.299 で、恒等の厳密さと学習しやすさが トレードオフになっていることが学習曲線に出る。

このページで学ぶこと

  1. OR 残差 + pass-through 初期化で、恒等写像が厳密に(max⁡∣y−x∣=0\max|y-x| = 0max∣y−x∣=0)作れること
  2. その代償 ── OR は立ったビットを落とせないので飽和する、というトレードオフ
  3. OR 残差と XOR 残差を同一 seed で比べた学習曲線の読み方

前提

  • 1. MNISTを学習する
  • LutLayerの数理 — 残差が効く仕組みの背景

LogicResNet(残差論理ConvNet)でMNISTを解く例。

深いネットワークが学習できるのは、ResNet の「skip接続」が 「何もしない(恒等写像)」を初期状態として無料で用意してくれるからだ。 実数NNではこれは x + f(x) と書き、f の重みを0に初期化すれば恒等になる。

論理ゲートNNには「0」に相当する重みが無い。 ゲートは真理値表であって 係数ではないので、「効果を0にする」という初期化ができない。ではどうするか。

このとき f(x) は x に 含まれる(x が 0 の位置では f(x) も必ず 0)。OR は吸収律

を持つので、合流すると x がそのまま戻ってくる。バイアスが完全に効いて f(x) = x まで行った場合は、OR の冪等性 x OR x = x による特別な場合にあたる (既定の parameterization=‘softmax’ では eval で各ゲートが「葉0 かつ 葉1でない」を 選ぶため、f(x) は x の真部分集合になる。図2で実物を確かめる)。

浮動小数の誤差込みで「ほぼ恒等」ではなく、ビット単位で完全に一致する。 これが論理NN固有の面白さで、このサンプルの前半(図1・図2)で実際に確かめる。

アーキテクチャ図解 1: 残差ブロックの中身(OR で合流する)

Section titled “アーキテクチャ図解 1: 残差ブロックの中身(OR で合流する)”

残差ブロック1個の中身は「2枚の畳み込み → 元の入力と OR で合流」だけである。 下の図の 破線が skip 接続 ── 入力 x を加工せずそのまま合流点まで運ぶ近道の配線で、 これがあるおかげで「何もしない」が初期状態として選べる。

アーキテクチャ図解 2: LogicResNet 全体(どこまでがビットか)

Section titled “アーキテクチャ図解 2: LogicResNet 全体(どこまでがビットか)”

緑の段は入力も出力も ビット(0か1)、橙の段は 実数(ビットを数え上げた整数と、 それを割ったロジット)。ビットのまま head まで進み、SpatialGroupSum で初めて 「1の個数を数える」実数の世界に出る、というのがこのモデルの形である。 数値は本サンプルの縮小レシピ(stem 32ch / stage_blocks=(1,1) / encode_bits=2)。

どう実現しているか(NNを触ったことがない人向けの要点)

  • ビット = 0か1しか取らない信号。普通のNNが実数を運ぶ配線を、このモデルは 0/1 の線として扱う。だから「掛け算・足し算」ではなく AND / OR / XOR で計算できる。
  • LutConv2d = 画像の上を滑らせる小さな真理値表(LUT)の束。3x3 の窓から 数本のビットを選び、「この入力ならこの出力」という表を1枚引く。表の中身が 学習対象で、実数の重みの代わりに「どの表を使うか」を連続値で持ち、 eval(推論)時に argmax で1枚に確定させる ── これが「焼いた回路」。
  • 残差接続(skip接続) = 入力をそのまま先へ回す近道の配線。深い網でも 「素通し」が常に選べるので、段を積んでも学習が壊れにくい。
  • pass-through 初期化 = 学習開始時のゲートを『素通し』寄りに置くこと。 実数NNは重みを0にすれば素通しになるが、真理値表には「0の重み」が無い。 代わりに「葉0(第1入力)を通す」ゲートへバイアスし、f(x) が x に収まるようにする。
  • 吸収律 = 「元より小さいもの」を OR しても元のままという性質。 f(x) ⊆ x なら x OR f(x) = x。f(x)=x まで一致した場合は 冪等(べきとう)(同じものを2回入れても変わらない性質、x OR x = x)の特別な場合。
  • ThermometerEncoder = 濃さを目盛りに変える符号化。実数の画素値を 「閾値をいくつ超えたか」の 0/1 の並びに直し、以降を論理の世界に持ち込む。
  • GroupSum = 最後に1の個数を数える復号。クラスごとに割り当てた出力ビットの 本数を数え、tau で割ってロジットにする。実数が出てくるのはここだけ。

ただし、この恒等性はタダではない。 OR は単調(x OR f(x) ≧ x)なので、 段を重ねるほど1が増えて飽和し、勾配が細る。もう一つの選択肢 ‘xor’ (a XOR b = a+b-2ab)は飽和しない代わりに、pass-through 初期化しても 恒等にはならない(恒等の条件が f(x)=0 になるため)。

後半では、この2つを同じ条件で MNIST に流して学習曲線を比べる(図3)。 本サンプルの主目的は恒等性の観察なので、精度を狙うレシピは experiments/train_logic_resnet.py(20000 step)を参照。

実行: uv run python examples/14_logic_resnet.py 期待結果: 恒等性 max|y-x| = 0.0、hard accuracy は XOR 0.35前後 > OR 0.28前後 (CPUで2〜3分の縮小レシピ)

準備: import と乱数種

Section titled “準備: import と乱数種”

使う部品は3つだけ ── LogicResNet(モデル本体)、LogicResNetConfig(その設定)、 LogicResBlock(残差ブロック単体。前半ではこれを1個だけ取り出して調べる)。 残りは MNIST の読み込みと作図の道具である。

このページで使う記号を先に決めておく。

  • x … 残差ブロックへの入力ビット(0か1しか取らない信号)
  • h … ブロック内 1枚目の LutConv2d の出力ビット
  • f(x) … 残差枝(LutConv2d 2枚)を通り抜けた出力ビット
  • y … 残差ブロックの出力ビット。y = merge(x, f(x))

前半: OR 残差で「厳密な恒等写像」を作る

Section titled “前半: OR 残差で「厳密な恒等写像」を作る”

ここからしばらくは学習をしない。初期状態のブロックが何をするかだけを見る。

実数の ResNet では残差の合流は足し算 y = x + f(x) で、f の重みを 0 に初期化すれば y = x(恒等写像 = 入力をそのまま返す写像)が無料で手に入る。ところがビットの世界で 足し算をすると 1 + 1 = 2 が出てしまい、値が {0,1} からはみ出す。

そこで LogicResNet は合流に OR を使う: y = x OR f(x) = 1-(1-x)(1-f(x))。 OR は **{0,1} に閉じた「足し算」**であり、しかも f(x)=0 の位置では y=x に戻る。 これに pass-through 初期化(= 学習開始時のゲートを「葉0(第1入力)をそのまま通す」側へ 寄せる初期化。真理値表には「重み 0」が無いので、実数NNの零初期化の代用として用意された)を 組み合わせると f(x) ⊆ x になり、OR の吸収律で y = x が厳密に(max|y-x| = 0 で)成立する。

「ほぼ恒等」ではなくビット単位で完全一致する ── それをこの節で実際に確かめる。

対照実験: pass-through 初期化を切る

Section titled “対照実験: pass-through 初期化を切る”

恒等が成立したのが「OR のおかげ」なのか「pass-through 初期化のおかげ」なのかを分けるため、 配線も構成もそのままで初期化だけを切ったブロックを作って比べる。OR は f(x) が 何であっても 1 を足す方向にしか働かないので、f(x) が x と無関係になった途端に 出力は入力から離れていく。

図1: 恒等性を目で見る

Section titled “図1: 恒等性を目で見る”

この図で見るもの: 同じ入力ビット x を、初期化の異なる2つの残差ブロックに通した結果を 並べる。左が入力 x、中央が pass-through 初期化ありの出力 y、右が初期化なしの出力。 3枚がチャネル0の 8x8 ビットで、黒が 1・白が 0 である。 中央が左と1ピクセルの狂いもなく一致するかだけを見ればよい。

読み取り: 中央は左と完全に同じ絵になっている。浮動小数の誤差込みで「ほぼ一致」なのでは なく max|y-x| = 0、つまりビット単位で厳密に恒等である。右は同じ配線・同じ構造なのに 黒(1)が明らかに増えている ── OR は 1 を足す方向にしか働けないので、f(x) が x と 無関係になると入力に無かった 1 が上乗せされる。恒等を作っているのは OR 単体ではなく、 OR と pass-through 初期化の組み合わせだと分かる。

残差ブロックの中を1枚の図で解剖する

Section titled “残差ブロックの中を1枚の図で解剖する”

図1 は入口と出口しか見ていない。次はブロックの内部、つまり x → h → f(x) → (skip の x と OR で合流) → y という流れを実データのまま追う。 そのためにまず、1枚目の LutConv2d の出力 h と、2枚目まで通した f(x) を取り出しておく。

図2 を描くための部品

Section titled “図2 を描くための部品”

以下は図2 のための描画ヘルパ(パネル・注記・配線)で、モデルの中身とは関係がない。 読み飛ばして図2 の説明へ進んでよい。ひとつだけ選択がある ── 8チャネルのうち どのチャネルを見せるかで、包含関係(f(x) ⊆ x)と違反の両方が読み取れる チャネルを自動で選んでいる。

図2 の右端には「このブロックの出力ビットがこの先どこへ流れるか」の縦ストリップを添える。 登場する段の意味は次のとおり。

  • OrPooling2d … 2x2 の窓を OR でまとめて解像度を半分にする間引き。実数CNNの max pooling に あたる操作で、これを挟むほど1つの出力ビットが見ている入力範囲(受容野)が広がる
  • head LutConv2d 1x1 … 分類用の出力ビットを作る最後の論理層
  • SpatialGroupSum … クラスごとに割り当てたチャネル群の 1 の本数を数える段。 ここが論理(ビット)と実数の境目で、以降は整数・ロジットの世界になる
  • GroupSum(tau) … 数え上げた本数を温度 tau で割ってロジットにする復号

図2: 残差ブロックを実データで解剖する

Section titled “図2: 残差ブロックを実データで解剖する”

この図で見るもの: 残差ブロックの構造図に、実際のビットを流し込んだもの。 左から x → h(1枚目の LutConv2d の出力)→ f(x)(2枚目まで通した残差枝の出力)→ OR(合流点)→ y と並び、上を回る破線が skip 接続(= 入力 x を加工せず合流点まで 運ぶ近道の配線)である。上段が pass-through 初期化あり、下段がなし。

見どころは f(x) のパネルで、上段の f(x) の黒(1)が x の黒の範囲に収まっているか (f(x) ⊆ x)を見る。収まっていれば OR の吸収律で y は x に戻る。 下段は x に無い位置にも 1 が出るので、OR は 1 を積み増すだけになる。

読み取り: 上段では f(x) の黒が x の黒の内側にしか出ておらず、OR で合流した y は x とまったく同じ絵になる ── 恒等が保たれている。下段は f(x) が x と無関係な位置にも 1 を出し、y は x より黒が増える。

ここで OR の代償がはっきりする。OR は一度立ったビットを絶対に落とせない単調な演算 (x OR f(x) ≧ x)なので、段を積むほど 1 が増えて飽和する ── 出力がほとんど 1 で 埋まってしまい、入力を変えても出力が動かなくなる状態で、こうなると勾配もほぼ流れない。

もう一つの選択肢が XOR 残差(a XOR b = a + b - 2ab)である。XOR は片方の入力を反転すると 出力も必ず反転する(自己逆元で、情報を潰さない)ため、深く積んでも飽和せず勾配が消えない。 代わりに f(x)=0 でない限り恒等にならないので、初期状態を恒等に置けない。

  • OR … 恒等を初期状態に置ける / 飽和して学習が鈍る
  • XOR … 恒等は初期状態にできない / 飽和せず学習が速い

このトレードオフが実際にどう出るかを、次の後半で同じ条件の学習曲線として見る。

後半: MNIST で OR 残差と XOR 残差を比べる

Section titled “後半: MNIST で OR 残差と XOR 残差を比べる”

後半は普通の画像分類である。20x20 に縮小した MNIST を、residual_mode だけを 差し替えた2つの LogicResNet で学習し、テスト精度の伸び方を比べる。 CPU で2〜3分に収まる縮小レシピなので絶対精度は低いが、2モードの差は再現する。

ハイパーパラメータ

Section titled “ハイパーパラメータ”

設定のうち3つは論理ゲートNN固有なので補足しておく。

  • encode_bits … ThermometerEncoder の目盛り数。実数の画素値を「閾値をいくつ超えたか」の 0/1 の並びに直して、以降を論理の世界に持ち込む
  • tree_depth / n_inputs … 1つの出力ビットを作る LUT木(小さな真理値表を木状に積んだ塊。 葉が入力ビット、根が出力ビット)の深さと各ノードの入力本数
  • tau(温度) … GroupSum が数え上げた本数を割る定数。ここでは1クラスあたり head_group_size(4) × 10x10 = 最大 400 まで数が伸びるので、tau=1 のままだとロジットが 数百に飛んで softmax が飽和し勾配が消える。群の大きさに合わせて割るのが肝である

学習結果: 恒等を捨てた XOR のほうが勝つ

Section titled “学習結果: 恒等を捨てた XOR のほうが勝つ”

上の出力に soft と hard の2つの精度が出ている。soft は train() モードで、 各ゲートが候補となる論理関数の連続的な混合のまま(= 勾配が流れる学習用の姿)。 hard は eval() モードで、各ゲートを argmax で1枚の真理値表に確定させた 「焼いた回路」の姿である。本命は hard で、soft だけ高い状態は「回路として決めきれて いない」サインになる。

結果は XOR の勝ちである。恒等写像という強い初期状態を持っているのは OR のほうなのに、 最終精度では飽和しない XOR が上回る ── 初期状態の良さより、学習の間ずっと勾配が 流れ続けることのほうが効く、というのがこのサンプルの結論である。

図3: OR 残差と XOR 残差の学習曲線

Section titled “図3: OR 残差と XOR 残差の学習曲線”

この図で見るもの: 同一 seed・同一ハイパーパラメータで、合流の演算だけを変えた 2本の学習曲線。橙が OR、青が XOR で、実線が hard(焼いた回路)、破線が soft(連続混合)。 横軸が学習ステップ、縦軸がテスト精度である。

見どころは2色の実線の開き方。OR / XOR のトレードオフ(恒等な初期状態か、 飽和しない勾配か)がそのまま曲線の形になって現れる。

読み取り: 青(XOR)の実線が橙(OR)を早い段階で追い越し、以降ずっと上を走る。 OR は序盤こそ恒等から出発できるが、層を通るたびに 1 が増えて飽和し、 出力が入力の変化に反応しなくなるので伸びが鈍る。XOR は恒等から始められない代わりに 情報を潰さないので、同じ予算でより遠くまで行ける。soft(破線)と hard(実線)が 大きく離れていないことも見ておくとよい ── 離散化しても壊れていない、ということである。

図4: 誤分類された手書き数字

Section titled “図4: 誤分類された手書き数字”

この図で見るもの: hard eval(焼いた回路の姿)で誤分類したテスト画像を先頭から10枚。 各タイトルの pred が予測、true が正解ラベルである。

読み取り: 縮小レシピの精度は3割前後なので誤りは多いが、並ぶのは人が見ても 崩れている字や、線の太さ・傾きが極端な字が中心になる。20x20 に縮めたうえ encode_bits=2 の粗い目盛りでビット化しているため、細い線の情報が符号化の段階で 落ちていることが効いている。精度を狙うレシピは experiments/train_logic_resnet.py (20000 step)を参照。

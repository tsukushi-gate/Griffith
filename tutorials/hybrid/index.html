2. ハイブリッドNNを作る

既存の Transformer ブロックの MLP 部分だけを LUT ベースの論理ゲートへ置換する (LL-ViT 型ハイブリッド)。Attention と LayerNorm は PyTorch の実数層のまま残し、 論理系と実数系で学習率を分けて同時に学習する。

このページで学ぶこと

  1. Transformer ブロックの MLP 部分だけを LUT へ置換する組み方(LL-ViT 型)
  2. Attention・LayerNorm を実数のまま残し、論理系と実数系で学習率を分ける理由
  3. 「全部を論理ゲートにしない」という設計判断がどこで効くか

前提

  • 1. MNISTを学習する — 全部が論理ゲートの場合を先に見る
  • PyTorchからの移行 — 層の対応表

このページについて

所要時間の目安: 約5分 / 実行環境: CPU のみ(GPU 不要) 元スクリプト: examples/02_hybrid_llvit.py 手元で試す: notebooks/02_hybrid_llvit.ipynb(このページと同じ内容の未実行ノートブック。uv run --group docs jupyter lab notebooks/ で開ける) コード出力はすべて 実際に実行した結果をそのまま埋め込んでいます。

▶ Colabで開く(リポジトリ公開後に有効化)

ハイブリッドNN(LL-ViT型)の例。

既存のTransformerブロックの「MLP部分だけ」をLUTベース論理ゲートに 置換する。Attention・LayerNormはPyTorch実数層のまま。

Transformer全体を論理ゲート化するのは難しいが、パラメータの大半を占めるMLPだけを 論理回路に落とせば、推論コストの大部分をGPUから剥がせる。このスクリプトは 「既存モデルに1行差し込むだけで部分置換できる」ことと、置換後も普通に勾配が流れて 損失が下がることを確認する。

このページで確認するのは次の4点。 どこが論理ゲートに変わりどこが実数のまま残るか、パラメータ予算がどう動くか、 論理系と実数系で学習率を分けるとなぜ効くのか、そして置換されたMLPが最終的に どんな2入力論理ゲートの集まりになるのか。

どこが実数のまま残り、どこがLUTになるのか

橙 = 実数(浮動小数点の掛け算・LayerNorm・softmax が要る部分)、 緑 = 論理ゲート(LutLayer。真理値表そのものなのでHDLへ焼ける)。 Binarize(ToLogic)と GroupSum(FromLogic)が2つの世界の国境で、 ここで実数 ⇄ ビットを行き来する。

置換されるのは各ブロックの mlp だけで、1ブロックあたり 512 ゲート (LutLayer 32→256 と 256→256)、2ブロックで 1,024 ゲート。 実数パラメータは 17,088 → 8,706(約半分)に減り、代わりに 論理パラメータ 16,384(= 1,024ゲート × 16種の論理関数のロジット)が付く。 Attention を実数のまま残しているので、この構成は「LL-ViT 型」と呼ばれる 部分論理化になる ── Attention まで論理にする道は Transformerを段階的に論理化で扱う。

実行: uv run python examples/02_hybrid_llvit.py 期待結果: 置換2箇所、損失が減少

準備: import と置換API

Section titled “準備: import と置換API”

本ライブラリから使うのは4つ。既存モデルを書き換えずに部分置換するための道具立てである。

  • replace_mlp_with_lut … モデルを再帰的に走査し、MLP と判定できた部分だけを LUT ブロックへ差し替える
  • LogicSpec … 置換後の論理回路の形(1ゲートの入力数・段数・幅)の指定
  • split_param_groups … パラメータを論理系(logic)と実数系(ann)に自動で振り分ける
  • LutLayer / gate_labels … 置換で挿入される層と、そのゲート名の取得

置換される「既存モデル」を用意する

Section titled “置換される「既存モデル」を用意する”

置換の出発点となる、ごく普通の Pre-LN Transformer ブロックを素の PyTorch で書く。 ここには本ライブラリ由来のものが何も入っていない ── 手元にある既存モデルを そのまま持ち込めることを示すために、あえてこうしている。

構成は LayerNorm → MultiheadAttention → 残差 → LayerNorm → MLP → 残差。 このうち置換の標的は self.mlp(Linear-GELU-Linear)だけで、 Transformer のパラメータの約2/3をこの MLP が占めるため、ここを論理化するだけで 実数パラメータの大半を剥がせる。

部分置換: MLPだけをLUTへ差し替える

Section titled “部分置換: MLPだけをLUTへ差し替える”

置換は関数呼び出し1回で終わる。LogicSpec が置換後の回路の形を決める。

  • n_inputs=2 … 1ゲートあたり2入力(difflogic 互換の16種の論理関数)
  • depth=2 … LUT 層を2段重ねる。ゲートの合成で非線形性を作る
  • neurons_per_output=8 … 出力1次元あたり8ゲートを割り当てる。表現力とコストのつまみ

戻り値の replaced に置換したモジュール名が入るので、意図した箇所だけが 置換されたかをコードで検証できる(黙って全部置き換わる事故を防ぐ)。

置換後にどんな層が入ったかを確認する

Section titled “置換後にどんな層が入ったかを確認する”

挿入された LutLayer の入出力幅がそのままゲート本数であり、 ハードウェアコストの単位になる。出力を見ると 1ブロックあたり 32→256 と 256→256 の2層 = 512ゲート、2ブロックで1,024ゲートだと分かる。

学習タスク: 勾配が通ることだけを確かめる

Section titled “学習タスク: 勾配が通ることだけを確かめる”

なぜランダムなターゲットへの回帰なのか ── このページで確かめたいのは精度ではなく、 「実数層 → 論理層 → 実数層」と異種の層をまたいでも1本の backward() が 最後まで通るか、という一点である。実データを使うとタスクの難易度が結果に混ざるので、 ノイズを丸暗記させるだけの課題にして、置換そのものの影響だけを見る。

なぜ学習率を分けるのか(勾配スケールの実測)

Section titled “なぜ学習率を分けるのか(勾配スケールの実測)”

ハイブリッドで最初につまずくのがここである。論理系と実数系では勾配の大きさが桁で違う。

論理ゲートのパラメータは「16種の論理関数に対するロジット」で、softmax を通ってから 出力に効くため勾配が小さくなりやすい。一方 Attention や LayerNorm の実数重みは 出力へ直接効く。同じ学習率で回すと、論理側だけがほとんど動かないまま終わる。

職人芸に見えるこの調整を、まず初期状態で1回 backward して平均 ∣grad∣|\mathrm{grad}|∣grad∣ を測る という形で数値にしておく。

学習: 学習率を分けた場合と分けない場合

Section titled “学習: 学習率を分けた場合と分けない場合”

上の実測が示すとおり実数側の勾配が1桁大きいので、split_param_groups で パラメータを2群に分け、論理側だけ学習率を上げる(経験則は logic_lr ≈ 0.01〜0.05、ann_lr ≈ 1e-3)。手でモジュール名を列挙する必要はない。

比較のため、同じ初期値から「全パラメータ一律 lr=1e-3」でも回し、 置換前と同じ設定のまま学習すると何が起きるかを並べて見る。

最適化器: LUT系と実数系で学習率を分ける

Section titled “最適化器: LUT系と実数系で学習率を分ける”

可視化: 何が置換され、何が残ったか

Section titled “可視化: 何が置換され、何が残ったか”

読み取り: 上の出力で、lr を分けたほうが損失の落ち方が良いことが数値で確認できる。 一律 lr でも損失自体は下がる ── 実数側だけで帳尻を合わせてしまうためで、 「動いていないのに動いているように見える」のがこの失敗の厄介なところである。

以下、置換の結果を4枚の図で見る。まずパラメータ数を数えるヘルパーを用意する。

パラメータを論理/実数に分けて数えるヘルパー

Section titled “パラメータを論理/実数に分けて数えるヘルパー”

図1: どこが実数のまま残り、どこが論理ゲートになったか

Section titled “図1: どこが実数のまま残り、どこが論理ゲートになったか”

左は Transformer ブロックの構成図。橙=実数、緑=論理ゲート、黄=両者の国境 (ToLogic / FromLogic。ここで実数 ⇄ ビットを行き来する)。 右は置換前後のパラメータ内訳を積み上げた棒グラフである。

読み取り: 左を上から下へ追うと、緑(論理)なのは中央の LutLayer 2枚だけで、 Attention・LayerNorm・残差はすべて橙のまま残っている。これが「LL-ViT 型」と呼ばれる 部分論理化である。右では実数パラメータが 17,088 → 8,706 と約半分に減り、 代わりに論理パラメータ 16,384(= 1,024ゲート × 16種の論理関数)が乗っている。 論理側の数は増えるが、これは掛け算に使う数ではなく真理値表の選択なので、 焼いたあとには乗算器として残らない。

図2: ハイブリッドでも勾配は最後まで流れる

Section titled “図2: ハイブリッドでも勾配は最後まで流れる”

学習曲線を2本重ねる。緑が lr 分離あり、灰の破線が一律 lr。同じ初期値・同じデータで、 違うのは学習率の与え方だけである。まず「損失が下がること自体」が、 異種の層をまたいで勾配が通っている証拠になる。

読み取り: 2本とも右下がりで、LUT ブロックを挟んでも学習は成立している。 ただし緑のほうが速く深く落ちる ── 灰(一律 lr)は論理側がほとんど動かないぶん鈍い。

図3: なぜ学習率を分ける必要があるのか

Section titled “図3: なぜ学習率を分ける必要があるのか”

前の節で測った平均 ∣grad∣|\mathrm{grad}|∣grad∣ を対数軸の棒グラフにする。 縦軸が対数であることに注意 ── 差は「少し」ではなく桁である。

読み取り: 実数側(橙)の勾配が論理側(緑)より1桁大きい。 「lr を分ける」は勘ではなく、この差を埋めるための機械的な操作である。

図4: MLPは結局どんな論理回路になったのか

Section titled “図4: MLPは結局どんな論理回路になったのか”

最後に、置換された MLP がどんなゲートの集まりになったかを見る。左は16種の 2入力論理関数それぞれが何個選ばれたか、右は各ゲートの確信度 (softmax 後の最大確率。1.0 に近いほど「自分は XOR だ」と言い切れている)の分布である。

読み取り(この図が最後なので先に書く): 今回のターゲットは乱数なので、 ゲート種別の分布は特定の関数へ偏らず比較的平らなままになる(意味のあるタスクでは AND / XOR などへ偏っていく)。右の確信度が 1.0 側へ寄っているほど soft と hard の 差が小さく、離散化しても壊れにくい ── ここが 0.5 付近に密集していたら、 学習は進んでいてもハードウェアには落とせない、という判断になる。

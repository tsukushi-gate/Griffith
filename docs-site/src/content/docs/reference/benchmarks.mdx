このライブラリで実測した数値を、**モデル × データセット × hard 精度 × 規模**で
横断的に並べる。各行に**いつ・どの環境で・どの条件で測ったか**を付けてある。

モデル単位で「代表精度・主要課題・世界初判定」を1行ずつ俯瞰したい場合は
[モデル動物園](/reference/model-zoo/) を先に読むとよい。

:::caution[数値の読み方]
- 掲載値はすべて **hard**(学習後に argmax でゲートを確定させ、**純ブール回路として
  推論**したときの値)を主とする。soft(学習時の連続緩和)の値は差分を見る目的でのみ併記する。
- 断りがない限り **単一シード・単一構成の実測**で、シード分散は取っていない。
- ここに載るのは**このライブラリ内の設定間比較**である。外部実装との横並び比較表は、
  条件を揃えた再測定をしていないため掲載しない(先行手法を本ライブラリ上で再実装して
  比較した行には、その旨を明記している)。
- 「要較正」と付いた行は**まだ収束していない・原因未特定**の記録であり、
  到達点ではなく現在地として載せている。
:::

## 3. 学習則の比較(MNIST)

| 学習則 | soft | hard | 条件 |
|---|---|---|---|
| BP(softmax N=2) | 0.983 | **0.977** | 6層・τ=10・50ep / RTX 5090 |
| BP(Hard-ST 選択) | — | **0.980** | 6層×64,000・50k iter / RunPod GPU |
| BP(Soft-Mix 選択) | — | 0.975 | 同上 |
| AP 法(Akiho Propagation、誤差ブロードキャスト型、backprop 不使用) | ≈0.90 | ≈0.85 | flat 4層×16,000・30ep |

AP 法は backprop を使わずに `重み += 誤差 × 基底 × 学習率` で LUT を直接更新する
自社の学習則で、**全結合 MLP では深さ 2〜8 のどこでも soft ≈0.90 で安定する**
(0.898〜0.909)。一方で **CNN では ≈0.11 に崩壊**(loss が ln 10 に固定=ランダム相当)、
**RNN(seq2seq)では chance 水準で成立しない**(破綻境界は系列長 T=1 と T=2 の間)。
崩壊の原因を「単調性の破れ」とする仮説は、単調錐への射影で単調度違反をゼロに強制しても
3 シード全てで崩壊したため**棄却**されている。一方、誤差ブロードキャストの符号を
ランダム化すると完全崩壊するため、**符号の一貫性は必須**である。

`DFA` と `EGGROLL`(進化戦略)も学習則として実装されているが、
現時点で公開できる MNIST 級の実測は XOR / パリティ / 全加算器での収束確認
(hard eval 100%)にとどまる。

学習則の仕組みは [学習則(BP/AP/DFA/ES)](/explanation/learning-rules/) を参照。

## 9. 自分で測る — `griffith bench`

同じ土俵で測り直すためのベンチマークコマンドが同梱されている。
レシピ YAML または保存済みチェックポイントを渡すと、
**hard eval 精度・ゲート数・forward レイテンシ**を測って JSON に落とす。

```bash
# レシピから(短時間学習 → best チェックポイントを計測)
uv run python benchmarks/bench.py configs/recipes/logic_xor.yaml

# 学習せずレイテンシとゲート数だけ測る(hard_acc は null になる)
uv run python benchmarks/bench.py configs/recipes/logic_xor.yaml --skip-train

# 保存済みチェックポイントを計測
uv run python benchmarks/bench.py outputs/<run>/checkpoints/best.pt
```

出力は `benchmarks/results/<日付>_<name>.json` に、次の固定スキーマで保存される。

```json
{
  "name": "...",
  "timestamp": "...",
  "config": { "...": "..." },
  "metrics": {
    "hard_acc": 0.0,
    "total_gates": 0,
    "latency_ms_b1": 0.0,
    "latency_ms_b128": 0.0
  },
  "env": { "python": "...", "torch": "...", "platform": "..." }
}
```

計測条件は次のとおり固定されている。

- **ゲート数** — `LutLayer` はニューロン数、`LutConv2d` はツリー内部ノード数を合算。
- **レイテンシ** — 再現性のため **CPU 固定**。ウォームアップ 5 回のあと 20 回計測の中央値を
  batch=1 と batch=128 の両方で取る(学習だけはレシピの device 設定に従う)。
- **環境** — Python / PyTorch / プラットフォームを JSON に記録する。

:::note[レイテンシ列がない理由]
上の各表は個別の実験レポートからの転記で、レイテンシは測定項目に入っていなかった。
`griffith bench` のスキーマは揃っているので、レイテンシつきの横断表は
測定結果が揃い次第ここへ追加する。
:::

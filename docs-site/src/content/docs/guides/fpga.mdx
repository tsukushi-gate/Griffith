:::caution[先行ガイド / ツールは統合中]
ここで紹介する FPGA 支援ツール群(`mdl-fpga`)は **本リポジトリへの統合作業中**で、
`tools/mdl-fpga/` として取り込まれる予定である。本ページは **フローと考え方を先に共有するための
先行ガイド** で、コマンド・オプションは統合時に変わる可能性がある。以下のコマンド例は
`mdl-fpga` を導入済みの環境を前提とする。
**統合完了後、実行可能な完全版ガイドへ差し替える予定**。

なお [HDLエクスポート](/guides/hdl-export/) までは本リポジトリだけで完結する。
`mdl-fpga` が無くても Verilog / VHDL の生成と等価性検証は行える。
:::

[HDLエクスポートと等価性検証](/guides/hdl-export/) で生成した Verilog は、そのまま FPGA に載る。
とはいえ FPGA 未経験者にとって、合成ツールの導入・ピン割り当て・書き込み・実機での確認は
それぞれが独立した壁になる。`mdl-fpga` はこの壁を **1 本のコマンド列** に畳むためのツール群である。

:::caution[「焼ける」と「精度が保たれる」は別の話]
このページで扱う等価性は、**IR(離散化済みの真理値表)と実機の bit 一致**である。
IR にした時点の回路が実機でそのとおり動くことは保証されるが、
**学習時の連続値モデルと、離散化した回路の精度が一致することは保証されない**。

真理値表がまだ 0/1 に決めきれていないモデルを丸めると、精度は大きく落ちうる。
[BinaryBrain互換API](/tutorials/binarybrain/) の短縮レシピはその実例で、
連続の真理値表では eval acc 0.803 だが、エントリを丸めると **0.211 まで崩壊**する
(BatchNorm 統計を再較正しても 0.632 止まり。エントリが 0.5 付近に密集したままなのが主因)。

したがって**焼く前に、必ず hard eval(`model.eval()`)の精度を確認する**こと。
soft と hard の差の読み方は [学習曲線の見方](/guides/training-curves/)、
差が出ないパラメータ化の例は [DWN](/tutorials/dwn/)(train/eval のロジット差 0.0)を参照。
:::

## 全体フロー

```
学習(ライブラリ) → IR(JSON) → convert → check(bit一致) → build(合成) → flash(書込) → hw-check(実機bit一致)
                                  ↑ detect(ボード自動認識) / advise(搭載可能性判定) / bundle(他PC書込用zip) / up(一気通貫)
```

IR は **固定入力** として扱われ、HDL 生成から先をこのツールが所有する。
つまり学習側の都合とボードの都合が混ざらない([IR が真実源](/explanation/architecture/))。

## 動詞(サブコマンド)

| 動詞 | 何をするか |
|---|---|
| `doctor` | **環境診断**。合成ツール・JTAG・シリアルの検出と「次の一手」を提示する。最初に必ず実行する |
| `detect` | 接続されているボードの自動認識(EDA 不要)。JTAG の IDCODE 等の署名とボード定義を照合して候補と確信度を出す |
| `advise` | **搭載可能性の事前判定**(EDA 不要)。回路規模がそのボードに載るかを実測則で見積もる |
| `convert` | IR の読み込みと検証。実数ノード(blackbox)が残っていれば明示的に拒否して誘導する |
| `check` | **ボード無しでの bit 一致検証**。参照シミュレータ ⇔ RTL、さらに生成器を二重化して相互照合する |
| `build` | HDL 生成 → 事前判定 → シミュレーション → 合成 → ビットストリーム。`--selftest` で自己検証回路を同梱できる |
| `flash` | JTAG 書き込み |
| `hw-check` | **実機での bit 一致**。UART 経由で全ベクトルを流して照合する |
| `up` | 上記を一気通貫(detect → advise → build → flash → hw-check)。失敗した段で停止し、原因と次の一手を段別に言い切る |
| `view` | 回路の可視化ビューア(クリック 1 回 = 1 クロックの対話シミュレーション、任意地点プローブ) |

## Tang Nano 20K での最短経路

Sipeed Tang Nano 20K は **ベンダー EDA のインストールが一切不要**(オープンツールチェーンで
合成・書き込みが完結)かつ **ケーブル 1 本**(JTAG と UART が同一ブリッジ)で済むため、
最初の 1 枚として最も敷居が低い。実機での受け入れ確認も済んでいる。

```bash
# 0) まず環境診断
mdl-fpga doctor

# 1) ボード無しで bit 一致を確認
mdl-fpga check model.ir.json

# 2) 一気通貫(検出 → 判定 → 合成 → 書込 → 実機照合)
mdl-fpga up <manifest>.json --hw-check
```

## 実機で「合っている」ことをどう確かめるか

実機確認には 2 経路が用意されている。

1. **UART 照合(`hw-check`)** — PC からテストベクトルを送り、応答を golden と全件照合する。
   USB-UART ブリッジの接続が必要
2. **オンチップ自己検証(`build --selftest`)** — 全ベクトルと期待値を回路に焼き込み、電源投入直後に
   自動照合する。**LED 点灯 = 全ベクトル bit 一致**。UART もPCも不要

検証の辺は次のように閉じている。

```
ライブラリ simulate(numpy bit-exact = 正解オラクル)
   ⇔ 自製コアの RTL シミュレーション(check の主判定)
   ⇔ 実機(hw-check / selftest)
   ⇔ ライブラリの HDL 生成器(生成器の二重化によるドリフト検出)
```

## 対応ボード

| Tier | ボード | 合成 | 状態 |
|---|---|---|---|
| Tier1 | **Sipeed Tang Nano 20K**(GW2AR) | オープンツールチェーン(**EDA 不要**) | 実機受け入れ済み |
| Tier1 | Terasic DE0-CV(Cyclone V) | ベンダー EDA | 実機テスト済み |
| Tier2 | Terasic DE10-Lite(MAX 10) | ベンダー EDA | 定義のみ(実機未検証) |

ボード定義は **物理的事実のみ**(ピン配置・デバイス・検出署名)を JSON に持ち、
**ピン番号や IDCODE の創作を禁止**して転記元を必ず記録する運用になっている(実配線事故の防止)。
合成バックエンドはボード定義の記述でディスパッチされるため、バックエンドを 1 つ足せば
`build` / `up` は無改修で新ベンダーに載る。

## 既知の落とし穴

:::danger[タイミングが PASS でも論理が化けることがある]
オープンツールチェーンの配置配線は、**配置依存で機能不良のビットストリームを生成することがある**
(タイミング検証は PASS のまま論理だけが化ける)。したがって
**実機検証は必ず `hw-check`(bit 一致)まで行う** こと。化けた場合は配置のシードを変えて
再ビルドする(使用シードはビルド結果に記録される)。
:::

その他、Windows では初回のみ USB ドライバの切り替えが必要になるなど、環境依存の手当てがある。
`doctor` が検出して次の一手を提示する設計になっているので、詰まったらまず `doctor` に戻ること。

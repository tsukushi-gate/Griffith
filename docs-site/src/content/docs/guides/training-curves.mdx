DLGN の学習曲線は普通の NN と読み方が違う。**見るべきは soft(連続緩和)の精度ではなく
hard(離散化後)の精度** であり、この 2 本の差が回路としての品質を直接表す
(→ [soft と hard の二相](/explanation/dlgn/))。

## 記録は wandb に集約する

本プロジェクトでは実験記録を [wandb](https://wandb.ai) に集約するのが規約である。
訓練スクリプトは共通ヘルパー経由で run を初期化する。

```python
from wandb_utils import init_wandb, log_metrics, log_images

init_wandb(
    run_name='mnist_n4_k16000',   # JST のタイムスタンプが自動付加され一意になる
    config_dict=vars(args),       # デバイス情報・パラメータ数・ゲート数が自動追加される
    model=model,
    group='dlgn-mnist',           # 比較したい run 群をまとめる。指定必須
    tags=['n4', 'softmax'],
    hypothesis='fan-in を 4 にすると hard 精度の落ち込みが減るはず',
)
```

規約のポイントは 3 つ。

1. **`group` を必ず指定する** — 後から run 群を横並びで比較するための単位になる
2. **`hypothesis` に「何を確かめたいか」を書く** — 曲線を見返すときに解釈の基準になる
3. **図・数値はローカル保存だけで終わらせない** — 画像は `log_images()`、ファイルは Artifact として
   必ず wandb にも残す(ローカルのみの保存は禁止)

git の短縮ハッシュが run の notes に自動記録されるため、**どのコードで出た曲線か** は後から必ず辿れる。
環境変数は `.env` に置く(`WANDB_API_KEY` が未設定なら wandb は自動的に無効化され、学習自体は動く)。

| 変数 | 既定 | 意味 |
|---|---|---|
| `WANDB_API_KEY` | (なし) | 未設定なら wandb 無効 |
| `WANDB_PROJECT` | `griffith-logic` | プロジェクト名 |
| `WANDB_MODE` | `online` | `offline`(後で sync)/ `disabled`(完全無効) |

## ログされる指標

| キー | 意味 | 見方 |
|---|---|---|
| `loss` | 訓練損失(soft) | 下がっていることの確認用。**これだけ見てはいけない** |
| `train_acc` | 訓練データの **hard** 精度 | `test_acc` との差 = 過学習の度合い |
| `test_acc` | テストデータの **hard** 精度 | ★ **これが本命**。回路にした後の実力 |
| `test_acc_soft` | テストデータの soft 精度 | `test_acc` との差 = **離散化ギャップ** |
| `best_test_acc` | hard 精度のベスト | チェックポイント保存の基準 |

## 曲線の読み方

### 1. soft と hard の差 = 離散化ギャップ

`test_acc_soft` と `test_acc` の 2 本を必ず重ねて見る。

- **2 本がぴったり重なる** — 理想。連続緩和がほぼ 1 つのゲートに収束しており、回路にしても劣化しない
- **soft だけ高く hard が低い** — 典型的な失敗。ゲート選択が曖昧なまま(softmax が分散したまま)
  精度を稼いでいる。**この状態のモデルを HDL にしても性能は出ない**
- **学習が進むほど差が縮む** — 正常な収束の姿。温度スケジューリングが効いている

ギャップが縮まらないときの打ち手は、選択方式を `hard_st` にする(訓練 = 推論にしてギャップを
構造的に 0 にする)、温度 τ の設定を見直す、パラメータ化を変える(N=4/6 なら `warp` が安定)など
([パラメータ化を選ぶ](/guides/parameterization/))。

### 2. hard 精度が階段状・ギザギザになる

hard 精度は argmax の結果なので、**連続的には動かない**。ゲート 1 個の argmax が入れ替わった瞬間に
出力が飛ぶため、曲線は本質的に階段状になる。多少のギザつきは異常ではない。
ただし **大きく落ちて戻らない** 場合は学習率が高すぎるか、正則化が強すぎる。

### 3. train_acc と test_acc が開く

DLGN、特に fan-in が大きい構成(N=6)は **表現力が高く暗記しやすい**。
`train_acc` だけ上がって `test_acc` が止まったら過学習を疑い、層幅を絞る・正則化を入れる・
fan-in を下げるのいずれかを試す(→ [分類と系譜 §6](/explanation/taxonomy/))。

### 4. hard 精度だけが崩壊する

学習配線を使う構成では、soft は良好なのに **hard 精度だけが崩壊** することがある。
配線の学習が不安定なケースなので、配線を固定する(第 1 層だけ学習配線にする)のが定石である。

## ローカルに出る図

訓練スクリプトは学習曲線などの図を `results/<実験名>/` 以下に PNG で保存する
(例: `*_curves.png` = loss と精度の推移)。**同じ画像を必ず `log_images()` で wandb にもログする**
のが規約で、ローカルのみの保存は禁止されている。理由は単純で、ローカルの PNG は
「どのコード・どの設定で出た図か」を失いやすく、数か月後に再現できなくなるからである。

`examples/` のサンプル(XOR やハイブリッド)は 1 分以内に終わる自己検証つきスクリプトなので、
曲線を眺める前に **まず期待結果が出ることを確認** する用途に向く。

```bash
uv run python examples/01_xor.py    # soft/hard ともに acc=1.00 になる
```

XOR のような小さな問題では **hard 精度が 1.00 に到達すること** が正常。到達しない場合、
曲線を細かく読むより先に構成(層数・幅・学習率)を疑ったほうが速い。

## run の回収

`init_wandb` はカレントディレクトリに直近の run ID を書き出す。CI・エージェント・
クラウド実行から結果を機械的に拾うときはこれを使う。

| ファイル | 内容 |
|---|---|
| `.wandb_last_run_id` | 直近の run ID(毎回上書き) |
| `.wandb_runs.jsonl` | run 情報の追記ログ |

Numbers measured with this library, laid out across **model × dataset × hard accuracy × scale**.
Every row records **when, on what hardware and under which conditions** it was measured.

If you want a one-line-per-model overview — headline accuracy, main open problem, world-first
verdict — read the [Model Zoo](/en/reference/model-zoo/) first.

:::caution[How to read these numbers]
- All headline values are **hard** (gates fixed by argmax after training, then **inference as a pure
  Boolean circuit**). Soft values (the relaxation used during training) are shown only so you can
  see the gap.
- Unless noted otherwise, each row is **a single seed and a single configuration**; seed variance
  was not measured.
- What is listed here is a **comparison between settings inside this library**. Side-by-side tables
  against external implementations are not published, because we have not re-measured them under
  matched conditions (rows where a prior method was re-implemented on top of this library say so
  explicitly).
- Rows marked "needs calibration" are records that **have not converged and whose cause is not yet
  identified** — they are listed as a current position, not as an achievement.
:::

## 3. Learning rules (MNIST)

| Learning rule | soft | hard | Conditions |
|---|---|---|---|
| BP (softmax N=2) | 0.983 | **0.977** | 6 layers, τ=10, 50 ep / RTX 5090 |
| BP (Hard-ST selection) | — | **0.980** | 6 layers × 64,000, 50k iter / RunPod GPU |
| BP (Soft-Mix selection) | — | 0.975 | same as above |
| AP (Akiho Propagation, error broadcast, no backprop) | ≈0.90 | ≈0.85 | flat, 4 layers × 16,000, 30 ep |

AP is our own learning rule, which updates LUTs directly as
`weight += error × basis × learning rate` without backprop. On fully connected MLPs it is
**stable at soft ≈0.90 at any depth from 2 to 8** (0.898–0.909). On **CNNs, however, it collapses
to ≈0.11** (loss pinned at ln 10, i.e. chance), and **on RNNs (seq2seq) it never rises above
chance** (the breaking point lies between sequence length T=1 and T=2). The hypothesis that the
collapse is caused by "broken monotonicity" has been **rejected**: even when projecting onto the
monotone cone to force zero monotonicity violations, all three seeds still collapsed. On the other
hand, randomizing the sign of the error broadcast destroys learning completely, so **sign
consistency is essential**.

`DFA` and `EGGROLL` (evolution strategies) are implemented as learning rules too, but the
measurements we can publish today stop at convergence checks on XOR / parity / full adder
(hard eval 100%) rather than MNIST-scale results.

For how the learning rules work, see [Learning rules (BP/AP/DFA/ES)](/en/explanation/learning-rules/).

## 9. Measure it yourself — `griffith bench`

A benchmark command ships with the library so you can re-measure on the same footing. Give it a
recipe YAML or a saved checkpoint and it measures **hard eval accuracy, gate count and forward
latency**, then writes them to JSON.

```bash
# From a recipe (short training run → measure the best checkpoint)
uv run python benchmarks/bench.py configs/recipes/logic_xor.yaml

# Measure only latency and gate count without training (hard_acc becomes null)
uv run python benchmarks/bench.py configs/recipes/logic_xor.yaml --skip-train

# Measure a saved checkpoint
uv run python benchmarks/bench.py outputs/<run>/checkpoints/best.pt
```

Output goes to `benchmarks/results/<date>_<name>.json` with this fixed schema.

```json
{
  "name": "...",
  "timestamp": "...",
  "config": { "...": "..." },
  "metrics": {
    "hard_acc": 0.0,
    "total_gates": 0,
    "latency_ms_b1": 0.0,
    "latency_ms_b128": 0.0
  },
  "env": { "python": "...", "torch": "...", "platform": "..." }
}
```

The measurement conditions are fixed as follows.

- **Gate count** — the sum of neuron counts for `LutLayer` and internal tree nodes for
  `LutConv2d`.
- **Latency** — **always on CPU**, for reproducibility. After 5 warm-up runs, the median of 20
  measurements is taken for both batch=1 and batch=128 (only training follows the device setting in
  the recipe).
- **Environment** — Python, PyTorch and the platform are recorded in the JSON.

:::note[Why there is no latency column]
The tables above are transcribed from individual experiment reports, where latency was not among the
measured quantities. The `griffith bench` schema covers it, so a cross-cutting table with latency will be
added here once the measurements are in.
:::

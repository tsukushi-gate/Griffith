微分可能論理ゲートネットワークは、**学習時は連続緩和(soft)、推論時は argmax で
確定した純ブール回路(hard)** という二相構造を持つ。この二相の性能差が
**離散化ギャップ**であり、「学習ではうまくいったのに回路にしたら落ちた」という
現象の正体である。ハードウェアに焼いたときに残るのは hard 側だけなので、
このギャップは実質的にそのまま製品性能の目減りになる。

ここでは、実測でギャップがどれくらい出るのか、そして何が効いたのかをまとめる。

## 1. ギャップの実測値(タスク別)

| タスク / モデル | soft | hard | ギャップ | 条件 |
|---|---|---|---|---|
| MNIST・softmax N=2・6層 | 98.30% | 97.74% | 0.56pp | RTX 5090、50ep、2026-04-20 |
| MNIST・softmax N=4・6層 | 95.66% | 94.54% | **1.12pp** | 同上 |
| MNIST・warp N=2・6層 | 96.05% | 96.11% | **−0.06pp**(hard が上) | 同上 |
| MNIST・warp N=4・6層 | 95.64% | 95.50% | 0.14pp | 同上 |
| 文字言語モデル(LogicGPT L3-C) | ppl ≈12.2 | ppl 15.54 | **0.29 nat** | A10G、Tiny Shakespeare、20k step |
| 物体検出(CenterNetLUT) | mAP 0.1791 | mAP 0.5425 | hard が大幅に上 | RTX 5090、Multi-MNIST 96×96。**mAP は修正前指標・再計測待ち** |

3 点だけ強調しておく。

- **ギャップは方式に強く依存する。** 同じデータ・同じ層数でも 1.12pp と −0.06pp が並ぶ。
- **hard が soft を上回ることがある。** warp N=2 と検出モデルがそれで、
  離散化がノイズ除去として働く場合がある。「必ず落ちる」ではない。
- **言語モデルでは絶対値が大きい。** 分類より深い合成を通るぶん、ギャップが効きやすい。

## 2. 対策その1: warp(Walsh–Hadamard 係数 + Gumbel 平滑化)

真理値表そのものではなく Walsh–Hadamard 基底の係数を学習し、ロジットの符号で
離散化する方式。訓練時から離散化を意識した学習になるため、
**MNIST N=2 で −0.06pp、N=4 で 0.14pp** と、ギャップがほぼ消える。
softmax の 11〜48% の FLOPs で回る点も併せて効く。

代償は最高精度で、同条件の softmax N=2(97.74%)に対し warp N=2 は 96.11% だった。
「ギャップは小さいが天井も低い」という位置づけになる。

## 3. 対策その2: Hard-ST(argmax 順伝播 + STE 逆伝播)

順伝播を最初から argmax にしてしまい、逆伝播だけ Straight-Through Estimator で
通す選択方式。2026-04-15、RunPod GPU、MNIST 28×28・6層・64,000 ニューロン/層・
N=2・Adam lr=0.01・bs=512・50,000 iteration・seed=0 での実測:

| | Soft-Mix(従来の softmax 加重平均) | Hard-ST |
|---|---|---|
| 最終精度(best hard) | 97.46% | **98.02%** |
| 97% 到達 iteration | 10,500 | **5,000** |
| selection gap(収束時) | 0.9〜1.0% | **0.2〜0.4%** |
| 壁時間 | **43 分** | 85 分 |

**収束は約 2.1 倍速く、最終精度は +0.56pt、選択のギャップは 1/3 以下**になった。
壁時間で逆転しているのは実装都合で、Soft-Mix は CUDA カーネル、Hard-ST は Python
フォールバックで動いているため(iteration あたり 18.8 it/s 対 9.2 it/s)。

なお Hard-ST の selection gap は理論上ゼロのはずだが、実測では 0.2〜0.4% 残った。
訓練時と評価時で入力が連続値と二値で異なることが原因である。

## 4. 対策その3: Gumbel ゲート選択ノイズ(言語モデルで最も効いた)

学習時のみゲート選択分布に Gumbel ノイズを載せる($\pi = \mathrm{softmax}((w+g)/\tau_g)$、
$g \sim \mathrm{Gumbel}(0,1)$)。評価時は完全に無効化されるため、回路の定義は変わらない。

Tiny Shakespeare の文字言語モデル(語彙 65・T=64・20k ステップ・A10G・seed=0、
全 validation で評価)で、射影層のパラメータ化と Gumbel の有無を分けた 3 腕アブレーション:

| 腕 | 射影のパラメータ化 | Gumbel | hard ppl | soft ppl | ギャップ(最終) |
|---|---|---|---|---|---|
| 基準(L3-C) | warp | なし | 15.54 | ≈12.2 | 0.29 |
| 対照 | softmax | なし | 15.44 → 終盤 17.9 | ≈11.9 | **0.41**(悪化) |
| **本命** | softmax | **あり($\tau_g$=1.0)** | **13.31** | ≈12.2 | **0.107** |

**ギャップ 0.29 → 0.107(−63%)、hard ppl 15.5 → 13.3(−14%)**。
soft 側の性能(≈12.2)は動いていないので、改善は純粋に離散化の側で起きている。

対照腕を置いたことが効いた。**warp → softmax の置換だけではむしろ悪化する**(ギャップ 0.41)
ので、改善は Gumbel ノイズ単体の寄与だと分離できている。学習曲線でも、Gumbel 腕は
ギャップが単調に縮小し(step 1,000 の 0.139 → 20,000 の 0.107)、対照腕は温度低下とともに
拡大した(0.27 → 0.41)。

現状の適用範囲は attention の射影層のみで、FFN 側は対象外である。
到達目標は逐次 MNIST 並みのギャップ 0.02〜0.05 で、まだ距離がある。

## 5. ギャップが引き起こす二次的な問題

物体検出(CenterNetLUT・Multi-MNIST 96×96・RTX 5090・1,000 エポック・
11 時間 45 分)では、mAP(hard) が epoch 78 で最高 0.5425 に達したあと不安定化した。
なお**この mAP は画像スコープのバグ(全画像の箱を1プールで照合していた)を修正する前の指標であり、再計測待ち**である(順位の議論には使えるが絶対値は信頼しないこと)。
soft と hard が別々の方向に動くため、**soft の指標で early stopping やモデル選択を
すると hard のピークを取り逃す**。hard 側を選定基準に含めるのが実務上の対応になる。

## 6. まとめ

| 打ち手 | 効果 | 副作用 |
|---|---|---|
| `warp` パラメータ化 | ギャップ ≈0(−0.06〜0.14pp) | 最高精度が softmax N=2 より低い |
| Hard-ST 選択 | selection gap 1/3、収束 2.1 倍、精度 +0.56pt | 現状は Python 実装で壁時間 2 倍 |
| Gumbel 選択ノイズ | 言語 LM でギャップ −63%、hard ppl −14% | 単一シード、適用は射影層のみ |
| hard 基準でのモデル選定 | ピーク取り逃しの回避 | 評価コストが増える |

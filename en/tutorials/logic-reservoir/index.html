Choosing Not to Train the Circuit (Reservoir Computing = an RNN That Is Never Trained)

Choosing not to train the circuit. We push sequences through a frozen random 512-bit logic circuit and train only the readout (5.9% of the whole) — and yet parity and delayed recall get solved anyway.

The theme of this page is that “what a reservoir holds is memory, not nonlinear computation over that memory”. delay-d recall is perfect for all of d=0..5, yet parity degrades as k grows. Furthermore, we use perturbation curves to show that a hard-evaluated pure Boolean circuit (leak=1.0) is bounded but does not contract (a one-bit difference actually spreads), and we discuss the trade-off between fading memory and hardware implementation.

What you’ll learn

  1. What can be solved by training only the readout (5.9% of the whole) on top of a frozen random logic circuit
  2. That what a reservoir holds is memory, not nonlinear computation over that memory
  3. The hardware pitfall that a hard-evaluated pure Boolean circuit is “bounded but does not contract”

Prerequisites

  • RNN: Logicizing LSTM / GRU — compare with a trained recurrent circuit

LogicReservoir: the option of not training the circuit (reservoir computing).

The sequence models so far (08 RDDLGN / 09 LogicLSTM / 10 LogicWaveNet) all learned the circuit itself by gradients. This example tries the exact opposite idea:

This is reservoir computing. The circuit (the reservoir) is created once from random numbers and never touched again. When you feed a sequence into it, the reservoir’s internal state spreads the history of the input into a “high-dimensional bit pattern” all by itself. All that is learned is the final linear layer that extracts the answer from that state.

Why this meshes with this library’s story:

The task is parity (exclusive OR). Answer the XOR of the last k bits of the sequence. Parity is a combination of “memory x nonlinearity”, the hardest possible shape of problem for a linear readout, and a classic benchmark for measuring the limits of a reservoir’s ability. Alongside it we also run delayed recall (delay-k recall), which measures the reservoir’s memory capacity itself.

Architecture, illustrated: only one layer at the edge is trained

Section titled “Architecture, illustrated: only one layer at the edge is trained”

The single most important picture is “what is frozen and what is trained”. The gray boxes (the reservoir) are created once at random and never updated again. The training gradient reaches only the orange readout; not one of them flows back into the gray boxes.

Unrolled along time, it is nothing more than passing through the same frozen circuit eight times (the figure shows the first real data point, the bit sequence 1 0 0 1 0 1 0 1).

How it actually works (the points that matter on a first read)

  • The circuit is drawn at random exactly once. Right after generating the wiring and truth tables determined by LogicReservoirConfig.seed, requires_grad=False is set and the state computation runs under no_grad. That is why backpropagation only ever flows through the one readout layer —— the reason training is extraordinarily cheap.
  • The state is rebuilt from scratch at every step: s(t) = frozen circuit([x(t) ⊕ s(t-1)]). There is no dedicated keep path like an LSTM’s, but with random wiring scattering it across a state as wide as 512 bits, traces of past inputs survive for a while.
  • The state is strictly 0/1. With leak=1.0 it is a complete replacement, so the reservoir stays a pure Boolean circuit. Divergence and saturation are impossible (the state space is finite).
  • Only the readout is trained: a linear map from 512 bits to 2 classes (1,026 parameters), while the 16,384 parameters of the circuit itself stay frozen (about 6% of the total is trained).
  • The limits show too: a linear readout can read out “what is remembered”, but is bad at “XOR-ing what is remembered”. That is why parity falls apart as k grows.

Run: uv run python examples/11_logic_reservoir.py Expected result: parity is 1.00 at k=1,2 and degrades at k=3,4 / delay recall is 1.00 for d=0..5 (about 15 seconds on a CPU)

Setup: imports and hyperparameters

Section titled “Setup: imports and hyperparameters”

All we need is LogicReservoir and LogicReservoirConfig, which fixes its configuration. We also import plot_circuit, since the last figure draws a circuit diagram.

Hyperparameters

Section titled “Hyperparameters”

The eye-catching line is RESERVOIR = 512 — the input carries only one bit per step, yet the state has 512 bits. This “high-dimensional space that widens by itself” is the apparatus of reservoir computing: the input history is projected into it, and only the readout is trained.

Data: a random bit stream

Section titled “Data: a random bit stream”

We simply build 512 random bit sequences of length 8. Many different targets can be derived from this stream later, so the reservoir states only have to be computed once and can be reused for every task (that is where the speed comes from).

The single bit is replicated into 8 lines because, against a 512-bit state, one line is too weak a drive and the state collapses into a fixed pattern that ignores the input.

Model: a frozen reservoir + a trained readout

Section titled “Model: a frozen reservoir + a trained readout”

Reservoir computing is a design in which the inside of the recurrent circuit is not trained at all. The input is fed into a randomly generated recurrent circuit, the states that appear there are treated as features, and only the one readout layer is trained.

Why does it work without training? The job asked of the recurrent circuit is to project the past inputs into a state in a mutually distinguishable form. As long as the projection is in a readable direction, it does not have to be a designed one — even a random high-dimensional map lets a linear readout pull out the components it needs afterwards. The idea is to move the whole training burden from the recurrence to the readout.

leak=1.0 means “replace the state completely at every time step”, and in that case the state stays strictly {0,1}\{0,1\}{0,1} — that is, the whole reservoir is a pure Boolean circuit. Figure 3 shakes exactly this point.

Training only the readout

Section titled “Training only the readout”

Backpropagation flows through the single readout layer and never takes a step into the reservoir. That is why the states can be computed once and reused, with no recomputation when the task changes.

Each task gets a brand-new readout. The reservoir is identical every time (deterministically regenerated from a fixed seed), so the difference between tasks is purely “whether that feature can be read”.

Computing the reservoir states once and for all

Section titled “Computing the reservoir states once and for all”

First we print the breakdown of what is trained. The fraction of all parameters held by the readout is exactly the size of “the part of this model that is being learned” (about 5.9% in practice).

Next we compute the states at every time step in one go. Inside states() it is no_grad + detach, so the computation graph is completely cut here and nothing is recomputed no matter what task we solve from now on.

We check that only the two values [0.0, 1.0] occur — a reservoir with leak=1.0 is a pure Boolean circuit, so an intermediate value appearing in the state would itself be a defect. The state at the final time step is taken as the “feature for readout” and reused for every task below.

Experiments: parity and delayed recall

Section titled “Experiments: parity and delayed recall”

Experiment 1: parity (XOR of the last k bits)

Section titled “Experiment 1: parity (XOR of the last k bits)”

Parity is whether the number of ones in a bit string is even or odd — that is, a chain of XORs. k=1k=1k=1 is easy, since it just means “answer the last bit as is”, but as kkk grows you have to “remember kkk bits and, on top of that, XOR them”. It is a task that probes both memory and nonlinear computation.

Experiment 2: delayed recall (memory capacity)

Section titled “Experiment 2: delayed recall (memory capacity)”

“Answer the bit that came in ddd steps ago, as is”. No XOR is needed, so this is a pure test of memory capacity, a classic metric in reservoir research. Paired with experiment 1, it separates “is the memory missing?” from “is the nonlinear computation missing?”.

Checking that it is frozen

Section titled “Checking that it is frozen”

“The reservoir is not trained” means nothing as a verbal promise, so we check it mechanically. We assert that the reservoir’s state_dict is bitwise identical before and after training, and further that it matches a circuit rebuilt from the same seed — if the circuit is determined by the random seed alone, everyone who runs it gets the same circuit, and it can be handed around as a hardware blueprint as is.

Visualization: what it can hold, and what it cannot

Section titled “Visualization: what it can hold, and what it cannot”

Figure 1: parity breaks down as k grows / delay recall does not

Section titled “Figure 1: parity breaks down as k grows / delay recall does not”

What to look at: parity (growing kkk) on the left and delayed recall (growing ddd) on the right, both with hard accuracy on the vertical axis and the coin-toss level as a dotted line. The star of the show is how differently the two panels break down: if only one of them collapses, that tells us which side the reservoir’s limit lies on.

Reading it: the right panel (delayed recall) stays at full marks from d=0d=0d=0 through d=5d=5d=5 without breaking — the entire 8-step history survives inside the 512 bits. The left panel (parity), by contrast, falls off sharply at k=3,4k=3,4k=3,4. In other words, what is missing is not memory but nonlinear computation over that memory. What a reservoir provides stops at “retaining the past in a distinguishable form”; anything beyond that (a composition such as XOR) is not a job a linear readout can do — that is the conclusion of this page.

Figure 2: the reservoir state itself

Section titled “Figure 2: the reservoir state itself”

What to look at: the time evolution of the state for one sample drawn in black and white (vertical = state bits, horizontal = time, black = 1). The input is only one bit per step yet the state has 512 bits, so the picture directly shows “a random circuit mapping the input history into high dimensions”.

Reading it: rather than a uniform grey wash, the pattern switches from one time step to the next — evidence that the state is being driven by the input bits. If instead every time step showed the same vertical stripes, the state would have collapsed into a fixed pattern that ignores the input (too weak an input drive) and the readout would have nothing to extract. The complete absence of intermediate grey also confirms that this is a pure Boolean circuit.

Figure 3: the trade-off between fading memory and leak

Section titled “Figure 3: the trade-off between fading memory and leak”

What to look at (drawn a few cells further down): fading memory (the echo state property) is the property that “the influence of inputs from long ago, and of the initial condition, fades over time”. Without it the reservoir drags its initial state along forever and cannot produce stable features for the same input.

Measuring it is simple: prepare a sequence in which only the first 3 steps are replaced, and watch whether the state difference from the original sequence shrinks over time. We overlay blue (leak=1.0, pure Boolean) and orange (leak=0.5, leaky integration) and compare which one decays.

leak is the knob that sets how fast the state is overwritten: st=leak⋅new+(1−leak)⋅st−1s_t = \mathrm{leak}\cdot\text{new} + (1-\mathrm{leak})\cdot s_{t-1}st​=leak⋅new+(1−leak)⋅st−1​, a low-pass filter. At 1.0 it is a complete replacement (= pure Boolean); below 1 the past state is mixed in, but the state is no longer exactly {0,1}\{0,1\}{0,1}.

We print the state-difference trajectory for the two leaks. Seeing the numbers first means the next figure’s verdict can already be read off the printed sequence.

Reading it (figure 3, next): orange (leak=0.5) decays downward once past the perturbed window, whereas blue (leak=1.0) does not fall — a random logic circuit also works in the direction of spreading a one-bit difference across layers, so being bounded does not by itself make it contract.

This is where the pitfall for hardware lies. If you want fading memory the only lever is to lower the leak, but the moment you do, the state leaves {0,1}\{0,1\}{0,1} and you lose the very advantage of “staying burnable as a pure Boolean circuit”. Fading memory and pure Boolean-ness are in a tug of war — the final lesson of this page.

Figure 4: the frozen random circuit “for real”

Section titled “Figure 4: the frozen random circuit “for real””

How to read it, and what it says (the last figure on this page). The 512-bit reservoir is far too large to draw every gate, so we generate a much smaller reservoir the same way (8-bit state, depth=2) and draw it as a circuit diagram. On the left are the inputs (the 12 bits of [xt;st−1][x_t ; s_{t-1}][xt​;st−1​]), in the middle and on the right the two LutLayer stages of 8 gates each, and the text inside each box is the settled gate name.

The thing to read off is that concrete gate names appear even though nothing was trained. The truth tables drawn at random already mean something as a circuit, so this model is “a circuit you can burn from the moment you create it”, and what training changes lives entirely outside this figure, in the readout.

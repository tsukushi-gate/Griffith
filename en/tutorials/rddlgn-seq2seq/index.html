A seq2seq Model Built from RNNs Alone (RDDLGN)

Using RDDLGN, where every fully connected layer of the encoder and decoder is replaced wholesale by LUTs, we train the sequence transformation tasks copy / reverse. This installment measures how far a fixed-length bottleneck without attention (a 384-bit context vector) can carry a sequence.

The pitfall is part of the lesson too: the default 'zero' of RDDLGNConfig.init_mode sets the initial state to 0.5 (a neutral value), so non-binary values flow into the context vector even though it should be hard eval. Setting init_mode='one' closes the hard path as purely Boolean and even raises accuracy (0.938 → 0.969).

What you’ll learn

  1. How to build a sequence transformation model with an RNN whose fully connected layers are replaced wholesale by LUTs (RDDLGN)
  2. A measurement of how far a fixed-length bottleneck without attention can carry a sequence
  3. That the choice of init_mode governs both the pure Booleanness of the hard path and the accuracy (0.938 → 0.969)

Prerequisites

  • 1. Training on MNIST
  • Choosing a Parameterization — why init_mode matters

▶ Open in Colab (enabled once the repository is public)

An example of training seq2seq with RDDLGN (recurrent differentiable logic gate network).

The samples so far (XOR, MNIST) were classifiers of the form “one input → one output”. This sample builds sequence → sequence, that is, an encoder-decoder shaped just like a translator, out of nothing but logic gates (LutLayer) instead of fully connected layers.

The model is RDDLGN (Bührer et al., 2025 / arXiv:2508.06097). It consists of five groups of logic gates:

There is no attention. The sequence read by the encoder is compressed into a single context vector, and the decoder assembles its output relying on that alone. This is the highlight of this sample: we check whether “memory through a fixed-length bottleneck can be done with logic gates alone”.

The tasks are copy (emit the input as-is) and reverse (emit the input in reverse order). Both use synthetic data with vocabulary 8 and length 4, and the example is self-contained, building the data the same way as CopyDataset / ReverseDataset in experiments/data/synthetic.py.

Architecture, illustrated

Section titled “Architecture, illustrated”

First the block-level overview. Green is logic gates (LutLayer), orange is the parts that stay real-valued, and blue is a bit vector.

Because there is no attention, everything the encoder read from the four tokens has to pass through these 384 bits. That this is the only path across is the single most important property of this model.

The detailed view, unrolled along time, is drawn as “Figure 0” below (the horizontal axis is time, showing how the same box — the same circuit — is reused at every step, together with the gate count of each block). What flows through it is the first real data point of the copy task, 3 5 4 4 → 3 5 4 4.

⊕ means concatenation, not addition. The P and M layers take the long bit vector [p(t-1) ⊕ context ⊕ l(t)] as their input directly.

How it actually works (the points that matter on a first read)

  • Token → bit vector: a word ID is turned into a real-valued vector by an embedding table, then squeezed into 0–1 by a sigmoid. That is the “logic value”. At eval time it is rounded to 0/1 at the 0.5 boundary (LogicEmbedding). This is the only place that behaves like an ordinary real-valued NN (orange).
  • A layer is a bundle of logic gates: N/K/L/P/M are nothing but stacked LutLayers. One LutLayer picks two input bits at random per gate and learns which of the 16 two-input Boolean functions to use, out_dim gates side by side. There is not a single matrix product.
  • Memory along time: the K layer receives the previous step’s output k(t-1) concatenated onto its input (the horizontal arrows in the figure). That alone is the path that carries a bit seen earlier into the next step.
  • The bottleneck: k(T), produced after reading the whole sequence, is the context bits. The decoder sees only those 384 bits. Longer sequences and reordering (reverse) come down to whether they fit into those 384 bits.
  • Output: GroupSum splits the bits produced by the M layers into one group per vocabulary entry and counts the ones, using the counts as scores. Only the counting is real-valued (orange).

Run: uv run python examples/08_rddlgn_seq2seq.py Expected result: hard token accuracy around 0.95 for both copy / reverse (about a minute and a half on CPU)

Setup and configuration

Section titled “Setup and configuration”

All we need is RDDLGN and RDDLGNConfig. Since figure 0 (the unrolled architecture diagram) is drawn by hand, we also import matplotlib’s shape parts.

Reproducibility

Section titled “Reproducibility”

Both the initial truth tables of the logic gates and the random wiring between gates (which gate looks at which two lines of the previous stage) are decided by random numbers. The wiring stays fixed during training, so changing the seed makes the circuit itself a different object.

Task and hyperparameters

Section titled “Task and hyperparameters”

A minimal setting with a vocabulary of 8 and a length of 4, aimed purely at whether a whole sequence can be carried across. The special tokens PAD, BOS (start-of-sequence marker) and EOS (end marker) follow the same conventions as an ordinary seq2seq.

Why is a binarization regularizer needed? LogicEmbedding uses sigmoid(embedding) as its logic value, so if the value settles near 0.5 by the end of training, the Heaviside binarization at eval time throws the information away wholesale. This weight lightly penalizes x(1−x)x(1-x)x(1−x) to push the values toward the ends, 0 or 1.

Data: copy and reverse

Section titled “Data: copy and reverse”

There are two tasks. copy emits the input as is (the identity map), and reverse emits it in reverse order. Neither can be solved without remembering the whole input, so both probe the capacity of the context vector directly.

The difference between them matters. copy emits what was read first, first, so it can get by even while the state is being overwritten. reverse has to emit the last token read first, so the order information of the sequence must also survive in the 384 bits — a strictly harder demand on the bottleneck.

Model: five groups of layers and init_mode

Section titled “Model: five groups of layers and init_mode”

RDDLGN is made of five groups of layers. The N layers transform the input-side tokens, the K layers are the recurrence along time (receiving the previous step’s output concatenated onto the input), the L layers transform the output-side tokens, the P layers are the decoder-side recurrence, and the M layers are the output stage that produces the vocabulary logits. Every one of them is just a stack of LutLayers; not a single matrix product appears.

One more thing matters in this cell: init_mode — the choice of the initial value of the recurrent hidden state, which decides whether the hard path closes as a pure Boolean circuit. The reason is spelled out in the comments in the code, and the result is measured in figure 3.

Teacher forcing (showing the answer during training only)

Section titled “Teacher forcing (showing the answer during training only)”

An autoregressive model normally takes “the token it emitted one step earlier” as input, but doing that during training makes early mistakes snowball and learning never progresses. So during training only, we shift the ground-truth sequence one step to the right and use it as input. That is teacher forcing, the standard practice for seq2seq.

Training loop

Section titled “Training loop”

Ordinary PyTorch inside. The loss is the per-time-step token classification cross entropy plus the binarization regularizer on the embeddings. Every 150 steps we record both soft (the shape it has while training, still continuously relaxed) and hard (the shape of the “baked circuit”, with both embeddings and gates binarized) accuracy, and figure 1 shows how the two lines approach each other as training proceeds.

The metric is token-level accuracy (averaging, position by position, whether that one token was right). It is more lenient than counting whole-sequence matches, but it lets figure 2 trace where the output breaks down.

Diagram: unrolling the architecture along time

Section titled “Diagram: unrolling the architecture along time”

The next two are drawing helpers (boxes and arrows). The colors follow the same legend as the Mermaid diagram at the top — green = logic gates, orange = real-valued computation, blue = bit vectors, gray = tokens.

Figure 0: the architecture unrolled in time

Section titled “Figure 0: the architecture unrolled in time”

What to look at: time runs along the horizontal axis and layers along the vertical one. The left half is the encoder (reading four tokens), the right half the decoder (writing one token at a time), and the blue box in the middle is the context bit vector — the only path between the two. What flows through is the first real data point of the copy task, 3 5 4 4.

Three things to notice. (1) Every column is the same circuit, merely reused at each time step (which is why unrolling in time does not multiply the hardware). (2) The horizontal arrows exist only in the K and P layers — that is the sole road along which information travels through time. (3) The width of the blue box, 384 bits, is the size of the hole through which the information of the entire sequence has to squeeze.

Reading it: on the encoder side only the K layer extends sideways, advancing as k(1) -> k(2) -> k(3) -> k(4) while being overwritten. All three columns on the decoder side are fed from the same blue box (dotted lines) — that is, the decoder never sees the original sequence and writes relying only on the 384 bits it was folded into. Comparing this with an attention-based model (the logic-gate GPT), which replaces those dotted lines with direct paths to every time step, makes the difference between the two vivid.

Running training and the results

Section titled “Running training and the results”

We train copy and reverse in turn with the same settings and the same seed. Whether both are solvable at the same circuit capacity, or whether reversing the order bites into the bottleneck, is what the output below and figure 1 compare.

If hard accuracy comes in around 0.95, that means a sequence transformation through a fixed-length bottleneck was achieved with logic gates alone. The threshold of 0.80 in the assert below is a loose line allowing for environment differences, set as the minimum bar for “the circuit can read”.

Visualization: how much the bottleneck could carry

Section titled “Visualization: how much the bottleneck could carry”

Figure 1: Learning curves (copy vs reverse)

Section titled “Figure 1: Learning curves (copy vs reverse)”

What to look at: copy on the left, reverse on the right, with token accuracy on the vertical axis. Orange is soft (the shape it has while training) and green is hard (the real circuit settled by argmax). If the two overlap as they rise, it means “the performance that was learned survives in the circuit as it is”.

Reading it: both panels climb to roughly the same height — at this length (4 tokens), even reverse, which flips the order, fits comfortably into 384 bits. If reverse alone were to stall here, that would be the sign that the width of the context vector (k_layer_sizes) or the sequence length has hit the bottleneck. Soft and hard stay close because the embedding binarization regularizer and init_mode='one' are doing their job.

Figure 2: Checking the predicted sequences

Section titled “Figure 2: Checking the predicted sequences”

What to look at: for the first 16 samples, “ground truth / prediction” is laid out position by position as a grid. Green is a match, red a miss. The figure exists to show not just the overall mean but where things break down. A model without attention tends to drop the middle of a sequence, which is the typical expectation.

Reading it: if the red cells are scattered around, the errors are uniform — a plain shortage of capacity rather than “a particular position being hard”. If instead red concentrated in one column (one position t), the information for that time step would be getting pushed out of the bottleneck; that is how things start to break as the sequence grows longer.

Figure 3: Is the context vector really a “discrete bit string”?

Section titled “Figure 3: Is the context vector really a “discrete bit string”?”

What to look at: the context vector emitted by the encoder, drawn directly as a black-and-white image. Black is 1, white is 0. That there is not a single grey pixel here is what guarantees the model “drops straight into HDL” (any grey would be an intermediate value that does not exist in a circuit).

The assert just before performs exactly that check. With init_mode='zero', the initial state of 0.5 propagates through time and breaks this — which is precisely why init_mode is a choice exposed in the config.

Reading it (the last figure on this page): there should be only black and white, with no intermediate grey at all. Notice further that although the pattern differs from row to row (= from sample to sample), some columns line up like vertical stripes — those are “unused bits” that take the same value for any input, and they are the slack in the bottleneck. Lengthen the sequence and this slack is eaten up first; only then do the red cells of figure 2 start to multiply.

DWN — solving MNIST with thermometer encoding and n-input LUTs

The exception in the logic-NN world: a discretization gap of zero. DWN (Differentiable Weightless Neural Network) combines a ThermometerEncoder — which drops real-valued pixels into a monotone bit string — with 64-entry n-input LUTs, and the maximum logit difference between train() and eval() is 0.0. In other words, the model being trained and the circuit being burned are identical from the start.

test acc 0.958. This is the page that shows how the “works in soft, falls apart in hard” problem covered on many other pages disappears purely through the choice of parameterization.

What you’ll learn

  1. The binarization technique of dropping real-valued pixels into a monotone bit string with ThermometerEncoder
  2. How to build a DWN out of 64-entry n-input LUTs (test acc 0.958)
  3. The mechanism that makes the discretization gap 0.0 — the model being trained and the circuit being burned are identical

Prerequisites

  • 1. Train on MNIST — the baseline to compare a plain LutLayer against
  • Choosing a parameterization

An example of solving MNIST with a DWN (Differentiable Weightless Neural Network).

The DLGN in 06_mnist.py was “a circuit of sparsely wired 2-input logic gates”. DWN (Bacellar et al., ICML 2024) is the same kind of logic circuit but with a different design philosophy:

  • The basic element is an n-input LUT (lookup table), not a gate. With n=6 you learn a whole 2^6=64-entry truth table (its expressiveness is in another league from a gate).
  • Real-valued inputs are dropped into bit strings by a ThermometerEncoder. A monotone code that expresses “how large the value is” as “how many bits are set”.
  • The forward pass is always hard, even during training (LUTs are binary, connections are argmax). So there is structurally no soft/hard discretization gap like DLGN has — the accuracy you watch during training is exactly the accuracy of the burned circuit.

The whole picture: how one real pixel becomes a logit

The numbers are this example’s actual settings (BITS=3 / 400 pixels / WIDTHS=(2000,1000) / N_INPUTS=6) and measured values. Pixel #71 is a real pixel of the first training image (label 5), and the thresholds are the measured values of encoder.thresholds[:, 71].

How it actually works (for readers new to neural networks)

  • LUT (lookup table) = a table that writes down the answer for every combination of inputs. With 6 inputs there are 2^6 = 64 combinations, so writing a 0 or a 1 into 64 cells expresses “any logic function of 6 inputs”. What DWN learns is the contents of that table itself, not multiplicative weights.
  • Thermometer encoding = a way of writing “how large the value is” as “how many bits are set”. 0.714 → 1 1 0, a darker pixel → 1 1 1. Unlike one-hot it preserves order, so nearby values give nearby bit strings and the downstream LUTs can handle magnitude relations easily.
  • Where to put the thresholds (distributive) = place the thresholds at quantiles of the training data. Most MNIST pixels cluster near 0, so uniform spacing leaves almost all the bits dead.
  • Learning the wiring (LearnableMapping) = which LUT looks at which input line is normally fixed at random. DWN holds a matrix of “1,200 input wires × 12,000 selection slots” and picks one wire per column with argmax. Gradients flow into that matrix too, so the wiring is learned.
  • EFD (Extended Finite Difference) = a table lookup is a staircase and cannot be differentiated. So a finite difference using “the value of the neighbouring cell” is used in place of the gradient. This is the core idea of DWN.
  • GroupSum = split the final layer’s 1,000 bits into 10 classes × 100, count the 1s, and divide by the temperature τ. There is not a single learnable weight, which is why it is called “weightless”.
  • Structurally zero discretization gap = the forward pass is always hard, even during training (LUT outputs are {0,1}, connections are argmax). In other words, the accuracy you watch during training is exactly the accuracy of the burned circuit. The soft/hard divergence check of DLGN (06_mnist.py) is unnecessary.

Preparation: imports and the random seed

Section titled “Preparation: imports and the random seed”

All we use is PyTorch, matplotlib, and three things from this library: ThermometerEncoder / DWNLayer / DWNClassifier.

Let us pin down the terminology here. The weightless in DWN (Differentiable Weightless Neural Network) means that it holds not a single multiplicative weight matrix. What an ordinary NN learns is “weights”; what DWN learns is the contents of a LUT (lookup table — a table that writes down the answer for every combination of inputs) itself. Looking a value up in a table is not a multiplication, so this circuit burns to hardware as it is.

Hyperparameters

Section titled “Hyperparameters”

Let us define the symbols first; they keep this meaning from here on.

  • q — the real-valued intensity one pixel carries. On MNIST, a continuous value in [0, 1]
  • z = BITS — how many bits one pixel is encoded into. Here, 3
  • t_1 … t_z — the thresholds of the thermometer encoding. q is compared against them to make bits
  • n = N_INPUTS — the number of input wires one LUT looks at. Here, 6. There are 2^n = 64 combinations of inputs, so a LUT has 64 entries (cells of the table)
  • Address — the row number being looked up. It is the n input bits read directly as an n-digit binary number, so it falls in the range 0 … 2^n - 1

In other words, one LUT is an element that only “reads 6 bits as a 6-digit binary number (= an address) and looks up a 64-row table once”. What is learned is the contents of those 64 cells, not coefficients.

Data: passed through as real values

Section titled “Data: passed through as real values”

The DLGN in 06_mnist.py collapsed the input to 0/1 up front; here we do not. Binarization is the job of ThermometerEncoder in the next section, and doing it there requires looking at the distribution of the training data to decide the thresholds. Collapsing the values here would throw that distributional information away.

Thermometer encoding: dropping reals into “bit strings that preserve nearness”

Section titled “Thermometer encoding: dropping reals into “bit strings that preserve nearness””

Why an encoding is needed at all. A LUT is an element that lines bits up into an address, so it cannot be fed a real-valued pixel q directly. Binarization has to happen somewhere.

Why one-hot will not do. Naively raising one line per value interval — a one-hot code — makes nearby values, such as 0.31 and 0.33, land on completely distant bit strings. A LUT that only looks a table up has no notion of “this address is near that address”, so not a single clue about magnitude relations survives downstream.

Thermometer encoding solves exactly this. Ones are set from the bottom up, one for each threshold q exceeds — in other words only the number of ones increases, monotonically — so the relation “nearby values give nearby bit strings” is preserved. That is why the downstream LUTs can handle magnitude relations. As the name says, the code has the same shape as the mercury column of a thermometer creeping upwards.

Why the thresholds go at empirical quantiles (the values obtained by lining the real data up and cutting at a given percentile). mode='distributive' places t_1 … t_z at empirical quantiles of the training data. MNIST pixels are heavily skewed towards pure black (near 0), so placing the thresholds at uniform spacing such as 0.25 / 0.5 / 0.75 leaves every bit constantly 0 for most pixels, and no information is carried at all. Quantiles cut where the data actually spreads out, so every bit does work.

Figure 1: one image becomes a stack of bit planes

Section titled “Figure 1: one image becomes a stack of bit planes”

What to look at in this figure. The leftmost panel is the original grayscale image; the three on the right are the bits of T(q) = (1_{q>t_1}, …, 1_{q>t_z}) folded back into 20x20 (= bit planes). What matters is whether the black dots thin out as you move right. The threshold t_b rises as b advances, so if monotonicity holds, only the darker pixels should survive.

Reading it. The N on figure in the titles drops reliably as we go from bit 0 to bit 2. That is the monotonicity of the thermometer code itself: the set of pixels where bit b is 1 necessarily contains the set where bit b+1 is 1 (they nest). The right way to read the three pictures is not as “three separate features” but as strata of the same digit, sliced at thresholds of intensity. It also matters that the outline of the original image survives in every bit, which means the shape information is not lost by binarization.

DWNLayer: just a row of n-input LUTs

Section titled “DWNLayer: just a row of n-input LUTs”

From here on everything lives in the world of bits. Before dropping DWNLayer straight into a classifier, let us check on its own — with a tiny layer of only 8 LUTs — what the layer actually does.

EFD (Extended Finite Difference) deserves a mention here too. A table lookup is a staircase function where “the output jumps when the address changes by one”, so it cannot be differentiated as it is (the gradient is 0 everywhere). Instead of a derivative, DWN propagates as the gradient the difference against a neighbouring cell (the entry whose address differs by one bit). That is the finite difference, and it is the core idea of DWN.

Assembling the classifier: encoder → 2 LUT layers → GroupSum

Section titled “Assembling the classifier: encoder → 2 LUT layers → GroupSum”

The parts are ready, so we wire them in series. Let us define the remaining terms together here.

  • LearnableMapping (learned wiring) — which LUT looks at which input bit line is normally fixed at random. DWN holds a matrix of “1,200 input wires × 12,000 selection slots” and picks one wire per column with argmax. Gradients flow into that matrix too, so the wiring itself is learned
  • GroupSum / popcount (counting the number of ones) — the final layer’s 1,000 bits are split into 10 classes × 100, and the bits that are set in each group are simply counted. The count is divided by the temperature τ to become a logit. That there is not a single learnable weighted sum is precisely why this method is called weightless

Training: an ordinary PyTorch loop inside

Section titled “Training: an ordinary PyTorch loop inside”

No special learning rule is needed. We just drive cross_entropy down with Adam. There is one decisive difference from 01_xor.py and 06_mnist.py, though — there is nowhere to measure a soft accuracy. DWN’s forward pass is always a hard table lookup, even during training, so only one kind of accuracy exists to be measured in the first place.

Checking the discretization gap: why it is 0 for DWN

Section titled “Checking the discretization gap: why it is 0 for DWN”

The discretization gap is the difference between “the accuracy you were watching during training” and “the accuracy after burning the circuit”. To pair up the terms: soft eval is evaluation while still continuously relaxed (train() mode), and hard eval is evaluation after discretizing and fixing everything (eval() mode).

Why DLGN has a gap. During training, one gate of a DLGN (06_mnist.py) is a soft mixture of the 16 two-input logic functions, and it can take intermediate states such as “70% XOR, 30% AND”. Burning it fixes it to a single function with argmax, so the model that was trained and the circuit that gets burned are different things. That is why the divergence check was mandatory there.

Why DWN has a gap of 0. DWN’s forward pass is always a hard table lookup, even during training: a LUT output is always in {0,1}, and the wiring is always fixed to one wire by argmax. No intermediate state exists. Only the gradient is approximated, via EFD (a finite difference), so the model being trained and the circuit being burned are identical from the start.

Below we verify mechanically that the claim is true. We evaluate the same weights in both train() and eval() mode and assert that the maximum logit difference is exactly 0.0.

Section titled “Material for Figure 2: pulling “the fate of one pixel” out of the trained model”

From here we look at three figures. First we gather the material that replaces the abstract explanation with measured values. We track exactly one point, pixel #71, and read everything out of the trained model: its real value q, the three thresholds t_1…t_3, the thermometer bits, the 6 input wires the LearnableMapping actually selected, and the address read plus the value of that entry (every number in the figure is one of these measured values).

Figure 2: from one real pixel to a logit (the whole picture)

Section titled “Figure 2: from one real pixel to a logit (the whole picture)”

What to look at in this figure. Following the six panels in the order (1) → (6) connects the whole path from one real-valued pixel to one logit. (1) the tracked pixel q is boxed in red on the image → (2) it is compared against the three thresholds to become the bit string T(q) → (3) the whole image becomes a 1,200-bit vector → (4) the LearnableMapping picks 6 wires out of 1,200 and reads them as a 6-digit binary number, the address → (5) that address looks up the 64-entry table once → (6) through two LUT layers and popcount, a logit.

Note in particular the red arrow running from (4) to (5). It draws the one and only operation of DWN: “read the 6 selected bits as a single address and look the table up”. The green boxes are the region where only bits flow (this part burns to hardware as it is); the orange boxes are the real-valued region, and only GroupSum and the logits are orange.

Reading it. Looking at the table in (5), the 64 cells separate clearly into deep green and deep purple. In other words, training does not leave the contents of the table muddied at intermediate values; it pushes each cell all the way to either the 0 side or the 1 side. The red-boxed cell is the answer for this image, and which part of the table is read is decided solely by the 6 bits selected in (4). As the footnote of (6) says, a total of 3,000 LUTs / 192,000 entries are what gets learned, everything flowing between the boxes is a bit in {0,1}, and the real numbers live only in the two rightmost boxes.

Figure 3: the learning curve (there is only one line to draw)

Section titled “Figure 3: the learning curve (there is only one line to draw)”

What to look at in this figure. The learning curve of 01_xor.py had two lines, soft and hard; here only one can be drawn, because DWN has no soft eval. This “there is only one line” is itself the visual consequence of a discretization gap of 0. What to watch is how quickly it rises and where it eventually plateaus.

Reading it. It shoots up to around 0.9 within the first few hundred steps and then converges gently towards about 0.95. The values shown here are the eval() values and, at the same time, the values of the model being trained itself (we confirmed a maximum difference of 0.0 above). That is, this curve is not a “provisional value that might drop once it is burned” — it shows the accuracy of the circuit itself from the very beginning. The accident of cheering at a high soft accuracy and then being betrayed by hard, as in DLGN, cannot happen in principle with this method.

Figure 4: the digits the circuit got wrong

Section titled “Figure 4: the digits the circuit got wrong”

What to look at in this figure, and what it tells us. We lay out the 10 images the circuit made of 3,000 LUTs dropped. Each title reads pred (prediction) / true (ground truth). What to check is whether it breaks in some strange, circuit-specific way; what actually lines up is mostly shapes a human would also find confusable, such as 4 and 9, 3 and 5, or 7 and 1. That its mistakes are continuous with human intuition is evidence that a circuit built out of nothing but bit strings and table lookups captures the shape of digits properly. Conversely, if unrelated digits were mixed in at random, that would be the point to suspect the encoding or the threshold settings.

Intro 1. Neural Networks and PyTorch Basics

The very first page for people who have never done machine learning. No DLGN appears here. Tensors → autograd → nn.Module → the training loop: the whole picture of PyTorch in one pass, on a 2-D toy classification problem (two interlocking crescents that no straight line can separate).

The subject is not accuracy but seeing with your own eyes what training actually does. Three figures — gradient descent walking down a 1-parameter loss, the decision boundary before and after training, and the real-valued weights that actually moved — confirm that a NN lives in the world of real numbers.

What a neural network is — PyTorch fundamentals from zero (intro course 1/3).

This page is the first one for people who have never done machine learning. Nothing about DLGNs (differentiable logic gate networks) shows up. All we do here is write and run an ordinary neural network (NN) in PyTorch and see for ourselves what training actually does.

We cover the following four things, which together are the whole picture of PyTorch.

  1. Tensors — the containers for the numbers a NN handles (spreadsheet cells gone multidimensional)
  2. Autograd — the machinery by which PyTorch works out “which way should I move this to get closer to the answer”
  3. nn.Module — the way to build a model by combining layers
  4. The training loop — predict → error → correct, repeated hundreds of times, in a five-line pattern

The subject is classifying 2-D toy data (two interlocking crescents; no straight line separates them), and we look side by side at how the decision boundary bends and at how the real-valued weights changed behind the scenes while it did.

Run: uv run python examples/24_nn_basics.py Expected result: test accuracy of 0.95 or more (a small 2-layer MLP, a few seconds on CPU)

In the next page, examples/25_pytorch_mlp.py, the same style of code moves on to handwritten digits (MNIST), and after that examples/26_mlp_to_dlgn.py replaces the same problem with logic gates.

Setup: the tools used on this page

Section titled “Setup: the tools used on this page”

All we use is PyTorch (torch) and matplotlib for the figures. The DLGN library never appears on this page — first we go once around an ordinary neural network.

  • torch … the core, providing tensors (multidimensional arrays of numbers) and autograd
  • torch.nn … layers (nn.Linear and friends) and the way to assemble a model
  • torch.nn.functional (F) … stateless functions such as loss functions

Training results depend on randomness. Both the initial weights (the starting point for the numbers a layer holds) and the noise in the data are drawn at random, so without fixing the seed the numbers change on every run and you can no longer tell “did it change because I edited the code, or because of the random numbers?”

Tensors: the containers for the numbers a NN handles

Section titled “Tensors: the containers for the numbers a NN handles”

A tensor is a multidimensional array of numbers, and every NN computation happens on top of one. 0-D = scalar, 1-D = vector, 2-D = matrix, and so on as the dimensions grow.

Here we place by hand an input x of “3 samples x 2 features”, a weight w mapping “2 features → 1 output”, and a bias b that shifts the output, then check what one NN layer does in the single line x @ w + b (a matrix product plus an addition). That is all a layer really is.

Build tensors, multiply, and add

Section titled “Build tensors, multiply, and add”

@ is the matrix product operator. The answer on the first row is 1.0×0.5+2.0×(−1.0)+0.1=−1.41.0 \times 0.5 + 2.0 \times (-1.0) + 0.1 = -1.41.0×0.5+2.0×(−1.0)+0.1=−1.4, which matches the hand computation. Multiply and add is all there is inside a layer, and training is nothing more than “changing the values of this w and b into good ones”.

Autograd: let the machine work out which way to move

Section titled “Autograd: let the machine work out which way to move”

Searching for a good w by hand is impossible, so we let the machine compute “which way would make this better”. That information is the gradient: a single number saying “how much does the loss increase if I increase this parameter a little”.

As the smallest possible example we use a loss with just one parameter ppp, loss=(p−3)2\mathrm{loss} = (p-3)^2loss=(p−3)2. It is a plain quadratic, minimized at p=3p=3p=3. A tensor marked requires_grad=True remembers the history of the computation, and calling loss.backward() puts the gradient into p.grad.

Compute a single gradient

Section titled “Compute a single gradient”

Differentiating by hand gives ddp(p−3)2=2(p−3)=2(0−3)=−6\frac{d}{dp}(p-3)^2 = 2(p-3) = 2(0-3) = -6dpd​(p−3)2=2(p−3)=2(0−3)=−6. The value autograd returns matches it — confirmation that PyTorch is not magic, just the chain rule applied mechanically.

Gradient descent: step a little in the direction opposite the gradient

Section titled “Gradient descent: step a little in the direction opposite the gradient”

Once you know the gradient, all that is left is to move a little in the opposite direction. That is gradient descent, with the update rule p←p−η⋅dlossdpp \leftarrow p - \eta \cdot \frac{d\mathrm{loss}}{dp}p←p−η⋅dpdloss​. η\etaη (lr in the code) is the learning rate, the size of one step: too large and you jump over the valley and diverge, too small and you never arrive.

We move in the opposite direction because the gradient points “the way that increases the loss”. Since we want to decrease the loss, the sign has to be flipped.

Figure 1: gradient descent walking down the valley

Section titled “Figure 1: gradient descent walking down the valley”

The grey curve is the loss (p−3)2(p-3)^2(p−3)2 and the orange dots are the position of ppp at each step. Watch the twelve steps’ worth of dots being drawn into the bottom of the valley (the green dashed line p=3p=3p=3).

What to read from it: the dots get closer together as they approach the bottom of the valley. That is because the gradient 2(p−3)2(p-3)2(p−3) shrinks as it nears the bottom, so the stride η⋅2(p−3)\eta \cdot 2(p-3)η⋅2(p−3) automatically shrinks too. “Big steps at first, careful ones once you are close” is behaviour nobody wrote explicitly; gradient descent produces it on its own. Training a NN just has tens of thousands to hundreds of millions of these dots — what happens is the same as this figure all the way through.

Dataset: two classes that no straight line can separate

Section titled “Dataset: two classes that no straight line can separate”

We prepare one classification problem. two moons (two interlocking crescents) is toy data deliberately shaped so that no single straight line can ever separate it, the standard way to test “can the model build a curved boundary”.

If the problem were linearly separable there would be no need to stack layers. We pick this shape precisely so that the reason for stacking layers is visible.

Split into training data and test data

Section titled “Split into training data and test data”

Of the 600 points, 400 go to training and the remaining 200 to test. The test set consists of problems never used in training, set aside to measure whether the model learned the rule rather than memorizing by rote. Accuracy measured on the training data alone can be pushed arbitrarily high by memorization, so it is not a useful metric.

Model definition: stack layers with nn.Module

Section titled “Model definition: stack layers with nn.Module”

nn.Sequential is the way of assembling “pass through the layers from top to bottom”. Here we stack three nn.Linear layers (multiply and add) alternating with nn.ReLU (zero out negatives).

Why insert ReLU — no matter how many nn.Linear layers you stack, composing them collapses into a single nn.Linear (the composition of linear maps is a linear map). In other words the boundary would stay a straight line. Inserting a single nonlinear function in between stops that collapse and makes it possible to build a curved boundary stitched together from line segments. ReLU max⁡(0,z)\max(0, z)max(0,z) is the cheapest way to do it.

The two outputs of the final nn.Linear(16, 2) are logits, the raw score for each class; the larger one becomes the predicted class.

The training loop: predict → error → correct

Section titled “The training loop: predict → error → correct”

This is the heart of training, and yet there are only four lines to write. What is more, this pattern does not change whatever the model is — in intro 3, where the insides are replaced by logic gates, this loop needs no rewriting at all.

  • F.cross_entropy … the classic loss for classification. It gets smaller the higher the score of the correct class is compared to the others, and lowering it is the goal of training
  • opt.step() … updates every parameter according to its gradient. Here we use not plain gradient descent but Adam (an improved version that adjusts the stride automatically for each parameter). It reduces the work of tuning learning rates by hand, so in practice it is the first choice

Evaluation and visualization: how did the boundary bend?

Section titled “Evaluation and visualization: how did the boundary bend?”

What to read from it: in the log above the loss falls monotonically and the test accuracy climbs from 0.5 (= random guessing) to over 0.95. “Training progressed” means exactly that these two numbers moved this way.

Numbers alone, though, do not tell you what kind of boundary was drawn. So we apply the model over the whole plane and paint the prediction at each position as a color. The next function returns the grid for that.

Figure 2: training makes the decision boundary “bend”

Section titled “Figure 2: training makes the decision boundary “bend””

The background color is “which class the model would answer if a point were at that position”: redder is class 1, bluer is class 0. The solid black line is the decision boundary (where the prediction switches). Left is before training, right is after. The scattered dots are the original data itself.

What to read from it: before training (left) the boundary is close to a straight line left to chance, cutting the crescents clean in half. After training (right) it bends so as to thread between the two crescents. What creates that bend is the kink of ReLU, and what decides where to kink are the learned weights. Intro 3 redraws this same figure in its logic gate version.

Figure 3: the training curve, and the “weights” that moved

Section titled “Figure 3: the training curve, and the “weights” that moved”

On the left is how training progresses (orange = loss, green = test accuracy). On the right is a heatmap of the 2×162 \times 162×16 weight matrix of the first layer, stacked before and after training, with red for positive and blue for negative values. It is the figure that confirms the change of the boundary above is nothing but the result of these 32 numbers moving.

What to read from it (stated in advance): on the left the loss falls monotonically and the accuracy climbs in steps before topping out above 0.95. On the right, the top two rows (before training) are an almost uniform pale color, while the bottom two rows (after training) separate clearly into deep red and deep blue — meaning each neuron has begun to take on a role such as “responds more the larger x0x_0x0​ is / is suppressed when x1x_1x1​ is large”. And what moved are real numbers with awkward values, not expressible as 0/1. From the next page on, these real-valued weights are replaced wholesale by the truth tables of logic gates.

Activity Recognition (UCI-HAR, Phone Accelerometer)

Guess “walking, sitting, climbing stairs” from a phone’s accelerometer. The raw signal of a smartphone worn at the waist (9 channels x 128 samples = 2.56 s) is thermometer-encoded with 4 thresholds into 4,608 bits and fed to a logic circuit of 9,000 gates. It is the smallest example of a logic-gate network receiving a sensor time series instead of an image.

Measured hard accuracy is 0.885 (2,947 test windows from 9 people who never appear in training). The second half goes through the same exit as Deploy: the trained circuit is exported to C99, every test window is inferred by C alone, and the result matches PyTorch’s hard eval exactly in integers; then the delivery size (about 140 KB) and the runtime memory (6 KB) are counted. The inference time per window was about 6.7 microseconds on the author’s machine (Apple M1 Max, 1 core, cc -O2) (a value that changes with the machine, so it is not put in the page’s output but written to latency.json).

The steps for putting this circuit on an ESP32 or an iPhone continue in Run on ESP32 and Run on iPhone.

What you’ll learn

  1. How to turn a real-valued sensor signal into 0/1 input lines with thermometer encoding (thresholds are quantiles of the training data)
  2. The flow of classifying the activity of unseen subjects with a logic circuit that takes 9ch x 128 steps x 4 thresholds = 4,608 bits
  3. How to carry the same circuit to C99 and make it match PyTorch hard eval in integers on every test window

Prerequisites

  • 4. Deploy — the same procedure as the second half
  • 1. Train on MNIST — the basics of LutLayer + GroupSum

▶ Open in Colab (enabled once the repository is public)

Guessing the activity from a phone’s accelerometer — an example that trains UCI-HAR with logic gates and carries it to C.

From the accelerometer and gyroscope of a smartphone worn at the waist (9 channels x 128 samples = a 2.56-second window), we guess one of 6 activities: walking, climbing stairs, descending stairs, sitting, standing, lying down. This page shows how a logic-gate network receives a sensor time series rather than an image.

A logic gate accepts only 0/1, so the real-valued signal is thermometer-encoded at the entrance. The value of each channel is compared with 4 thresholds (the 20/40/60/80th percentiles of the training data) and replaced by 4 bits saying whether each was exceeded. 9ch x 128 steps x 4 thresholds = 4,608 bits become the input lines of the circuit as they are.

The second half goes through the same exit as Deploy. The trained circuit is exported to IR -> a distribution bundle -> C99 source and built with cc, all 2,947 test windows are inferred by C alone, and we check that the result matches PyTorch’s hard eval exactly in integers.

Orange is the real-valued sensor signal, blue is the 0/1 bit string and the class scores, and green is the logic circuit.

Run: uv run python examples/27_har.py Expected: hard accuracy 0.80 or more / C inference and PyTorch match exactly on 2,947 windows x 6 classes (the first run downloads the UCI zip (about 60 MB) into data-uci-har/. A C compiler cc is required)

Setup: imports, random seed, output directory

Section titled “Setup: imports, random seed, output directory”

The training side uses two new parts, load_uci_har (reading the raw signals) and thermometer_encode (thermometer encoding); the rest is the same LutLayer + GroupSum as MNIST. The exit side uses the same griffith_logic.deploy parts as Deploy.

Output directory and hyperparameters

Section titled “Output directory and hyperparameters”

Artifacts go to out_examples/har/ (the name har.bundle.json is fixed). The circuit stacks DEPTH LutLayers and aggregates into 6 classes at the end. The input is as wide as 4,608 bits, so the first layer gets more gates than for MNIST (400 bits). It is sized to finish within 3 minutes on CPU.

Dataset: raw accelerometer and gyroscope signals

Section titled “Dataset: raw accelerometer and gyroscope signals”

load_uci_har returns the raw Inertial Signals as float32 (N, 9, 128) (it downloads only the first time and caches into data-uci-har/har_raw.npz). The 9 channels are x/y/z of the body acceleration (body_acc, the motion with gravity removed), the gyroscope (body_gyro), and the total acceleration (total_acc, gravity included). Labels are activity numbers 0-5.

What matters is that the data is split by subject: no window of the same person appears in both training and test (a setting that measures whether unseen people can be recognized too).

Data source: Jorge Reyes-Ortiz, Davide Anguita, Alessandro Ghio, Luca Oneto, Xavier Parra, “Human Activity Recognition Using Smartphones”, UCI Machine Learning Repository, 2013 (doi:10.24432/C54S4K). It is licensed under CC BY 4.0. The data is not bundled with the repository; it is fetched from UCI.

Thermometer encoding: turn a real-valued signal into 4,608 bits

Section titled “Thermometer encoding: turn a real-valued signal into 4,608 bits”

The thresholds are decided from the training data only, per channel, at the 20/40/60/80th percentiles (fit_thermometer_thresholds). Using the test distribution would make the evaluation optimistic, so the test side gets the same thresholds. Because the cuts are quantiles, every bit is 1 for about 80/60/40/20% of the training data, so the information is used without bias.

thermometer_encode turns (N, 9, 128) into 0/1 values of shape (N, 9, 128, 4). Lined up with reshape, they become the input lines of the circuit (in the order channel -> time step -> threshold): 4,608 lines.

Checking that it really is a thermometer

Section titled “Checking that it really is a thermometer”

The thresholds are ascending, so if “a high threshold is exceeded” at some point, “the lower thresholds are also exceeded”. We check this monotonicity (patterns like 0001 never appear) over all the data.

Model and training: an ordinary PyTorch loop

Section titled “Model and training: an ordinary PyTorch loop”

The model is DEPTH LutLayers and GroupSum(k=6), the same shape as for MNIST. GroupSum splits the last layer’s gates into 6 groups and counts the ones in each group to make the 6 class scores. The training loop is ordinary PyTorch with cross_entropy + Adam, and every 500 steps it measures soft (the training-time face) and hard (the discretized circuit) accuracy side by side.

IR and bundle: wrap the trained model into one file

Section titled “IR and bundle: wrap the trained model into one file”

The procedure is the same as Deploy. export_ir fixes the circuit into the IR, and build_bundle / save_bundle wrap the IR and the class names into har.bundle.json. The input is a 0/1 string of 4,608 bits (the thermometer-encoded result); producing this encoding (the thresholds) is Python’s job. The threshold table is also written out to har_thresholds.json.

The delivery size (compressed) is measured with gzip. gzip.compress writes the current time into its header by default, so we pin it with mtime=0. export_ir also puts the time of export (created_at) into the IR metadata, so we overwrite it with a fixed time as well, so that the same training result always gives the same bytes and the same byte count.

C code generation and build

Section titled “C code generation and build”

We read the bundle back, create model.c / model.h with generate_c, and pass them to cc together with the runtime. The driver is a small main that only “reads a file of bit strings, runs mdl_infer, and measures the time of the whole loop”.

Infer every test window in C and compare with PyTorch in integers

Section titled “Infer every test window in C and compare with PyTorch in integers”

We write the 4,608 bits of all test windows (2,947 of them) to a file and feed it to the C executable. The 6 integer class scores that come back are compared among PyTorch hard eval, the IR reference implementation simulate and C, and we pin down with assert that not a single element differs.

Delivery size and speed: how many microseconds to judge a 2.56-second window

Section titled “Delivery size and speed: how many microseconds to judge a 2.56-second window”

One sensor window is a 2.56-second recording, so the time available for judging is 2.56 seconds. We count how fast C inference is against that, and how many bytes you have to ship. The speed (us/window) changes with the machine and from run to run, so it is not burned into this page’s output (it is measured above and written to out_examples/har/latency.json). On the author’s machine (Apple M1 Max, 1 core, cc -O2) the measured value is about 6.7 us/window, which is about 1/380,000 (roughly 1e-6 times) of the 2.56 seconds available for judging. The byte counts are the same every time for the same circuit.

Visualization: waveforms with thermometer bits, and the confusion matrix

Section titled “Visualization: waveforms with thermometer bits, and the confusion matrix”

The first figure is the 9-channel waveform of one window (the first test window). The dashed lines are the 4 thresholds decided from the training data, and which lines the waveform exceeds becomes the input bits directly.

Figure 1: waveforms of the 9 channels and the thresholds

Section titled “Figure 1: waveforms of the 9 channels and the thresholds”

Rows are the body acceleration (top), the gyroscope (middle) and the total acceleration (bottom); columns are x/y/z. This window is “standing” (STANDING), and the motion channels only wobble a little. The threshold lines cut the value range into 5 bands.

Reading: how many dashed lines the waveform crosses decides the code at each time step (0000 / 0001 / … / 1111). Because the thresholds are quantiles, the lines are spaced widely for channels that move a lot, while for quiet channels the values cluster tightly in a small range — even with the same “4 bits”, the scale is fitted to the size of the signal.

Figure 2: confusion matrix and per-activity accuracy

Section titled “Figure 2: confusion matrix and per-activity accuracy”

A table relating C’s predictions to the true labels. Rows are the truth, columns are the prediction, and the numbers are window counts. It matches PyTorch exactly, so this is also the confusion matrix of PyTorch hard eval.

Reading: the mistakes concentrate within two groups, “sitting <-> standing” and “walking / climbing stairs / descending stairs”, and there is almost no confusion across groups. With a phone at the waist, both sitting and standing keep the body almost still and differ only slightly in the direction of gravity, whereas “lying down” changes the direction of gravity a lot and so every window is correct. In other words, the circuit’s errors are biased toward activities that really are confusable from the sensor’s point of view.

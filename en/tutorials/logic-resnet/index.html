Residual connections in logic NNs can build the identity *exactly*

Residual connections in logic NNs can build the identity map exactly. Combining an OR residual with pass-through initialization gives max⁡∣y−x∣=0.0\max|y - x| = 0.0max∣y−x∣=0.0 ── not an approximation but a bit-exact match, so the input comes straight through. What a real-valued ResNet only approximates at initialization holds here strictly.

There is a cost, though. OR can never lower a bit once it is set, so it saturates. With the same seed, hard acc comes out as XOR residual 0.361 > OR residual 0.299, and the learning curves show the trade-off between exactness of the identity and ease of learning.

What you’ll learn

  1. That an OR residual + pass-through initialization builds the identity map exactly (max⁡∣y−x∣=0\max|y-x| = 0max∣y−x∣=0)
  2. Its cost — OR can never lower a bit once it is set, so it saturates: the trade-off
  3. How to read the learning curves of OR vs XOR residuals run with the same seed

Prerequisites

  • 1. Train on MNIST
  • The math of LutLayer — the background on why residuals work

An example of solving MNIST with LogicResNet (a residual logic ConvNet).

Deep networks can be trained because the “skip connection” of a ResNet hands you “do nothing (the identity map)” for free as the initial state. In a real-valued NN you write this as x + f(x), and initializing the weights of f to 0 gives the identity.

A logic gate NN has no weight that corresponds to “0”. A gate is a truth table, not a coefficient, so you cannot initialize it to “have zero effect”. So what do we do?

At this point f(x) is contained in x (wherever x is 0, f(x) is necessarily 0 as well). OR obeys the absorption law

so the merge hands x straight back. The case where the bias takes full effect and f(x) = x is just a special case of that, covered by the idempotence of OR, x OR x = x (with the default parameterization=‘softmax’, at eval each gate picks “leaf 0 AND NOT leaf 1”, so f(x) is a proper subset of x. Figure 2 shows this on real data).

Not “almost the identity” up to floating-point error, but a bit-exact match. That is what makes logic NNs interesting here, and the first half of this sample (figures 1 and 2) checks it for real.

Architecture diagram 1: inside a residual block (merging with OR)

Section titled “Architecture diagram 1: inside a residual block (merging with OR)”

A single residual block is nothing more than “two convolutions → merge with the original input via OR”. The dashed line in the figure below is the skip connection ── the shortcut wiring that carries the input x to the merge point untouched, and it is what makes “do nothing” available as the initial state.

Architecture diagram 2: the whole LogicResNet (where do the bits end?)

Section titled “Architecture diagram 2: the whole LogicResNet (where do the bits end?)”

In the green stages both inputs and outputs are bits (0 or 1); the orange stages are real numbers (the integer you get by counting ones, and the logit you get by dividing it). The signal stays as bits all the way to the head, and only at SpatialGroupSum does it step into the real-valued world of “counting how many ones there are” — that is the shape of this model. The numbers are those of the shrunk recipe used in this sample (stem 32ch / stage_blocks=(1,1) / encode_bits=2).

How this is achieved (the essentials, for readers new to neural networks)

  • A bit = a signal that is only ever 0 or 1. Where an ordinary NN runs real numbers along its wires, this model treats them as 0/1 lines. That is why it can compute with AND / OR / XOR instead of multiplications and additions.
  • LutConv2d = a bundle of small truth tables (LUTs) slid across the image. It picks a few bits out of a 3x3 window and looks up one table saying “for this input, this output”. The contents of the table are what gets learned: instead of real-valued weights it holds “which table to use” as a continuous value, and at eval (inference) time argmax fixes it to a single one ── that is the “burned circuit”.
  • Residual (skip) connection = shortcut wiring that passes the input straight through. Even in a deep network “just pass it along” is always available, so learning does not break as you stack stages.
  • Pass-through initialization = putting the gates near “just pass it through” at the start of training. A real-valued NN passes things through by setting weights to 0, but a truth table has no “weight of 0”. Instead we bias toward the gate that “passes leaf 0 (the first input)”, so that f(x) stays inside x.
  • The absorption law = OR-ing something “smaller than the original” leaves the original unchanged. If f(x) ⊆ x then x OR f(x) = x. The case where f(x) matches x exactly is the special case covered by idempotence (feeding the same thing in twice changes nothing, x OR x = x).
  • ThermometerEncoder = an encoding that turns intensity into a scale. It rewrites a real-valued pixel as a row of 0/1 saying “how many thresholds it exceeded”, carrying everything downstream into the world of logic.
  • GroupSum = the decoding that counts ones at the end. It counts how many of the output bits assigned to each class are on and divides by tau to get a logit. This is the only place real numbers appear.

This exactness is not free, though. OR is monotone (x OR f(x) ≧ x), so the more layers you stack the more ones appear, it saturates, and gradients thin out. The other option, ‘xor’ (a XOR b = a+b-2ab), does not saturate, but pass-through initialization does not give you the identity (the condition for the identity becomes f(x)=0).

In the second half we run these two on MNIST under identical conditions and compare the learning curves (figure 3). The main goal of this sample is to observe exactness of the identity, so for an accuracy-oriented recipe see experiments/train_logic_resnet.py (20000 steps).

Run: uv run python examples/14_logic_resnet.py Expected result: identity max|y-x| = 0.0, hard accuracy XOR around 0.35 > OR around 0.28 (a shrunk recipe that takes 2-3 minutes on a CPU)

Preparation: imports and the random seed

Section titled “Preparation: imports and the random seed”

There are only three pieces to use ── LogicResNet (the model itself), LogicResNetConfig (its configuration), and LogicResBlock (a single residual block; in the first half we pull just one of these out and inspect it). The rest is the machinery for loading MNIST and plotting.

Let us fix the notation used on this page up front.

  • x … the input bits to the residual block (a signal that is only ever 0 or 1)
  • h … the output bits of the first LutConv2d inside the block
  • f(x) … the output bits after passing through the residual branch (two LutConv2d)
  • y … the output bits of the residual block. y = merge(x, f(x))

First half: building an exact identity map with an OR residual

Section titled “First half: building an exact identity map with an OR residual”

For a while there is no training at all. We only look at what a block does at initialization.

In a real-valued ResNet the residual is merged by addition, y = x + f(x), and initializing the weights of f to 0 hands you y = x (the identity mapping = the map that returns the input unchanged) for free. But adding in the world of bits produces 1 + 1 = 2, and the value escapes {0,1}.

So LogicResNet merges with OR: y = x OR f(x) = 1-(1-x)(1-f(x)). OR is an “addition” that is closed on {0,1}, and wherever f(x)=0 it falls back to y=x. Combine that with pass-through initialization (= an initialization that biases the gates at the start of training toward “pass leaf 0 (the first input) through unchanged”; since a truth table has no “weight of 0”, this was provided as the stand-in for zero-initialization in a real-valued NN) and you get f(x) ⊆ x, so by the absorption law of OR y = x holds exactly (max|y-x| = 0).

Not “almost the identity” but a bit-exact match ── this section checks that for real.

Control experiment: turning pass-through initialization off

Section titled “Control experiment: turning pass-through initialization off”

To separate whether the identity held thanks to OR or thanks to pass-through initialization, we build a block with the same wiring and the same configuration but the initialization switched off and compare. OR can only ever push toward adding ones, whatever f(x) is, so the moment f(x) becomes unrelated to x the output drifts away from the input.

Figure 1: see the identity with your own eyes

Section titled “Figure 1: see the identity with your own eyes”

What to look at: the same input bits x, run through two residual blocks that differ only in their initialization, shown side by side. Left is the input x, middle is the output y with pass-through initialization, right is the output without it. All three are the 8x8 bits of channel 0, with black for 1 and white for 0. All you need to check is whether the middle matches the left without a single pixel off.

Reading it: the middle is exactly the same picture as the left. It is not “almost equal” up to floating-point error but max|y-x| = 0, i.e. bit-exactly the identity. The right has the same wiring and the same structure, yet black (1) has clearly increased ── OR can only push toward adding ones, so once f(x) is unrelated to x, ones that were not in the input get piled on top. What builds the identity is not OR on its own but the combination of OR and pass-through initialization.

Dissecting the inside of a residual block in a single figure

Section titled “Dissecting the inside of a residual block in a single figure”

Figure 1 only looked at the entrance and the exit. Next we follow the inside of the block ── the flow x → h → f(x) → (merged with the skip x via OR) → y ── on real data. To do that we first pull out the output h of the first LutConv2d and f(x) after the second.

The parts used to draw figure 2

Section titled “The parts used to draw figure 2”

What follows are the plotting helpers for figure 2 (panels, annotations, wiring); they have nothing to do with the model itself. Feel free to skip ahead to the explanation of figure 2. There is just one choice being made ── which of the 8 channels to show ── and it is picked automatically so that both the containment (f(x) ⊆ x) and its violation can be read off.

Along the right edge of figure 2 we add a vertical strip showing “where the output bits of this block flow next”. The stages that appear there mean the following.

  • OrPooling2d … downsampling that OR-s together each 2x2 window and halves the resolution. It is the counterpart of max pooling in a real-valued CNN, and each one you insert widens the input range a single output bit sees (its receptive field)
  • head LutConv2d 1x1 … the final logic layer, producing the output bits used for classification
  • SpatialGroupSum … the stage that counts how many ones are on in the group of channels assigned to each class. This is the boundary between logic (bits) and real numbers; from here on we are in the world of integers and logits
  • GroupSum(tau) … the decoding that divides the counted number by the temperature tau to get a logit

Figure 2: dissecting the residual block on real data

Section titled “Figure 2: dissecting the residual block on real data”

What to look at: the architecture diagram of the residual block with actual bits poured through it. From left to right: x → h (the output of the first LutConv2d) → f(x) (the output of the residual branch after the second) → OR (the merge point) → y, and the dashed line looping over the top is the skip connection (= the shortcut wiring that carries the input x to the merge point untouched). The top row is with pass-through initialization, the bottom row without.

The panel to watch is f(x): check whether the black (1) of f(x) in the top row stays inside the black of x (f(x) ⊆ x). If it does, the absorption law of OR sends y back to x. In the bottom row ones appear in positions x does not have, so OR only piles ones on.

Reading it: in the top row the black of f(x) only ever appears inside the black of x, so the y merged with OR is exactly the same picture as x ── the identity is preserved. In the bottom row f(x) puts ones in positions unrelated to x, and y ends up with more black than x.

Here the price of OR becomes clear. OR is a monotone operation that can never lower a bit once it is set (x OR f(x) ≧ x), so the more stages you stack the more ones appear and it saturates ── the output fills up with ones, stops moving when the input changes, and at that point gradients barely flow either.

The other option is the XOR residual (a XOR b = a + b - 2ab). Flipping either input of XOR necessarily flips the output (it is its own inverse, and destroys no information), so it does not saturate however deep you stack it and gradients do not vanish. In exchange it is not the identity unless f(x)=0, so the identity cannot be its initial state.

  • OR … the identity can be the initial state / saturates and learning slows
  • XOR … the identity cannot be the initial state / no saturation and learning is faster

The second half below shows how this trade-off actually plays out, as learning curves run under identical conditions.

Second half: comparing OR and XOR residuals on MNIST

Section titled “Second half: comparing OR and XOR residuals on MNIST”

The second half is ordinary image classification. We train two LogicResNets that differ only in residual_mode on MNIST shrunk to 20x20 and compare how their test accuracy grows. It is a reduced recipe that fits in 2-3 minutes on a CPU, so the absolute accuracy is low, but the gap between the two modes reproduces.

Hyperparameters

Section titled “Hyperparameters”

Three of these settings are specific to logic gate NNs, so they deserve a note.

  • encode_bits … the number of ticks on the ThermometerEncoder. It rewrites a real-valued pixel as a row of 0/1 saying “how many thresholds it exceeded”, carrying everything downstream into the world of logic
  • tree_depth / n_inputs … the depth of the LUT tree that produces one output bit (a bundle of small truth tables stacked in a tree, with input bits at the leaves and the output bit at the root) and the number of inputs each node takes
  • tau (temperature) … the constant that GroupSum divides the counted number by. Here the count for one class goes up to head_group_size(4) × 10x10 = 400, so leaving tau=1 makes the logits jump to the hundreds, saturating softmax and killing gradients. Dividing by the group size is the key

Results: XOR, which gave up the identity, wins

Section titled “Results: XOR, which gave up the identity, wins”

The output above reports two accuracies, soft and hard. soft is train() mode, where each gate is still the continuous mixture of its candidate logic functions (= the training-time form that gradients flow through). hard is eval() mode, where argmax fixes each gate to a single truth table ── the “burned circuit” form. hard is the one that counts; a high soft with a low hard is a sign that the circuit has not been pinned down yet.

The result is a win for XOR. OR is the one holding the strong initial state of an identity mapping, and yet the non-saturating XOR comes out ahead on final accuracy ── having gradients keep flowing throughout training matters more than starting from a good initial state. That is the conclusion of this sample.

Figure 3: learning curves of the OR and XOR residuals

Section titled “Figure 3: learning curves of the OR and XOR residuals”

What to look at: two learning curves run with the same seed and the same hyperparameters, changing only the merge operation. Orange is OR, blue is XOR; solid lines are hard (the burned circuit) and dashed lines are soft (the continuous mixture). The x axis is the training step and the y axis is test accuracy.

The thing to watch is how far the two solid lines spread apart. The OR / XOR trade-off (an identity initial state, or gradients that never saturate) shows up directly in the shape of the curves.

Reading it: the blue (XOR) solid line overtakes the orange (OR) early on and stays above it from there. OR does get to start from the identity, but ones accumulate every time the signal passes a layer until it saturates and the output stops reacting to changes in the input, so its growth stalls. XOR cannot start from the identity, but it destroys no information and so gets further on the same budget. It is also worth noting that soft (dashed) and hard (solid) do not diverge much ── discretization does not break it.

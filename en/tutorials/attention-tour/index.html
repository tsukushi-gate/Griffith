A tour of four logic-gate attention variants

A tour that runs and compares, in one go, four attention variants in which the dot product becomes XNOR similarity and softmax becomes argmax, on small tasks: associative recall, positional lookup, and sorting.

Boolean / MultiQuery / Positional all solve their task at hard accuracy 1.000 (6,144 params), and only Pointer, which solves a 4-element sort, stays at 0.835. Drawing the hard attention weight matrix shows every row is one-hot, and for Pointer a permutation matrix appears — you can see with your own eyes that “where to look” is learned as a discrete selection, not as a continuous weighted average.

What you’ll learn

  1. How attention is replaced: dot product → XNOR similarity, softmax → argmax
  2. What each of the four variants (Boolean / MultiQuery / Positional / Pointer) is good and bad at
  3. How to read the hard attention weight matrix — the one-hot rows, and the permutation matrix that appears for Pointer

Prerequisites

  • The ladder to logic — why the task is still solvable after throwing away softmax
  • Transformer (a logic-gate GPT)

Comparing four logic-gate attention variants on small associative-recall (key-value lookup) tasks.

Every example up to MNIST (examples/06_mnist.py) was a straightforward “input bit string → class” classifier. Here we step into attention mechanisms, where the circuit decides for itself where to look.

Attention in a logic-gate NN replaces the Transformer’s dot product + softmax as follows:

XNOR and popcount are both pure combinational circuits, so what you get after training is literally “a content-addressable memory (CAM) with no multipliers”. Continuous relaxation (softmax) is used only during training, and the moment you enter eval() it switches to argmax discrete selection — the same design philosophy as LutLayer’s soft/hard.

The four variants toured here (griffith_logic.models.attention):

  1. DLGNBooleanAttention Single-query associative recall. The minimal form of attention
  2. DLGNMultiQueryAttention Multiple queries applied in parallel to the same KV memory (a multi-head-like extension)
  3. DLGNPositionalAttention Keys are not inputs but “fixed position numbers”. Look up by position, not content
  4. DLGNPointerAttention Pointer-Network style. Autoregression plus a mask repeats “pull, then erase” and solves sorting (= repeated application of associative recall)

The four variants differ only in “how memory is looked up”; the training loop, the loss, and the data format can all stay the same. The theme of this page is the contrast: swap which piece, and what becomes solvable?

The three parts attention is made of (in beginner’s terms)

  • XNOR = an agreement detector. A single gate that outputs 1 when two wires carry the same value, 0 otherwise. Line up one per bit and you get a map of which bits agree
  • popcount = a majority count (an adder tree that counts the 1s). Counting the 1s in that map tells you “how many bits agree” = the similarity. Not a single multiplier is needed
  • MUX (multiplexer) = a selector. A traffic switch that routes exactly one input to the output, told by “which number to pass”. Instead of softmax’s weighted average, it passes the value of the winning slot as is

Figure 1 pushes concrete bit strings through these three parts: from the query 101101 and the agreement counts against the four keys (3/6, 6/6, 4/6, 4/6) all the way to the MUX picking out the value 1010.

Where the four variants differ

The only differences are “where the question comes from” and “what happens after the selection”; the middle — XNOR + popcount + MUX — is exactly the same in all four. Variants 1-3 use the same widths, so the circuits are the same size too (6,144 parameters each), and only Pointer grows, by its autoregressive cell and query producer (9,280 parameters).

The heart of the replacement: dot product + softmax becomes XNOR + popcount + MUX

Section titled “The heart of the replacement: dot product + softmax becomes XNOR + popcount + MUX”

A Transformer’s attention is softmax(q·k/√d)·V: it measures how close a query is to a memory with a real-valued dot product and blends the values with a softmax weighted average. That needs multipliers and an exponential, which is heavy for a circuit made only of logic gates. The logic-gate version replaces it with three parts.

  • XNOR (the negation of exclusive OR) = an agreement detector. One gate that returns 1 when two wires carry the same value and 0 otherwise. Laid out across the bit width, it becomes a map of “which bits agree”
  • popcount = an adder tree that counts how many bits are 1. Counting the ones in the agreement map gives “how many bits agree” = the similarity. Not a single multiplier is required
  • MUX (multiplexer) = a selector. A traffic switch that, given a “which one to pass” select line, lets exactly one input through to the output. Instead of a softmax weighted average, it passes the value of the winning slot as it is

Why the replacement works: the dot product of two binary vectors is the number of agreeing bits (the flip side of the Hamming distance), so the meaning of the similarity the dot product measured is not lost. The selection side follows the same idea: while training, a softmax (temperature tau_attn) blends all slots so gradients flow, and at eval() it switches to an argmax that takes only the highest-scoring slot (= hard attention). This is exactly the same design philosophy as LutLayer’s soft/hard.

Figure 1: following “attention = XNOR + popcount + MUX” with concrete bits

Section titled “Figure 1: following “attention = XNOR + popcount + MUX” with concrete bits”

What to look for: hand-written vectors from before training flow from left to right, and the figure follows the whole path from the query 101101 and the number of agreeing bits with the four keys (3/6, 6/6, 4/6, 4/6) to the MUX picking out the value 1010. Bit boxes are filled = 1 / empty = 0. Green marks the logic (the part that can be burned into a circuit as is) and orange the real-valued part (the training-time softmax only, which leaves nothing in the circuit).

What it says: only the one key that matches exactly reaches a popcount of 6/6, and every other key necessarily falls short. That is why a rule made of comparators alone — “pick the slot with the largest popcount” — settles the answer: no exponential and no division appear anywhere. This is the heart shared by all four variants below.

The shared training loop

Section titled “The shared training loop”

All four models can be trained with nothing but “forward, then cross entropy”. Switching attention between soft and hard is handled by model.train() / model.eval(), so the training code is literally identical across the four variants.

At every evaluation we measure both soft and hard. soft is the form you see during training (the softmax weighted average) and hard is the form after burning (argmax picks exactly one slot); the closer the two are, the more the attention has already committed to a single slot. That is what this pair of numbers is for.

Training the four variants in turn

Section titled “Training the four variants in turn”

From here we run the four variants from top to bottom. The only differences are where the question comes from and what happens after the selection; the XNOR + popcount + MUX in the middle is completely shared by all four.

1. BooleanAttention — the minimal form of attention (content-addressed). Only two things were replaced: the dot product became an XNOR popcount, and softmax became an argmax (at eval() time). The encoders that produce Q/K/V and the decoder that reads the selected V are ordinary LutStacks, so the Transformer skeleton is left intact. The task is associative recall (key-value lookup): given four (key, value) pairs and one query, answer with the value of the matching key. The query key matches one of the memory entries exactly, so the number of agreeing bits is maximal at the correct slot (= key_bits) and strictly smaller everywhere else. What training decides is not the similarity formula but the wiring by which the key/query encoders scatter bits into a code that makes agreement stand out.

Re-measuring Pointer by exact sequence match

Section titled “Re-measuring Pointer by exact sequence match”

Measuring sequence tasks by “every step correct” makes their difficulty easy to see: even at 0.85 element-wise, the probability that all four elements are right can fall close to that value raised to the fourth power. Training feeds the ground-truth pointers (teacher forcing) while evaluation feeds the model’s own output back in (free-running), and that mismatch also shows up most strongly in the exact-sequence number.

Figure 2: convergence curves of the four variants, overlaid

Section titled “Figure 2: convergence curves of the four variants, overlaid”

What to look for: solid = hard (argmax, the burned-circuit form), dashed = soft (softmax, the training-time form). All four are overlaid on one plot so you can compare when each takes off and, above all, how closely the solid and dashed lines coincide.

What it says: for 1–3 the solid and dashed lines almost coincide. Attention has already committed to a single slot, so replacing softmax with argmax does not change the output. Only 4 (Pointer) keeps the two lines apart and stalls — a sign that it is still stuck on an unconfident weighted average.

Figure 3: accuracy and parameter count side by side

Section titled “Figure 3: accuracy and parameter count side by side”

What to look for: the final hard accuracy on the left and the parameter count (a proxy for circuit size) on the right. It is a cost-effectiveness comparison: “did it solve the task” and “what did it pay for that”, lined up the same way.

What it says: 1–3 use the same widths, so their sizes match exactly and they still reach a perfect score. In other words the difficulty of these three tasks is set by how memory is looked up, not by circuit size. MultiQuery in particular handles two queries at the same size as Boolean — sharing the KV encoder is free, and the variant’s aim of “buying bandwidth without buying area” comes through directly. Only Pointer grows, by an autoregressive cell and a query producer, and even then its accuracy does not get there.

Figure 4: where attention actually points

Section titled “Figure 4: where attention actually points”

What to look for (this is the last figure, so here is how to read it in advance): attention in eval() mode is one-hot — exactly one cell per row is 1. The three panels on the left are “test samples (vertical) × memory slots (horizontal)”; the place to look up changes from sample to sample, so the pattern is scattered — that is the picture of looking things up correctly by content (1, 2) or by address (3). The rightmost panel is, for a single sample, “decode step (vertical) × input slot (horizontal)”, and the thing to check is that each row and each column lights at most one cell. That means the output is a permutation matrix (a 0/1 matrix representing a rearrangement): evidence that the cumulative mask forbids choosing the same slot twice, and confirmation that sorting really did reduce to repeated associative recall.

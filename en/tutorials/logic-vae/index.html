Folding an image into 96 bits — a binary-latent VAE

Throw away the VAE reparameterization trick (the multiplication and square root of a Gaussian latent). Replace the latent with a Bernoulli bit string — which is literally a comparator — and the whole VAE fits onto a logic circuit: a 196-pixel digit is folded into 96 bits and reconstructed.

recon BCE 43.27 / pixel agreement 0.907. The reconstruction is clearly readable as a digit. A difference map of how the image changes when one latent bit is flipped (red = turned on, blue = turned off) lets you peek at what each of the 96 bits is responsible for.

What you’ll learn

  1. How to throw away the reparameterization of a Gaussian latent and replace the latent with a Bernoulli bit string
  2. The structure of a binary-latent autoencoder that folds a 196-pixel digit into 96 bits and reconstructs it
  3. How to read “what each bit is responsible for” from a difference map made by flipping one latent bit

  • 1. Train on MNIST

LogicVAE — an example of building a binary-latent VAE out of logic gates alone.

The classifier in 06_mnist.py went one way: image → class. Here we step into the opposite direction, making an image from a circuit. We build a VAE (variational autoencoder) purely from LutLayer stacks, compressing an image into a 96-bit latent bit string and then reconstructing it.

Why a “binary latent” (the subject of this example): An ordinary VAE’s latent is a continuous Gaussian, and the reparameterization z = μ + σ·ε needs multiplication and a square root. For a logic circuit this is the worst possible partner; it simply does not map onto a circuit. LogicVAE avoids that wall by swapping the latent for a Bernoulli bit string. Bernoulli sampling is z = 1{q > u} for u ~ U(0,1) — that is, a stochastic threshold comparison = a comparator, which is a logic circuit in itself. Gradients reach the encoder via straight-through (forward = comparator / backward = the gradient of σ) (see _STBernoulli in griffith_logic/models/logic_vae.py).

Data flow (with the real class names)

Section titled “Data flow (with the real class names)”

Green is the logic circuit, where everything stays in bits, orange is where real numbers appear, and blue is the comparator that drops a real number back into a bit. Real numbers only ever appear as logits (the result of an addition), and the moment they pass the comparator they are bits again.

How it actually works (in four lines)

Section titled “How it actually works (in four lines)”
  1. The encoder. Pixels are turned into bits by a thermometer code (brightness written as a monotone string of 0/1) and pushed through a stack of LutLayers. At the end GroupSum counts “how many gates fired” and produces 96 real-valued logits.
  2. Reading a real number as a probability. q = σ(logit) is read directly as “the probability that this bit is 1”. Unlike a Gaussian latent there is no pair of mean and variance — a single probability is all a bit latent carries.
  3. Turning it into a bit with a comparator. Draw one uniform random number u and set z = 1 if q > u. This is both an exact sample from Bernoulli(q) and, literally, a threshold comparison = a comparator; at inference time a random source and one comparator are enough. Gradients flow via straight-through: the hard bit goes forward, and ∂q/∂logit = q(1−q) comes back.
  4. Decoder and loss. The 96 bits go through a LutLayer stack and GroupSum turns them into pixel logits. The loss is ELBO = recon + β·KL, where recon is the pixel BCE and KL is KL(Bern(q) ‖ Bern(0.5)) = q·log(q/0.5) + (1−q)·log((1−q)/0.5), a closed form that needs neither integration nor sampling.

Words you may be meeting for the first time:

  • latent — the compressed “inner representation” of an image; here, a string of 96 bits.
  • logit — a real-valued score meaning “the larger, the more it looks like a 1”; a sigmoid turns it into a probability.
  • straight-through (ST) — using the discretized value in the forward pass while sending the gradient of a smooth approximation backwards, so discrete sampling does not cut the gradient.
  • KL — how far apart two probability distributions are; here, how far a latent bit has drifted from a fair coin (Bern(0.5)).

Run: uv run python examples/18_logic_vae.py Expected result (measured with seed=0, about 80 seconds on CPU): recon BCE=43.3 / KL=13.2 / pixel agreement of the reconstruction=0.907 / active bits=1.00 (all 96 latent bits are doing work)

Setup: imports and the random seed

Section titled “Setup: imports and the random seed”

All we use is PyTorch and matplotlib, plus three things from this library: LogicVAE (the model itself), load_mnist (the data) and plot_circuit (drawing the circuit). No special VAE framework is required.

Let us line up the vocabulary first.

  • autoencoder — a model trained to squeeze an image into a small representation and then restore the original image from it. The “squeezing” half is called the encoder, the “restoring” half the decoder.
  • VAE (variational autoencoder) — an autoencoder with one extra constraint: the squeezed representation must stay close to a distribution decided in advance (the prior). Thanks to that constraint, once training is done you can make new images simply by drawing at random from the distribution.
  • latent — the squeezed representation itself. In this example it is a string of 96 zeros and ones.
  • prior — the distribution the latent is expected to follow. Here it is a Bernoulli(0.5) on every bit, a fair coin — in other words, “96 coin flips”.

Hyperparameters and data

Section titled “Hyperparameters and data”

A reduced recipe that fits in 2-3 minutes on CPU. The larger IMG / LATENT / STEPS are, the cleaner the reconstructions become — and the longer this page takes to build.

The one that matters most is LATENT = 96, which is the width of the circuit’s information channel. The picture drawn by 196 pixels must always pass through these 96 wires before it is restored. KL_WEIGHT is the β (the weight of the penalty that pulls the latent towards the prior) that appears later in the “Training” section.

Data: 14x14 binary MNIST

Section titled “Data: 14x14 binary MNIST”

We use the handwritten digits as binary images. The VAE reconstruction loss is a per-pixel BCE (explained below), so the target pixels must be strictly 0 or 1.

Keeping 28x28 would mean squeezing 784 pixels into 96 bits, and the shapes collapse within 3000 steps. We shrink to 14x14 = 196 pixels with 2x2 average pooling, binarize at threshold 0.3, and end up with the straightforward compression problem “196 pixels → 96 bits → 196 pixels”.

The model: encoder, comparator sampler, decoder

Section titled “The model: encoder, comparator sampler, decoder”

This page uses exactly three symbols — q / u / z. Let us define all of them here, once.

  • q — what the encoder emits: the probability that each latent bit is 1 (a real number between 0 and 1). The latent has 96 bits, so there are 96 values of q as well. It is a number you read as “for this image, bit number 3 is 1 with probability 0.8”.
  • u — the uniform random number drawn for the sampling (a number picked with equal probability from between 0 and 1). One is drawn for each bit, so there are 96 of them too.
  • z — the latent bit string actually sampled (96 zeros and ones). Making it takes a single line: z = 1 if u < q else 0. The larger q is, the more likely that bit becomes 1.

This single comparison u < q is by itself a sample from Bernoulli(q) (Bernoulli = a coin whose chance of heads is q). In other words, a circuit that carries a probability q is physically nothing more than “one random source and one comparator” — no multiplication and no exponentials are needed. The number line in Figure 5 below is exactly a picture of this comparison.

Why Bernoulli (a binary latent) instead of a Gaussian latent? An ordinary VAE’s latent is a real-valued vector, and its sampling uses reparameterization (the standard trick of feeding randomness in from outside to keep things differentiable), z = μ + σ·ε — a formula containing a multiplication and a square root. The moment you choose a real-valued latent, floating-point numbers take up residence in the middle of the circuit, and it can no longer be burned into hardware as it stands. Replace the latent with a bit string and everything from the encoder’s exit to the decoder’s entrance becomes exactly 96 wires, closing the circuit cleanly.

straight-through — an approximation that rounds to 0/1 in the forward pass (inference) but, in the backward pass (gradients) alone, pretends the rounding never happened. Discretization would otherwise make the gradient exactly zero and stop learning; this trick delivers the gradient to “the far side of the comparator”. It is the standard way of handling discrete sampling differentiably.

Let us also look at the names of the parts.

  • ThermometerEncoder — an encoding that converts brightness into a string of 0/1 like a thermometer bar. It turns 1 pixel into 4 bits, so 196 pixels become 784 bits.
  • GroupSum — the exit of the logic gates. It splits the output bits into k groups and counts how many ones are in each group, turning them into real numbers. This is the border between “the world of bits” and “the world of real numbers”.

The evaluation function: measuring it as a pure Boolean circuit

Section titled “The evaluation function: measuring it as a pure Boolean circuit”

Quality is always measured along the hard eval path. hard eval means fixing every LUT to a single truth table by argmax and using none of the continuous relaxation used for training — that is, running it as the same pure Boolean circuit you would burn onto an FPGA.

There are two numbers to watch. pix_acc is the pixel agreement when the reconstruction is thresholded at 0.5. active is the fraction of the 96 latent bits that are “not stuck at always-0 or always-1”; it is the watchdog for posterior collapse (the phenomenon where the latent stops being used and the decoder ignores its input, emitting only average-looking pictures). The closer to 1.0, the healthier.

Training: ELBO = recon + β·KL

Section titled “Training: ELBO = recon + β·KL”

The loss is the ELBO (evidence lower bound, the standard objective minimized in a VAE), and its body is nothing but the sum of two terms, recon + β·KL.

  • recon (the reconstruction term) — the penalty for how well the original image was restored. It is measured as the sum over pixels of the BCE (binary cross entropy = a loss measuring the mismatch of two binary values). The implementation uses BCEWithLogits, the numerically stable version with the sigmoid folded inside.
  • KL (the KL divergence) — how far apart two probability distributions are. Here it is the penalty for how far the latent distribution Bern(q) emitted by the encoder has moved away from the prior Bern(0.5) — put plainly, “the cost of packing information into the latent”. The further a bit strays from a fair coin, the more it costs.
  • β — the weight applied to that KL (KL_WEIGHT = 0.1 in this code). Making it larger pulls the latent towards the prior, discarding information and leaning towards generation. Making it smaller improves reconstruction, but the latent drifts away from the prior and generating from coin flips stops working.

The KL between two Bernoullis can be written as the closed form q·log(q/0.5) + (1−q)·log((1−q)/0.5), so neither integration nor sampling is needed. Just as with a Gaussian VAE, the KL term takes one line.

The thing to watch in the log above is that recon falls while KL rises. The rising KL is the sign that “the latent bits have been pushed away from a fair coin to pack information in”, and the reconstruction improves as the payoff. That tug-of-war between the two terms is training itself.

As long as active bits stays at 1.00, no posterior collapse has occurred and all 96 bits are doing work.

Visualization: reconstruction, bit flips, generation

Section titled “Visualization: reconstruction, bit flips, generation”

Figure 1: original / 96-bit latent / reconstruction

Section titled “Figure 1: original / 96-bit latent / reconstruction”

For eight digits we line up the original image on the top row, the latent bit string z in the middle (the 96 bits folded into 8x12 to form a band), and the reconstruction at the bottom.

The middle row is what to look at. The monochrome dots there are all the information the circuit carries around, and the pictures at the bottom are made from those 96 zeros and ones alone.

The reconstructions on the bottom row are readable as digits, but the strokes are thicker than the originals and the fine flicks are rounded off. We are dropping 196 pixels down to 96 bits, so the discarded information disappears as “detail”. Comparing the bands in the middle, even two copies of the same digit have different patterns — the latent encodes “this one picture”, not “the class”.

Figure 2: flipping the latent bits one at a time

Section titled “Figure 2: flipping the latent bits one at a time”

We pick one latent from the trained model and flip each of the first 8 bits in turn, decoding again each time. The top row is the image after the flip, the bottom row its difference from the original (red = pixels newly turned on / blue = pixels turned off).

Why can’t we “nudge the latent a little”? With a continuous-latent VAE you can shift the latent vector slightly to make an in-between picture, but with a binary latent the only operation allowed is a bit flip. This one-bit flip is what corresponds to interpolation in a continuous latent, and it makes the controls of generation completely discrete. Flipping one bit is, in the end, swapping the 0/1 of one input wire into the circuit.

Looking at the differences on the bottom row, each bit is clearly in charge of a different place. One bit repaints the upper half of the digit, another the sweep at the lower left. Every single one takes charge of some feature of the image, so the 96 bits are not merely a compression result but a representation whose parts carry meaning. It is also characteristic of a binary latent that moving one bit can make the picture jump a long way; the gradual change of a continuous latent is impossible here in principle.

Figure 3: generation from the prior, and the learning curves

Section titled “Figure 3: generation from the prior, and the learning curves”

The first figure is generation from the prior Bernoulli(0.5): the latent z is made by 96 coin flips and simply pushed through the decoder — new pictures unlike any of the training images. The second is the learning curve, with recon (orange) on the left axis and KL (green) on the right.

As for the generation, the 3000-step reduced recipe only gets as far as “the seed of a digit” starting to show; it does not become a clear digit. That is because the latent has not yet been pulled close enough to the prior — for a recipe aimed at generation quality, see the full-run script (experiments/train_logic_vae.py).

The learning curve, on the other hand, is unambiguous. KL rises while recon falls — we pay the penalty of pushing the latent bits away from a fair coin and buy reconstruction quality with it. This is exactly the tug-of-war that the β knob adjusts.

Figure 4: one real image passing through, end to end

Section titled “Figure 4: one real image passing through, end to end”

We draw one actual image passing through the model exactly as it happens. The top row is the encoder (image → bits → gate network → 96 probabilities q); the bottom row is the sampler and the decoder (q → comparator → latent bits z → gate network → restored image).

The small pictures inside the figure are not explanatory illustrations but the real values computed by this code. The numbers inside the boxes are the real gate counts (= the output neurons of each LutLayer).

The palette is the project-wide one: green = logic gates (staying in bits) / orange = where real numbers appear / blue = the comparator (dropping a real number into a bit) / grey = data. It lets you follow by colour how far the section that can be burned as a circuit extends.

The point of this figure is that there are only two orange boxes. Only where GroupSum counts “how many gates fired” is a real number involved; everything else flows on as bits. Real numbers appear only as logits (the result of an addition), and the instant they pass the blue comparator they are bits again (= the peripheral-FP policy: a design policy that banishes real numbers to the periphery of the circuit and keeps the centre closed in bits).

Compare the picture of q at the exit of the top row with the picture of z on the bottom row: the smooth shading of q turns, immediately after the comparator, into 96 black-and-white dots. This is the one place in this circuit where a real number becomes a bit.

Figure 5: the moment a continuous value becomes a bit

Section titled “Figure 5: the moment a continuous value becomes a bit”

We zoom in on the blue box of the previous figure — the inside of the comparator — on a number line.

On the left are the first 10 latent bits. The length of the green bar is q (the probability that the bit is 1) and the blue triangle is the position of the uniform random number u that was drawn; if u falls inside the bar then z = 1, otherwise z = 0. Why can one comparator produce a probability? Because this single comparison u < q is itself sampling from Bernoulli(q) (a random source + a comparator = a stochastic bit source).

On the right is a histogram of q over all 96 bits for the same single image. The closer a bit is to either end, 0 or 1, the more it is “decided regardless of the random number”; the closer to the middle, the more it fluctuates.

On the right-hand side of the number line, the bits whose q has swung all the way to 0 or 1 give the same answer wherever the random u lands. The further training proceeds the more such “decided bits” there are, but the KL term pushes back against them, so not every bit swings to an extreme — and that balance is what β decides.

Figure 6: the real circuit of the trained decoder

Section titled “Figure 6: the real circuit of the trained decoder”

Finally we draw the inside itself of what we have been calling “the decoder”.

On the left is the trained decoder. It has 2,592 gates, so plot_circuit automatically switches to the overview (layers = boxes, arrows = wire counts). On the right is a shrunken version built from the same classes and the same wiring rule (8 latent bits → 2x2 pixels, 44 gates), where one node = one LUT and every line is an actual wire.

Let us say in advance what to read from it. In the right-hand figure, the 8 inputs lined up on the left edge are the latent bits z, and the bundle of wires heading right from them is exactly what “the decoder = a logic circuit” looks like. This single picture shows that a VAE decoder exists as a mesh of gates and wires rather than a chain of matrix products. The shrunken version is untrained, so its nodes are still shown as LUT (a mixture of the 16 logic functions); as training proceeds each one of them resolves into a concrete logic function such as AND or XOR. The wire counts written on the arrows of the left-hand overview show, in numbers, the very subject of this example: from the encoder’s exit to here it stays closed at 96 wires.

Intro 2. Build an MLP in PyTorch

With the same toolkit as the previous page, we scale up to handwritten digits (MNIST 20x20). An MLP that is nothing but three stacked nn.Linear layers reaches test accuracy 0.95.

The highlight of this page is that “where the real-valued weights live” becomes a picture. The first-layer weights have the same 400 dimensions as the input, so laying them back out as 20x20 shows the shape that neuron is looking for directly. On the next page, these weights are replaced wholesale by the truth tables of logic gates.

About this page

Estimated time: about 8 minutes / Environment: CPU only (no GPU required) Source script: examples/25_pytorch_mlp.py Try it locally: notebooks/25_pytorch_mlp.ipynb (an unexecuted notebook with the same content as this page; open it with uv run --group docs jupyter lab notebooks/) Every code output below is the result of an actual run, embedded verbatim.

▶ Open in Colab (enabled once the repository is public)

Build a small MLP in PyTorch and read handwritten digits (introductory course 2/3).

The “tensors, autograd, nn.Module, training loop” you saw on the previous page are carried over as-is to real data. The subject is MNIST handwritten digits cropped to 20x20: the input is 400 numbers (pixel brightness) and the output is the 10 classes 0-9.

There are only three things to write, and all of them use the same tools as the previous page.

  • An MLP (multilayer perceptron) of three stacked nn.Linear layers
  • A loss from F.cross_entropy
  • The opt.zero_grad() → backward() → step() training loop

The theme of this page is not accuracy itself but grasping with your own eyes “where the real-valued weights live”. The first-layer weights have the same 400 dimensions as the input, so laying them back out as a 20x20 image turns “the shape that neuron is looking for” into a picture. On the next page, examples/26_mlp_to_dlgn.py, the weights seen here are replaced wholesale by the truth tables of logic gates.

Run: uv run python examples/25_pytorch_mlp.py Expected result: test accuracy around 0.95 (an MLP with 2 hidden layers, about 10 seconds on CPU)

Setup: imports and the random seed

Section titled “Setup: imports and the random seed”

The tools are exactly the same as in intro 1; the only addition is loading the data. load_mnist20x20 is the MNIST loader bundled with this library, and it returns images with the black border dropped from 28x28 down to 20x20 = 400 pixels.

We go down to 400 pixels to match the official recipe of the difflogic paper, and using the same input as the logic gate version on the next page keeps the comparison fair.

Hyperparameters (the numbers a human decides before training)

Section titled “Hyperparameters (the numbers a human decides before training)”

A hyperparameter is a setting that training does not move and a human fixes in advance (what training moves are the “parameters” = the weights). Here there are four of them — the width of the hidden layer, the number of iterations, the mini-batch size, and how many images to use — all pinned to values that fit in about 10 seconds on CPU.

Dataset: handwritten digits, MNIST 20x20

Section titled “Dataset: handwritten digits, MNIST 20x20”

One image consists of 20x20 pixels, and we stretch it into a single row and feed it to the model as a 400-dimensional vector. Each pixel value is a real number from 0 (white) to 1 (black).

Note that we pass binarize_threshold=None and keep the values real rather than binarizing them. A real-valued NN can eat real-valued input directly — and this is exactly the place where the logic gate version on the next page will have to “drop down to bits”.

Model definition: an MLP of three nn.Linear layers

Section titled “Model definition: an MLP of three nn.Linear layers”

An MLP (multilayer perceptron) is the most naive kind of NN: nothing but nn.Linear layers and activation functions stacked alternately. Here we stack three of them while narrowing the width, 400 → 128 → 64 → 10.

Why narrow the width — the earlier layers build features such as “lines and curves” out of “collections of pixels”, and the later ones judge “which digit that combination of features is”; writing that division of labour down plainly gives this shape. The final 10 outputs are the per-class logits (raw scores), and passing them through softmax turns them into “the probability of being that digit”.

Training: run it with mini-batches

Section titled “Training: run it with mini-batches”

The body of the loop is identical to intro 1, with a single difference — instead of using all the data every time, we draw only BATCH images at random and update from them, which is mini-batch training.

Why mini-batches — computing the gradient over all 20000 images makes one step far too heavy. A gradient computed from only part of the data is a noisy approximation of the true gradient, but it buys you many more steps, so for the same amount of compute time it gets further. The noise itself also helps escape local minima.

Evaluation: reading the training curve

Section titled “Evaluation: reading the training curve”

Figure 1: loss and test accuracy

Section titled “Figure 1: loss and test accuracy”

Orange is the loss on the training data (left axis), green is the test accuracy (right axis). Overlaying the two axes lets a single figure confirm “when the loss falls, does the accuracy really rise”.

What to read from it: in the first few hundred steps the loss plunges and the accuracy passes 0.9. After that it settles gently onto around 0.95. Notice that there is only one curve — in a real-valued NN “the model being trained” and “the model you use” are the same thing, so one kind of accuracy is enough to measure. In the DLGN on the next page this becomes two curves, soft and hard.

Looking at the learned “real-valued weights”

Section titled “Looking at the learned “real-valued weights””

The theme of this page. We look at what the NN learned directly, as a picture rather than as numbers.

Figure 2: lay the first-layer weights back out as 20x20

Section titled “Figure 2: lay the first-layer weights back out as 20x20”

The first-layer weights amount to 400 numbers per neuron, the same number of dimensions as the input image. So laying those 400 numbers back out as 20x20 gives a map of where in the image that neuron looks and responds. Red is a positive weight (a dark spot there strengthens the response), blue a negative one (a dark spot there suppresses it). We lay out twelve neurons.

What to read from it: in every neuron a pattern that looks like a “template” emerges, with red and blue speckled around the center of the image. What was learned is not the structure (what connects to what) but this shading of color = the real values, and those values are awkward decimals averaging 0.07 in absolute value (see the output just above). It is precisely this real number, which 0/1 cannot express, that requires a multiplication at every inference — that is, the very reason multipliers are needed.

Looking at the misclassifications

Section titled “Looking at the misclassifications”

Figure 3: the digits it got wrong

Section titled “Figure 3: the digits it got wrong”

Finally we lay out ten images the model got wrong. “How it fails” says more about a model’s character than the accuracy number does — if it fails on shapes a human would hesitate over too, the model is capturing shape.

What to read from it (stated in advance): what lines up are only pairs a human would waver over for a moment as well, such as 4 and 9, 7 and 1, or 3 and 5; unrelated errors such as reading a 0 as a 7 do not appear. It gets roughly 100 of 2000 images wrong — that is the level an “ordinary MLP with real-valued weights” reaches, and it becomes the baseline for comparison when we replace it with logic gates on the next page.

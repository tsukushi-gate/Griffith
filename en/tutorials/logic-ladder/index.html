The Ladder of Logifying the Transformer: How Far Can Attention Become a Circuit?

A ladder you climb one rung at a time to find out how far attention can be turned into a logic circuit. Starting from an ordinary floating-point Transformer (L0), we replace pieces in order: gating the projections (L1) -> XNOR-popcount scores (L2) -> a MUX selector (L3-C), and compare accuracy on a copy task along with the attention maps.

The conclusion is counterintuitive. The biggest drop comes from L1 (gating the projections); switching to XNOR and removing softmax are nearly free (L2 returns to 1.000, and L3-C still reaches 0.990). In the L3-C attention map exactly one cell lights up per row — in other words, the picture says attention was a learned MUX all along.

What you’ll learn

  1. The route from a floating-point Transformer (L0) to a MUX selector (L3-C), logifying one rung at a time
  2. At which rung accuracy drops — the one that bites hardest is gating the projections (L1)
  3. The view that an attention map going one-hot means attention is a learned MUX

Prerequisites

  • Transformer (Logic Gate GPT) — the finished form waiting at the top of the ladder
  • 2. Building a Hybrid NN — designs that stop partway up

The “ladder of logification” — an example that compares, stage by stage, how far attention can be made into a logic circuit.

examples/07_logic_gpt.py was a GPT that was “all logic gates from the very start”. Here we do the opposite: start from an ordinary floating-point Transformer (L0) and logify attention one rung at a time, measuring where performance drops. This is the ladder of LogicLadderGPT (D1).

By the time we reach L3-C, attention can be written with nothing but “logic gates + comparators + MUX”. That is, the exp and division of softmax disappear, and it can be burned into a circuit as is. This is the demonstration of the research claim “attention = a learned multiplexer (MUX)”; the full-scale results on sMNIST/Shakespeare are in experiments/attention_ladder/REPORT.md.

The three substitutions that turn attention into a circuit (with concrete values)

Attention is the operation “find the entry (K) closest to the question (Q) and pull out its content (V)”. A real-valued Transformer does this with multiplications and exponentials, but a logic circuit has no multipliers. So each stage is replaced, in beginner’s terms, by these parts.

  • XNOR = an agreement detector: a single gate that outputs 1 when two wires carry the same value. Line up one per bit
  • popcount = a majority count (adder tree): counting the 1s tells you “how many bits agree” = the similarity. The dot product of two binary vectors is the agreement count, so the meaning of similarity is not lost
  • MUX = a selector: a switch that routes exactly one input to the output, told by “which number to pass”

The ladder: what stays real-valued and what becomes a circuit at each rung

Orange = real-valued (needs multipliers and exp) / green = logic gates (can be burned into a circuit as is). This sample uses d_model=64, n_heads=2, n_layers=2, qk_bits=v_bits=64. From L1 on, the logic part is 896 gates (the total number of LutLayer outputs: projections 64×3 in 2 layers + FFN (128+128) in 2 layers), and the whole model has 68,422 parameters at L0 versus 5,578 at L3-C (3,584 of them in LutLayer). Throw away the multipliers and the size drops by an order of magnitude too.

The implementation is a single class, LadderAttention in griffith_logic/blocks/causal_attention.py: you move between rungs just by switching two strings, score (fp_dot / xnor_popcount) and norm (softmax / mux_gumbel). The projection is _LogicProjection (Binarize + LutLayer), and from L1 on the FFN is fixed to LogicMLP at every rung so that “one rung = one variable” holds.

The task is a “copy task”: a random sequence -> a separator symbol -> the same sequence, trained with next-token prediction. Copying requires attention that “looks K+1 steps back”, so the quality of attention shows up directly in accuracy (an FFN alone cannot solve it). The size is small enough to fit in 2-3 minutes on CPU.

Run: uv run python examples/12_logic_ladder_gpt.py Expected result: L0 = copy accuracy 1.00, L1 ≈ 0.7, L2 / L3-C recover to around 1.00

Setup: imports and the random seed

Section titled “Setup: imports and the random seed”

All four rungs are built from the single class LogicLadderGPT. The difference between rungs is expressed purely by a configuration dict — we never swap implementations. That is the device that keeps “one rung = one variable”.

Since this page compares rungs against each other, the initial conditions are shared across all of them. What is fixed here covers both data generation and weight initialization, and each rung re-draws the same seed again later.

Task: the copy task

Section titled “Task: the copy task”

A random sequence -> a separator symbol -> the same sequence, trained with next-token prediction. The last K tokens are correct simply by “copying the token K+1K+1K+1 steps back”, so the accuracy directly mirrors whether attention pulls the right position — the minimal induction task, which no amount of extra FFN width can solve.

Batch generation is three lines: the random sequence of length K, the separator SEP, then the same sequence again. Scoring covers only the second half of K tokens — the first half is random, so there is nothing to get right there in the first place.

The rungs of the ladder: what gets logified, one step at a time

Section titled “The rungs of the ladder: what gets logified, one step at a time”

The ladder has four rungs, and attention gets closer to a circuit the higher you climb.

  • L0 — an ordinary nn.MultiheadAttention + a real-valued FFN. Zero logification; the ceiling that everything else is measured against
  • L1 — only the q/k/v projections become LutLayers, with their outputs binarized to {0,1}\{0,1\}{0,1}. Scores are still real dot products and normalization is still softmax
  • L2 — scores move to XNOR-popcount. The multipliers disappear, replaced by a count of “how many bits matched” (XNOR = a gate that outputs 1 when two lines agree; popcount = an adder tree that counts the raised bits)
  • L3-C — the softmax weighted average becomes a MUX selector, passing exactly one key

Why can a MUX do the selecting? Boiled down, a softmax weighted average is a device that decides “how much of which slot’s contents to pass through”. If the weight is concentrated on a single line, that is the same job as a tree of 2:1 multiplexers (an element that passes one of two inputs according to a select line). L3-C imposes that limit structurally from the start, which is precisely why one can say “attention is a learned MUX”.

Only the attention side differs; the skeleton such as d_model is identical across rungs. Breaking that would make it impossible to tell whether a performance gap comes from logification or from capacity.

Training loop (shared by all four rungs)

Section titled “Training loop (shared by all four rungs)”

The same loop serves all four rungs. Not a single rung-specific branch is written; only the difference in the configuration dict changes the behavior. There are two devices worth noting.

  • Temperature annealing — the selector’s temperature is lowered 2.0 -> 0.5, shifting it gradually from “blend everything vaguely” to the hard “pick one”. Starting hard would leave no gradient and learning would never get going
  • Auxiliary loss — a term that sharpens the selection is added, scaled by AUX_LAMBDA. It is 0 on L0-L2, so the same expression works for every rung

Evaluation always runs under eval(), where the selector becomes a deterministic hard argmax — the shape of the baked circuit.

Running it: climbing all four rungs from the same initial conditions

Section titled “Running it: climbing all four rungs from the same initial conditions”

Train the four rungs in order and line up the copy accuracies at the end. What matters is not the absolute values but the steps between them: “at which rung does it drop” is exactly the answer to “where does the cost of logification live”.

Visualization: where it drops, and where it comes back

Section titled “Visualization: where it drops, and where it comes back”

Figure 1: learning curves of the ladder

Section titled “Figure 1: learning curves of the ladder”

What to look at: the learning curves of all four rungs overlaid on one plot. The vertical axis is copy accuracy (hard eval), and the dashed line is the 1/51/51/5 level of answering at random. What matters is not the end points themselves but which rung’s curve separates from the rest.

Reading it: the only rung that drops is L1 (gating the projections); L2 and L3-C above it pass almost for free. In other words the cost of logification lies neither in “how the score is computed” nor in “giving up softmax”, but concentrates on turning vectors into bits. The mechanism of attention itself gets along well with circuits — that is the conclusion of this ladder.

Figure 2: bar comparison of the final accuracies

Section titled “Figure 2: bar comparison of the final accuracies”

What to look at: just the end points of figure 1, turned into horizontal bars so the steps can be read as numbers. It exists to confirm, as a list of final values, the parts where the curves overlap and are hard to tell apart.

Reading it: the gap between L0 and L3-C is tiny, and only L1 dips one step down. This single picture says that a fully logified attention lines up with a floating-point one. Conversely, the dip at L1 shows that how to design the binarization of the projections is the real point of contention in this field.

Figure 3: the inside of attention

Section titled “Figure 3: the inside of attention”

What to look at: heatmaps of the attention weights of L0 (softmax) and L3-C (MUX selector) on the same input. The vertical axis is the query position, the horizontal axis the key position, and brighter means larger weight. The correct answer for the copy task is “look K+1K+1K+1 steps back”, so a diagonal line offset by K+1K+1K+1 from the main diagonal means the position is being pulled correctly.

Reading it: a diagonal shows up in both, but the quality differs. Around L0’s line the weights blur, whereas in L3-C exactly one cell lights up and the rest is pitch black. That is because this is a selection, not a weighted average — the freedom to blur simply does not exist. One picture shows the same task being solved by averaging on one side and by selecting on the other.

Figure 4: reading the same single row across the four rungs (the actual weight values)

Section titled “Figure 4: reading the same single row across the four rungs (the actual weight values)”

How to read it, and what it says (the last figure on this page). We take just the row of the last query position out of the heatmaps of figure 3 and stack the four rungs as bar charts. For each rung the sharpest row among all layers and heads is plotted, so “can this rung point at the copy source?” can be judged from a single row. The red dashed line marks the correct copy source.

The thing to read is the contrast across the four rungs. L0 pins 1.00 on the correct position. L1 cannot build a peak and spreads out (the true face of the rung where accuracy drops shows up right here). L2 returns to 1.00 even with XNOR scores. And L3-C, being a MUX, is structurally always a single bar — the 1.00 of L0 and L2 is “a softmax that happened to get sharp”, whereas in L3-C the selection itself is discrete. The final picture in which the claim “attention is a learned MUX” can be read off the weight values themselves.

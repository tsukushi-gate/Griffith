Appendix: XOR Internals

An appendix that peeks at the mechanism of the collapse from soft (continuous relaxation) to hard (a discrete circuit) in the smallest possible setting. With only 2 input bits and 16 gates, the circuit before and after training can be drawn node by node, so the claim “training is the work of picking one gate out of sixteen candidates, one gate at a time” turns straight into a picture. This is the round where what happened in MNIST is shrunk to 4 samples and a few dozen lines.

What you’ll learn

  1. See the whole moment of dropping from soft (continuous relaxation) to hard (a discrete circuit), in a minimal 16-gate setting
  2. The view that training is “picking one logic function per gate out of the 16 candidates”
  3. How to read the circuit diagram (the mixture before training with resolve=False / the fixed gates after training with resolve=True)

Prerequisites

  • Core Concepts — just get the soft/hard vocabulary down first

About this page

Estimated time: about 5 minutes / Environment: CPU only (no GPU required) Source script: examples/01_xor.py Try it locally: notebooks/01_xor.ipynb (an unexecuted notebook with the same content as this page; open it with uv run --group docs jupyter lab notebooks/) Every code output below is the result of an actual run, embedded verbatim.

▶ Open in Colab (enabled once the repository is public)

The smallest example of learning XOR.

Train XOR in soft mode with a differentiable logic gate layer (LutLayer) and confirm that it stays at 100% as a discrete circuit (hard eval) too.

This script lets you experience the library’s central claim — “a logic gate network trained by gradients under continuous relaxation loses no accuracy when it is discretized with argmax into a pure Boolean circuit” — in a minimal setting of 4 patterns and 40 lines. XOR is the smallest problem that a single linear separation cannot solve, which makes it a touchstone for “did it really learn a nonlinear logic?”.

The whole circuit (32 gates, 2 inputs, 2 output classes)

Only bits flow through the green stretch, so it can be burned onto FPGA LUTs as is. Reals appear only at the very end, where the wires are counted and compared. The wiring and gate types that were actually learned can be inspected in the second circuit diagram on this page (before vs. after training).

How it is done

  • One neuron = one truth table. An ordinary NN neuron is “weighted sum → activation”; a LutLayer neuron is replaced by a table that looks at 2 wires and returns 0 or 1
  • Only the contents of the table are learned. Which 2 wires of the previous layer a neuron looks at (the wiring) is chosen randomly at the start and then frozen. What moves is only “is this table an AND or an XOR?”
  • The table is held as a blend of 16 candidates. There are only 16 possible 2-input logic functions, so learning “a weighting over those 16” (= 16 parameters per gate) makes it differentiable. At inference the heaviest one is fixed — that is the soft → hard discretization
  • Depth is what builds expressive power. The second layer reads the 16 bits of the first, so more complex logic is assembled as a composition of gates. XOR has 2 inputs, so a single table would suffice; here we use the same 2-layer structure as MNIST (example 06) at its smallest possible size

Run: uv run python examples/01_xor.py Expected result: accuracy 1.00 in both soft and hard

Setup: imports and the random seed

Section titled “Setup: imports and the random seed”

All you need is PyTorch, matplotlib, and four things from this library: LutLayer, GroupSum, the dataset, and the circuit plotter. No special training framework is required.

The idiomatic way to load the library is import griffith_logic as gl, and public symbols are referenced as gl.LutLayer (writing from griffith_logic import LutLayer gives you the same object).

Dataset: the 4 patterns of XOR

Section titled “Dataset: the 4 patterns of XOR”

XOR takes 2 input bits, so the possible inputs are (0,0) / (0,1) / (1,0) / (1,1) — that is all of them. There is therefore no need to split train and test data: what we want to see is not “did it memorize” but did it land on the correct truth table as a circuit.

Model definition: two LutLayers + GroupSum

Section titled “Model definition: two LutLayers + GroupSum”

LutLayer is a layer where “one output neuron = one N-input LUT (lookup table = truth table)”, sitting where nn.Linear + activation would be in an ordinary NN. GroupSum is the exit from the world of logic gates to classification scores: it counts the bits of the final layer per class.

The three lines below are the entire circuit this page deals with (32 gates in total).

Preparing to train: how to measure soft/hard, and gate decisiveness

Section titled “Preparing to train: how to measure soft/hard, and gate decisiveness”

In this library accuracy is always measured in two ways.

  • soft = train() mode. Each gate is still a “probabilistic mixture” of the 16 logic functions (= continuous relaxation). Gradients flow, but it is not a circuit yet
  • hard = eval() mode. Each gate is fixed to a single logic function with argmax. From here on it is not a training-time approximation but the same pure Boolean circuit you would burn onto an FPGA

Being happy about soft alone is the most common failure in this field, so build the habit of measuring both from the start.

Training loop

Section titled “Training loop”

The body is entirely ordinary PyTorch. No special learning rule is needed (that is an advantage of this method). To draw the learning curves, record the loss and both soft/hard accuracies at every step. hard is re-measured by switching to eval() each time, so you can see step by step when it reached the correct answer as a circuit (typically it rises later than soft). There are only 4 patterns of data, so measuring every step barely increases the runtime.

Evaluation: always look at both soft and hard

Section titled “Evaluation: always look at both soft and hard”

Once training is done, put the two numbers side by side. The essential point is that hard is 1.00; if only soft is high and hard drops, it is a sign that the mixture is camped out in an intermediate state, i.e. “not decided as a circuit”.

Visualization: learning curves, circuit diagram, gate decisiveness

Section titled “Visualization: learning curves, circuit diagram, gate decisiveness”

Figure 1: learning curves (loss and soft/hard accuracy)

Section titled “Figure 1: learning curves (loss and soft/hard accuracy)”

Left is the loss (all 500 steps), right is the two kinds of accuracy. Accuracy only moves in the first few dozen steps, so the right panel zooms into the beginning (both stay flat at 1.00 afterwards).

The highlight is on the right: hard (solid, dark green) chases soft (dashed, gray) and in the end both overlap at 1.0. That is exactly the central claim of this library — “train under continuous relaxation → discretize with argmax and nothing breaks”.

On the right, hard jumps in steps because the output only changes at the moment the argmax result switches: it is not a continuous quantity moving smoothly, the circuit itself is rewritten discretely. The vertical dotted line is the step from which hard stays at 1.00 “forever after”; just before it the curve touches 1.00 once and falls again — that is merely passing by the correct circuit.

Figure 2: circuit diagram (the same code becomes this circuit)

Section titled “Figure 2: circuit diagram (the same code becomes this circuit)”

The three-line nn.Sequential written above is in fact “gate nodes and the wires connecting them”, i.e. the circuit itself. Put the before/after side by side to see in one picture what training did.

  • left (resolve=False) — before training. Each node is a mixture of 16 logic functions, hence shown as LUT. The color intensity is the degree of certainty (distribution entropy); the paler it is, the more undecided
  • right (resolve=True) — after training. The name of the logic function fixed by argmax (AND / XOR / NAND / !A / A>=B …) goes into the node

The truth tables the names come from are the very ones export_ir uses when emitting Verilog, so the gates in this figure = the gates of the circuit actually burned.

Comparing left and right, before training every node is a pale LUT, while after training concrete logic-function names such as XOR and NAND line up. The claim that training is “picking one gate at a time out of 16 candidates” is drawn literally as a picture.

Figure 3: seeing “did it pick one out of 16?” as numbers

Section titled “Figure 3: seeing “did it pick one out of 16?” as numbers”

Quantify the color intensity (certainty) of Figure 2 as a histogram over all 32 gates. The x axis is the max probability of each gate’s logic-function distribution, the y axis is how many gates fall there.

  • before training (gray) — a hill on the left. Initialization is random, so it is slightly more biased than perfectly uniform (the dashed 1/16 = 0.0625), but every gate is still an ambiguous mixture that is “nothing in particular”
  • after training (green) — the whole distribution moves right and many gates exceed 0.9, meaning each gate can now assert “I am XOR” / “I am AND”

If this is not pushed to the right edge yet hard acc is 1.00, it was merely luck, and a slight perturbation can turn the circuit into something else. Conversely, if it is at the right edge, discretization by argmax “throws almost nothing away”, so hard eval does not break.

2. Build a Hybrid NN

Replace only the MLP part of an existing Transformer block with LUT-based logic gates (an LL-ViT style hybrid). Attention and LayerNorm stay as PyTorch real-valued layers, and the logic side and the real-valued side are trained together with separate learning rates.

What you’ll learn

  1. How to wire up a replacement of only the MLP part of a Transformer block with LUTs (LL-ViT style)
  2. Why attention and LayerNorm stay real-valued, and why the logic side and the real-valued side get separate learning rates
  3. Where the design decision “do not turn everything into logic gates” pays off

Prerequisites

  • 1. Train on MNIST — see the all-logic-gate case first
  • Migrating from PyTorch — the layer correspondence table

About this page

Estimated time: about 5 minutes / Environment: CPU only (no GPU required) Source script: examples/02_hybrid_llvit.py Try it locally: notebooks/02_hybrid_llvit.ipynb (an unexecuted notebook with the same content as this page; open it with uv run --group docs jupyter lab notebooks/) Every code output below is the result of an actual run, embedded verbatim.

▶ Open in Colab (enabled once the repository is public)

An example of a hybrid NN (LL-ViT style).

It replaces “only the MLP part” of an existing Transformer block with LUT-based logic gates. Attention and LayerNorm remain PyTorch real-valued layers.

Turning an entire Transformer into logic gates is hard, but if you push just the MLP, which holds most of the parameters, into a logic circuit, you can peel most of the inference cost off the GPU. This script confirms that “you can do partial replacement by dropping one line into an existing model”, and that gradients still flow and the loss still decreases afterwards.

This page checks four things: where the model turns into logic gates and where it stays real-valued, how the parameter budget moves, why splitting the learning rate between the logic side and the real-valued side helps, and what collection of 2-input logic gates the replaced MLP finally becomes.

What stays real-valued, and what becomes a LUT

Orange = real-valued (the parts that need floating-point multiplies, LayerNorm, softmax), green = logic gates (LutLayer: a truth table, so it can be burned into HDL). Binarize (ToLogic) and GroupSum (FromLogic) are the border between the two worlds, where real numbers and bits cross over.

Only the mlp of each block is replaced: 512 gates per block (LutLayer 32→256 and 256→256), 1,024 gates across the two blocks. Real-valued parameters drop from 17,088 to 8,706 (about half), and in exchange 16,384 logic parameters appear (= 1,024 gates × the logits over the 16 two-input logic functions). Because attention is left real-valued, this configuration is the partial logification known as the “LL-ViT type” — the road that makes attention logical as well is covered in The Ladder of Logification.

Run: uv run python examples/02_hybrid_llvit.py Expected result: 2 replacements, loss decreases

Setup: imports and the replacement API

Section titled “Setup: imports and the replacement API”

Four things are used from this library. They are the toolkit for doing partial replacement without rewriting your existing model.

  • replace_mlp_with_lut … walks the model recursively and swaps only the parts it can judge to be an MLP for a LUT block
  • LogicSpec … the specification of the shape of the logic circuit after replacement (inputs per gate, depth, width)
  • split_param_groups … automatically sorts parameters into the logic side (logic) and the real-valued side (ann)
  • LutLayer / gate_labels … the layer inserted by the replacement, and how to get its gate names

Preparing the “existing model” to be replaced

Section titled “Preparing the “existing model” to be replaced”

Write the starting point of the replacement — a perfectly ordinary Pre-LN Transformer block — in plain PyTorch. Nothing here comes from this library; that is deliberate, to show that you can bring an existing model of your own as it is.

The structure is LayerNorm → MultiheadAttention → residual → LayerNorm → MLP → residual. Of these, the target of the replacement is only self.mlp (Linear-GELU-Linear), and since about 2/3 of a Transformer’s parameters live in this MLP, turning just this into logic peels off most of the real-valued parameters.

Partial replacement: swapping only the MLP for LUTs

Section titled “Partial replacement: swapping only the MLP for LUTs”

The replacement takes a single function call. LogicSpec decides the shape of the circuit that replaces it.

  • n_inputs=2 … 2 inputs per gate (the difflogic-compatible 16 logic functions)
  • depth=2 … stack 2 LUT layers; nonlinearity comes from composing gates
  • neurons_per_output=8 … assign 8 gates per output dimension — the expressiveness/cost knob

The returned replaced holds the names of the replaced modules, so you can verify in code that only the intended places were replaced (which prevents the accident of everything being silently swapped).

Checking which layers the replacement inserted

Section titled “Checking which layers the replacement inserted”

The input/output width of each inserted LutLayer is literally the number of gates, and that is the unit of hardware cost. The output shows two layers per block, 32→256 and 256→256 = 512 gates, so 1,024 gates across the two blocks.

The training task: confirming only that gradients get through

Section titled “The training task: confirming only that gradients get through”

Why a regression onto random targets — what this page wants to confirm is not accuracy but a single point: whether one backward() still runs all the way through even when it crosses heterogeneous layers, “real-valued → logic → real-valued”. Real data would mix the difficulty of the task into the result, so the task is nothing but memorizing noise, leaving only the effect of the replacement itself in view.

Why the learning rates are split (measuring the gradient scale)

Section titled “Why the learning rates are split (measuring the gradient scale)”

This is the first place a hybrid trips you up. Gradient magnitudes differ by orders of magnitude between the logic side and the real-valued side.

Logic gate parameters are “logits over the 16 logic functions”; they act on the output only after passing through a softmax, so their gradients tend to be small. Real-valued weights in attention or LayerNorm, by contrast, act on the output directly. Run both at the same learning rate and the logic side alone barely moves from beginning to end.

Rather than leave this adjustment as craft lore, put a number on it: run one backward pass from the initial state and measure the mean ∣grad∣|\mathrm{grad}|∣grad∣.

Training: with and without split learning rates

Section titled “Training: with and without split learning rates”

As the measurement above shows, the real-valued side’s gradients are an order of magnitude larger, so split_param_groups splits the parameters into two groups and raises the learning rate on the logic side only (the rule of thumb is logic_lr ≈ 0.01–0.05, ann_lr ≈ 1e-3). There is no need to enumerate module names by hand.

For comparison, the same run is repeated from the same initial values with “a uniform lr=1e-3 for every parameter”, to put side by side what happens if you keep training with the pre-replacement setup.

Optimizer: separate learning rates for the LUT side and the real-valued side

Visualization: what was replaced and what remained

Section titled “Visualization: what was replaced and what remained”

Reading it: in the output above you can see numerically that the loss falls better when the learning rates are split. The uniform lr does lower the loss as well — because the real-valued side alone balances the books — and “it looks like it is working when it is not” is what makes this failure mode so nasty.

Figure 1: what stayed real-valued and what became logic gates

Section titled “Figure 1: what stayed real-valued and what became logic gates”

The left panel is the structure of the Transformer block. Orange = real-valued, green = logic gates, yellow = the border between the two (ToLogic / FromLogic, where real numbers and bits cross over). The right panel is a stacked bar chart of the parameter breakdown before and after replacement.

Reading it: following the left panel from top to bottom, the only green (logic) parts are the two LutLayers in the middle; attention, LayerNorm and the residuals all stay orange. This is the partial logification called the “LL-ViT type”. On the right, real-valued parameters fall from 17,088 to 8,706 — about half — and in exchange 16,384 logic parameters (= 1,024 gates × 16 logic functions) ride on top. The logic-side count goes up, but these are not numbers used in multiplications; they are a choice of truth table, so they leave no multipliers behind once the circuit is burned.

Figure 2: gradients flow all the way through even in a hybrid

Section titled “Figure 2: gradients flow all the way through even in a hybrid”

Two learning curves are overlaid. Green is with split learning rates, the dashed gray is the uniform lr. Same initial values, same data — the only difference is how the learning rate is given. First of all, “the loss decreasing at all” is the evidence that gradients cross the heterogeneous layers.

Reading it: both curves slope down, so training works even with the LUT block in the middle. The green one falls faster and deeper, though — the gray (uniform lr) is sluggish because the logic side barely moves.

Figure 3: why the learning rates need to be split

Section titled “Figure 3: why the learning rates need to be split”

The mean ∣grad∣|\mathrm{grad}|∣grad∣ measured in the previous section, as a bar chart on a logarithmic axis. Note that the vertical axis is logarithmic — the difference is not “a little” but an order of magnitude.

Reading it: the real-valued side (orange) has gradients an order of magnitude larger than the logic side (green). “Splitting the lr” is not a hunch but a mechanical operation for closing this gap.

Figure 4: what logic circuit did the MLP become in the end?

Section titled “Figure 4: what logic circuit did the MLP become in the end?”

Finally, look at what collection of gates the replaced MLP became. The left panel shows how many times each of the 16 two-input logic functions was chosen; the right shows the distribution of each gate’s confidence (the maximum probability after softmax; the closer to 1.0, the more firmly it can say “I am an XOR”).

Reading it (written up front, since this is the last figure): the target here is random, so the distribution of gate types stays comparatively flat instead of skewing toward particular functions (on a meaningful task it skews toward AND / XOR and the like). The closer the confidence on the right sits to 1.0, the smaller the gap between soft and hard, and the less discretization breaks things — if it were clustered around 0.5, the verdict would be that training is progressing but the result cannot be dropped into hardware.

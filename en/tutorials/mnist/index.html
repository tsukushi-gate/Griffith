1. Train on MNIST

A plain pile of logic gates learns to read handwritten digits. 4000 AND / OR / XOR gates that hold no real-valued weights and perform no multiplication decide their truth tables by gradient descent alone — and end up getting 86% of MNIST right. This page runs that for real so you can check it yourself.

The toolkit is just two LutLayers + GroupSum + an ordinary PyTorch training loop. Three figures — an overview of the circuit, the training curves (soft/hard), and misclassified examples — show what a “learned circuit” actually looks like.

What you’ll learn

  1. That simply running two LutLayers + GroupSum in an ordinary PyTorch training loop makes 4000 logic gates able to read handwritten digits
  2. Why you must always look at soft (continuous relaxation) and hard (discrete circuit) accuracy side by side, and how to tell them apart
  3. What a learned circuit looks like — how to read the overview, the training curves, and the misclassified examples

Prerequisites

  • Core Concepts — the five concepts soft/hard, LutLayer, GroupSum, IR, HDL
  • Intro 3. Replacing an MLP with a DLGN — start here if neural networks are new to you

About this page

Estimated time: about 10 minutes / Environment: CPU only (no GPU required) Source script: examples/06_mnist.py Try it locally: notebooks/06_mnist.ipynb (an unexecuted notebook with the same content as this page; open it with uv run --group docs jupyter lab notebooks/) Every code output below is the result of an actual run, embedded verbatim.

▶ Open in Colab (enabled once the repository is public)

An example of training MNIST (20x20) with a differentiable logic gate network.

XOR (examples/01_xor.py) was a toy problem with four patterns. Here the same toolkit (LutLayer + GroupSum + an ordinary PyTorch training loop) is scaled up to real data with 400 input bits and 10 classes, until a circuit of 4000 gates reads handwritten digits.

The official difflogic recipe (6 layers x 8000 gates, 200k iters) reaches the paper-level 97.7%, but it takes hours on a GPU. This example is shrunk to “2 layers x 2000 gates, 20000 training images, 4000 iters” so it finishes in 1-2 minutes on CPU, and the hard accuracy it reaches is around 0.86 (for an accuracy-oriented recipe, see DLGN_FULL=1 in tests/l3_paper/test_dlgn_mnist.py).

The single most important concept on this page is the two faces, soft and hard.

  • soft (the training-time face) … each gate is a continuous mixture of the 16 logic functions. It is differentiable so it can be trained, but in this state it cannot be burned onto hardware
  • hard (the face as a circuit) … a genuine logic circuit with the mixture fixed to one function by argmax. Inference is nothing but bit operations, but it cannot be differentiated

Training proceeds in soft, while what you actually use is hard. You therefore have to keep checking that the gap between the two accuracies (the discretization gap) is small. The figures below are the tools for doing exactly that.

The whole circuit (exactly the same shape as XOR, only the numbers grow)

There is no convolution and no matrix product — note that the whole thing is 4,000 two-input gates, and that reals only appear from GroupSum onwards.

How it is done

  • One pixel = one input wire. The 20×20 image is fed into the circuit directly as 400 bit lines (the border of the 28×28 original is dropped as a black frame, as in the official difflogic recipe)
  • Each gate looks at only 2 wires of the previous layer. Instead of a dense connection, the 2 inputs of every gate are drawn at random and frozen (sparse wiring). That is why 2,000 gates still cost only 2000×16 = 32,000 parameters
  • Classification is just counting. GroupSum splits the 2,000 outputs into 10 groups of 200 and counts how many 1s stand in each group; the class with the most is the answer. τ=10 is the temperature that count is divided by, which flattens the softmax and stabilizes training
  • The two faces, soft and hard. During training (soft) each gate is a mixture of the 16 logic functions; at inference (hard) argmax fixes one, giving a genuine circuit. Measuring the gap between the two (the discretization gap) is the theme of this example

Run: uv run python examples/06_mnist.py Expected result: hard accuracy around 0.86 (the assert is loosely set at 0.70)

Setup: imports and the random seed

Section titled “Setup: imports and the random seed”

All you need is the usual PyTorch set plus three things from this library.

  • LutLayer … the layer where one neuron = one LUT (lookup table, i.e. a truth table)
  • GroupSum … the exit from the world of logic to class scores (it counts bits per class)
  • plot_circuit … draws the trained model as a circuit diagram

No dedicated training framework appears. The training loop below is plain PyTorch.

Hyperparameters

Section titled “Hyperparameters”

K is the most important knob. K is the number of gates per layer, and it translates directly into “the number of gates once burned onto an FPGA” — that is, silicon area. In a real-valued NN width trades accuracy against compute time, but in a logic gate network width is the implementation cost, so balancing accuracy against K is the center of tuning.

Dataset: reading an image as 400 input wires

Section titled “Dataset: reading an image as 400 input wires”

We use MNIST cropped from 28x28 to 20x20 by dropping the black border — 400 pixels, the same preprocessing as the official difflogic recipe. Those 400 pixels become 400 input wires of the circuit directly: one pixel = one wire.

binarize_threshold=None keeps the values continuous in [0,1][0,1][0,1] on load. Training on continuous values and binarizing only for evaluation with round() is the practice of the official recipe.

Dropping the evaluation inputs to bits

Section titled “Dropping the evaluation inputs to bits”

Why binarize only for evaluation — hard eval is a measurement that imitates “the circuit actually burned onto an FPGA”. What enters the input pins of a circuit is only the High/Low of a wire, so feeding it a real number like 0.37 would overstate the real-world performance.

Model definition: two LutLayers + GroupSum

Section titled “Model definition: two LutLayers + GroupSum”

The three lines below are the entire circuit this page deals with (4,000 gates in total).

  • LutLayer(400, K, n_inputs=2) … lines up K gates that each look at only 2 of the 400 input wires. Which 2 (the wiring) is drawn randomly at initialization and fixed; what training moves is only “the truth table for those 2 inputs”
  • The second LutLayer(K, K) … complex logic such as XOR is built by this composition of gates
  • GroupSum(k=10, tau=10.0) … splits the final 2000 bits into 10 classes x 200 wires and counts how many ones are standing in each group. tau is the temperature the count is divided by; larger values make the softmax gentler and stabilize training

Why 2 inputs instead of a full connection — there are only 16 two-input logic functions in total, so learning “a weighting over those 16” is differentiable (16 parameters per gate). A fully connected gate would make the truth table explode exponentially and kill that trick.

Training: an ordinary PyTorch loop measuring both soft and hard

Section titled “Training: an ordinary PyTorch loop measuring both soft and hard”

The training itself is completely ordinary PyTorch (cross_entropy + Adam); nowhere do you have to be aware that this is a logic gate network. That is the practical advantage of the method.

The one convention is the use of model.train() / model.eval(), which is the switch between soft and hard. This is not a matter of statistics as with BatchNorm: eval() changes the mathematics of the model itself, from “a mixture of 16 functions” to “one function fixed by argmax”. So both are measured every time, and the gap between them (the discretization gap) is monitored.

Visualization: what the learned circuit looks like

Section titled “Visualization: what the learned circuit looks like”

What to read from the log above: soft and hard rise almost together, and hard accuracy ends up around 0.86. That is: 4,000 gates that hold no real-valued weights and perform no multiplication get 86% of handwritten digits right. Below, three figures show what this circuit looks like.

Figure 1: an overview of the learned circuit

Section titled “Figure 1: an overview of the learned circuit”

The whole picture first. With 4,000 gates all nodes cannot be drawn, so plot_circuit switches automatically to an overview (layers as boxes, arrows annotated with the number of wires). Comparing it with the all-node drawing in Appendix: XOR shows how the same API changes its display with scale.

What to read from it: 400 input wires pass through two LutLayers (2,000 gates each) and drop into 10 classes at the GroupSum — a single straight path. No branches, no convolutions, no normalization; 86% comes out of exactly this simplicity.

Figure 2: training curves (soft and hard)

Section titled “Figure 2: training curves (soft and hard)”

The two curves soft (orange) and hard (green) are overlaid. Hard is the real one: it is the score of the circuit you can burn. The gap between the two curves is the discretization gap.

What to read from it: the small gap the two curves open early on closes as training proceeds. In other words “the model being trained” and “the circuit after burning” converge to the same thing, and it is in a state where you can take it out as a circuit as is. If only orange rose and green failed to follow, that would be a sign that the gate mixtures are sitting in an intermediate state (undecided about which logic function to be), and you would suspect the amount of training, tau, or the parameterization.

Figure 3: the digits the circuit got wrong

Section titled “Figure 3: the digits the circuit got wrong”

Ten images hard eval got wrong, shown as the bit patterns the circuit actually received (after round()). You cannot judge “why it got them wrong” unless you look at the post-processing form.

What to read from it: what lines up is mostly pairs a human would hesitate over too — 4 and 9, 7 and 1, 5 and 3 — which shows the circuit is capturing shape properly. If it were full of unrelated pairs (reading a 0 as a 7, say), you would suspect undertraining.

Digging deeper into the evaluation: weak spots and decisiveness

Section titled “Digging deeper into the evaluation: weak spots and decisiveness”

A single overall accuracy number tells you neither “which class is weak” nor “how confidently it answers”. So two more quantities are measured.

  • Per-class hard accuracy … identifies the digits it is bad at
  • Margin … the top-1 logit −-− the top-2 logit. It expresses by how much that one image was won. A GroupSum logit is “how many of the 200 gates for that class emitted a 1” divided by tau, so the margin reads plainly as a vote difference

Putting the margin side by side for soft and hard measures how much of the decision’s sharpness was lost by discretization, from an angle independent of the accuracy number.

Groundwork for Figure 4: computing per-class accuracy and the margins

Section titled “Groundwork for Figure 4: computing per-class accuracy and the margins”

Figure 4: which class it is weak at (left) and the sharpness of its decisions (right)

Section titled “Figure 4: which class it is weak at (left) and the sharpness of its decisions (right)”

On the left, per-class hard accuracy (dashed line = overall average, orange = the weakest class); on the right, a histogram of the margins (orange fill = soft, green outline = hard).

What to read from it (written up front, since this is the last figure): on the left, 0 and 1 are easy while classes with many look-alike siblings — 8, 5, 2 — sink; a bias that a single overall accuracy cannot show becomes visible here for the first time. On the right, the soft and hard distributions almost coincide. That means the sharpness of the decision was not lost by discretization — that is, it is fine to turn this into a circuit as is. If only the hard side had piled up near 0, that would be a sign of information being dropped by the argmax.

ThermometerEncoder

Section titled “ThermometerEncoder”

Defined in: griffith_logic.encoding.thermometer.ThermometerEncoder (class)

Thermometer encoding layer.

Arguments

  • bits — number of bits z per feature (the number of thresholds)
  • mode — ‘uniform’ (evenly spaced) | ‘distributive’ (empirical quantiles)
  • input_bits — number of quantization bits B for the input when converting to IR (export_ir). With None (the default) the encoder stays at the boundary (outside the IR). When set, the extractor takes the per-feature B-bit code c (LSB first, position d·B + j) as input, treats it as the real value q = c / (2^B − 1) (the same as ToTensor’s uint8 → [0, 1]), and bakes the threshold comparison into the truth table of a B-input lut_layer. The torch forward still receives the real value q as before

Attributes

  • thresholds — (bits, n_features) thresholds (fixed after fitting)

DWNLayer

Section titled “DWNLayer”

Defined in: griffith_logic.layers.dwn.DWNLayer (class)

The DWN LUT layer: binary input → n-input LUT × n_luts → binary output.

Arguments

  • in_bits — number of input bits
  • n_luts — number of LUTs (RAM nodes) = number of output bits
  • n_inputs — number of inputs n per LUT
  • mapping — ‘random’ (fixed random connections) | ‘learnable’ (Learnable Mapping)
  • efd — EFD coefficient: ‘paper’ (1/(H+1)) | ‘official’ (α·β^H) alpha, beta: coefficients for efd=‘official’ (the official defaults when None)
  • ste — binarize the output to {0,1} (official default True)
  • clamp_luts — clamp the tables to [−1,1] on every forward during training (official default True)
  • lm_tau — softmax temperature of the Learnable Mapping

LearnableMapping

Section titled “LearnableMapping”

Defined in: griffith_logic.layers.dwn.LearnableMapping (class)

Layer that learns the input→LUT connections by gradient descent.

During training it keeps a weight matrix W ∈ ℝ^{in×out}, and by default the forward is the hard selection x_{argmax(W[:,i])} (no inference-time overhead).

Progressive wiring hardening (adapted from the two-phase scheme of SparseLUT arXiv 2503.12829): With forward_mode=‘soft’ the forward becomes the soft mixture x @ softmax(W/tau_soft, dim=0) (pure autograd, no discontinuous jumps in selection). ProgressiveWiringScheduler decays tau_soft geometrically and switches to forward_mode=‘hard’ (the usual argmax+STE) later in training. This is the lever introduced after wiring learning with hard selection collapsed in. Eval is always hard argmax (forward_mode is only consulted during training).

Arguments

  • in_features — number of input bits P
  • out_features — number of output bits Q (= number of LUTs × inputs per LUT)
  • tau — softmax temperature for the backward pass (official default 0.001)

DWNClassifier

Section titled “DWNClassifier”

Defined in: griffith_logic.models.dwn.DWNClassifier (class)

Classifier built from thermometer encoding + multi-layer DWN LUTs + popcount aggregation.

Arguments

  • in_features — number of real-valued input features D
  • n_classes — number of classes k
  • layer_widths — number of LUTs in each DWNLayer (the last one must be divisible by n_classes)
  • bits — bits per feature for thermometer encoding
  • encoder_mode — ‘uniform’ | ‘distributive’ (distributive requires fit_encoder)
  • n_inputs — number of inputs n per LUT
  • mapping — connection scheme of the first layer: ‘random’ | ‘learnable’ (later layers are fixed to random)
  • efd — EFD coefficient: ‘paper’ (1/(H+1)) | ‘official’ (α·β^H)
  • tau — GroupSum temperature (official default 1/0.3)

ConditionalSum

Section titled “ConditionalSum”

Defined in: griffith_logic.models.llvit.ConditionalSum (class)

Dense encoded-value summation after binary LUT outputs.

During training this uses fp32 encoded values. When use_quantized_eval=True and the module is in eval mode, the encoded values are symmetrically quantized to int4-style levels and dequantized for forward execution.

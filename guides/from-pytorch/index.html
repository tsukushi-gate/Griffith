PyTorchユーザーのための対応表

このライブラリは 普通の PyTorch である。nn.Module を継承し、loss.backward() が通り、 torch.optim がそのまま使える。だから移行は速い。

一方で 意味が違うだけで名前が同じものがいくつかあり、そこが事故の温床になる。 最たるものが model.eval() で、PyTorch では Dropout と BatchNorm の挙動が変わるだけだが、 ここでは モデルの数学そのものが変わる(実数の混合 → ブール回路)。

このページは PyTorch の語彙から本ライブラリの語彙への 翻訳表である。

PyTorch もこれからなら

このページは PyTorch を書ける人向けの翻訳表である。NN 自体が初めてなら、 先に 入門コース(全3本)を走らせるのが近道 ── PyTorch の基礎 → MLP で MNIST → 同じ問題を DLGN へ置き換え、まで実行つきで通る。 考え方だけ先に掴みたいなら NNからDLGNへ。

このページで分かること

  1. 対応表 — nn.Linear / nn.Conv2d / 出力層 / 最適化 / エクスポートの置き換え先
  2. model.eval() の意味の違い — soft から hard への切り替えと離散化ギャップ
  3. PyTorch の常識が通じない点 — 浮動小数点前提の技法、pretrained 資産がないこと

最小の対応 — 同じネットを 2 通りで書く

Section titled “最小の対応 — 同じネットを 2 通りで書く”

見た目はほとんど同じで、loss.backward() も optimizer.step() も変わらない。 違うのは 1 ニューロンの中身である。nn.Linear の 1 出力が「入力全部の重み付き和」なのに対し、 LutLayer の 1 出力は 入力線のうち N 本だけを疎に拾う LUT(真理値表)1 個であり、 学習されるのは重みではなく 「どの論理関数になるか」 である。

model.eval() の意味が違う

Section titled “model.eval() の意味が違う”

PyTorch で eval() が変えるのは Dropout と BatchNorm の挙動だけで、 同じ関数の近似が返る。ここでは違う。

soft(train())hard(eval())
入力[0,1][0,1][0,1] の実数round() で 0/1 のビット
LUT 重みsoftmax(W)(全 2N2^N2N エントリに配分)one_hot(argmax(W))(1 エントリのみ)
出力実数ビット
意味連続近似がどれだけフィットしているか論理回路としての真の性能

この 2 つの精度差を 離散化ギャップ と呼ぶ。

ギャップ解釈打ち手
0〜0.5pt健全。ゲートが特定のエントリへ十分収束しているそのまま
1pt 以上連続近似には効いているが回路になると崩れるエポック増 / パラメータ化を見直す
soft も低いそもそも学習できていないlr・τ・容量(k, 層数)を疑う

焼く前に必ず hard eval を見る

連続の真理値表が 0.5 付近に密集したまま丸めると精度は崩壊する。 実例として、eval acc 0.803 のモデルがエントリを丸めた途端 0.211 まで落ちたケースがある (BatchNorm 統計を再較正しても 0.632 止まり)。 soft の成績は回路の成績ではない。

ギャップを構造的に 0 にする選択肢もある。selection='hard_st'(forward は argmax、 backward だけ softmax の勾配で近似する CAGE 方式)、warp パラメータ化(実測 −0.06pp)、 DWN(train/eval のロジット差 0.0)がそれにあたる。

PyTorch の常識が通じない点

Section titled “PyTorch の常識が通じない点”

正直に列挙する。ここを知らずに始めると必ず詰まる。

1. 見るべき指標は soft ではなく hard

Section titled “1. 見るべき指標は soft ではなく hard”

学習は soft でしか進まないが、成績表として意味があるのは hard の方である。 test_acc が hard、test_acc_soft が soft。慣れるまでは逆に読みがちなので注意。

2. 事前学習資産が使えない

Section titled “2. 事前学習資産が使えない”

timm / torchvision / HuggingFace のような pretrained の生態系が存在しない。 しかも「強い実数モデルを変換すれば済む」も成り立たない ── 蒸留 / 転写初期化 / 層別二値蒸留の 3 経路を実測して、いずれもスクラッチ学習を上回らなかった(転写初期化は大きく劣化)。 native DLGN の強みは自由なブール論理を学べることで、算術構造の転写はその自由を縛るためである (→ DLGNの分類と系譜)。

現実解は スクラッチ学習か、実数のまま残すべき部分を残す ハイブリッド化(Transformer の MLP だけ LUT へ置換する等)。

3. 浮動小数点前提の技法が意味を失う

Section titled “3. 浮動小数点前提の技法が意味を失う”

最終成果物は乗算を含まないブール回路である。したがって

  • 精度(FP16/BF16/量子化)のチューニングは推論側では無意味 ── 出力は 0/1 のビットしかない
  • 重みの大きさそのものに意味がない。意味を持つのは「どのエントリが最大か」だけ
  • 正則化の主戦場は離散化ギャップの管理であって、重みのノルムではない
  • 数値誤差ではなくビット一致で正しさを測る(3段等価性)

4. 学習率のスケールが違う

Section titled “4. 学習率のスケールが違う”

Adam で 1e-3 前後という感覚は通じない。0.01 が既定で、 independent や深い直列構成では 0.1〜0.3 まで上げる。 「損失が初期値から動かない」の第一容疑者は常に学習率である。

5. 「層の幅」の意味が違う

Section titled “5. 「層の幅」の意味が違う”

LutLayer(in, out) の out は ゲート数であり、そのまま回路の面積になる。 MNIST では 2,000(スモーク)〜 64,000(論文再現)の桁で動かす。 nn.Linear の隠れ次元より 1〜2 桁大きい数字が普通、という点で見た目が驚く。

6. GPU が要らないのは推論側だけ

Section titled “6. GPU が要らないのは推論側だけ”

学習は PyTorch 上の実数計算なので、学習時は GPU があると速い。 「GPU 不要」は焼いた後の回路の話である(CUDA は必須ではなく、CPU / MPS でも動く)。

7. アーキテクチャ以外に 3 つの軸がある

Section titled “7. アーキテクチャ以外に 3 つの軸がある”

PyTorch では「層の選択」がほぼ設計のすべてだが、ここでは パラメータ化 / 選択(selection)/ 学習則という直交する 3 軸が加わる。 何を選べばよいかは 何を使えばいいのか(選択ガイド) にまとめてある。

8. nn.Linear の置き換えは 1:1 ではない

Section titled “8. nn.Linear の置き換えは 1:1 ではない”

nn.Linear(784, 256) を LutLayer(784, 256) に置き換えても等価にはならない。 1 ゲートは N 本しか入力を見ないので、同じ表現力を得るにはゲート数を大きく取り、層を重ねる 必要がある。ハイブリッド化 API(LogicSpec(n_inputs=2, depth=2, neurons_per_output=8))が depth と neurons_per_output というつまみを持つのはこのためである。

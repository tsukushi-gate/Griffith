クラウドGPU

論理ゲートネットワークは 推論には GPU が要らない(それが売りである)が、 学習には GPU が効く。とくに 6 万ゲート級・200 エポック級の再現実験は、 ローカル CPU では現実的な時間に収まらない。 このページは「どこで回すか」を決めるためのガイドである。

このページで分かること

  1. デバイスの使い分け — CPU / MPS(Apple Silicon)/ CUDA をどの規模で選ぶか
  2. クラウドへ投げる手順 — 同じスクリプト・同じ引数のままクラウド GPU で走らせる実行例
  3. 長時間ジョブの作法 — デタッチ実行・成果物の回収・監視の考え方

まずローカルで動く

Section titled “まずローカルで動く”

本ライブラリは CUDA を必須にしていない。CUDA カーネルは高速化のための任意機能で、 利用できない環境では自動的に Python 実装へフォールバックする。

デバイスは指定しなければ cuda → mps → cpu の順に自動検出される。 明示したいときは設定の run.device に書く。

デバイス選択の目安

Section titled “デバイス選択の目安”
デバイス何に使うか目安の規模備考
CPU実装の健全性チェック、XOR・パリティなど論理関数の学習、CI〜数千ゲート・数分決定的に回るので回帰テスト向き。logic_xor レシピは数秒
MPS(Apple Silicon)ローカルでの MNIST スモーク、UI・エディタの動作確認〜1万ゲート・十数分CUDA カーネルは使われず Python 実装で動く
CUDA(ローカル GPU)標準的な実験の主戦場1万〜6万ゲート・数十分LUT カーネルが JIT コンパイルされ最速
クラウド GPU論文再現、長時間 run、ハイパーパラメータ掃引6万ゲート以上・時間単位手元を閉じても走り続けられる

推論側に GPU は要らない

学習が終わって IR → HDL へ落とした後の回路は、FPGA でも CPU のビット演算でも動く。 GPU が要るのは訓練時の連続緩和を回している間だけである (→ パラメータ化を選ぶ の「推論時の性能差はゼロ」)。

Section titled “クラウド GPU で回す”

長時間ジョブの作法

Section titled “長時間ジョブの作法”

数時間走るジョブでは、次の 3 点を守ると事故が減る。

1. デタッチして投入する

Section titled “1. デタッチして投入する”

同期呼び出しは避ける

クラウド関数を同期的に呼ぶ(結果をポーリングして待つ)形にすると、 クライアント側がポーリングを止めた時点でジョブごとキャンセルされ得る。 投入は非同期(spawn)経由にし、待ちたい場合だけ明示的に結果を取りに行くこと。 同梱のエントリポイントと griffith launch --modal / griffith sweep --modal はこの形になっている。

2. 監視を張る

Section titled “2. 監視を張る”

投入したら放置せず、ログを追うか無出力検知を同時に回す。

「静かだから順調」とは限らない。ハートビート(epoch / step / loss)が 数サイクル同じ値なら、直接ログを見に行くこと。

3. 成果物を回収する

Section titled “3. 成果物を回収する”

学習の成果はコンテナと一緒に消えては困るので、永続ボリュームと実験トラッキングの 両方に残す設計になっている。

ボリューム名は環境変数 MD_MODAL_VOLUME で指定する(未設定なら既定名が使われる)。 griffith collect も同じ変数を見るので、シェルの初期化ファイルか .env に一度書いておけばよい。

チェックポイントは実験トラッキング側(wandb Artifacts)にも上げられる。 アップロード量は環境変数で制御する。

WANDB_ARTIFACTS動作
offアップロードしない
best(既定)訓練終了時に best のみ 1 回
all定期保存もすべて

つまずきどころ

Section titled “つまずきどころ”
症状原因対処
手元を閉じたらジョブが消えたデタッチせずに投入した--detach と --background をセットで付ける
コールドスタートが毎回 2〜3 分遅いCUDA カーネルのJITコンパイル(キャッシュはコンテナローカル)想定どおり。多数を並列投入する前に 1 本だけ先に走らせる
投入したのに始まらない同時実行 GPU 数の上限に達してキューで待っている投入前チェック(scripts/modal_preflight.py)で上限超過を検出する
ローカルでは動くのにクラウドで落ちるデータやチェックポイントを絶対パスで参照している相対パス規約に従う(スクリプトは無改造で動く前提)
GPU を使っているはずが遅いCPU にフォールバックしている起動ログの「デバイス: …」行を確認する

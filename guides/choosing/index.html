何を使えばいいのか(選択ガイド)

このライブラリは選択肢が多い。アーキテクチャ 20 種以上 × パラメータ化 5 種 × fan-in(N)3 種 × 学習則 4 種。全部を理解してから始める必要はなく、 実際には タスク と デプロイ先の制約 の 2 つでほぼ決まる。

このページは「私は何を使えばいいのか」に 1 ページで答える ための決定表である。

まず迷ったらこれ

LutLayer(n_inputs=2, parameterization='softmax') を数段 + GroupSum(k, tau=10)、学習則は bp。

これが difflogic 互換の基準線で、精度で頭一つ抜ける構成でもある (MNIST 6層 50ep で hard 97.74%)。ここから外れる理由ができたときだけ、 以下のフローチャートで選び直せばよい。

選択は 4 つしかない

Section titled “選択は 4 つしかない”

4 つは 直交している(→ アーキテクチャ全体像)。 アーキテクチャを変えてもパラメータ化の選び方は変わらないし、その逆も同じである。 なので順に決めてよい。

事前学習モデルからの「変換」は近道にならない

「強い MLP を DLGN へ変換すれば強くなる」は成り立たない。社内で 3 経路 (蒸留 / 疎化 fan-in 集合の転写初期化 / 層別二値蒸留)を実測したが、 いずれもスクラッチ学習を上回らなかった。転写初期化は大きく劣化した。 native DLGN の強みは「ゲートを自由なブール論理として学べること」にあり、 算術構造を転写するとその自由が制約になるためである (→ DLGNの分類と系譜)。

現実解は 2 つ: スクラッチ学習するか、実数のまま残すべき部分を残す ハイブリッド化。「どこまで論理化できるか」を段階的に測りたいなら 論理化の梯子 が実験の型になる。

2. デプロイ先 → fan-in(N)

Section titled “2. デプロイ先 → fan-in(N)”

1 ゲートが何本の入力を読むか。「どちらが偉いか」ではなくデプロイ先で決まるノブである。

目的有利な N
FPGA 実装面積6
CPU / GPU 推論速度2
訓練の安定性2

N が増えるとゲートあたりのパラメータが 2N2^N2N で増え、訓練メモリも増える。 difflogic が 2 入力を選んだのは「FPGA に最適だから」ではなく、 訓練の綺麗さ(厳密勾配の 16 ゲート)と CPU/GPU 速度のためである (→ DLGNの分類と系譜)。

3. N → パラメータ化

Section titled “3. N → パラメータ化”

真理値表をどの連続空間で持つか。ここでの選択が離散化ギャップを直接決める。

5方式の性格

Section titled “5方式の性格”
方式重みの持ち方パラメータ数/ゲート表せる hard 関数由来
softmax(N=2)16 ゲート上の softmax16全 16 関数difflogic(DLGN)
softmax(N≥4)2N2^N2N エントリ上の softmax2N2^N2N単一 minterm か FALSE のみ—

raw[0,1][0,1][0,1] の実数を直接保持2N2^N2N全 22N2^{2^N}22N 関数BinaryBrain
warpWalsh–Hadamard 係数 + Gumbel2N2^N2N全 22N2^{2^N}22N 関数WARP

競合するか独立かが本質的な違いである。

softmax は 1 つ上げると他が下がるので、1 回の backward で全パラメータへ勾配が連動して届く。 independent は該当エントリにだけ届く代わりに、任意のビットパターンを作れる。

N=6 で 1 万ゲートなら 64 万 vs 6 万。iwp は 10 倍以上軽く学習も速いが、 XOR のような「組み合わせが本質」の関数を表現できないのが代償である。 LDDLGN の論拠は「学習済みモデルのゲートは大半が AND/OR/NOT に収束する」という観察で、 実際に XOR 系に収束するゲートはごく少数だった、という実証に賭けている。

確定知見: N≥4 の softmax は選んではいけない

Section titled “確定知見: N≥4 の softmax は選んではいけない”

N≥4 の softmax は 16 ゲート表ではなく 2N2^N2N エントリ上の単体(simplex) になる。 合計が 1 なので離散化(確率 > 0.5)で立てられるビットは高々 1 個 ── つまり hard 表として作れるのは 単一 minterm か恒偽(FALSE)だけである。 パススルー・OR・XOR といった日常的な関数が構造的に作れない。

実験でも、畳み込み構成で softmax を independent に替えただけで 半分のエポック数にもかかわらず精度 +3.2pt。全結合 MNIST でも softmax N=4 は hard 94.54% / ギャップ 1.12pp にとどまり、同条件の warp N=4(95.50% / 0.14pp)に劣る。 表現力の欠落は学習量では埋まらない、というのがこの知見の要点である。

確定知見: independent は学習率を上げる

Section titled “確定知見: independent は学習率を上げる”

independent は sigmoid 経由で、飽和気味の初期化と組み合わさると 深い直列合成で勾配が急速に減衰する。実測では勾配ノルムが 10−510^{-5}10−5 程度まで落ち、 既定の lr=0.02 では 10 エポック回しても soft 精度が動かなかった。lr ≥ 0.3 で学習が進む。

4. 環境の制約 → 学習則

Section titled “4. 環境の制約 → 学習則”

「どのゲートになるか」を学ぶには、各ゲートの重みへ誤差をどう配るかを決める必要がある。 既定は bp で、それ以外を選ぶ動機は 「逆伝播の経路まで回路に実装したくない」 という一点にある。

学習則微分は要るか制約使いどころ
bp要る(全経路)なし。共通ランナー run_training が扱う唯一の則既定。精度が最優先のとき
dfa局所的にのみ出力が 2D/3D、block_upstream=True のみ層間の逆伝播を切りたい。層内の勾配は正確なまま
ap不要parameterization='independent' 前提。全結合の直列形のみbackprop 非依存の実証
eggroll不要(forward のみ)2D パラメータのみ。評価回数がコストhard 精度そのものを直接最適化したいとき

AP 法の到達点と限界(数字を出すときの注意)

MNIST 全結合で soft ≈ 0.90 / hard ≈ 0.85 で安定する一方、同条件の BP 法は soft 0.983 / hard 0.977 で、BP に 6〜8pt 届かない。 さらに Conv ツリー + OrPooling 構成では accuracy ≈ 0.11(chance)へ崩壊する。 原因は「単調性の破れ」ではなく、OR 系の集約を経由した誤差ルーティングが 有用な学習信号を作らないことにあった ── つまり 接続構造と学習則は独立に設計できない。

「AP 法で MNIST 98%」は誤り。98% はすべて BP 法の数字である。 数字を出すときは必ず学習則を明記すること。

学習則はモデル全体ではなく 層ごとに指定でき、with_learning + HybridTrainer で 「特徴抽出は bp、出力ヘッドだけ dfa」といった混在が書ける (→ 学習則(BP/AP/DFA/ES))。

選択に共通する原則

焼く前に必ず hard eval を見る。 soft の成績は連続近似の成績であって、 回路の成績ではない。連続の真理値表が 0.5 付近に密集したまま丸めると精度は崩壊する (実例: eval acc 0.803 → 丸めると 0.211)。 このライブラリで「良い選択」とは、hard 精度が高く、かつ soft と hard の差が小さい選択のことである。
